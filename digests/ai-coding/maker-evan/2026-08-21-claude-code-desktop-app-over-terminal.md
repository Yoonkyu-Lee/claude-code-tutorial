# 이제 터미널 안 씁니다 — 클로드 코드 데스크탑 앱으로 바뀐 것들

> maker-evan · 2026-08-21 · 14,204회 · 10분 14초(614초) · [영상 링크](https://youtu.be/qGtDJ2FwNFc)
> 정리 방식: 시간순 심층 워크스루 (paraphrase) + 주제별 상세 요약
> 검증 배너: 앱 기능·단축키·토큰 절감폭·버그 사례는 모두 **화자의 사용 경험 기반 주장(미검증)**. 공식 문서로 교차 확인하지 않았다.

## 요약 (주제별)

### 1. 영상의 핵심 논지 — "기능"이 아니라 "손이 가는 횟수"
- 화자는 클로드 코드를 쓰면서 터미널을 거의 안 쓰게 됐고, 하루 종일 한 번도 안 여는 날도 있다. 이유는 데스크탑 앱이 **올해 4월에 화면이 통째로 재설계**됐기 때문(주장/미검증) — 세션 목록과 격자 작업 공간이 생겼다.
- 앱을 평가하는 기준을 "예쁘다"가 아니라 **같은 일을 하는 데 손이 몇 번 덜 가느냐**로 못박고, 그 몇 번이 하루 수십 번 쌓이면 일의 양 자체가 달라진다고 본다. `[의견]`
- 관통 명제 두 개: "도구가 귀찮으면 사람이 일을 줄인다. 그게 진짜 손해다"[02:14], "도구가 바뀌면 습관이 바뀌고 습관이 바뀌면 결과가 바뀐다"[03:11]. `[의견]`

### 2. 세션 관리 — 목록 + 단축키 + worktree 격리
- **터미널의 문제**: 여러 세션을 굴리려면 탭/분할/새 창을 늘리게 되고, 어느 창이 어느 프로젝트인지 헷갈린다. 화자 본인이 엉뚱한 창에 명령을 쳐 넣은 적이 여러 번. 이전 대화 재개도 명령어 → 목록 호출 → 눈으로 훑기 → 번호 선택 순서를 거쳐야 한다.
- **앱**: 왼쪽에 세션 목록이 항상 떠 있고 실행 중/완료/중단 상태가 한 줄씩 보인다. 클릭 한 번으로 대화 진입, **Ctrl+Tab**=다음 세션, **Cmd+N**=새 세션. 상태 필터·프로젝트별 그룹핑이 있고, 끝난 세션은 자동으로 목록에서 내려간다.
- **격리**: 세션마다 **git worktree**로 저장소 사본을 하나씩 준다(프로젝트 안 숨은 폴더). 두 세션이 같은 파일을 동시에 고쳐도 서로 밟지 않고, 브랜치 접두어도 커스터마이즈 가능(주장/미검증).
- 터미널에서 같은 걸 하려면 워크트리 생성·이동·삭제를 손으로 해야 해서, 화자는 귀찮아서 결국 한 번에 하나씩만 시켰다고 인정한다.

### 3. 전환 비용 — 프로젝트·모델·실행 위치
- **프로젝트 전환**: 터미널은 폴더 이동 → 재실행 → 로딩 대기. 앱은 목록에서 폴더를 고르면 끝이고, 그 폴더의 규칙 파일이 자동으로 따라와 어디서 시작하든 같은 설정·같은 스킬이 물린다.
- **실행 위치**: 원격에서 일할지 내 컴퓨터에서 일할지를 같은 자리에서 고르고, 클라우드에 띄워 저장소를 여러 개 붙일 수도 있다(주장/미검증).
- **모델 전환**: 보내기 버튼 옆 목록에서 바로 교체되고, 현재 모델이 계속 눈에 보인다. 화자는 "무거운 설계는 좋은 모델, 단순 정리는 빠르고 싼 모델"이라는 판단을 하루에도 여러 번 하는데, **명령어를 외워야 하는 일은 결국 안 하게 된다**는 이유로 이 가시성·1클릭을 크게 평가한다. `[의견]`

### 4. 브라우저 자동화 — 영상이 꼽은 최대 차이
- **터미널 방식의 벽 ①**: Playwright 같은 도구를 붙이면 클로드가 새 창을 띄우는데 그건 "완전히 남의 브라우저"라 쿠키·세션·저장된 계정이 없다. 로그인 화면 앞에서 멈추고, 직접 로그인해 주거나 인증 정보를 따로 주입해야 한다.
- **터미널 방식의 벽 ②(더 아픈 쪽)**: 페이지를 한 번 읽을 때마다 화면 구조가 통째로 넘어와 복잡한 페이지는 **5만 토큰을 넘기기도 한다**(주장/미검증). 클릭 몇 번에 대화 한 판이 날아가, 정작 시키려던 일 전에 지친다.
- **앱 방식**: 크롬 확장으로 **지금 쓰고 있는 로그인된 크롬을 그대로** 쓴다. 새 창 없이 열린 탭을 그대로 보고, 스튜디오·메일·문서 도구에 이미 들어간 상태로 시작한다. 컨텍스트 소모는 **전체 창의 10% 미만** 수준(주장/미검증). 확장 1회 설치만 하면 준비 작업이 사라진다.
- 화자가 체감 차이를 가장 크게 느낀 지점: 터미널에선 브라우저를 시킬 때마다 마음의 준비를 했는데, 앱에선 그냥 시키고 대체로 그냥 된다. `[의견]`

### 5. 작업 공간(UI) 기능들
- **격자 레이아웃**: 창을 격자로 나누고 어느 칸에 뭘 넣을지 드래그로 배치. 화자의 현재 구성은 **왼쪽=대화 / 가운데=변경 내용(diff) / 오른쪽=미리 보기** 3분할.
- **내장 터미널**: **Ctrl+백틱(`)** 으로 열리며 **현재 세션이 작업 중인 폴더에서** 열린다 → "터미널을 버리는 게 아니라 안으로 넣는 것"[05:17].
- **내장 편집기 + diff**: 대화에 뜬 파일 경로를 누르면 그 자리에서 열리고, 그 사이 디스크에서 파일이 바뀌었으면 알려준다. diff 화면을 보게 된 뒤 되돌리는 일이 확 줄었다(주장/미검증).
- **미리 보기 칸**: 웹페이지·문서·이미지를 띄우고 로컬 서버를 돌려 실제 화면으로 확인 → 만들고 보고 고치는 사이클이 한 창에서 끝난다.
- **표시 상세도 토글 (Ctrl+O)**: 도구 사용 내역 전체 보기 ↔ 결론만 보기를 순환. 화자는 "감시할 때는 전부, 믿고 맡길 때는 결과만". `[의견]`
- **옆 대화 (Cmd+;)**: 대화를 옆으로 분기해 잠깐 딴 걸 물어보되 그 내용이 원 대화로 넘어가지 않는다. 터미널에선 세션을 하나 더 띄워야 해서 창 증식 문제로 되돌아간다.

### 6. 백그라운드 자동 실행과 활동 대시보드
- 사람이 안 볼 때 도는 기능이 있고, 트리거는 세 갈래 — **정해진 시간(스케줄) / 저장소 이벤트 / 외부 신호(웹훅류)**. 한 규칙에 여러 트리거를 같이 걸 수도 있다(주장/미검증).
- **요금제에 따라 하루 실행 횟수 상한**이 있다.
- 활용 예: 검사(테스트)가 실패하면 알아서 고쳐보게 하기, 다 통과하면 알아서 병합하게 하기. 완료 시 알림이 뜨므로 다른 일 하다 확인.
- **활동 대시보드**: 세션 수, 어떤 모델을 얼마나 썼는지가 보인다. 화자는 이걸로 자기 습관을 처음 숫자로 봤다.
- 터미널로도 예약 실행은 가능하고 "오히려 그쪽이 자유롭다"고 인정하지만, 스크립트 작성·시간 설정·로그 확인이 필요해 **대부분은 그 설정을 끝까지 안 한다**는 게 화자의 판단. `[의견]`

### 7. 리스크·주의 — 편할수록 사람이 선을 긋는다
- 로그인된 브라우저를 쓴다는 건 그만큼 위험도 함께 온다는 뜻. 확장을 붙였다고 아무거나 시키면 안 된다.
- 화자의 개인 규칙: **결제나 게시처럼 되돌리기 어려운 일은 직접 확인하고 자기가 누른다.** "편한 도구일수록 어디까지 맡길지는 사람이 정해야 한다"[04:59]. `[의견]`
- 운영 습관: 앱이 가끔 화면을 제대로 안 그리므로 **중요한 작업 전에는 한 번 재시작하고 시작한다.**

### 8. 앱의 버그 — 숨기지 않고 나열한 부분
- 앱 실행 직후 코드 화면이 그대로 죽는 문제 — 원인은 **앱 껍데기와 안쪽 실행 파일(CLI)의 버전 불일치**.
- **유령 폴더 탭** — 지워지지도 않고, 열면 그런 폴더가 없다고 나온다.
- **윈도우 쪽이 더 시끄러웠다** — 설치 실패, 시작 지연 30초, 메모리 20GB 사용 보고까지 올라왔다.
- 그중 몇 개는 **고치지 않겠다는 답**이 나와 사용자들이 크게 반발했고, 화자도 그 반응이 이해된다고 한다. (모두 화자 목격/전문 기반, 미검증)
- 그럼에도 쓰는 근거: **"버그는 시간이 지나면 고쳐지지만, 손이 많이 가는 구조는 시간이 지나도 안 고쳐진다. 후자가 훨씬 비싼 문제다"**[08:12]. `[의견]`

### 9. 터미널이 여전히 나은 자리 (3가지)
- **세밀한 조작**: 실행 시 붙이는 옵션들 — 모델 지정, 권한 범위, 반복 횟수 상한, 출력 형식. 이런 건 아직 앱 화면에 다 나와 있지 않다(주장/미검증).
- **자동화**: 다른 프로그램 안에 끼워 넣거나 스크립트로 엮어 돌리는 일은 지금도 터미널이 맞다.
- **원격**: 남의 서버에 붙어 그 안에서 일할 때는 터미널이 더 빠르고 확실하다.

### 10. 결론 — 갈아타기가 아니라 기본값 이동
- 앱과 터미널은 **같은 엔진 · 같은 규칙 파일 · 같은 설정**을 쓰고 스킬과 권한 규칙도 공유한다. 앱에서 하던 일을 터미널에서 이어서 해도 된다 → "갈아타는 문제가 아니라 손에 맞는 걸 골라 쓰는 문제"[09:15].
- 앱을 써도 **터미널 실력이 필요 없어지지 않는다** — 내장 터미널을 매일 쓰게 되고, 달라지는 건 "어디서 시작하느냐"뿐이다.
- 선택 기준: 세션 다중 운용 → 앱 / 프로젝트·모델 전환이 잦음 → 앱 / 브라우저 작업 → 앱(로그인 재사용·준비 작업 없음·토큰 절감) / 스크립트 자동화 → 터미널. 사실상 결론은 **둘 다 쓰기**이고, 화자는 기본으로 켜는 쪽만 앱으로 옮겼다.
- 실행 권유: 오늘 앱을 켜고 하던 세션 하나만 옮겨 보라 — 한 시간이면 감이 온다.

## 3줄 오리엔테이션
- 클로드 코드 데스크탑 앱이 올해 4월 UI를 전면 재설계했고, 화자는 그 뒤 기본 실행 창을 터미널에서 앱으로 옮겼다.
- 앱의 이점은 "화려한 기능"이 아니라 **같은 일에 손이 몇 번 덜 가느냐** — 세션 목록·워크트리 격리·모델 전환·로그인된 크롬 재사용·격자 작업 공간·백그라운드 실행.
- 그럼에도 앱에는 버그가 적지 않고, 세밀한 CLI 옵션·스크립트 자동화·원격 서버 작업은 여전히 터미널이 낫다. 결론은 "둘 다 쓰되 기본값을 앱으로".

## 전문 — 시간순 워크스루

### [00:00–00:24] 터미널을 안 여는 날이 생겼다
화자는 클로드 코드를 쓰면서 터미널을 거의 안 쓰게 됐다고 시작한다. 몇 달 동안 검은 창만 보고 살던 사람이 하는 말이라는 단서를 스스로 붙인다. 지금은 하루 종일 터미널을 한 번도 안 여는 날도 있다는 것.

> "저는 이제 클로드 코드를 쓰면서 터미널을 거의 안 [씁]니다. 몇 달 동안 검은 창만 보고 살던 사람이 하는 말입니다." [00:00]

이유는 클로드 코드가 더 이상 터미널 전용 물건이 아니기 때문이다. 데스크탑 앱이 있고, 단순히 존재하는 수준이 아니라 **올해 4월에 화면이 통째로 다시 만들어졌다**(주장/미검증). 세션 목록이 생겼고, 화면을 나눠 쓰는 작업 공간이 생겼다.

### [00:24–00:46] 영상의 약속 — 손이 몇 번 덜 가는지 세고, 버그도 숨기지 않는다
화자는 그 뒤로 일하는 방식 자체가 바뀌었다고 하고, 오늘은 그 차이가 정확히 어디서 나는지를 보여주겠다고 예고한다. "그냥 예쁘다"는 얘기가 아니라 **손이 몇 번 덜 가는지를 하나씩 세워보겠다**는 프레임을 미리 못박는다.

그리고 시작 전에 한 가지를 먼저 밝힌다 — 앱에도 버그가 있고, 그것도 적지 않다. 그 얘기를 뒤에서 숨기지 않고 그대로 하겠다고 약속한 뒤, 그럼에도 자신은 여전히 앱을 쓴다며 그 이유를 보자고 넘어간다. (영상 후반 [07:30] 이후에서 실제로 이 약속을 지킨다.)

### [00:46–01:10] 첫 번째 차이 — 터미널에서 세션 여러 개를 굴릴 때 생기는 혼란
첫 번째 차이는 **세션을 다루는 방식**이다. 화자는 요즘 일을 하나만 시키고 기다리는 사람은 거의 없다고 전제한다. 이쪽 저장소에서 기능 하나를 만들게 시켜 놓고, 저쪽에서는 어제 못 잡은 버그를 붙잡고 싶은 게 자연스러운 사용 패턴이라는 것.

터미널에서 이걸 하려면 결국 창을 나누게 된다. 탭을 열거나, 화면을 반으로 쪼개거나, 창을 하나 더 띄운다. 그러다 보면 **어느 창이 어느 프로젝트였는지 헷갈리고**, 화자 본인도 엉뚱한 창에 명령을 쳐 넣은 적이 여러 번 있다고 고백한다. 이전 대화를 이어가려면 명령어부터 쳐야 하고, 목록을 부르고 눈으로 훑고 번호를 골라 들어가야 한다.

### [01:10–01:43] 앱의 세션 목록 — 항상 떠 있고, 클릭 한 번이면 들어간다
앱에서는 왼쪽에 세션 목록이 항상 떠 있다. 지금 돌고 있는 것, 끝난 것, 멈춰 있는 것이 한 줄씩 보이고, 클릭 한 번이면 그 대화 안으로 그대로 들어간다.

단축키도 정리해서 소개한다(주장/미검증):
- **Ctrl+Tab** — 다음 세션으로 이동
- **Cmd+N** — 새 세션을 그 자리에서 열기

여기에 더해 **상태로 필터링**할 수 있고 **프로젝트별로 묶어서** 볼 수도 있다. 일이 끝난 세션은 알아서 정리되어 목록에서 내려간다.

### [01:43–02:03] 세션마다 폴더가 따로 — git worktree 기반 격리
화자가 "진짜 중요한 게 하나 더 있다"며 짚는 것은 **세션별 작업 폴더 분리**다. 앱은 git worktree 방식으로 세션마다 저장소 사본을 하나씩 준다. 프로젝트 안에 숨은 폴더가 생기고 각 세션이 거기에 자리를 잡는다.

그래서 두 세션이 같은 파일을 동시에 고쳐도 서로를 밟지 않는다. 브랜치 이름 앞에 붙는 접두어(prefix)도 원하는 대로 바꿀 수 있다(주장/미검증).

### [02:03–02:17] 도구가 귀찮으면 사람이 일을 줄인다
이걸 터미널에서 직접 하려면 손이 꽤 많이 간다 — 워크트리를 만들고, 옮겨 다니고, 끝나면 지워야 한다. 화자는 그 과정이 귀찮아서 결국 한 번에 하나씩만 시켰다고 인정한다. 그리고 이 영상 전체를 관통하는 명제를 여기서 처음 꺼낸다.

> "도구가 귀찮으면 사람이 일을 줄입니다. 그게 진짜 손해입니다." [02:14] `[의견]`

### [02:17–02:43] 두 번째 차이 — 프로젝트 갈아타는 비용
두 번째는 **갈아타는 비용**이다. 프로젝트 전환부터 보면, 터미널에서는 폴더로 이동해서 다시 실행해야 한다. 경로를 치고, 엔터를 치고, 다시 뜰 때까지 기다린다.

앱에서는 작업할 폴더를 목록에서 고르면 그걸로 끝이다. 그 폴더에 적어둔 규칙 파일(프로젝트별 CLAUDE.md류)도 알아서 같이 따라온다. 어디서 시작하든 같은 설정과 같은 스킬이 물려 있다. 또 **원격에서 일할지 내 컴퓨터에서 일할지도 여기서 고르고**, 클라우드에 띄워 놓고 저장소를 여러 개 붙일 수도 있다(주장/미검증).

### [02:43–03:00] 모델 전환도 버튼 하나
모델도 마찬가지다. 보내기 버튼 바로 옆에 모델 목록이 있고, 눌러서 고르면 그 자리에서 바뀐다. **지금 어떤 모델로 일하고 있는지가 계속 눈에 보인다**는 점을 화자는 강조한다.

화자는 이게 생각보다 훨씬 크다고 본다 — 무거운 설계는 좋은 모델에 맡기고 단순한 정리는 빠르고 싼 모델로 돌리는 게 맞다는 판단을, 하루에도 여러 번 하게 되기 때문이다. `[의견]`

### [03:00–03:17] 손이 가벼워야 실제로 바꾼다
자주 하려면 손이 가벼워야 한다는 논리로 이어진다. **명령어를 외워야 하는 일은 결국 안 하게 되고**, 눈에 보이고 한 번 누르면 되니까 실제로 바꾸게 된다.

> "도구가 바뀌면 습관이 바뀌고 습관이 바뀌면 결과가 바뀝니다. 이게 화면 하나가 가진 힘입니다." [03:11] `[의견]`

### [03:17–03:38] 세 번째 — 브라우저를 대신시키는 일 (영상의 핵심)
세 번째가 오늘 영상의 핵심이라고 화자가 직접 말한다: **브라우저를 대신시키는 일**. 요즘 일 중에 브라우저 안에서 끝나는 게 정말 많다 — 관리자 화면에 들어가 어제 숫자를 확인하고, 어딘가에 글을 하나 올리고, 로그인해야 볼 수 있는 자료를 받아온다.

이걸 터미널에서 클로드에게 시키려면 먼저 브라우저를 조종할 도구를 붙여야 한다. 보통 **Playwright**를 많이 쓴다.

### [03:38–03:56] 터미널 방식의 첫 번째 벽 — 남의 브라우저
그러면 클로드가 새 브라우저 창을 하나 띄우는데, 문제는 **그 창이 완전히 남의 브라우저**라는 점이다. 내 로그인 정보가 거기엔 없다. 쿠키도 없고, 세션도 없고, 저장된 계정도 없다.

그래서 볼 것도 못 보고 로그인 화면 앞에서 멈춘다. 직접 로그인을 해 주거나 인증 정보를 따로 넣어 줘야 한다.

### [03:56–04:11] 더 아픈 문제 — 페이지 한 번 읽는 데 5만 토큰
화자가 "더 아픈 건 따로 있다"며 꺼내는 건 **컨텍스트 비용**이다. 페이지를 한 번 읽을 때마다 화면 구조가 통째로 넘어오고, 복잡한 페이지는 그것만으로 **5만 토큰이 넘어가기도 한다**(주장/미검증). 클릭 몇 번에 대화 한 판이 통째로 날아가는 셈이고, 정작 시키려던 일을 하기도 전에 앞에서 지친다.

### [04:11–04:36] 앱의 해법 — 로그인된 내 크롬을 그대로 쓰는 확장
앱에서는 **크롬 확장**을 쓴다. 화자가 지금 열어 놓고 쓰고 있는 바로 그 크롬, 로그인되어 있는 그 상태를 그대로 쓴다. 새 창이 뜨지 않고 이미 열려 있는 탭을 그대로 본다. 스튜디오든 메일이든 문서 도구든 **이미 들어가 있는 채로** 시작한다.

컨텍스트도 훨씬 덜 먹는다 — 전체 창의 **10%가 안 되는 수준**으로 잡힌다(주장/미검증). 설치할 게 없는 건 아니어서 확장은 한 번 깔아야 하지만, 그 한 번이 끝나면 준비 작업이 사라진다.

### [04:36–04:47] 체감 차이가 가장 컸던 지점
화자는 이 차이를 체감으로 가장 크게 느꼈다고 말한다. 터미널에서는 브라우저를 시킬 때마다 마음의 준비를 했는데, 앱에서는 그냥 시키고 대체로 그냥 된다는 것.

> "잘 만들었다는 말이 나오는 지점이 여기입니다." [04:46] `[의견]`

### [04:47–05:01] 편할수록 사람이 선을 그어야 한다 (리스크)
곧바로 균형추를 단다. 확장을 붙였다고 아무거나 시키면 안 된다 — **로그인된 브라우저를 쓴다는 건 그만큼 위험도 같이 온다는 뜻**이다. 그래서 화자는 결제나 게시처럼 되돌리기 어려운 일은 직접 확인하고 자기가 누른다.

> "편한 도구일수록 어디까지 맡길지는 사람이 정해야 합니다." [04:59] `[의견]`

### [05:01–05:19] 네 번째 — 격자 작업 공간과 "안으로 들어온" 터미널
네 번째는 **작업 공간**이다. 앱은 창을 격자로 나눠 쓰고, 어느 칸에 무엇을 넣을지 직접 끌어다 놓는다. 터미널도 한 칸에 넣을 수 있는데, **Ctrl+백틱(`)** 을 누르면 바로 열리고, **지금 세션이 일하고 있는 그 폴더에서** 열린다.

> "그러니까 터미널을 버리는 게 아니라 안으로 넣는 겁니다." [05:17]

### [05:19–05:33] 내장 편집기와 변경 내용(diff) 화면
파일 편집기도 앱 안에 들어 있다. 대화에 뜬 파일 경로를 누르면 그 자리에서 열리고, 그 사이 디스크에서 파일이 바뀌었으면 알려준다. 바뀐 내용을 보는 화면(diff)도 따로 있어서 어디가 어떻게 달라졌는지 눈으로 훑고 넘어간다. 화자는 이걸 보고 나서 **되돌리는 일이 확 줄었다**고 한다(주장/미검증).

### [05:33–05:48] 미리 보기 칸 — 만들고 보고 고치는 게 한 창에서
미리 보기 칸도 있다. 웹페이지도 띄우고, 문서도 띄우고, 이미지도 본다. 로컬 서버를 돌려서 진짜 화면으로 확인할 수도 있다. 만들고 보고 고치는 사이클이 **한 창 안에서 끝난다**는 게 요지다.

### [05:48–06:00] 표시 상세도 토글 (Ctrl+O)
화자가 하나 더 마음에 들어 하는 건 **화면에 얼마나 보여줄지를 고를 수 있다**는 점이다. 도구를 어떻게 썼는지 전부 볼 수도 있고, 결론만 간단히 볼 수도 있다. **Ctrl+O**를 누르면 그 모드가 순환하며 바뀐다.

> "저는 감시할 때는 전부 보고 믿고 맡길 때는 결과만 봅니다." [06:00] `[의견]`

### [06:00–06:22] 옆 대화(사이드 대화) — Cmd+;
그리고 "옆 대화"라는 기능이 있다. **Cmd+세미콜론(;)** 을 누르면 대화가 옆으로 갈라진다. 작업 도중에 잠깐 따로 물어보고 싶은 게 생겼을 때 쓰고, **그 내용이 원래 대화로 넘어가지 않는다**. 흐름을 안 망치면서 딴 걸 물어보는 장치다.

이걸 터미널에서 하려면 세션을 하나 더 띄워야 하고, 그러면 또 창이 늘어나 [00:46] 구간에서 말한 첫 문제로 되돌아간다.

### [06:22–06:34] 화자의 3분할 레이아웃
화자는 요즘 화면을 셋으로 나눠 쓴다 — **왼쪽은 대화, 가운데는 바뀐 내용(diff), 오른쪽은 미리 보기**. 예전에는 이 셋을 보려고 창을 계속 갈아탔다는 대비를 붙인다.

### [06:34–06:52] 다섯 번째 — 사람이 안 보고 있을 때 도는 기능
다섯 번째는 화자가 늦게 발견한 부분이다. 앱에는 **사람이 안 보고 있을 때 도는 기능**이 있다. 트리거는 세 갈래로 소개된다(주장/미검증):
- 정해진 시간에 알아서 시작 (스케줄)
- 저장소에 무슨 일이 생겼을 때 시작 (저장소 이벤트)
- 외부에서 신호를 보내서 시작 (웹훅류)

하나의 규칙에 이걸 여러 개 같이 걸 수도 있다. 다만 **요금제에 따라 하루에 돌릴 수 있는 횟수가 정해져 있다**.

### [06:52–07:06] 자동 수정·자동 병합·알림
활용 예로 두 가지를 든다 — 검사(테스트/CI)에서 실패가 나면 알아서 고쳐보게 할 수 있고, 검사가 다 통과하면 알아서 합치게(merge) 할 수도 있다. 끝나면 알림이 뜨므로 다른 일을 하다가 그때 확인하면 된다.

### [07:06–07:14] 활동 대시보드 — 습관을 숫자로 보다
활동을 모아 보는 화면도 따로 있다. 세션이 몇 개였고 어떤 모델을 얼마나 썼는지가 보인다. 화자는 이걸 보고 나서 **자기 습관을 처음으로 숫자로 봤다**고 말한다.

### [07:14–07:30] 터미널로 같은 걸 하려면 — 할 수는 있지만 안 하게 된다
터미널에서 이걸 하려면 예약 실행을 직접 걸어야 한다. 스크립트를 짜고, 시간을 걸고, 로그를 따로 봐야 한다. 화자는 "할 수는 있다, 오히려 그쪽이 자유롭다"고 공정하게 인정하면서도, **대부분의 사람은 그 설정을 끝까지 안 한다**고 본다. 화면에 버튼으로 있으면 그냥 누른다는 것 — 그 차이라는 결론. `[의견]`

### [07:30–07:58] 약속했던 얘기 — 앱의 버그들
이제 도입에서 약속한 버그 얘기로 들어간다. 앱에는 버그가 꽤 있다며 구체 사례를 나열한다(모두 화자 목격/전문 기반, 미검증):
- 앱을 켜자마자 코드 화면이 그대로 죽는 일 — **앱 껍데기와 안쪽 실행 파일(CLI)의 버전이 안 맞아서** 생긴 문제였다.
- 폴더 탭이 유령처럼 남는 현상 — 지워지지도 않고, 열면 그런 폴더가 없다고 나온다.
- **윈도우 쪽이 더 시끄러웠다** — 설치가 막히거나, 시작이 30초씩 늦거나, 메모리를 20GB씩 먹는다는 얘기까지 올라왔다.

그중 몇 개는 **고치지 않겠다**는 답이 나왔고, 그래서 사람들이 단단히 화를 냈다고 전한다. 화자는 그 반응이 이해가 간다고 덧붙인다.

### [07:58–08:10] 화자 본인이 겪는 자잘한 문제
화자도 자잘하게 겪는다. 가끔 화면이 제대로 안 그려지고, 가끔은 껐다 켜야 정상으로 돌아온다. 그래서 **중요한 작업 전에는 한 번 새로 켜고 시작한다**는 개인 운영 습관을 공개한다.

### [08:10–08:21] 그런데도 앱을 쓰는 이유
그럼에도 앱을 쓰는 이유는 단순하다고 말한다.

> "버그는 시간이 지나면 고쳐집니다. 손이 많이 가는 구조는 시간이 지나도 안 고쳐집니다. 저는 후자가 훨씬 비싼 문제라고 봅니다." [08:12] `[의견]`

### [08:21–08:31] 앱 장점의 요약 — 누적되는 "손이 덜 가는 횟수"
정리하면 앱의 장점은 화려한 기능이 아니라 **같은 일을 하는 데 손이 몇 번 덜 가느냐**다. 그 몇 번이 하루에 수십 번 쌓이면 결국 일의 양이 달라진다는 논리다. `[의견]`

### [08:31–08:52] 터미널이 나은 자리 ① 세밀한 조작
반대쪽도 공평하게 말하겠다며 터미널이 확실히 나은 자리 셋을 든다. 첫째는 **세밀한 조작** — 실행할 때 뒤에 붙이는 옵션(플래그)들이다. 어떤 모델로 돌릴지, 권한을 어디까지 줄지, 몇 번까지 반복하게 할지를 직접 지정하고, 결과를 어떤 형식으로 뱉을지도 고를 수 있다. 이런 건 **아직 앱 화면에 다 나와 있지 않다**(주장/미검증).

### [08:52–09:05] 터미널이 나은 자리 ② 자동화 ③ 원격
둘째는 **자동화** — 다른 프로그램 안에 끼워 넣어서 돌리는 경우, 스크립트로 엮는 일은 지금도 터미널이 맞다. 셋째는 **원격** — 남의 서버에 붙어서 그 안에서 일해야 할 때는 터미널이 여전히 더 빠르고 확실하다.

### [09:05–09:20] 둘은 결국 같은 물건 — 갈아타는 문제가 아니다
다행인 건 둘이 결국 같은 물건이라는 점이다. **같은 엔진을 쓰고, 같은 규칙 파일과 설정을 쓰며, 스킬도 권한 규칙도 그대로 공유한다.** 앱에서 하던 일을 터미널에서 이어서 해도 된다.

> "그러니까 이건 갈아타는 문제가 아닙니다. 손에 맞는 걸 골라 쓰는 문제입니다." [09:15]

### [09:20–09:30] 터미널 실력은 여전히 필요하다
한 가지를 더 덧붙인다 — 앱을 쓴다고 터미널 실력이 필요 없어지는 게 아니다. 앱 **안에 들어 있는 터미널을 결국 매일 쓰게** 된다. 달라지는 건 능력의 필요 여부가 아니라 **어디서 시작하느냐**다.

### [09:30–09:55] 최종 정리 — 선택 기준 4가지
마지막 정리에서 상황별 권고를 준다:
- **세션을 여러 개 굴린다면 앱** — 눈으로 보고 눌러서 옮기는 게 명령어보다 빠르다.
- **프로젝트와 모델을 자주 바꾼다면 앱** — 손이 가벼워야 실제로 바꾸게 되기 때문.
- **브라우저를 시킬 일이 있다면 앱이 훨씬 낫다** — 로그인해 둔 내 크롬을 그대로 쓰고, 준비 작업도 없고, 토큰도 훨씬 덜 쓴다.
- **스크립트로 엮어 돌릴 일이 있다면 터미널.**

그리고 사실 결론은 **둘 다 쓰면 된다**는 것이고, 자신은 기본으로 켜는 쪽을 앱으로 옮겼을 뿐이라고 정리한다.

### [09:55–10:07] 마무리 — 오늘 세션 하나만 옮겨 보라
아직 터미널만 쓰고 있다면 오늘 한 번만 해보라는 실행 권유로 끝난다. 앱을 켜고, 하던 세션 하나만 그쪽으로 옮겨 보라는 것. **한 시간이면 왜 이런 영상을 찍었는지 감이 온다**는 말이 마지막 문장이다. (별도의 유료 상품·단톡방 유입 등 세일즈 장치는 이 영상 자막에 없다.)
