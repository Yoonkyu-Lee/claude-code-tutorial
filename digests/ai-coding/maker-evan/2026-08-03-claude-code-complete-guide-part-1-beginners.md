## 요약 (주제별)

### 1. 이 영상의 전제: 터미널·명령어 없이 쓰는 왕초보 입문 1부
- 대상은 개발·코딩을 모르고 "AI 툴은 나랑 안 맞는다" 싶었던 사람. "먼저 터미널을 엽니다"에서 탭 닫던 사람을 위한 것.
- 두 약속: "터미널 열어라"를 한 번도 안 한다 / "이건 다들 아시죠?" 없이 세션·폴더·버튼 위치까지 처음부터 설명. 카카오톡처럼 아이콘 더블클릭 → 한국어 한 문장.
- 상황이 달라진 근거: **Claude 데스크톱 앱 안에 Claude Code가 통째로 들어왔다** — 예전의 개발자 도구를 노션·카카오톡 쓰듯 말풍선에 한국어로 쓰는 형태로 넣었다.

### 2. 챗봇과의 결정적 차이 + "에이전틱"
- 챗봇은 말로 답만 하고, Claude Code는 컴퓨터의 **진짜 폴더·진짜 파일을 열고 만들고 고친다**. "월간 보고서 양식 만들어 줘" → 챗봇은 글로 예시만, Claude Code는 `.md` 파일을 실제로 만들어 지정 폴더에 저장. 우리 일 대부분이 결국 파일 하나가 남는 일이라서 이 차이가 크다.
- **에이전틱** = "스스로 판단해서 여러 단계를 밟는". 목표만 던지면 거기까지 가는 단계를 스스로 설계. 비유: 챗봇은 상담 창구, Claude Code는 일 맡기고 자리 떠도 되는 동료. 회의록 20개 예시(폴더 확인→파일 하나씩 읽기→추리기→빠진 것 확인·추가→재확인·보고).

### 3. 내부 작동: 파악·행동·확인 루프 + 도구 세트
- 루프 = ① 파악(파일·폴더·웹 조사) → ② 행동(파일 만들기·고치기·실행) → ③ 검증(맞는지 확인, 틀리면 1번으로). 한 요청 안에서 수십 번 돈다.
- **이 루프 안에 사람도 들어가 있다** — "멈춰"·"그거 말고 이거로" 하면 반영. 위험 작업 앞에선 Claude가 먼저 멈추고 물음. 화면에 "읽기: 회의록 3월…" 식으로 계속 떠서 그 자리에서 세울 수 있다.
- 파일을 다루는 건 **도구(tools)** 덕분(AI 모델 혼자는 글만 씀): 파일·검색·실행·웹·브라우저·위임·질문. **도구 선택은 사용자가 안 한다** — 한 문장이면 알아서 고른다.

### 4. 용도와 한계 (솔직한 단점)
- "코딩 도구 아니냐"에 대해: 코딩에 강한 건 맞지만 컴퓨터로 할 수 있는 일이면 대부분 도와줌. 비개발 직군 예: 자료 조사·발표자료 초안·문서 작성·긴 문서 요약·데이터 정리·파일 정리·웹 확인.
- 한계 다섯: ① 회사 사정(사내 규칙·승인 절차)을 모름(안 알려주면 일반론) ② 사실을 틀릴 수 있음(숫자·날짜·인용문 검증 필수) ③ 권한 밖은 안 건드림(장점) ④ 되돌릴 수 없는 일(메일·결제·배포)은 반드시 물음 ⑤ 최종 판단은 사람 몫.
- 관통 원칙: "결과물은 사람이 검토한다". 특히 **숫자·날짜·사람 이름·회사명·금액·인용문** 여섯은 반드시 직접 확인.

### 5. 왜 데스크톱 앱 · 구독 · 모델
- 창구는 여러 개(터미널·웹·모바일·슬랙·크롬 확장)지만 **안에서 도는 방식(루프·도구)은 동일**, 다른 건 화면·편의 기능뿐. 데스크톱 앱을 고르는 이유 다섯: 터미널 몰라도 됨 / 변경을 눈으로 봄 / 여러 작업 나란히 / 미리보기 / 확장 쉬움. 실행 환경은 처음엔 **로컬**만 알면 됨.
- 구독: **프로**(입문에 충분) → 한도 자주 걸리면 **맥스**로. (자막상 "네 가지"라 했으나 두 등급만 명시됨 — `[불명확]`.)
- 모델: 화면 오른쪽 아래에서 교체. 화자 소개(미검증) — **페이블 5 > 오퍼스 5**(가장 똑똑), **소넷**(균형, 일상 대부분 충분), **하이쿠**(빠름·가벼움, 요약·형식 변환·반복). 옆에 **사고 강도**(낮음=빠르고 저렴 … 매우 높음=가장 깊게). 실전 규칙: 기본값으로 쓰다 결과 얇을 때만 한 단계 올리기.

### 6. 설치 절차
- 준비물 셋: 맥/윈도우 컴퓨터, Claude 계정 + 유료 구독, 인터넷. 순서: "Claude AI 다운로드" → OS 맞는 설치 파일 → 실행(맥: 아이콘을 응용 프로그램 폴더로 끌기 / 윈도우: 안내대로) → 로그인.
- 윈도우만 추가: 로컬 세션 돌리려면 **Git for Windows** 설치 후 앱 재시작(맥은 대부분 기본 포함). Claude Code는 데스크톱 앱에 이미 들어 있어 **별도 설치 없음**.

### 7. 화면 구조 · 세션 · 작업 폴더
- 홈 화면 세 덩어리: 왼쪽 위 홈/코드 탭 · 오른쪽 작업 영역 · 아래 입력창. 탭 셋: **챗**(파일 접근 안 함) / **코워크**(격리 가상환경 자율 작업, 오늘 안 다룸) / **코드**(내 컴퓨터 파일 직접, 오늘의 주인공). 판단 한 줄: "끝났을 때 파일이 남아야 하나? 남아야 하면 코드."
- **세션** = 작업 단위. 각자 대화 기록·작업 폴더·변경 내역을 따로 갖고 여러 개 동시 실행 가능. 보내기 전 확인 넷: 환경·작업 폴더·모델·권한 모드.
- **작업 폴더** = "이 서랍 안 자료로 일해"라 서랍 지정 → 그 안은 읽고 쓰되 바깥은 안 건드림(안전장치). 바탕화면/문서에 "AI 작업실" 폴더 새로 만들어 프로젝트로 지정 권장.
- 화면 컴포넌트는 총 **11개**지만 매일 만지는 건 넷: **폴더·입력창·권한 모드·모델**.

### 8. 입력 조작: 단축키와 세 특수문자
- 엔터=보내기 / 시프트+엔터=줄바꿈 / ESC=즉시 중단. 중단 없이 방향만 바꾸려면 그냥 새 메시지 입력.
- **/(슬래시)**: 명령어 목록(model·usage·context·config·schedule·init·doctor·compact·clear 등) + 아래에 설치된 스킬즈 이름. **@(골뱅이)**: 에이전트·스킬즈 + 파일·폴더. **+(플러스)**: 파일/사진 첨부(PDF·엑셀·이미지)·폴더 추가·커넥터(Gmail·드라이브)·플러그인. 비개발자 활용 팁: 화면 캡처를 붙이고 "여기 이 부분 이상해"가 말 설명보다 정확.

### 9. 첫 실습 세 요청
- ① "이 폴더에 뭐가 있는지 살펴보고 뭘 도와줄 수 있는지 알려줘"(빈 폴더면 없다고 답 — 정상). ② "`테스트.md` 만들고 '안녕하세요, 첫 파일입니다' 써줘" → 수동 모드면 승인 요청·미리보기 → 승인 시 실제 생성. **폴더를 직접 열어 파일이 진짜 있는지 확인**하는 게 챗봇과 다름을 체감하는 순간. ③ "주간 회의록 양식 만들어 줘(참석자·안건·결정 사항·담당자·마감일, 표 형태)" — 실무형, 마음에 안 들면 이어 말하면 됨.

### 10. 안전 핵심: 권한 모드 다섯 + 화자 조합
- ① **수동**(매번 물음, 초보 강력 추천) ② **편집 자동 수락**(편집·폴더 생성은 알아서, 나머지 물음 — 빠르지만 나중에 한꺼번에 검토) ③ **계획 모드**(안 고치고 계획만, 읽기·조사만 가능, 화자 "진짜 좋다") ④ **자동**(대부분 스스로, 배경 안전 검사, 위험 판정 시 물음) ⑤ **권한 무시**(배우는 동안 쓰는 모드 아님).
- 화자가 가장 많이 쓰는 조합([의견]): 계획 모드로 시작 → 계획 읽고 고쳐 달라 → 승인 → 편집 자동 수락/수동으로 바꿔 실행. 되돌리는 비용이 크니 플랜을 먼저 짜면 문제가 거의 없다.

### 11. 보안 · 품질 · 스킬 예고
- 보안: **프롬프트 인젝션** = 외부에서 프롬프트를 넣어 원치 않는 결과 유도·(보안) 키 탈취 시도. 위험한 보안 정보(키 등)는 공유 금지.
- 품질 = 요청 차이. 좋은 요청 네 요소: **목적·대상·형식·제약**. 맥락(배경)은 세세하게 아낌없이.
- 잘된 요청은 두 번째부턴 안 쓰고 "이 요청 방식을 스킬로 만들어 줘" → 스킬화. "한 번에 다 시키지 말고" 스킬로 "딸깍" 만들기 추천. (스킬 실제 제작법은 예고만, 상세는 2부로.)
- 1부 마무리 + 무료 전자책("왕초보를 위한 클로드 코드 입문 책") 댓글 신청 안내(세일즈/유입 장치) + 2부 예고.

## 3줄 오리엔테이션
- 터미널(검은 화면)·명령어 없이, Claude 데스크톱 앱 안에 통째로 들어온 Claude Code를 "카카오톡처럼 아이콘 더블클릭 → 한국어 한 문장"으로 쓰는 왕초보 입문 1부.
- 챗봇과의 결정적 차이는 "말로 답만 하는 게 아니라 내 컴퓨터의 진짜 파일을 열고 만들고 고친다"는 점. 그 뒤에 파악·행동·확인 루프, 도구 세트, 권한 모드, 스킬즈가 있다.
- 설치부터 화면 버튼 하나하나·안전장치·좋은 요청 쓰는 법까지 훑고, 오늘 영상에서 가장 중요한 단어로 "스킬즈"를 예고하며 2부로 넘긴다.

## 전문 — 시간순 워크스루

### [00:00–00:20] 데모 훅: 한 문장으로 회의록 20개 정리
지금 화면에 보이는 문서는 회의록 20개를 읽고 결정 사항만 뽑아 표로 정리한 것이라고 소개한다. 화자가 한 일은 앱을 켜고 한국어로 한 문장 — "이 폴더 회의록에서 결정 사항 뽑아서 표로 정리해 줘" — 을 쓴 것뿐이라고 강조한다. 검은 화면(터미널)을 열지 않았고 명령어를 하나도 외우지 않았다는 점을 전면에 건다.

> "제가 한 일은 딱 하나입니다. 앱을 켜고 한국어로 한 문장 썼어요." [00:05]

### [00:20–00:50] 대상 선언 + 두 가지 약속
이 영상은 완전 왕초보용이며, 개발·코딩을 몰라도, "AI 툴은 나랑 안 맞는 것 같다" 싶었던 사람을 위해 만들었다고 밝힌다. 앱 설치 첫 클릭부터 화면 버튼 하나하나가 뭘 하는지 전부 다룬다. 영상이 좀 길다며 차 한 잔·중간 끊어보기를 권하고, 두 가지 약속을 건다. ① "터미널을 열어라"는 말을 한 번도 안 한다(검은 화면에 명령어 치는 건 어렵다는 전제). ② "이건 다들 아시죠?" 식으로 아는 척하고 넘어가는 부분 없이, 세션·폴더 저장·버튼 위치까지 처음부터 설명한다.

> "이 영상에서 저는 '터미널을 열어라'는 말을 한 번도 안 합니다." [00:50]

### [00:50–01:20] 오늘의 진행: 여섯 덩어리 예고
이미 좀 아는 사람에게는 답답할 수 있다고 미리 양해를 구하고, 처음 켜보는 사람 속도로 간다고 못박는다. 카카오톡 켜듯 아이콘 더블클릭하고 평소 말하듯 한국어로 쓰는 것만 할 것이라고 정리. 오늘 갈 길을 여섯 덩어리로 예고한다 — ① Claude Code가 뭔지, 챗봇과 뭐가 다른지 ② 앱 설치·첫 화면·버튼 하나하나 뜯어보기(가장 길고 가장 중요) ③ 안전하게 쓰는 법("AI가 내 파일 지워버리면?" 걱정 푸는 파트) ④ 잘 시키는 법 ⑤ 기억하게 만드는 법(반복 설명 없애기) ⑥ 스킬즈(오늘 가장 중요한 단어).

### [01:52–02:46] 왜 이 영상인가: "터미널을 엽니다"에서 탭 닫던 사람들
AI로 일 절반 줄였다는 얘기는 계속 들리고 유튜브엔 다들 잘 쓰는 것 같아 검색해 안내글을 열면, 첫 줄부터 "먼저 터미널을 엽니다"로 시작해 탭을 닫아버린 경험을 짚는다. 화자는 이게 사용자 잘못이 아니라고 본다([의견]) — 기획자·마케터·디자이너·대표가 왜 검은 화면을 배워야 하나, 엑셀 쓰려고 엑셀 만드는 법을 배우진 않는다는 비유. 그런데 상황이 달라졌다며, **Claude 데스크톱 앱 안에 Claude Code가 통째로 들어왔다**고 알린다. 예전엔 개발자 도구였던 걸 이제 앱 아이콘 더블클릭 → 말풍선 창에 한국어로 쓰면 되는 형태(노션·카카오톡 쓰듯)로 넣어뒀다는 뜻. 오늘 영상은 터미널을 못 열어 여기까지 못 왔던 사람을 위한 것이라고 정리한다.

### [02:46–03:04] 한 문장 정의: "컴퓨터 안에 앉아 진짜로 일하는 조수"
Claude Code를 한 문장으로 "여러분 컴퓨터 안에 앉아서 진짜로 일하는 조수"라 정의한다. 사무실 만능 조수 한 명을 상상하라며 — 보고서 초안 잡기, 자료 찾기, 엑셀 정리, 파일을 폴더별로 나누기, 필요하면 웹사이트를 직접 열어 확인까지 — 를 예로 든다.

### [03:04–03:52] 챗봇과의 결정적 차이: 진짜 파일을 만든다
챗봇과 결정적으로 다른 한 지점만 이해하면 오늘 전반이 끝난다고 한다. 챗봇은 말로 답만 하고, Claude Code는 컴퓨터의 진짜 폴더·진짜 파일을 열고 읽고 만들고 고친다. "월간 보고서 양식 하나 만들어 줘"를 예로: 챗봇은 화면에 양식 예시를 글로 보여주고 복사·붙여넣기는 사용자 몫이지만, Claude Code는 `월간 보고서 양식.md` 파일을 실제로 만들어 지정한 폴더에 저장한다. 폴더를 열면 파일이 진짜 거기 있다. 이 차이가 큰 이유는, 우리가 일하며 하는 대부분의 작업이 결국 파일 하나가 남는 일이기 때문이다 — 보고서 파일, 정리된 엑셀, 기획서 초안, 회의록. 말로 듣는 게 아니라 손에 잡히는 결과물이 필요하다는 것.

> "챗봇은 말로 답만 해요. 클로드 코드는 여러분 컴퓨터의 진짜 폴더를, 진짜 파일을 열고 읽고 만들고 고칩니다." [03:13]

### [03:52–04:54] "에이전틱" = 스스로 판단해 여러 단계를 밟는
Claude Code 설명에 자꾸 나오는 단어 "에이전틱(agentic)"을 우리말로 "스스로 판단해서 여러 단계를 밟는"으로 옮긴다. 일반 챗봇은 "보고서 써 줘" 하면 한 번 답하고 끝(주고받고 끝)이지만, Claude Code는 목표만 던지면 거기까지 가는 단계를 스스로 설계한다. 비유: 일반 챗봇은 물어보면 답해주는 상담 창구, Claude Code는 일을 맡기고 자리에 돌아와도 되는 동료. 앞서의 회의록 예시를 다시 풀어 보인다 — "이 폴더 회의록 20개에서 결정 사항 뽑아서 정리해 줘" 한 문장을 받으면 ① 폴더 목록 확인 → ② 회의록 파일을 하나씩 읽기 → ③ 결정 사항 추려 정리 문서 만들기 → ④ 빠진 회의록 없는지 다시 확인 → ⑤ "하나 빠졌네" 하고 그 파일 읽어 추가 → ⑥ 다시 확인 후 보고. 1번 파일 열어라, 2번 줄 고쳐라 식 지시가 필요 없고 목적만 주면 된다.

### [04:54–05:50] 파악·행동·확인 루프 + 그 안에 사람도 있다
방금 그 과정의 규칙은 아주 단순하다며, "새 박자"를 계속 반복하는 것이라 설명한다. ① **파악(맥락)**: 파일 읽고 폴더 살피고 필요하면 웹으로 자료 조사. ② **행동**: 파일을 만들거나 고치고 필요한 걸 실행(실제 작업). ③ **검증**: 결과가 맞는지 확인, 틀렸으면 다시 1번으로. 이 파악·행동·확인 루프가 한 번 돌고 끝나는 게 아니라 요청 하나 안에서 수십 번 돌 수도 있다. 여기서 중요한 것은 **이 루프 안에 사용자도 들어가 있다**는 점 — 방향이 틀렸다 싶으면 "멈춰"라 하면 되고, 진행 중에 "그거 말고 이거로" 던지면 하던 동작을 끝내고 반영한다. 위험한 작업 앞에서는 Claude가 먼저 멈추고 물어보며, "깜깜히 진행되지 않는다"는 게 핵심. 화면에도 "읽기: 회의록 3월…" 식으로 계속 뜨고, 클릭하면 자세한 내역이 펼쳐지며, 이상하다 싶으면 그 자리에서 세울 수 있어 마음이 편하다.

### [05:50–06:31] 도구(tools) 때문에 파일을 다룬다 — 도구는 자동 선택
"AI가 어떻게 내 파일을 열어?"에 대한 답은 **도구**다. AI 모델 혼자서는 사실 글만 쓰고, 실제로 뭔가 하려면 도구가 필요하다. Claude Code가 강한 이유가 이 도구 세트를 가져서다. 예로 파일 작업·검색·실행·웹·브라우저 조작·위임·질문 등을 든다. 좋은 소식은 **어떤 도구를 쓸지 사용자가 고를 필요가 없다**는 것 — "지난달 매출 데이터에서 이상한 숫자 좀 찾아줘" 한 문장이면 폴더에서 파일 검색·읽기·계산·문서화까지 알아서 도구를 골라 처리한다.

### [06:31–06:39] 결과 차이는 어디서? → 스킬즈 예고
도구는 모든 사용자에게 똑같이 주어지는데 결과 차이는 어디서 나느냐고 묻고, "Claude가 우리의 방식을 아느냐"에서 온다고 답한다. 그 지식을 넣어주는 장치가 바로 **스킬즈(Skills)**이며 오늘 후반부의 주인공이라고 다시 예고한다.

### [06:39–07:04] "코딩 도구 아니에요" — 비개발 직군 활용 예시
"Claude Code는 코딩 도구 아니에요?"라는 질문을 많이 봤다며, 코딩에 특히 강한 건 맞지만 컴퓨터로 할 수 있는 일이면 대부분 도와준다고 한다. 비개발 직군이 실제로 많이 쓰는 예: 자료 조사, 발표자료 초안, 문서 작성, 긴 문서 요약, 데이터 정리, 파일 정리, 웹 확인. 실제로 브라우저를 열어 페이지를 보고 판단하거나, 화면을 캡처해 확인하고 문제가 있으면 고치고 다시 확인할 수도 있다.

### [07:04–07:52] 솔직한 한계 다섯 + 관통 원칙
"좋은 얘기만 하면 안 된다"며 한계(단점)를 짚는다. ① 회사 사정(사내 규칙·승인 절차·팀 사정)을 모른다 — 안 알려주면 일반론으로 답한다. ② 사실을 틀릴 수 있다 — 특히 숫자·날짜·인용문은 사람이 검증해야 한다. ③ 권한 밖은 안 건드린다(단점이 아니라 장점) — 지정한 폴더 바깥은 함부로 안 만진다. ④ 되돌릴 수 없는 일(메일 발송·결제·배포)은 반드시 물어본다. ⑤ 최종 판단은 사람 몫 — 결과를 쓸지 말지는 사용자가 정한다. 영상 전체를 관통하는 원칙으로 "결과물은 사람이 검토한다"를 제시하고, 특히 여섯 개 — **숫자·날짜·사람 이름·회사명·금액·인용문** — 은 반드시 직접 확인하라고 강조한다.

### [07:52–08:32] 창구는 여러 개, 안은 동일 — 왜 데스크톱 앱인가
Claude Code를 쓸 수 있는 창구는 여러 개(터미널·웹·모바일 앱·슬랙·크롬 확장)이지만, 어디서든 **안에서 도는 방식은 똑같다** — 파악·행동·확인 루프와 도구 세트가 전부 동일하고, 다른 건 화면과 편의 기능뿐이다. 그럼 왜 데스크톱 앱을 고르나? 다섯 가지: ① 터미널을 몰라도 됨 ② 뭐가 바뀌었는지 눈으로 볼 수 있음 ③ 여러 작업을 나란히 돌림 ④ 미리보기가 붙어 있음 ⑤ 나중에 확장이 쉬움. 실행 환경도 고를 수 있는데, 처음엔 **로컬** 하나만 알면 된다 — 내 컴퓨터에서 내 폴더로, 내가 보는 앞에서 일하는 방식. 클라우드·SSH 같은 건 지금은 흘려들어도 된다.

### [08:32–08:55] 구독 등급: 프로로 시작 → 한도 걸리면 맥스
쓰려면 유료 구독이 필요하다고 솔직히 말한다. 크게 네 가지로 나뉜다면서, **프로**(개인용, 가볍게 쓰는 사람, 입문에 충분)와 **맥스**(개인이지만 많이 쓰는 사람, 사용량 한도가 훨씬 큼)를 설명한다. (자막상 "네 가지"라 했으나 프로·맥스 두 등급만 명시되고 나머지는 언급되지 않는다 — `[불명확: 자막에서 두 등급만 열거됨]`.) 처음이라면 프로로 시작하고, 한도가 자주 걸리면 그때 맥스로 올리라고 권한다.

### [08:55–09:34] 모델 고르기 + 사고 강도
Claude 안에도 성격이 다른 모델이 여러 개 있고 화면 오른쪽 아래에서 언제든 바꿀 수 있다고 한다. 화자는 "오퍼스(Opus)가 제일 똑똑하다"고 했다가, 요즘 "페이블(Fable)"이라는 게 나왔다며 **페이블 5가 가장 똑똑하고 그다음이 오퍼스 5**라고 정정한다([불명확: 자막 원문 "페이블 5"·"오프스 5" — 모델명·버전 표기 미검증]). **소넷(Sonnet)**은 균형형으로 일상 업무 대부분에 충분, **하이쿠(Haiku)**는 제일 빠르고 가벼워 단순 요약·형식 변환·반복 작업에 특화. 모델 옆에 **사고 강도**가 있어 얼마나 깊게 생각할지를 정한다 — 낮으면 빠르고 저렴, 보통은 균형, 높으면 꼼꼼, 매우 높으면 가장 깊게. 실전 규칙: 기본값으로 쓰다가 결과가 얇다 싶을 때만 한 단계 올린다. 처음부터 최고 사양으로 돌리기보다 사용량을 빨리 소진하지 않게 하는 게 더 중요하다는 게 화자 판단([의견]).

### [09:34–10:44] 설치: 준비물과 순서
이제 손을 움직이자며 준비물 셋을 든다 — 맥이나 윈도우 컴퓨터, Claude 계정 + 유료 구독, 인터넷 연결. 설치 순서: ① 브라우저에서 "Claude AI 다운로드"로 가서 본인 OS에 맞는 설치 파일 내려받기 ② 설치 파일 실행 — 맥이면 내려받은 파일 열고 Claude 아이콘을 응용 프로그램 폴더로 끌어다 놓기, 윈도우면 설치 파일 클릭 후 안내대로 ③ (자막상 4단계로 건너뜀) Claude 앱 실행하고 계정 로그인. 윈도우 사용자만 추가로, 로컬 세션이 돌려면 **Git for Windows**가 깔려 있어야 하니 설치 후 앱을 다시 켠다(맥은 대부분 기본 포함이라 신경 안 써도 됨). 좋은 소식: **따로 설치할 게 없다** — 데스크톱 앱 안에 Claude Code가 이미 들어 있어 개발 도구를 별도로 깔 필요가 없다.

### [10:44–11:15] 홈 화면 구조: 크게 세 덩어리
로그인하면 홈 화면이 나오는데 처음엔 복잡해 보이지만 크게 세 덩어리로 보라고 한다. ① 왼쪽 위 탭 전환부에 **홈**(일반 대화)과 **코드**(오늘의 주인공) 두 개 — 새 작업 만들기·프로젝트·아티팩트 설정·최근 대화 등이 있다. ② 오른쪽 작업 영역: 대화와 결과물이 나오는 곳. ③ 아래쪽 입력창. 처음 켜면 신규 기능 안내 팝업이 뜰 수 있는데 오른쪽 위 X나 키보드 ESC로 닫으면 된다.

### [11:15–11:58] 세 탭: 챗 / 코워크 / 코드 — 판단 기준 한 줄
"로그인" 안내가 반복되는 건 그냥 버그니 껐다 켜면 되는 문제라고 짚는다. 탭은 크게 **챗·코워크·코드** 셋으로 구분된다. **챗**은 일반 대화형 AI로 내 파일에 접근하지 않는다. **코워크**는 격리된 가상 환경에서 스스로 오래 일하는 모드(자기 환경에서 돌아가며, 오래 걸리는 자율 작업용 — 오늘은 다루지 않음). **코드**는 내 컴퓨터의 파일을 직접 다루는 작업 공간으로, 내가 지정한 폴더에 접근한다(오늘의 주인공). 언제 어느 탭을 쓰냐의 판단 기준을 한 줄로: "작업이 끝났을 때 내 컴퓨터에 파일이 남아야 하나? 남아야 하면 코드."

> "작업이 끝났을 때 내 컴퓨터에 파일이 남아야 하나? 남아야 하면 코드." [11:50]

### [11:58–12:31] 세션이란 무엇인가: 격리된 작업 단위
첫 세션을 시작하기 전 단어 하나를 배운다 — **세션**은 하나의 작업 단위(대화 하나라고 생각하면 됨)다. 성질 네 가지: ① 각자 자기 대화 기록을 가진다(다른 세션 내용을 모름) ② 각자 자기 작업 폴더를 가진다(세션마다 다른 프로젝트) ③ 각자 자기 변경 내역을 가진다(서로 방해 안 함) ④ 여러 개를 동시에 띄울 수 있다. 세션을 만들면 메시지 보내기 전 확인할 게 넷 — 환경, 작업 폴더, 모델, 권한 모드. 이 중 작업 폴더 하나만 제대로 이해하고 간다.

### [12:31–13:04] 작업 폴더 = "이 서랍 안 자료로 일해" (안전장치)
작업 폴더는 어느 폴더에서 일할지 알려주는 첫 단추다. 비유: 인턴이 첫 출근을 했을 때 "이 서랍 안에 있는 자료로 작업해"라고 서랍을 지정해주는 것 — 그 서랍 안 자료는 마음대로 꺼내 봐도 되고 다른 서랍은 함부로 안 연다. Claude Code도 지정한 폴더 안 파일을 읽고 쓸 수 있고 그 바깥은 함부로 안 건드린다. 이게 안전장치다. 바탕화면이나 문서 폴더에 "AI 작업실" 같은 폴더를 새로 만들고 그걸 프로젝트로 지정하라고 권한다.

### [13:04–13:42] 첫 세 요청: 살펴보기 → 파일 만들기 → 실무 양식
준비가 끝나면 입력창에 한국어로 쓴다. ① "이 폴더에 뭐가 있는지 살펴보고 어떤 작업을 도와줄 수 있는지 알려줘" — 빈 폴더면 아직 아무것도 없다고 답하는데 그것도 정상. ② "이 폴더에 `테스트.md` 파일 만들고 안에 '안녕하세요, 첫 파일입니다'라고 써줘" — 수동 모드면 여기서 승인 요청이 뜨고, 뭐가 만들어질지 미리 보여주고 허락을 구하며, 승인하면 파일이 실제로 생성된다. 폴더를 직접 열어 파일이 진짜 생겨 있는지 확인해보라고 강권한다 — "아, 챗봇과 다르구나" 하고 체감되는 순간. ③ "우리 팀 주간 회의록 양식을 만들어 줘. 참석자·안건·결정 사항·담당자·마감일 항목이 들어가야 하고 표 형태로" — 실무형 요청이고, 마음에 안 들면 그냥 이어서 말하면 된다.

### [13:42–14:29] 화면 완전 해부: 컴포넌트 11개, 매일 만지는 건 넷
화면에서 가장 실용적인 부분이라며(버튼이 뭘 하는지 모르면 아무것도 못 시작한다) 앱을 켜놓고 하나씩 눌러보며 듣기를 권한다. 왼쪽 맨 위 홈·코드, 사이드바 위 새로 생성, 사이드바 아티팩트(만든 결과물 모아보기), 사이드바 사용자 지정 등 각 컴포넌트가 구성되며 총 **11개**다. 많아 보여도 실제로 매일 만지는 건 넷 — **폴더, 입력창, 권한 모드, 모델**. 이 넷만 손에 익으면 된다.

### [14:29–15:04] 세션 목록 + 입력 조절법
가운데 세션 목록은 각 줄이 진행 중인 작업이고 옆에 상태 배지(입력 필요·진행 중·완료)가 붙는다. 각 줄 오른쪽엔 작업 폴더 이름과 마지막 활동 시간이 뜨며, 세션이 여러 개일 때 어느 게 어느 프로젝트인지 여기서 구분한다. 입력 조절법: 보내기는 **엔터**, 줄바꿈은 **시프트+엔터**, 작업 즉시 중단은 **ESC**. 마지막 하나가 중요 — 중단하지 않고 방향만 바꾸려면 그냥 새 메시지를 입력하고 엔터 치면 되고, 그러면 문제가 없다.

### [15:04–15:52] 슬래시·골뱅이·플러스 세 특수문자 ① 슬래시·골뱅이
입력창에 알아둘 명령어는 몇 개뿐이며, 특수문자 세 개로 정리한다. **슬래시(/)**: 하나만 치면 명령어 목록이 뜬다. 자주 쓰는 것으로 model, usage, context, config, schedule, init, doctor, compact, clear 정도를 든다(다 외울 필요 없이 슬래시 치면 목록이 다 나옴). 그 목록 아래쪽에 **설치된 스킬즈 이름들**도 같이 나오는데, 지금은 낯설어도 오늘 영상 끝까지 보면 이 목록에 사용자가 만든 게 올라가 있게 된다고 예고. **골뱅이(@)**: 치면 다른 목록이 뜨며 두 종류가 섞여 나온다 — 하나는 에이전트·스킬즈(특정 역할의 전문가들), 하나는 파일·폴더.

### [15:52–16:22] ② 플러스 + 캡처 붙여넣기 팁
**플러스(+)**: 입력창 아래 플러스 버튼. 파일 또는 사진 추가(PDF·엑셀·이미지를 대화에 첨부), 폴더 추가(작업 대상 폴더를 하나 더 연결), 커넥터(Gmail·드라이브 같은 외부 서비스 연결), 플러그인(기능 확장 묶음 관리)이 있다. 비개발자가 많이 쓰는 건 파일 또는 사진 추가. 특히 유용한 방식은 화면을 캡처해 붙여놓고 "여기 이 부분 이상해"라고 말하는 것 — 말로 위치를 설명하는 것보다 캡처 한 장이 훨씬 정확하다.

### [16:22–16:47] 중간 점검 + "지금부터가 진짜"
여기까지가 절반 조금 안 된다며 지금까지 한 것을 정리한다 — 앱 깔고, 폴더 지정하고, 파일 하나 만들어 보고, 버튼이 뭘 하는지 훑었다. 솔직히 여기까지만 해도 "이 폴더 문서들 요약해 줘" 정도는 오늘부터 쓸 수 있다. 그런데 지금부터가 진짜라며, "같은 앱을 쓰는데 왜 누구는 결과가 좋고 누구는 별로인지" 그 차이가 어디서 오는지 알려주겠다고 넘어간다.

### [16:47–17:44] 권한 모드 다섯 가지
Claude Code는 실제 파일을 다루므로 되돌리기 어려운 작업 앞에서 사람에게 물어보도록 설계됐고, 얼마나 자주 물어볼지를 정하는 게 권한 모드다. ① **수동**: 파일 고치거나 명령 실행할 때마다 물어본다 — 처음 쓰는 사람에게 강력 추천. 뭘 하려 할 때마다 멈추고 미리보기를 보여주고, 승인하면 진행·거부하면 다른 방법을 제안. ② **편집 자동 수락**: 파일 편집·폴더 만들기 정도는 알아서 하고 나머지는 물어본다 — 문서 여러 개 고치는 작업이 훨씬 빨라지지만 편집 결과를 나중에 한꺼번에 검토해야 한다. ③ **계획 모드**: 아무것도 안 고치고 "이렇게 하겠습니다"라는 계획만 세운다(파일 읽고 조사는 되지만 수정은 안 됨) — 화자는 "이게 진짜 좋다"고 평가([의견]). ④ **자동**: 대부분 스스로 판단하되 배경에서 안전 검사가 계속 돌아가고, 위험 판정이 나면 무조건 사람에게 물어본다. ⑤ **권한 무시(건너뛰기)**: 진지하게 — 배우는 동안은 쓰는 모드가 아니라고 못박는다.

### [17:44–18:20] 화자가 제일 많이 쓰는 조합
다섯 개 중 화자가 가장 많이 쓰는 조합을 공개한다. ① 큰 작업 시작할 때 **계획 모드**로 들어간다. ② Claude가 제시한 계획을 읽고 마음에 안 드는 부분을 고쳐 달라 한다. ③ 계획이 마음에 들면 승인. ④ **편집 자동 수락이나 수동**으로 바꿔 실행. 이 순서가 좋은 이유는 되돌리는 비용이 훨씬 크기 때문 — 플랜을 먼저 짜고 하면 문제가 거의 없어진다는 게 화자 경험([의견]).

### [18:20–18:36] 승인 요청 반복의 귀찮음
수동 모드로 쓰다 보면 승인 요청이 계속 뜨는 문제가 있는데, 이런 부분은 잘 처리하면 된다고 한다. 계속 누르는 귀찮음이 있지만 굉장히 편리하게 쓸 수 있다는 정리(자막이 다소 뭉개져 구체 처리법은 명시되지 않음 — `[불명확: 원문 발화가 흐림]`).

### [18:36–19:04] 보안: 프롬프트 인젝션
보안 파트로 넘어가 **프롬프트 인젝션**을 설명한다 — Claude Code 외부에 어떤 프롬프트를 넣어 강제로 원치 않는 결과를 유도하거나 (보안) 키 같은 걸 탈취하려는 시도라고 풀이한다([불명확: 자막 "보완적/보완성"은 문맥상 "보안"의 음차로 교정]). 이를 방지하기 위해 굉장히 위험한 보안 정보(키 등)는 공유하면 안 된다고 당부한다.

### [19:04–19:40] 품질 ① 좋은 요청 네 요소 + 맥락은 아낌없이
같은 앱을 쓰는데 결과가 다른 첫 번째 이유는 "요청이 다르다"는 것. 좋은 요청에는 네 가지가 들어간다 — **목적, 대상, 형식, 제약**. 이 넷이 꼭 있어야 좋은 요청이 된다. 그리고 맥락(배경)은 아낌없이 줘야 한다 — 간단히가 아니라 정말 세세하게 설명하고, 그걸 기반으로 처리하게 해야 한다.

### [19:40–19:51] 품질 ② 잘된 요청은 스킬로 만들기
잘된 요청은 두 번부턴 안 써도 된다며, "이 요청 방식을 스킬로 만들어 줘"라고 하면 스킬을 만들어 처리해준다고 한다. "한 번에 다 시키지 마세요"라 하고, 스킬을 이용해 "딸깍"해서 만드는 걸 추천한다. (오늘 가장 중요한 단어였던 스킬즈의 실제 만드는 법은 여기서 짧게만 예고되고 상세는 다루지 않는다.)

### [19:51–20:08] 1부 마무리 + 무료 전자책 이벤트 + 2부 예고
오늘 1부는 여기서 마무리한다고 알린다. 마지막으로 무료 전자책 이벤트 — "왕초보를 위한 클로드 코드 입문 책"을 나눠주고 있으니 댓글을 확인해 신청하라는 안내(세일즈/댓글 유입 장치). 다음 2부에서 다시 만나자며 끝맺는다.
