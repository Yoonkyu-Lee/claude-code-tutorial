# 유튜브 자동화, 제가 쓰는 스킬 5종 전부 공개합니다

> 메이커 에반(@maker-evan) · 2026-08-23 · 조회수 1,139회 · 9분 30초 · [영상 링크](https://youtu.be/A-DT1jLBbyw)
> 정리 방식: 시간순 심층 워크스루 (paraphrase) + 주제별 상세 요약
> 검증 배너: 이 영상은 화자가 판매 중인 유료 스킬 묶음(스킬샵 링크)을 소개하는 **홍보성 영상**이다. 등장하는 채널 성과 수치(조회수·구독자·업로드 편수), 개선 효과(음량 편차, 편집 시간), 구매자 후기·커뮤니티 인원은 모두 **화자 주장이며 미검증**이다.

## 요약 (주제별)

### 1. 문제 정의 — 유튜브가 막히는 지점은 늘 같다
- 외주: 편당 수십만 원, 월 4편이면 100만 원 초과, 순서 기다리면 2주 소요(주장/미검증).
- 직접 제작: 배울 게 많고 시간이 든다 — 대본 붙잡으면 새벽 2시, 자료 찾다 대본은 한 줄도 못 쓰는 날, 썸네일 열 번 갈아엎기, 편집 배우다 채널을 먼저 접음.
- [의견] 문제는 의욕이 아니라 항상 같은 병목이라는 것이 화자의 전제.

### 2. 전체 구조 — 5개 스킬 파이프라인
- 순서: **자료 조사 → 대본 → 편집 → 쇼츠 → 게시**. 다섯이 따로 놀지 않고 앞 단계 결과물이 뒤 단계 입력이 된다("자료가 대본이 되고, 대본이 화면이 되고, 화면이 게시물이 된다").
- 중간에 파일을 옮겨 담는 수작업이 없어 사람이 끼어들 자리가 거의 없다. 사람 몫은 **주제 선정 + 결과 검수**뿐이며, 화자는 아침에 나와 있는 원고를 10분 정도 읽고 넘긴다(주장).
- 스킬의 정의: "순서와 기준을 파일 하나에 적어둔 업무 매뉴얼" — 매번 길게 설명하지 않아도 결과가 일정하게 나온다[01:53].

### 3. 단계별 설계 판단
- **자료 조사**: 주제 한 줄 → 웹 검색으로 공식 문서·뉴스·실사용 후기 수집. 대본 품질이 여기서 결정되므로 "검색 먼저, 글은 나중". 근거 없는 대본은 문장이 매끄러워도 30초면 들킨다([의견]).
- **대본**: 전문성 유지 ↔ 초심자 이해도는 서로를 잡아먹는 목표. 해법은 **비유를 먼저 깔고 숫자를 뒤에 붙이기**, 익숙한 장면 뒤에 용어 붙이기. 출력은 줄 단위이며 **한 줄 = 자막 한 덩어리 = 화면 한 장**, 챕터 표시도 대본에 내장해 타임스탬프를 수작업으로 만들지 않는다. "대본이 곧 설계도"[03:40].
- **편집**: 순서가 핵심 — 화면을 먼저 만들면 반드시 어긋나므로 **나레이션 타임코드를 먼저 확정하고 그 위에 화면을 올린다**. 음성은 대본 전체를 한 번에 합성(문장 단위 합성 시 톤이 줄마다 달라짐). 자막은 합성된 음성을 다시 전사해 **단어 단위 시각**으로 붙인다(문장 중간 절단 자막을 쓰면 3초씩 밀림).
- **쇼츠**: 긴 영상에서 세로 영상을 재활용. 가로를 그냥 자르면 글자가 잘리므로 **세로 안전 영역 자동 계산** 후 자막·핵심 요소 재배치. 한 편 = 결과물 두 개, 긴 영상은 검색 유입 / 쇼츠는 추천 유입.
- **게시**: 제목·설명·타임스탬프·썸네일 생성. 타임스탬프는 대본 챕터에서 그대로 나온다.

### 4. 화면(비주얼) 규칙
- 흰 배경 + 검은 선 인포그래픽, 다색 사용 금지, 강조는 **반전(검은 면에 흰 글자)만**. 이유는 "화면이 조용해야 말이 들린다"([의견]).
- 말로 때울 수 있는 건 그리지 않음 / 개념 설명은 반드시 그림 / 실제 화면이 필요할 때만 캡처.
- **같은 캡처 두 번 금지** — 스킬이 중복을 자동 탐지해 같은 화면이 두 번 나오면 **에러를 내고 멈춘다**.

### 5. 썸네일·제목 전략
- 새 스타일을 발명하지 않고, **채널에 쌓인 데이터에서 클릭률 높았던 썸네일의 배경·글자 배치를 그대로 재현**한다.
- 근거 주장: 알고리즘은 채널을 하나의 묶음으로 인식하므로 튀는 썸네일보다 일관된 썸네일이 유리(화자 주장/미검증).
- 문구는 위아래로 짧게 분할(위·아래 각각의 내용은 [불명확: 자막 "위에 선어자, 아래의 선호자"]), 길면 작은 화면에서 안 읽히므로 **휴대폰 화면에서 먼저 확인 후 결정**.
- 썸네일 3장 + 제목 3개로 A/B 테스트. 제목 각도는 **결과 선언 / 정면 대비 / 호기심 유발** 세 갈래. "어떤 각도가 먹히는지는 사람이 아니라 데이터가 알려줍니다"[06:04].

### 6. 시행착오 3건 (129편 운영에서 나온 수정)
- **음량 편차**: 문장 단위 합성 시 구간별 음량이 널뛰어 실측 **17까지 차이**(단위 미명시, 문맥상 dB) — 17이면 어떤 줄은 거의 안 들리는 수준이고 사후 보정으로 해결 불가. 전체 일괄 합성으로 바꾸자 편차가 [불명확: "이 데시벨 아래로" — 한 자릿수 dB 추정] 감소. 교훈: "문제가 보정이 아니라 만드는 단위에 있었다"[06:38].
- **자막 오류·잘림**: 화면 맞춤 자동 축소를 쓰면 자막 크기가 계속 변함 → **크기 고정 + 긴 줄은 어절 단위로 끊어 순차 표시**, 두 줄 자막 금지, 화면 아래쪽은 자막 자리로 비워 둠.
- **쇼츠 화면 잘림**: 안전 영역 계산 도입으로 해소.
- 세 건 모두 한 번 밟을 때마다 영상 한 편을 다시 만들어야 했던 함정이라고 밝힘(주장).

### 7. 환경·준비물
- Node + pnpm 환경(편집 단계가 **Remotion** — 영상을 코드로 만드는 라이브러리 — 을 쓰기 때문), 썸네일용 **Replicate 토큰** 1개.
- 설치는 폴더 하나 받아 설치 스크립트 1회 실행 → Claude Code 스킬 폴더에 자리 잡음. Cursor·Codex 등 다른 에이전트에서도 같은 방식으로 동작한다는 주장.
- 개발 환경이 처음인 사람은 이 앞단에서 시간이 걸린다고 명시.

### 8. 한계 — 화자가 직접 밝힌 "안 되는 것" 4가지
1. **결과 미보장**: 조회수는 채널 정체성·시청자층에 좌우되며 같은 스킬로도 어떤 채널은 터지고 어떤 채널은 조용하다. 화자 채널도 초반엔 조회수가 오래 붙지 않았음. "도구가 결과를 만드는 게 아니라, 시간이 줄어 시도 횟수가 늘고 그 횟수가 결과 확률을 올린다"[07:38].
2. **주제 선정은 자동화 불가**: 무엇을 다룰지·어떤 톤일지는 채널 주인의 판단. 화자도 매번 여기서 가장 오래 고민.
3. **디자인 유한**: 정해진 스타일 안에서의 변주 구조. 완전히 다른 비주얼은 직접 손봐야 하며, 스킬 파일은 열어 고칠 수 있게 해뒀음(구매자가 [불명확: "하시슈 분석" — 해시태그 분석 추정] 이나 대형 채널 벤치마킹을 붙인 사례 주장).
4. **준비물 장벽 + 환불 불가**: 디지털 파일이라 환불되지 않음을 사전 고지. "이걸 숨기고 팔면 결국 서로 손해입니다"[08:33].

### 9. 성과 주장 수치 (전부 미검증)
- 최근 90일 조회수 152만 3,000회 / 28일 만에 구독자 3,192명 증가, 현재 3만 명 / 두 달간 129편 업로드.
- "사람을 더 쓴 게 아니라 만드는 방식을 바꾼 결과"[01:04].
- 구매자 후기: 의료 종사자가 "전문성 있는 주제인데 일반인이 알아듣게 나온다"고 평, 회사 홍보 채널 개설 사례("자료 조사부터 대본까지 한 번에 되는 게 결정적"), 자막 싱크가 잘 맞는다는 후기 반복.

### 10. 세일즈 구조
- 판매처: **스킬샵**에 유료 스킬 묶음 등록, 링크는 영상 설명란.
- 커뮤니티: 카카오톡 오픈 채팅과 디스코드 운영(인원은 [불명확: 자막에 "3,명"·"2,명"으로 자릿수 잘림] — 각각 3천 명대·2천 명대로 보이나 확정 불가). "혼자 세팅하다 막히는 자리를 서로 알려주는 곳".
- 소구 논리: 내가 밟은 함정이 이미 메워져 있으니 같은 실수를 반복할 필요가 없다 → "제가 아까운 건 돈보다 그 시간이었습니다"[07:18], "영상 만들 시간에 채널을 키우시라는 게 제 이야기입니다"[09:10].
- CTA: 직접 돌려 보고 막히는 부분·희망 주제를 댓글로, 구독 요청.

## 3줄 오리엔테이션
- 화자는 유튜브 영상 제작 전 과정을 Claude Code 스킬 5개(자료 조사 → 대본 → 편집 → 쇼츠 → 게시)로 묶어, 주제 한 줄을 넣으면 반대쪽에서 영상이 나오는 파이프라인을 만들었다고 말한다.
- 각 단계가 무슨 판단 기준으로 움직이는지(음성 먼저·화면 나중, 단어 단위 자막 싱크, 단색 인포그래픽, 중복 화면 에러, 썸네일은 기존 데이터 재현)를 순서대로 설명한다.
- 후반부는 129편을 돌리며 고친 실패 3건과, 이 도구가 **못 하는 것 4가지**(결과 미보장·주제 선정·디자인 한계·환경 준비물, 환불 불가)를 밝힌 뒤 판매 링크와 커뮤니티로 이어진다.

## 전문 — 시간순 워크스루

### [00:00–00:43] 유튜브를 시작하려는 사람이 늘 멈추는 자리
화자는 오늘 자신이 쓰는 유튜브 제작 스킬을 통째로 공개하겠다고 열고, 먼저 문제 정의부터 시작한다. 유튜브를 시작하려는 사람들이 의욕이 없어서가 아니라 **항상 같은 지점**에서 멈춘다는 것이다. 외주는 편당 수십만 원이라 한 달 네 편만 올려도 100만 원이 넘고(주장/미검증), 순서를 기다리면 2주 뒤에나 결과물이 나온다. 직접 하려니 배울 것이 너무 많고 시간이 문제가 된다.

> "대본을 붙잡고 앉으면 새벽 2시가 됩니다. 자료를 찾다가 정작 대본은 한 줄도 못 쓰는 날도 많습니다." [00:29]

썸네일은 열 번쯤 갈아엎게 되고, 편집을 배우다가 채널을 먼저 접는 경우도 많다는 것이 화자의 진단이다. [의견] "그래서 오늘도 유튜브를 시작하지 못합니다."

### [00:43–01:11] 스킬 5개로 묶었다 — 성과 주장
화자 본인도 같은 자리에서 막혀 있었고, 그래서 이 문제를 도구로 풀기로 했다고 말한다(자막 "독구로"는 "도구로"의 오인식). Claude Code 스킬 다섯 개로 제작 과정을 통째로 묶어, **주제만 넣으면 반대쪽에서 영상이 나오는 구조**를 만들었다는 것이다. 이어 성과 수치를 제시한다 — 지난 90일 조회수 152만 3,000회, 28일 만에 구독자 3,192명 증가, 현재 3만 명, 두 달 동안 업로드 129편(전부 주장/미검증).

> "사람을 더 쓴 게 아니라 만드는 방식을 바꾼 결과입니다." [01:04]

### [01:11–01:41] 전체 그림 — 앞 단계의 결과물이 뒤 단계의 입력
스킬 묶음은 **자료 조사 / 대본 / 편집 / 쇼츠 / 게시** 다섯으로 나뉘며, 다섯이 따로 노는 게 아니라 한 줄로 이어져 있다. 앞 단계 결과물이 곧 뒤 단계 입력이 되어 "자료가 대본이 되고, 대본이 화면이 되고, 화면이 게시물이 된다"는 구조이고, 중간에 파일을 옮겨 담는 작업이 없어 사람이 끼어들 자리가 거의 없다는 설명이다. 사람이 하는 일은 주제를 정하고 결과를 검수하는 것뿐이며, 화자는 아침에 나와 있는 원고를 10분 정도 읽고 넘긴다고 한다(주장).

### [01:41–02:21] 설치와 준비물 — Node·pnpm·Replicate 토큰
설치는 폴더 하나를 받아 설치 스크립트를 한 번 실행하면 끝나고, Claude Code가 읽는 스킬 폴더에 그대로 들어간다고 말한다. 커서(Cursor)나 코덱스(Codex) 같은 다른 에이전트에서도 같은 방식으로 동작한다는 주장도 덧붙인다. 화자는 스킬의 정의를 이렇게 정리한다.

> "스킬이라는 게 별 게 아닙니다. 순서와 기준을 파일 하나에 적어둔 업무 매뉴얼입니다. 그래서 매번 길게 설명하지 않아도 결과가 일정하게 나옵니다." [01:53]

편집 단계는 **Remotion**(영상을 코드로 만드는 라이브러리)을 쓰기 때문에 Node와 pnpm 환경이 필요하고(자막 "PMPM"은 pnpm의 오인식), 썸네일에는 **Replicate 토큰** 하나가 필요하다. 준비물은 그게 전부라고 말한다. [의견] "편집을 배우는 게 아닙니다. 이미 돌아가고 있는 공장을 통째로 받는 쪽에 가깝습니다."

### [02:23–02:43] 1단계 — 자료 조사가 대본 품질을 결정한다
주제 한 줄을 던지면 스킬이 웹을 뒤져 근거를 모으고, 공식 문서·뉴스·실제 사용 후기까지 같이 본다. 화자는 이 단계가 중요한 이유를 대본 품질이 여기서 결정되기 때문이라고 설명한다. 근거 없이 쓴 대본은 문장이 매끄러워도 내용이 비어 있고, 시청자는 그걸 30초 안에 알아챈다는 것이다([의견]). 그래서 **검색을 먼저 하고 글은 나중에 쓴다**는 순서를 고정했다.

### [02:46–03:24] 2단계 — 대본: 전문성과 이해도의 충돌을 어떻게 푸는가
대본 스킬은 모아둔 자료를 읽고 구어체 대본으로 다시 쓴다. 여기서 신경 쓴 두 가지는 (1) 전문성을 낮추지 않는 것, (2) 처음 듣는 사람도 알아듣게 만드는 것인데, 이 둘은 보통 서로를 잡아먹는다 — 쉽게 쓰면 얕아지고 정확하게 쓰면 안 읽힌다. 해법으로 대본 스킬은 **설명을 비유로 먼저 깔고 숫자를 뒤에 붙이며**, 어려운 말을 먼저 던지지 않고 익숙한 장면을 하나 깐 뒤 용어를 붙인다. 근거로 구매자 후기 두 건을 든다(주장/미검증): 의료 쪽 일을 하는 사람이 "전문성이 필요한 주제인데 일반인이 알아듣게 나온다"고 적었고, 회사 홍보 채널을 시작했다는 후기도 있었으며 자료 조사부터 대본까지 한 번에 되는 게 결정적이었다고 했다.

### [03:24–03:43] 대본 출력 형식 — 한 줄 = 자막 한 덩어리 = 화면 한 장
대본은 줄 단위로 나오고, **한 줄이 자막 한 덩어리이자 동시에 화면 한 장**이다. 화자는 이 형식이 뒤 단계 전부를 결정한다고 말한다 — 말과 그림이 어긋나지 않는 이유가 여기 있다는 것이다. 또한 챕터 표시를 대본 안에 같이 넣기 때문에 나중에 타임스탬프를 손으로 만들 필요가 없어진다.

> "대본이 곧 설계도가 되는 셈입니다." [03:40]

### [03:43–04:23] 3단계 — 편집: 음성을 먼저 확정하고 그 위에 화면을 올린다
편집 단계는 대본을 음성으로 만들고 그 음성 위에 화면을 붙인다. 화자는 여기서 **순서**가 중요하다고 강조한다. 많은 사람이 화면을 먼저 만들고 음성을 나중에 맞추는데, 그러면 말이 늘어지면 화면이 남고 말이 빨라지면 화면이 잘려 반드시 어긋난다는 것이다. 이 스킬은 반대로 **나레이션 타임코드를 먼저 확정하고 그 시각 위에 화면을 올린다**. 음성은 문장마다 따로 만들지 않고 대본 전체를 한 번에 합성하는데, 문장 단위로 만들면 목소리 톤이 줄마다 달라지기 때문이다. 자막도 같은 원리로, 만들어진 음성을 다시 전사해 **단어 단위 시각**을 뽑고 그 시각에 자막을 붙여 싱크가 밀리지 않게 한다. 문장 중간에서 끊긴 자막을 그대로 쓰면 3초씩 밀린다는 것이 근거이고, 후기에서 자막 싱크가 잘 맞는다는 말이 반복해서 나오는 이유라고 덧붙인다(주장/미검증).

### [04:27–05:00] 화면 원칙 — 흑백 인포그래픽, 같은 화면 두 번 금지
화면은 **흰 배경에 검은 선으로 그린 인포그래픽**이다. 색을 여러 개 쓰지 않고 강조는 반전(검은 면에 흰 글자)으로만 한다. 이유는 "화면이 조용해야 말이 들리기 때문"이다([의견]). 규칙은 세 가지로 정리된다 — 말로 때울 수 있는 건 그리지 않는다, 개념을 설명할 때는 반드시 그림으로 그린다, 실제 화면을 보여줘야 할 때만 캡처를 쓴다. 여기에 **같은 캡처를 두 번 쓰지 않는다**는 규칙이 붙는데, 같은 그림이 두 번 나오면 시청자가 바로 지루해하기 때문이다. 스킬이 중복을 자동으로 잡아내며, 같은 화면이 두 번 나오면 **아예 에러를 내고 멈춘다**. 화자는 이 원칙들 덕분에 편집 시간이 크게 줄었다고 말한다(주장/미검증).

### [05:00–05:21] 4단계 — 쇼츠: 새로 만들지 않고 같은 재료를 다시 쓴다
긴 영상이 완성되면 거기서 세로 영상을 뽑는다. 가로 화면을 세로로 그냥 자르면 글자가 잘리므로, **세로 안전 영역을 자동 계산**해 자막과 핵심 요소가 화면 안에 들어오도록 다시 배치한다. 쇼츠는 새로 만드는 게 아니라 같은 재료를 다시 쓰는 것이고, 한 편을 만들면 결과물이 두 개가 된다. 유입 경로가 다르다는 점도 짚는다 — 긴 영상은 검색으로, 쇼츠는 추천으로 들어온다([의견]/화자 경험).

### [05:21–06:10] 5단계 — 게시: 썸네일은 발명하지 않고 재현한다
게시 단계는 제목·설명·타임스탬프·썸네일을 만든다. 타임스탬프는 대본의 챕터 표시에서 그대로 나온다. 썸네일은 **채널에 이미 쌓인 데이터를 기준으로** 만드는데, 잘 눌린(클릭률 높은) 썸네일의 배경과 글자 배치를 그대로 재현하고 새 스타일을 발명하지 않는 것이 핵심이다. 근거는 "알고리즘은 채널을 하나의 묶음으로 인식하므로 튀는 썸네일보다 일관된 썸네일이 유리하다"는 주장이다(화자 주장/미검증). 문구는 위아래로 짧게 쪼개며 [불명확: 자막 원문 "위에 선어자, 아래의 선호자입니다" — 위·아래 각각에 무엇을 넣는지 명확히 복원되지 않음], 길게 쓰면 작은 화면에서 안 읽히므로 **휴대폰 화면에서 먼저 확인하고 결정**한다. 마지막으로 썸네일 세 장으로 A/B 테스트를 걸고, 제목도 세 개를 각도를 나눠 건다 — 하나는 결과 선언, 하나는 정면 대비, 하나는 호기심을 건드리는 문구.

> "어떤 각도가 먹히는지는 사람이 아니라 데이터가 알려줍니다." [06:04]

### [06:10–06:44] 시행착오 1 — 음량 편차는 보정이 아니라 '만드는 단위'의 문제였다
화자는 이 흐름이 처음부터 작동한 게 아니라 129편을 굴리며 고쳐온 결과물이라며 대표적 실패 세 가지를 꺼낸다. 첫째는 음성에 잡음이 섞여 나오는 문제였다. 문장 단위로 나눠 음성을 만들면 구간마다 음량이 널뛰었고, 실측으로 **17까지 차이**가 났다(단위는 명시되지 않았으나 문맥상 dB). 17이면 어떤 줄은 거의 안 들리는 수준이고, 뒤에 보정을 아무리 걸어도 해결되지 않았다. 그래서 대본 전체를 한 번에 합성하는 방식으로 바꾸자 편차가 [불명확: 자막 원문 "이 데시벨 아래로" — 한 자릿수 dB로 보이나 값 확정 불가] 떨어졌다.

> "문제가 보정이 아니라 만드는 단위에 있었던 겁니다. 고칠 자리를 잘못 잡으면 시간만 계속 나갑니다." [06:38]

### [06:44–07:01] 시행착오 2 — 자막이 틀리고 잘리는 문제
둘째는 자막 문제였다. 글자 크기를 화면에 맞춰 줄이면 자막이 계속 커졌다 작아졌다 한다. 그래서 **크기는 고정하고, 긴 줄은 어절 단위로 끊어 순서대로 보여주는** 방식으로 바꿨다. 두 줄 자막은 아예 쓰지 않으며, 화면 아래쪽을 자막 자리로 비워 두는 것도 규칙이다.

### [07:01–07:20] 시행착오 3 — 쇼츠 화면 잘림, 그리고 "함정은 이미 메워져 있다"
셋째는 쇼츠에서 화면이 잘리는 문제였고, 안전 영역 계산을 넣어 없앴다. 화자는 이 셋이 전부 자신이 직접 밟은 함정이며, 한 번 밟을 때마다 영상 한 편을 다시 만들어야 했다고 말한다. [세일즈 장치] "스킬을 받으시면 이 함정들은 이미 메워져 있습니다. 같은 실수를 다시 하실 필요가 없습니다."

> "제가 아까운 건 돈보다 그 시간이었습니다." [07:18]

### [07:20–07:48] 한계 1 — 결과는 보장되지 않는다
"다 되는 것처럼 들릴 수 있다"며 안 되는 것도 정확히 말하겠다고 전환한다. 첫째, 결과는 보장되지 않는다. 조회수는 채널 정체성과 시청자층에 따라 완전히 달라지고, 같은 스킬로 만들어도 어떤 채널은 터지고 어떤 채널은 조용하다. 화자 자신의 채널도 초반에는 조회수가 오래 붙지 않았다고 밝힌다.

> "이 스킬은 한 편 만드는 시간을 줄여 주는 도구입니다. 시간이 줄면 같은 기간에 더 많이 시도할 수 있습니다. 그 시도 횟수가 결과 확률을 올리는 것이지 도구가 결과를 만드는 게 아닙니다." [07:38]

### [07:48–08:03] 한계 2 — 주제는 사람이 정한다
둘째, 무엇을 다룰지와 어떤 톤으로 갈지는 여전히 채널 주인의 판단이며 이 부분은 자동화되지 않는다. 화자도 매번 여기서 제일 오래 고민한다고 말한다. [의견] "무엇을 만들지는 결국 채널을 아는 사람이 정해야 합니다."

### [08:01–08:22] 한계 3 — 디자인이 무한하지 않다
셋째, 정해진 스타일이 있고 그 안에서 변주하는 구조라 완전히 다른 비주얼을 원하면 직접 손을 대야 한다. 다만 스킬 파일을 열어 고칠 수 있게 해뒀고, 실제로 구매자 중 자기 채널에 맞게 고쳐 쓰는 사람들이 있다고 말한다(주장/미검증). 사례로 [불명확: 자막 원문 "하시슈 분석" — 해시태그 분석으로 추정되나 확정 불가] 기능을 붙이거나 대형 채널 벤치마킹을 붙인 경우를 든다.

### [08:22–08:36] 한계 4 — 준비물이 없으면 시작이 막히고, 환불은 안 된다
넷째, Node와 Remotion 환경 그리고 API 토큰이 필요해서 개발 환경이 아예 처음인 사람은 이 앞에서 시간이 걸린다. 그리고 **디지털 파일이라 환불은 되지 않는다**고 명시한다.

> "이걸 숨기고 팔면 결국 서로 손해입니다. 그래서 먼저 말씀드립니다." [08:33]

### [08:36–09:30] 정리 — 도구가 지켜주는 건 시간과 일정한 톤 + 커뮤니티·판매 안내
정리 파트에서 다시 다섯 스킬(자료 조사·대본·편집·쇼츠·게시)이 한 줄로 이어져 있고, 주제 한 줄을 넣으면 반대쪽에서 영상이 나오며, 129편을 굴리며 함정은 미리 메워뒀지만 주제와 방향은 여전히 사람이 정한다고 요약한다.

> "이 도구가 지켜주는 건 시간과 일정한 톤입니다. 매번 다른 결과가 나오면 채널이 쌓이지 않습니다." [08:50]

[세일즈 장치] 이어 커뮤니티를 안내한다 — 같은 방식으로 영상을 만드는 사람들이 카카오톡 오픈 채팅과 디스코드에 모여 있고, 혼자 세팅하다 막히는 자리를 서로 알려주는 곳이라고 설명한다(인원은 [불명확: 자막에 "3,명", "2,명"으로 자릿수가 잘려 나옴 — 각각 3천 명대·2천 명대로 보이나 확정 불가], 주장/미검증). 스킬은 **스킬샵**에 올려 두었고 링크는 설명란에 넣겠다고 밝힌다. 마무리로 직접 굴려 보고 막히는 부분은 댓글로 남겨 달라, 어떤 주제로 돌려보고 싶은지도 궁금하다며 구독을 요청한다.

> "영상 만들 시간에 채널을 키우시라는 게 제 이야기입니다." [09:10]
