> jocoding (@jocoding) · 2026-06-18 · 길이 30:04 · [영상 링크](https://www.youtube.com/watch?v=Fh8U67i1yT8)
> 정리 방식: 시간순 심층 워크스루 (paraphrase) + 주제별 상세 요약
> 검증 배너: 스위트북(SweetBook) 북프린트 API 협찬/홍보 성격의 실습 튜토리얼(제목에 "ft. Book Print API" 명시). 수익 구조·단가·마진 수치는 모두 화자 주장이며 미검증. 자막 오인식 도구명·API명은 설명란 목차·링크로 매핑해 교정하고 원문 병기함.

## 요약 (주제별)

### 무엇을 만드는가 — 실물 연계형 AI 동화책 SaaS
- 바이브 코딩(Claude Code)으로 "주제 입력 → AI가 글·그림 동화책 PDF 생성 → 결제 → 실물 책 인쇄·배송"까지 이어지는 SaaS를 만든다.
- 1단계(디지털 PDF SaaS)와 2단계(실물 책 연계)로 분리. 1단계만으로도 수익형 SaaS가 된다고 주장하고, 2단계에서 실물 책이라는 새 수익 채널을 붙인다.
- 동화책은 예시일 뿐, 여행 포토북·AI 화보집·운동 일지·펫 포토북·자작 소설·1인 개발자 전자책 실물 출판 등으로 확장 가능하다고 제안(의견).

### 북프린트 API(스위트북) — 핵심 도구와 과금
- 스위트북은 20년 넘게 포토북·단행본을 만든 회사로, 자체 생산 라인을 REST API 하나로 개방. 파트너는 콘텐츠+결제만 맡고 인쇄·제본·후가공·포장·배송은 자동 대행.
- 과금은 선불 충전 방식: API 사용료 자체는 0원이고 책이 실제 인쇄될 때만 권당 단가가 충전금에서 차감(주장). 1인 개발자도 부담 없이 붙일 수 있다는 게 세일즈 포인트.
- 추천 활용 영역: (1) 기록→책 전환으로 ARPU 상승, (2) 퀴즈·교육·기관·단체 참여자 콘텐츠 묶음, (3) 커뮤니티 크리에이터의 디지털 팬덤→실물 굿즈.
- 문서화가 잘 돼 있고 AI 에이전트용 llms.txt / llms-full.txt를 제공해, AI가 처음 보는 API도 문서를 읽고 정확히 쓸 수 있다는 점을 강조.

### 기술 스택
- 프론트엔드·백엔드: Next.js(풀스택, 백엔드는 서버리스).
- AI 생성: OpenAI — 텍스트 GPT-5.5(기본은 GPT-5.4 미니였으나 화자가 5.5로 상향), 이미지 GPT 이미지 2(한글 텍스트를 그림 안에 안 깨지고 렌더).
- DB·로그인: Supabase / 결제: Polar(글로벌·샌드박스 지원) / 실물 책: 스위트북 북프린트 API.
- 개발 환경: GitHub Codespaces(클라우드 IDE, 로컬 설치 불필요) + Claude Code(코덱스 CLI·Gemini CLI 등 대체 가능) / 배포: Vercel.

### 실전 절차 (1단계 — 디지털 SaaS)
- Codespaces에서 Next.js 템플릿으로 시작 → Claude Code 네이티브 인스톨·구독 로그인 → Vercel CLI로 배포(문서 URL 주고 AI에게 시킴, 프로덕션 URL은 vercel.app 공개 주소).
- 1단계 요구사항을 한글로 입력하면 AI가 가격·이미지 모델 등을 되묻고 기능을 통째로 생성. 가격은 4.99달러, 이미지 모델 GPT 이미지 2 선택.
- Supabase 연동은 Vercel Storage의 Supabase 인티그레이션으로 연결(리전 서울, 프로덕션만), 환경 변수·키를 자동 제공받아 `.env.local`·스니펫에 반영.
- OpenAI API 키는 platform.openai.com에서 프로젝트 생성 후 발급해 `.env.local`에 삽입.
- 마이그레이션은 수동: Codespaces에선 브라우저 로그인이 안 돼 토큰 방식(`npx supabase login --token`) → `npm run db link` → `npm run db push`.

### 실전 절차 (결제·2단계 — 실물 책)
- Polar: 샌드박스 생성(가상 결제로 플로우 점검), 이름·통화(KRW) 설정, API 토큰 발급 → `.env.local` POLAR_ACCESS_TOKEN → `npm run setup polar web`. 원화 기본 통화로 인한 상품 생성 오류는 오류 메시지를 Claude Code에 붙여 자동 수정.
- 2단계는 스위트북 llms-full.txt(약 11,000줄) 전체를 `llms-full.txt` 파일로 붙여 넣고, "실물 책으로 받기 버튼 → 주소 입력 → Polar 결제 → 북프린트 API" 요구를 한글로 입력 + 판형 스펙(고아질 스퀘어북 하드커버) 첨부.
- 스위트북 API 키는 api.sweetbook.com 파트너 포털에서 라이브/샌드박스별 발급, 충전금 충전. 로컬에 Polar 프린트 프로덕트 아이디 + 스위트북 북프린트 API 키 + API 베이스(샌드박스→라이브) 설정.
- 오류가 나면 항상 메시지를 Claude Code에 붙여 넣어 자동 해결하는 패턴이 반복된다.

### 규격·품질 세부
- 실물 책 규격: 고아질 스퀘어북 하드커버 기준 최소 24페이지(표지·내지 포함) → 본문 22페이지로 생성.
- 테스트는 Polar 샌드박스 테스트 카드(4를 연타, 나머지 임의)로 결제. 샌드박스에서 인쇄 주문 전송·주문 번호까지 확인 후 API 키·베이스를 라이브로 바꿔 운영 전환.
- 실물 책 리뷰(의견): 표지 실크필 코팅[불명확]으로 고급스럽고, "P본"[불명확, 제본 방식 추정]이라 잘 펴지고 튼튼, 인쇄 색감·선명도 충분. 하드/소프트커버 모두 가능.

### 수익 구조 (화자 주장·미검증)
- 예시 기준: 고객이 실물 책에 29,000원 결제, 스위트북 주문 API가 충전금에서 13,860원 차감 → 권당 15,140원이 파트너 수익으로 남는 구조(화자가 설정한 예시 가격 기준, 미검증).
- 충전금은 선불(예시에서 10만 원 보유), 실제 주문마다 차감되며 주문 현황을 대시보드에서 추적.

### 세일즈·홍보 구조
- 제목에 "ft. Book Print API" 명시된 스위트북 협찬성 실습 튜토리얼. 설명란 최상단에 북프린트 API 링크, 조코딩 창업 책·조코헌트·AX 컨설팅 링크가 배치됨(자세한 평가는 하지 않음, 원문은 하단 '영상 더보기란' 참조).

## 3줄 오리엔테이션
- 바이브 코딩(Claude Code)으로 "주제 입력 → AI가 동화책 PDF 생성 → 결제 → 실물 책 인쇄·배송"까지 이어지는 SaaS를 30분 만에 만드는 실습.
- 핵심 도구는 스위트북의 북프린트 API — 콘텐츠·결제만 파트너가 맡으면 인쇄·제본·포장·배송을 대행하고, 책이 실제 인쇄될 때만 충전금에서 차감되는 선불 방식(API 사용료 0원 주장).
- 기술 스택은 Next.js + Supabase + Polar + OpenAI + 북프린트 API. 1단계(디지털 PDF SaaS) → 2단계(실물 책 연계)로 나눠 구현하고, 마지막에 실제 배송된 책까지 리뷰한다.

## 전문 — 시간순 워크스루

### [00:00–01:31] 인트로 — 화면 밖으로 나오는 바이브 코딩 결과물
조코딩은 자신이 바이브 코딩으로 만든 실물 책을 들어 보이며 시작한다. 보통 바이브 코딩으로 앱·웹을 만들면 결과물은 화면 안에만 머무는데, 내가 만든 디지털 콘텐츠가 클릭 한 번에 진짜 종이 책이 되어 집 앞으로 배송된다면 어떨까를 화두로 던진다. 이걸 가능하게 한 도구가 스위트북(SweetBook)의 북프린트(Book Print) API라고 소개한다.

### [00:20–01:19] 북프린트 API가 뭔가 — 추천 영역과 과금 구조 (홍보 파트)
> "스위트북은 20년 넘게 포토북과 단행본을 만들어 온 회사인데, 이 자체 생산 라인을 REST API 하나로 열어둔 서비스입니다." [00:27]

파트너사가 콘텐츠와 결제만 책임지면 인쇄·제본(자막 "재본")·후가공·포장·배송(자막 "배손")까지 전부 자동 처리된다고 설명한다. 추천 활용 영역 세 가지를 든다 — (1) 여행·라이프로그·다이어리처럼 기록을 책으로 전환해 고객당 단가(ARPU, 자막 "ARP")를 올리려는 서비스, (2) 퀴즈·교육·기관·단체처럼 참여자 콘텐츠를 묶어 결과물을 만드는 곳, (3) 커뮤니티 크리에이터처럼 디지털 팬덤을 실물 굿즈로 확장하려는 서비스.
> "무엇보다 좋은 점은 API 사용료 자체가 0원이라는 점인데요. 책이 실제로 인쇄될 때만 권당 단가가 차감되는 선불 충전 방식이라 1인 개발자도 부담없이 붙여 볼 수 있습니다." [01:08] (주장)

### [01:31–02:24] 전체 구조와 기술 스택
지금부터 실물 책이 연계되는 수익형 AI 동화책 SaaS를 바이브 코딩으로 만든다고 예고하고, 먼저 큰 그림과 기술 스택을 소개한다. 프론트엔드는 Next.js, 백엔드는 서버리스로 구현해 풀스택으로 가고, AI는 OpenAI의 텍스트·이미지 AI로 동화책을 생성한다. 데이터베이스와 로그인은 Supabase, 결제는 Polar로 글로벌 결제까지 받을 수 있게 하며, 가장 중요한 실물 책 연계는 스위트북 북프린트 API로 처리한다.

### [02:24–03:23] 2단계 구현 계획 — 디지털 SaaS → 실물 책 채널
서비스를 두 단계로 나눈다. **1단계**는 일반 디지털 콘텐츠 SaaS: 동화 주제를 입력하고 Polar로 결제하면 OpenAI API로 텍스트·이미지를 생성해 PDF 동화책을 만들어 주는 기본 서비스로, 이것만으로도 수익형 SaaS가 된다(주장). **2단계**는 실물 책으로 이어지는 새 수익 채널: 1단계에서 완성된 동화책 PDF와 배송 주소만 입력하면 결제를 받고, 북프린트 API가 콘텐츠를 실물 책으로 바꿔 제작부터 배송까지 한 번에 진행한다. 북프린트 API 사용법이 간단해 1인 개발자도 쉽게 실물책 연계형 서비스를 만들 수 있다고 강조한다.

### [03:23–04:20] 상세 플로우 다이어그램
좀 더 상세히 보면, **1단계**는 로그인 → 동화 주제 입력 → PDF 결제(Polar 샌드박스 환경) → 결제 완료 시 webhook(자막 "웹")을 받아 OpenAI의 GPT-5.5·GPT 이미지 2로 동화책 생성 → 미리보기 + PDF 다운로드. **2단계**는 "실물 책 받기" 버튼 → 주소 입력 → 책 결제(Polar) → 완성된 PDF가 있으니 결제 완료 후 스위트북 북프린트 API로 전송 → 실제 인쇄·제본·포장·배송으로 2~3일 뒤 책 도착.

### [04:20–05:07] 개발 환경 — GitHub Codespaces + AI 선택
개발 환경으로 GitHub Codespaces(자막 "기터브 코드 스페이스")를 쓴다. 클라우드 기반 IDE라 내 컴퓨터에 아무것도 설치하지 않고, 클라우드에서 컴퓨터 한 대를 빌려 웹 브라우저 하나만 켜면 쓸 수 있어 어떤 컴퓨터 환경에서도 똑같이 개발할 수 있다. AI는 OpenAI 코덱스 CLI, Claude Code, Gemini CLI(자막 "재미나 CL") 중 아무거나 써도 되며, 이번에는 Claude Code로 진행한다.

### [05:07–06:11] Codespaces 세팅과 Next.js 템플릿
Codespaces 주소로 접속해 무료로 시작하기를 누르고 로그인하면 코드 스페이스 화면이 뜬다. Create를 누르면 Next.js 템플릿이 제공돼 있어 처음부터 만들지 않고 이 템플릿을 바로 쓴다. 템플릿을 선택하면 Next.js가 이미 설치된 상태로 클라우드 컴퓨터가 빌려지고, 브라우저 주소만으로 별도 설치 없이 개발 환경이 마련된다. 예시 페이지의 화살표 버튼을 누르면 Next.js 웹페이지가 뜨고, 클릭하면 카운트가 증가하고 에러도 정상적으로 나오는 걸 확인한다.

### [06:11–07:19] Claude Code 설치와 로그인
Claude Code 공식 가이드 문서에서 설치 명령어(네이티브 인스톨)를 복사해 터미널에 붙여 넣는다(붙여넣기용 클립보드 권한 허용 필요). 설치 후 `claude`를 입력하면 실행된다. Claude 구독자라면 구독 계정과 연동할 수 있는데, 클라우드 환경이라 인증 URL이 뜨면 한 번 더 눌러 승인 → 인증 코드 발급 → 복사 → 마우스 우클릭으로 붙여 넣기 → 로그인 완료. 엔터를 쭉 누르면 시작된다.

### [07:19–08:33] Vercel 배포 개념 — CLI를 AI에게 맡기기
Codespaces의 예제 사이트는 코드 스페이스가 꺼지면 주소가 사라져 접속 불가이므로, 클라우드에 올려 누구나 접속하게 만든다. Next.js 앱 배포에 많이 쓰는 Vercel(자막 "셀/for셀/벌셀")로 배포한다. vercel.com에 회원가입하고, Start Deploying 버튼으로도 되지만 요즘은 AI에게 CLI(커맨드 라인 인터페이스)를 시킨다. Vercel CLI 문서 주소를 AI에게 주고 "Vercel CLI 설치하고 배포해 줘"라고만 입력하면 AI가 터미널 명령어를 알아서 입력하며 배포한다.

### [08:33–09:33] Vercel 배포 실행과 확인
AI가 설치는 됐다며 Vercel 로그인이 필요하다고 안내 → 브라우저 로그인 선택 → 인증 URL → Allow → CLI가 내 Vercel 계정과 연결된다. 그러면 배포가 진행되고 프로덕션 URL(뒤에 vercel.app)이 나온다. 들어가 보면 아까와 같은 데모 페이지지만 이제 코드 스페이스가 꺼져도 누구나 접속할 수 있는 공개 웹사이트다. Vercel 대시보드에서 방금 올린 Next.js 프로젝트가 잘 올라간 것을 확인한다.

### [09:33–10:38] 1단계 코드 생성 — AI에게 요구사항 입력
준비가 끝났으니 원하는 걸 AI에게 입력하기만 하면 된다. 1단계 요구사항을 한글로 그대로 입력한다 — "AI 동화책 서비스 만들어 줘, 로그인 DB는 Supabase, 주제를 입력하고 Polar로 결제하면 OpenAI API 기반으로 글과 그림이 있는 동화책 PDF가 생성되도록". 그러면 AI가 여러 옵션을 되물어 응답한다 — API 키(아직 안 만들었으니 2번 선택), 동화책 한 권 가격(추천대로 4.99달러), 이미지 생성 모델(최근 나온 GPT 이미지 2 = 3번), 그리고 "M라우터"[불명확: 원문 "M라우터", 추천 옵션] 추천대로 진행. 잠시 기다리니 기능은 다 완성되고 이제 연결만 하면 된다.

### [10:38–13:07] Supabase 연동 — Vercel 인티그레이션 활용
API 키를 일일이 넣어도 되지만, Supabase에도 CLI, Polar에도 CLI, OpenAI엔 API 문서가 있으니 각 주소를 붙여 놓고 "문서 참고해서 CLI로 연결할 수 있는 건 알아서 연결하고 최신 문서 기반으로 코드 수정해라"고 시킨다. 진행 중 Supabase CLI 로그인을 토큰 입력으로 요구하는데, 더 쉬운 방법으로 Vercel 프로젝트 → Storage → Supabase 연결 기능을 쓴다. Create → Supabase 로그인 → 리전 서울 → Continue → Vercel을 통해 Supabase에 연동된다(Supabase 회원가입은 필요). 프로덕션만 체크해 서로 프로덕션끼리 연결(Connect)하면 DB까지 연동되고, 환경 변수·API 키를 아예 제공해 준다. 이걸 복사해 프로젝트 `.env.local`에 붙여 넣고 하나 더 만들어 이름을 바꾼 뒤, 코드 스니펫으로 복사해 Next.js Supabase 관련 값 칸에 붙여 넣으면 값들이 잘 들어간다.

### [13:07–14:30] 기록 & OpenAI API 키 발급
Vercel 인티그레이션으로 연결했다는 사실을 별도로 기록해 둔다("Vercel Integrations로 Supabase 연결하고 ENV로 토큰 및 환경 변수 저장해 두었음"). Polar는 브라우저 로그인이 되지만 OpenAI API 키는 발급이 필요하다. platform.openai.com 접속 → 로그인 → 카드 등록 → 프로젝트 생성(이름 "스위트북") → API keys → 키 생성(이름 "스위트북 API") → 발급된 키를 복사해 `.env.local`의 OpenAI API 키 칸에 붙여 넣는다. 기본으로 GPT-5.4 미니가 쓰였는데, 화자는 빡세게 GPT-5.5로 진행한다. [의견]

### [14:30–16:03] Supabase 마이그레이션 — 사용자가 직접 하는 단계
일부 단계(로그인·DB 연결 관련 마이그레이션)는 사용자가 직접 해야 한다. 별도 터미널을 열고 `supabase login` — 코드 스페이스 환경에서는 브라우저 로그인이 안 돼 토큰 방식으로 진행한다. Supabase Tokens 주소에서 액세스 토큰(이름 "스위트북 토큰")을 발급 → 복사 → `npx supabase login --token <토큰>` 형태로 우클릭 붙여넣기 후 엔터 → 로그인. 이어 `npm run db link`로 연결(연결 오류가 뜨면 오류 메시지를 Claude Code에 던지면 알아서 수정해 준다), 마지막으로 `npm run db push`까지 수행하면 데이터베이스 연결이 끝난다.

### [16:03–18:03] Polar 결제 연동 (샌드박스)
Polar도 토큰 발급 방식과 CLI 방식이 있는데, CLI가 편하지만 코드 스페이스 환경에서는 안 되므로 API 토큰 방식으로 진행한다. polar.sh 로그인 → 온보딩에서 샌드박스 생성(가상 결제로 실제 카드 결제 없이 결제 플로우 점검 가능) → 이름 "조코딩 스위트북", 금액 단위 KRW(자막 "코리아 1") → 시작 → 대시보드. Settings → Developers → API 토큰에서 모든 권한을 준(샌드박스라서) "스윗북 토큰" 발급 → 복사 → `.env.local`의 POLAR_ACCESS_TOKEN에 붙여 넣기 → `npm run setup polar web` 실행 → 연결. 상품 생성이 자동 실패하는데, 오류를 Claude Code에 붙여 넣으면 기본 통화를 원화로 설정해 생긴 오류임을 찾아 수정 → 재실행하면 상품 생성 확인.

### [18:03–18:38] 1단계 셋업 마무리
"완료"를 입력하면 셋업이 끝났다고 하고, 아직 등록 안 된 키가 있으면 "해 달라"고 하면 AI가 모든 키 등록을 완료한다. 환경 변수 동기화 후 재배포하면 되는데, "Vercel ENV 자동 동기화 해줘"만 해도 알아서 처리하고 재배포까지 하면 1단계 완료.

### [18:38–20:31] 1단계 테스트 — 회원가입부터 PDF 생성까지
배포된 사이트에서 로그인·회원가입 → 이메일 인증. 인증 후 화면이 이상한 건 Supabase Authentication의 URL이 localhost로 되어 있어서이므로, 배포된 주소로 반영하면 로그인이 잘 된다. "AI 동화책 메이커"에 동화 주제("코딩과 AI에 대한 모험 이야기"), 주인공 이름(조코딩), 대상 연령(초등학교 저학년)을 입력하고 결제. Polar 샌드박스 테스트 카드는 4를 연타(4444…)하고 나머지는 임의 입력 → 결제 → 동화책 생성 → 완성, PDF 다운로드. 처음엔 한글이 깨져 안 나왔는데, "글씨 안 나온다"고 다시 요청해 수정 → 이번엔 텍스트를 그림 안에 포함시키니 GPT 이미지 2가 한글도 안 깨지고 자연스럽게 써 줘 동화책이 잘 만들어진다. 1단계 구현 완료.

### [20:31–21:48] Book Print API 연동 시작 — 판형과 문서
2단계 실물 책 연계. 스위트북 북프린트 API로 주문 가능한 종류는 세 가지이고, 동화책에는 "고아질[불명확: 원문 "고아질", 판형명] 스퀘어북 하드커버"가 적절해 보이니 그 규격대로 동화책이 나오게 만든다. 북프린트 API의 장점은 문서화가 잘 돼 있고, AI 시대에 맞춰 "빠른 시작 → AI 에이전트 지원" 메뉴에 llms.txt / llms-full.txt(자막 "lms.txt / llms풀.txt")를 제공한다는 점이다. 이 덕에 AI가 처음 보는 북프린트 API도 문서를 읽고 정확히 쓸 수 있다.
> "저희는 이걸 읽어 볼 필요도 없습니다. 왜냐면 AI가 이걸 다 대신 읽어 주기 때문이죠." [21:41]

### [21:48–23:33] llms-full.txt 주입 + 2단계 프롬프트
llms-full.txt 페이지 전체를 복사(Ctrl A, Ctrl C)해 Codespaces 작업 환경에 `llms-full.txt` 파일을 만들어 붙여 넣는다(11,000줄짜리 문서를 사람은 한 줄도 안 읽고 AI가 알아서 읽는다). 1단계에서 연결을 다 해 둬서 2단계는 하고 싶은 것만 한글로 풀어 쓰면 된다 — "스위트북 북프린트 API를 이용해 실물 책 기능을 구현하고 싶어, 완성된 책 화면에 '실물 책으로 받기' 버튼 추가, 클릭하면 주소 입력 후 책 제작권 상품을 Polar 결제로 실물책 받도록 해 줘"라고 입력하고, `llms-full.txt`를 참고하라고 끌어다 놓고, 원하는 책 스펙(판형 정보·제품 안내)을 그대로 긁어 붙인 뒤 "고아질 스퀘어북 하드커버에 맞는 규격으로 PDF가 생성·출력되도록"이라고 덧붙여 엔터. AI가 종합 판단해 구현을 완료한다(1단계를 해 둔 덕에 더 빠르다).

### [23:33–25:02] 스위트북 API 키 발급과 로컬 설정
AI가 셋업 다음 단계(마이그레이션, Polar 새 상품 등록, 환경 변수 등록, 스위트북 연동)를 안내한다. API 키는 api.sweetbook.com(설명란 URL로 확정, 자막 원문 "api.setbook.com")에 접속 → 로그인 → 파트너 포털에서 책 주문용 충전금을 충전할 수 있고, 아래쪽에 API 키가 있어 라이브/샌드박스 환경별로 발급 가능하다(화자는 이미 두 개 발급해 둠). AI가 책 제작권에 대한 Polar 프로덕트 아이디와 스위트북 API 키를 넣을 칸을 만들어 놨으니, 값을 복사해 로컬에 교체한다. 기존과 달리 새로 추가된 것은 Polar 프린트 프로덕트 아이디와 스위트북 북프린트 API. 베이스는 일단 샌드박스 환경으로 두고 잘 되면 운영으로 바꾸며, API 키는 미리 받아둔 샌드박스용으로 넣고 저장한다.

### [25:02–26:49] 2단계 샌드박스 테스트 — 규격·주문 확인
"다음 단계 진행해 줘, 스위트북 API 키는 넣어 두었어"라고 시키면 모든 셋업 완료. 하드커버 사이즈에 맞게 전체 플로우를 테스트한다 — 주제 "AI 로봇과 친구하는 조코딩의 이야기", 주인공 조코딩, 저학년 대상 → 테스트 카드(4444…) 결제 → 이번엔 스위트북 북프린트 API 규격에 맞게 생성. 완성본은 고아질 스퀘어북 기준 최소 24페이지(표지·내지 포함)라 본문은 22페이지짜리로 나오고, 표지·내지를 각각 다운받아 잘 만들어진 걸 확인한다. 아래에 생긴 "실물 책으로 받기"로 주소 입력 → 결제 → 스위트북 인쇄 주문 전송이 자동으로 되고 주문 번호까지 나온다. 샌드박스에서 정상 확인.

### [26:49–28:03] 운영 환경 전환
운영 전환은 간단하다 — 스위트북 API 키를 샌드박스용에서 라이브(운영) 환경 키로 바꾸고, API 베이스도 샌드박스에서 라이브로 변경하면 똑같이 동작하되 실제 책이 발송되는 API로 동작한다. 그리고 Vercel에 배포해야 하므로 "ENV 로컬의 스위트북 API 베이스를 라이브 환경으로 변경해 두었어, 반영해"라고 시켜 배포하면 실제 배송 가능한 API가 연결된다.

### [28:03–28:43] 실제 주문과 수익 구조 (핵심 수치)
새 동화책을 만들어 실제 배송과 연계된 스위트북 북프린트 API로 배송을 건다. 결제 → 인쇄 주문 전송. 원래 충전금 잔액은 10만 원이었는데 실제 주문이 들어와 차감된다.
> "고객이 29,000원 결제를 했고요. 스위트북 주문 API로 충전금에서 13,860원이 빠져나갔습니다. 즉 한 권 실물 책이 주문될 때마다 파트너에게 15,140원이 수익으로 남는 구조입니다." [28:20] (주장/미검증 — 화자가 설정한 예시 가격 기준)

주문 진행 상황도 한눈에 확인할 수 있다.

### [28:43–29:25] 실물 책 리뷰
책이 도착해 열어 본다. 안전하게 배송됐고, 바이브 코딩과 API 요청으로 만든 동화책이 잘 왔다. 표지에는 실크필 코팅[불명확: 원문 "실크필 코팅"]이 들어가 부드럽고 고급스럽고, "P본"[불명확: 원문 "P본", 제본 방식으로 추정]이라 잘 펴지고 튼튼하다. 안쪽 인쇄 품질도 색감·선명도가 충분하다. [의견] 이번엔 하드커버로 제작했고 소프트커버도 된다고 한다.

### [29:25–29:53] 다양한 활용 사례
동화책뿐 아니라 여행 사진 포토북, AI 화보집, 운동 일지, 펫 포토북, 자작 소설, 1인 개발자의 전자책 실물 출판 등 다양한 콘텐츠를 실물 책과 연계해 새 수익 채널을 만들 수 있다. 기존에 디지털 콘텐츠만 제공하던 사업자도 실물 책 연계로 추가 수익을 창출할 수 있다고 제안한다. [의견]

### [29:53–30:06] 마무리
아래 설명란에서 자세한 내용을 확인하고, 만들고 싶은 게 있으면 북프린트 API를 활용해 보라고 권하며 마친다.
