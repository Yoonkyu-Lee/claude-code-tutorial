# 글 작성부터 업로드까지, 워크플로우 무료로 공개합니다.

> dekilab · 2026-09-10 · 9,272회 · 13분 8초 · [영상 링크](https://youtu.be/fbvAh2QkKpc)
> 정리 방식: 시간순 심층 워크스루 (paraphrase) + 주제별 상세 요약
> 화면 시연 기반 튜토리얼. 강의·오픈채팅방 홍보가 포함되어 있으며, 자동화의 안정성·성공률에 대한 서술은 화자 주장(미검증)이다.

## 요약 (주제별)

### 1. 이 워크플로가 만드는 것 — 파이프라인 전체 구조
- 입력: **내 사진 + 내 메모(타임라인·먹은 것 수준의 간단 메모)**. 출력: **네이버 블로그에 임시저장된 내 문체의 글**.
- 5단계 파이프라인: ① 내 과거 글로 **문체 문서(블로그 스타일)** 생성 → ② 사진 관찰 + 메모로 **마크다운 초안** 작성 → ③ **검수자 에이전트**가 사진·메모와의 정합성 검증 → ④ 이미지에 **모자이크 + 워터마크** 스크립트 처리 → ⑤ **Playwright**로 네이버 에디터에 입력 후 **임시저장**.
- 중간 포맷은 **마크다운**. 브라우저 자동화 스크립트가 이 마크다운을 읽어 네이버 에디터에 그대로 옮긴다.
- 지난 "블로그 에이전트 팀" 영상과의 차이: 그건 **주제만 던지면 리서치→생성 이미지**로 만드는 정보성 글, 이번 건 **맛집·여행·제품 후기·일상**처럼 내 사진과 내 경험이 들어가는 글.

### 2. 1단계가 전부다 — 문체 학습(블로그 스타일 문서)
- 화자의 가장 강한 주장: **다른 단계를 아무리 잘 만들어도 문체 학습이 부실하면 결국 "AI가 쓴 글"이 나온다.** [의견] AI 티가 나는 것보다도, 블로그는 글 작성자의 개성이 본질이라는 이유.
- 방법: 프로젝트 폴더에 `samples` 폴더를 만들고 **과거에 내가 쓴 블로그 글을 마크다운으로 최소 3개 이상** 넣는다. 화자는 4개 사용.
- **샘플 1개만 넣으면 그 글 하나를 그대로 따라 하는 경향**이 있다(주장/경험칙) — 그래서 3개 이상이 하한.
- 프롬프트: "samples의 글은 내가 직접 쓴 네이버 블로그 글이니 전부 확인해서 **블로그 스타일 문체 파일**을 만들어 달라. 안에 **문체·글의 구성·쓰지 않는 표현**을 포함할 것."
- 결과 문서에는 문체, 자주 쓰는 표현, 구성, 쓰지 않는 표현이 정리되고, Claude가 **문장 길이·사진 수·사진 위치**까지 파악해 반영한다.
- 운영 원칙: 테스트 글을 시켜 보며 스타일 문서를 **반복해서 깎아 나간다**. 초안이 마음에 안 들면 다음 단계로 가지 말고 1단계로 되돌아간다. 장기적으로도 퇴고하며 느낀 점을 계속 반영해 이 문서를 키운다.

### 3. 초안 생성 — 사진 관찰을 먼저 저장시키는 순서
- `photo` 폴더에 글에 쓸 사진을 넣는다.
- 프롬프트 순서가 중요: ① 블로그 스타일 문서를 읽어 문체 파악 → ② `photo` 폴더 사진을 **전부 열람** → ③ 각 사진에 **무엇이 찍혔는지 관찰 내용을 먼저 저장** → ④ 사용자 메모 + 사진을 종합해 **초안 작성**.
- 사용자가 넣은 메모는 **타임라인과 먹은 음식 정도**로 매우 간단하다.
- 결과물에는 문체 반영뿐 아니라 **이미지 배치 위치**와 **네이버 지도 태그**까지 생성된다.
- [의견] 워크플로 완성 후에는 메모조차 **음성 모드**로 입력해 바로 글로 만들 수 있다.

### 4. 검수자 에이전트 — 컨텍스트 격리가 설계의 핵심
- 만든 이유: 초안을 여러 번 써 보니 **사진·메모와 맞지 않는 내용**이 섞여 들어가는 문제가 있었다.
- 설계 조건: 검수자는 **사용자가 넣은 이미지 · 메모 · 블로그 스타일만** 보고, **현재 대화의 컨텍스트는 전달받지 않는다**. 그래서 "사진 기록·메모와 초안이 맞는가"만 독립적으로 판단한다.
- 검증: **근거 없는 사실을 일부러 초안에 넣고** 테스트했더니 정상적으로 잡아냈다(주장/미검증, 화면 시연 기반).

### 5. 이미지 자동 처리 — 모자이크 + 워터마크
- 동기: 블로그 운영자들은 보통 이미지에 워터마크를 넣거나, 의도치 않게 찍힌 **얼굴·번호판**을 하나씩 모자이크한다. 이 수작업을 스크립트화한다.
- 요청 내용: 사람이 나온 이미지를 확인해 **모자이크** 처리 + **우측 하단에 블로그명 워터마크** 삽입. 워터마크 문구는 각자 블로그 이름으로 바꾼다.
- 프롬프트에 **처리 결과를 직접 확인해 정상 작동 여부를 검증하는 단계**까지 함께 넣어 두었다.
- 결과: 얼굴 모자이크 + 우측 하단 워터마크가 적용된 이미지가 그대로 글에 들어간다.

### 6. 네이버 업로드 자동화 — Playwright 기반
- **화면 제어(GUI 매크로)가 아니라 자동화 스크립트** 방식. 도구는 **Playwright**.
- 요청: "Playwright로 네이버 블로그 에디터에 초안을 입력하고 **임시저장**하는 스크립트를 만들어라. 단 **발행은 하지 말 것**."
- 사전 단계로 **에디터 구조(로그인/글쓰기/제목/본문/툴 버튼/발행 버튼 위치)를 `에디터 DOM` 문서에 기록**하게 하고, 그 문서를 근거로 입력 스크립트를 만든다.
- 실행 시 **Chromium** 창이 뜨고 사용자가 직접 로그인하면 **로그인 상태가 유지**된다. 상황에 따라 **재로그인이 필요할 수 있고**, 작업이 무거워 시간이 걸린다.
- Claude는 여러 **시행착오를 거치며 그 내용을 `CLAUDE.md`에 저장**하고, 임시저장 실행 전 사용자에게 확인을 요청한다.

### 7. 안전장치 — 왜 발행을 자동화하지 않는가
- 이유 둘: **네이버 정책/약관 문제**, 그리고 **자동화 초기에는 글 상태를 사람이 반드시 확인해야 한다**는 품질 문제.
- 구조적 방지책: **자동 저장은 항상 끄고**(자막 원문 "항상 맞고" = "막고"로 판단), **임시저장은 저장 버튼을 누르는 순간에만** 동작하도록 스크립트 구조를 변경.
- 최종 흐름은 반자동: AI 초안 → 임시저장 → **사람이 육안 확인·수정** → 사람이 발행.

### 8. 결과물 검증 — 임시저장 글에서 확인된 것
- 평소 문체대로 작성된 본문, **적절한 이미지 위치와 캡션**, 실제 장소의 **네이버 지도 삽입**, 블로그 스타일에 맞춘 개인적 마무리 문구([불명확: 원문 "개인구"]), 그리고 이미지의 **워터마크·모자이크** 적용.

### 9. 스킬로 묶기 & 워크플로 문서화
- Claude **스킬** 기능으로 앞 단계들을 하나로 결합: **이미지 확인 → 이미지 처리 → 초안 작성 → 검수**를 한 번에 실행하는 글 작성 스킬(자막 "라이트 스킬", 영문 `write` 스킬로 추정).
- 마지막에 이 글 작성 스킬과 **네이버 자동 업로드 과정을 이어 붙이고**, 자동 업로드 중 겪은 시행착오를 **CLAUDE.md에 재정리**해 워크플로를 문서로 고정한다.
- 이렇게 만든 워크플로를 자기 블로그 주제(맛집·제품 리뷰·일상 등)에 맞춰 커스텀해 쓰면 된다.

### 10. 준비물 체크리스트
- **유료 구독 Claude**(Codex로 대체 가능하다고 언급), **Node.js** 설치(자동 업로드용), **내 과거 블로그 글 3개 이상**, **글에 쓸 사진**, **네이버 계정**, 작업 환경은 **VS Code + 새 프로젝트 폴더**.

### 11. 확장 아이디어 (영상에서 제안만 된 것)
- **히어로 이미지**: 내가 찍은 사진 위에 제목을 얹어 대표 이미지 생성.
- **음성 입력**: 메모를 타이핑 대신 녹음 → 전사 → 바로 네이버 글까지 정리.
- 평소 고민하던 기능을 Claude와 대화하며 직접 구현.

### 12. 세일즈·유입 구조 (정보로서 기록)
- **Claude Code 자동화 강의**: 데키랩이 실제 쓰는 워크플로우를 끝까지 따라 만드는 구조이고, 막히면 **전용 단톡방**에서 질문할 수 있다는 점을 차별점으로 제시. 상세는 영상 설명란.
- **프롬프트 무료 배포**: 영상에서 쓴 프롬프트 전부를 **오픈 채팅방**에서 공유. 좋아요 요청 + 설명란의 오픈채팅 링크로 유입시키는 구조. 인트로(00:33)에서 이미 "끝까지 보면 프롬프트 받는 법을 알려준다"고 예고해 시청 유지에 활용.

## 3줄 오리엔테이션
- Claude Code로 "내 사진 + 내 메모 → 내 문체의 네이버 블로그 글 → 이미지 모자이크·워터마크 → 네이버 블로그 임시저장"까지를 한 워크플로로 묶는 과정을 처음부터 끝까지 시연한다.
- 핵심은 자동화 기술이 아니라 **1단계(내 과거 글로 문체 문서 만들기)** 이며, 이게 부실하면 뒤 단계를 아무리 잘 만들어도 "AI가 쓴 글"이 나온다는 게 화자의 일관된 주장이다.
- 발행(publish)은 일부러 자동화하지 않는다 — 네이버 약관 문제와 글 품질 확인을 이유로 임시저장에서 끊고 사람이 최종 확인한다.

## 전문 — 시간순 워크스루

### [00:00–00:39] 인트로 — 지난 블로그 에이전트 영상의 후속
화자는 몇 달 전 올린 "블로그 에이전트 팀" 영상이 많은 시청을 받았고, 그걸 참고해 실제로 자동화에 성공했다는 피드백도 많이 받았다고 말한다(주장/미검증). 오늘 만들 것은 **블로그에 업로드할 사진과 메모를 입력하면 → 평소 쓰던 문체에 맞게 글을 작성하고 → 검수한 다음 → 첨부 이미지에 모자이크와 워터마크까지 넣고 → 네이버 블로그에 자동 업로드되는 워크플로우**다. 영상을 끝까지 보면 사용된 프롬프트를 다운로드하는 방법까지 안내한다고 예고한다(세일즈/유입 장치).

### [00:41–01:08] 지난 영상과의 차이 — 정보성 글 vs 내 경험 글
지난 블로그 영상은 **주제만 던지면 리서치 → 글 작성 → 필요한 이미지 생성**으로 완성된 정보성 글을 만들어 주는 방식이었다. 반면 오늘 자동화하는 글은 네이버 블로그에서 실제 주류를 이루는 유형, 즉 **맛집 후기·여행·제품 후기·일상 블로그**처럼 "내 사진과 내 경험을 넣는 글"이다.

> "내 사진과 내 경험을 넣는 블로그 글입니다." [01:06]

### [01:08–01:51] 원리 — 문체 학습 → 초안 → 검수 → 이미지 처리 → 브라우저 자동화
원리는 간단하다고 설명한다. ① 내가 평소 쓰던 글로 **문체를 학습시킨 Claude**에게 이번에 쓸 글의 내용과 사진을 간단히 전달하면 마크다운으로 초안을 써 준다. ② **검수자 에이전트**를 따로 만들어 잘못된 정보나 오탈자가 없는지 확인하게 한다. ③ 블로그에 들어갈 사진을 적절히 배치하고 **사람 얼굴이나 번호판처럼 문제가 될 수 있는 부분을 모자이크**하고 **워터마크**를 추가한다(자막 원문 "오토마크/어토마크"는 워터마크의 오인식). ④ 완성된 글을 **Playwright**(자막 원문 "플레이라이트")로 컴퓨터가 스스로 브라우저를 조작해 네이버 블로그 에디터에 입력하고 **임시저장**까지 시킨다.

### [01:51–02:13] 왜 임시저장까지만 하는가
임시저장된 글들을 사람이 직접 육안으로 확인해 틀린 부분이 없는지 점검한 뒤 최종 발행하는 흐름으로 이어진다. 자동 발행도 기술적으로 가능하지만 **네이버 정책 문제**가 있고, 자동화 초반에는 작성되는 글의 상태를 반드시 확인하고 올려야 문제가 없기 때문에 임시저장까지만 자동화한다는 게 화자의 판단이다. [의견] 자동화 범위를 의도적으로 좁게 잡는 선택.

### [02:13–02:23] 오늘의 예시와 응용 범위
오늘은 **여행 블로그**를 예시로 시연하되, 같은 방식을 맛집 후기·제품 리뷰·일상 블로그에 필요에 따라 응용해 보기를 권한다.

### [02:24–03:01] 준비물 4가지
① **유료 구독된 Claude** — Codex를 써도 괜찮지만 오늘은 Claude로 진행한다. ② **Node.js**(자막 원문 "노드 GS") — 자동 업로드 과정에서 사용하므로 검색해서 자기 OS에 맞는 버전을 설치한다. ③ **내가 과거에 작성한 블로그 글 최소 3개 이상** — Claude가 참고할 문체 소스. ④ **블로그 글에 쓸 사진**과 **네이버 계정**.

### [03:03–03:13] 작업 환경 — VS Code에 새 프로젝트 폴더
VS Code를 켜고 새로운 프로젝트 폴더를 하나 생성한 뒤, 그 안에서 차근차근 워크플로우를 만들어 간다.

### [03:13–03:36] 1단계가 제일 중요하다 — 문체 학습
당장 자동화부터 하고 싶겠지만, 가장 중요한 것은 **내가 지금까지 써 온 블로그 글을 Claude에게 학습시키는 것**이라고 강조한다. 다른 단계를 아무리 잘 만들어도 이 단계가 안 잡히면 결국 "AI가 작성한 글"이 나오기 때문이다. [의견] AI 티가 나는 것도 문제지만, 그보다 **블로그는 글 작성자의 개성이 중요**하기 때문에 이 과정이 정말 중요하다는 게 화자의 관점이다.

> "AI 티가 나는 건 둘째 치고 결국 블로그는 글 작성자의 개성이 중요한 거기 때문에 이 과정이 정말 중요하다." [03:29]

### [03:36–04:04] samples 폴더 — 과거 글을 마크다운으로 넣기
방법은 간단하다: Claude에게 지금까지 쓴 글을 보여주고 "내가 그걸 어떻게 쓰는지"를 문서로 뽑아 두는 것. 프로젝트 폴더 안에 **samples 폴더**를 만들고 과거 블로그 글을 **마크다운 파일** 형태로 정리해 넣는다. 화자는 총 4개를 넣었다. 샘플을 하나만 넣으면 **그 글 하나만 똑같이 따라 하는 경향**이 있으므로 반드시 3개 이상 넣으라고 당부한다(주장/경험칙).

### [04:04–04:30] 프롬프트 ① — 블로그 스타일(문체) 파일 생성
Claude에게 "samples 안에 있는 글은 내가 직접 쓴 네이버 블로그 글인데, 전부 확인해서 **블로그 스타일이라는 문체 파일**을 생성해 달라"고 요청한다. 파일 안에는 **문체·글의 구성·쓰지 않는 표현** 등을 포함시켜 달라고 지정했다. 이렇게 요청하면 Claude가 문장 길이, 사진 수, 사진 위치 등을 파악해 `블로그 스타일` 마크다운 파일을 만들어 준다.

### [04:30–05:03] 스타일 문서 검증과 반복 튜닝
생성된 블로그 스타일 문서를 열어 보면 문체, 자주 쓰는 표현, 구성, 쓰지 않는 표현 등이 정리돼 있다. 이어 "블로그 스타일을 참고해서 특정 주제로 글 하나 작성해 줘"라고 시켜 보면 학습시킨 문체대로 글이 나오는 것을 확인할 수 있다. 이 테스트를 반복하며 **스타일 문서를 깎아 나가는 과정**이 필요하고, 귀찮아도 한 번 잡아 두면 앞으로 계속 쓸 자동화의 **중심 문서**가 되므로 여러 번 테스트해 잘 써 두라고 권한다.

### [05:04–05:27] photo 폴더 — 글에 쓸 사진 준비
스타일 문서가 잘 만들어졌다면, 블로그 글에 사용할 이미지들을 담을 **photo 폴더**를 만들어 여행 후기에 들어갈 사진들을 넣어 둔다.

### [05:27–06:00] 프롬프트 ② — 사진 관찰 저장 + 메모 기반 초안 작성
Claude에게 ① 블로그 스타일 문서를 읽고 내 문체를 파악한 다음, ② photo 폴더의 사진을 **전부 보게** 하고, ③ 각 사진에 무엇이 찍혔는지 **관찰 내용을 먼저 저장**하게 한 뒤, ④ 사용자가 주는 **메모와 사진을 종합해 여행 글 초안을 작성**하도록 요청했다. 메모에는 **타임라인 정도와 무엇을 먹었는지** 정도만 간단히 적었다. [의견] 워크플로를 완성한 뒤에는 이런 메모조차 **음성 모드**로 간단히 입력해 바로 블로그 글을 만들 수도 있겠다고 덧붙인다.

### [06:00–06:29] 초안 결과 확인 — 그리고 안 맞으면 1단계로
요청하면 Claude가 블로그 스타일과 사진들을 확인해 블로그 글 초안을 써 준다. 결과물에는 학습시킨 문체가 반영돼 있고, **이미지의 위치**와 **네이버 지도 태그**까지 생성돼 있다. 다만 결과가 "내가 생각하던 글과 다르다" 싶으면 **다시 1단계로 돌아가 블로그 스타일을 더 수정하고 오라**고 권한다(테스트 목적이면 일단 진행해도 무방).

### [06:29–06:46] 마크다운 초안이 뒤 단계의 입력이 된다
현재 초안은 마크다운 형태로 작성되는데, 이후 **브라우저 자동화 단계에서 스크립트가 이 마크다운 문서를 읽고 그대로 네이버 블로그에 글을 작성**하게 된다. 즉 마크다운이 파이프라인의 중간 포맷 역할을 한다.

### [06:46–07:19] 프롬프트 ③ — 검수자 에이전트(컨텍스트 격리가 핵심)
초안을 몇 번 써 보니 **사진이나 메모와 잘 맞지 않는 내용**이 들어가는 경우가 있어서, 이를 잡아 줄 **검수자 에이전트**를 만들어 달라고 요청한다. 설계 조건이 중요하다: 검수자는 **사용자가 넣은 이미지·메모·블로그 스타일만** 보고, **현재 진행 중인 대화의 컨텍스트는 전달받지 않게** 해서, 사진 기록과 메모가 초안과 잘 맞는지만 판단하게 한다.

> "현재 진행하고 있는 대화의 컨텍스트는 전달하지 않게 해서 사진 기록과 메모가 작성된 글의 초안과 잘 맞는지만 확인할 수 있게끔" [07:09]

### [07:19–07:34] 검수자 테스트
생성된 검수자 에이전트에 **근거 없는 사실을 일부러 넣고** 테스트한 결과, 해당 내용을 정상적으로 잡아냈고 검수자가 제대로 작동하는 것을 확인했다(주장/미검증 — 화면 시연 기반).

### [07:35–08:09] 프롬프트 ④ — 이미지 자동 처리(모자이크 + 워터마크)
블로그를 본격적으로 운영하는 사람들은 이미지에 워터마크를 넣거나 의도치 않게 찍힌 얼굴을 하나씩 모자이크로 지우는 경우가 있다. 그래서 이 작업도 **스크립트로** 넣는다 — 사용자(사람)가 나온 이미지를 직접 확인해 모자이크를 하고 워터마크를 넣어 달라고 요청한다. 워터마크 문구의 "내 블로그명" 부분은 각자의 블로그 이름으로 수정하면 된다. 처리된 결과물을 **직접 확인해 정상 작동했는지 검증하는 과정까지** 프롬프트에 함께 요청해 두었다.

### [08:09–08:22] 이미지 처리 결과
처리 결과를 보면 **얼굴에는 모자이크**가 적용되고 **우측 하단에는 블로그 이름 워터마크**가 들어간 것을 확인할 수 있다. 이 상태의 이미지가 그대로 블로그 글에 올라가게 된다.

### [08:22–08:48] Claude 스킬로 지금까지의 단계를 하나로 묶기
다음으로 **Claude 스킬(skill)** 을 활용해 지금까지 만든 작업들을 하나로 묶는다. "글을 작성하는 스킬"을 생성해 달라고 요청했고, 순서는 **이미지 확인 → 이미지 처리 → 글 초안 작성 → 검수**까지 포함된다. 이제 이 스킬(자막에서는 "라이트 스킬" — 영문 `write` 스킬로 추정)을 호출하면 지금까지의 과정이 한 번에 진행된다.

### [08:48–09:18] 강의 소개 (세일즈 장치 — 정보로서 1회 기록)
자동 업로드 구현에 들어가기 전, 데키랩이 진행 중인 **Claude Code 자동화 강의**를 소개한다. 데키랩이 실제로 쓰는 자동화 워크플로우를 끝까지 따라 만들어 보며 학습하는 구조이고, 혼자 영상만 보고 끝내는 게 아니라 **막히면 전용 단톡방에서 물어볼 수 있다**는 점을 차별점으로 든다. 자세한 내용은 영상 설명란 참고.

### [09:18–09:43] 자동 업로드 접근 — 화면 제어가 아니라 스크립트
자동 업로드는 **화면 제어(GUI 조작 매크로) 방식이 아니라 자동화 스크립트**로 구현한다. 이 과정에서 **Playwright**라는 브라우저 조작 도구를 쓴다. 로그인 버튼은 어디 있고 글쓰기 버튼은 어디 있으며, 에디터에 들어가 제목과 본문을 입력할 수 있게 만든 뒤 **임시저장까지** 하는 과정을 구현한다.

### [09:43–10:20] 프롬프트 ⑤ — Playwright 스크립트 + 에디터 DOM 문서화
Claude에게 "Playwright로 네이버 블로그 에디터에 초안을 입력하고 임시저장하는 스크립트를 만들어 달라, 단 **임시저장까지만 하고 발행은 하지 말 것**"이라고 요청한다. 사용자가 한 번 로그인해 두면 **로그인 상태가 유지**된다. 그다음 글쓰기 버튼을 클릭해 제목·본문·툴 버튼·발행 버튼 등 **에디터의 구조가 어떻게 생겼는지를 `에디터 DOM` 문서에 기록**하게 하고(자막 원문 "에디터 도미"), 그 문서를 바탕으로 작성한 글을 에디터에 입력해 임시저장까지 하도록 요청해 두었다.

### [10:20–10:42] 실행 — Chromium 창, 로그인, 시행착오의 CLAUDE.md 기록
실행하면 Google Chrome과 같은 계열인 **Chromium** 브라우저 창이 뜨는데, 이때 테스트할 계정으로 로그인해 주면 된다. 꽤 무거운 작업이라 시간이 걸릴 수 있고, 상황에 따라 **한 번 더 로그인이 필요할 수도** 있다. 기다리면 Claude가 여러 시행착오를 거치며 그 내용을 **CLAUDE.md 파일에 저장**하고, 이제 임시저장을 해도 되겠는지 사용자에게 물어본다.

### [10:42–10:56] 자동 발행 방지용 구조 변경
추가로 자동으로 발행되는 것을 막기 위해, **자동 저장은 항상 끄고(자막 원문 "항상 맞고"는 "막고"의 오인식으로 보임), 임시저장 요청은 저장 버튼을 누르는 순간에만 작동**하게 구조를 바꿔서 실행하도록 요청해 두었다. [의견] 사고로 발행되는 사태를 구조적으로 차단하려는 안전장치.

### [10:56–11:23] 결과 확인 — 네이버 임시저장 글
네이버 블로그에 들어가 임시저장 글을 확인하면 Claude가 작성한 블로그 글이 실제로 저장돼 있다. 평소 쓰던 문체에 맞춰 글이 작성돼 있고, **적절한 이미지 위치와 캡션**, 그리고 **실제 위치의 네이버 지도**까지 삽입돼 있다. 블로그 스타일에 맞춘 개인적인 마무리 문구까지 들어갔고([불명확: 원문 "개인구"]), 이미지에는 **워터마크와 모자이크**가 적용된 것을 확인할 수 있었다.

### [11:23–11:43] 사람이 하는 마지막 단계와 장기 개선
AI가 초안을 작성해 주면 사용자는 임시저장된 글을 한 번 읽어 보고 수정할 부분을 빠르게 고쳐 발행하면 된다. 장기적으로 워크플로 성능을 높이려면 **퇴고를 거치며 느낀 사항을 계속 Claude에게 요청해 블로그 스타일 문서를 발전시켜 나가면 된다**(자막 원문 "태고"는 "퇴고"로 판단).

### [11:43–11:55] 발행까지 자동화하지 않은 이유 재확인
발행 버튼을 누르는 것까지 자동화해 완전 자동 업로드도 가능하지만, **네이버의 약관**과 **블로그 글의 퀄리티**를 위해 임시저장으로 구현했다고 다시 못박는다.

### [11:55–12:20] 마무리 정리 — 스킬 연결과 CLAUDE.md 재정리
마지막으로 지금까지 구현한 **글 작성 스킬(`write` 스킬)** 과 **네이버 자동 업로드 과정**을 이어 붙인다. 그리고 자동 업로드 단계에서 Claude가 겪은 시행착오를 **CLAUDE.md에 다시 한번 정리**하게 해서 워크플로우를 문서화해 두었다. 이렇게 만든 워크플로우를 자기가 쓸 블로그 글 주제에 맞게 커스텀하면 된다.

### [12:20–12:32] 프롬프트 무료 배포 (세일즈/유입 장치 — 정보로서 1회 기록)
오늘 사용한 프롬프트들은 모두 **오픈 채팅방**에서 공유하고 있으니, 좋아요를 누르고 영상 설명란의 오픈 채팅방으로 들어와 무료로 자료를 확인하라고 안내한다.

### [12:32–12:58] 확장 아이디어 3가지
① **히어로(대표) 이미지 생성** — 내가 찍은 이미지 위에 제목을 얹어 대표 이미지를 만들기. ② **음성 입력** — 글에 넣을 내용을 타이핑하는 대신 음성으로 녹음하고 전사해서 바로 네이버 글까지 정리하기. ③ 평소 고민하던 기능들을 Claude와 이야기하며 직접 구현해 보기.

### [12:58–13:08] 클로징
영상이 도움이 됐다면 구독과 좋아요를 부탁한다는 인사로 마무리한다.
