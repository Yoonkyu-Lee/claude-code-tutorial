## 요약 (주제별)

### 무엇을 만드는가 — 전체 그림
- 1탄에서 만든 숙박업소 웹사이트에 **실사용 기능 3종**을 코드 없이 클로드로 붙이는 실습편: ① 예약 문의 폼 → 구글 스프레드시트 자동 저장, ② 문의 시 손님/주인 자동 알림 메일 + 답장 자동화, ③ 문의를 한눈에 보는 관리자 페이지.
- 적용 범위: 숙박업소는 예시일 뿐, 미용실·과일 판매·필라테스 등 **고객 문의가 필요한 모든 업종**에 같은 방식 적용 가능.
- 화자 표현: "예약 문의를 대신 받아주는 AI 직원 한 명을 뽑은 셈"([의견]).

### 아키텍처 — 서버/DB 없이 구글 스택으로
- 원래 폼 데이터를 주인이 확인하려면 **서버 + 데이터베이스**가 필요하고, 화자는 "이 부분이 개발자 영역이며 웹사이트 견적이 확 뛰는 지점"이라고 설명([의견]).
- 대안으로 **구글 스프레드시트를 데이터베이스처럼** 쓰고, **구글 앱스크립트**로 구글 서비스(시트·Gmail)를 연결. 사용자는 "앱스크립트란 구글 서비스끼리 연결하는 언어" 정도만 이해하면 되고, **앱스크립트 코드는 전부 클로드가 작성**.
- 최종 상태: 웹사이트는 간단 배포, 관리자 페이지는 **로컬 전용**(서버·DB·로그인·회원가입 없음). 다음 3탄에서 본격 배포 + 데이터베이스 예정.

### 기능 ① 폼 → 스프레드시트 저장 (실전 절차)
- 예약 폼에 이메일·아동 동반 여부 등 필드 추가 요청. 최종 폼 항목: 이름·연락처·이메일·사용 기간·(성인/아동) 인원수·객실 타입·추가 요청 사항, 필수 항목 별도 표시.
- 클로드에게 "폼 제출 시 구글 앱스크립트로 시트에 한 줄씩 기록되게 만들고, 내가 직접 할 일은 순서대로 알려달라" 요청.
- 절차: (1) 새 스프레드시트 생성·이름 지정 → (2) 확장 프로그램 → 앱스크립트에서 기존 `코드.gs` 지우고 클로드 코드 붙여넣기 → Ctrl+S → (3) 테스트 함수 실행 + **권한 승인**("구글 미확인 앱" 경고 → 좌측 하단 "고급" → 승인 → 계속) → (4) **웹 앱으로 배포**(유형 웹 앱, 인증 "나", 액세스 "모든 사용자") → 다시 권한 승인 → **웹 앱 URL** 확보 → 클로드에게 URL 전달하면 클로드가 폼↔시트 연결 및 작동 확인까지 수행.
- 주의: `코드.gs` 수정 시마다 **새 버전으로 재배포** 필요. 테스트 행은 삭제.

### 기능 ② 자동 알림 메일
- 문의 접수 시 **손님에게는 "접수됨" 메시지**, **주인(나)에게는 Gmail로 "새 문의 왔다"** 알림을 보내도록 앱스크립트 내용 작성 요청. (화자 주장: 이런 자동 알림은 보통 유료 솔루션·월정액 기능 / 미검증)
- 절차: 클로드가 수정한 `코드.gs` 교체·저장 → 테스트 메일 함수 실행·권한 승인 → 손님/주인 메일 모두 수신 확인 → **"배포 관리"에서 새 버전 배포**(새 배포 아님) → 실제 문의 넣어 시트·메일 동시 확인.
- 한계: 이 메일들은 **접수 확인일 뿐** 고객 질문에 답하지 않음(무엇을 묻든 완료 문자만).

### 기능 ②-b 답장 자동화 (Gmail 커넥터)
- **클로드 데스크톱 앱**에서 사용자 지정 → 커넥터 → Gmail 커넥터 연결, 도구 권한 "항상 허용".
- 클로드 코드에서 "오늘 들어온 새 문의 알림 메일을 찾아 분류하고 존댓말 답장 초안 작성" 요청 → 클로드가 **초안 A(당일 예약 가능)/초안 B(예약 어려움)** 두 예시 제시.
- 현재는 재고 데이터가 주인에게만 있어 **A/B 판단은 사람 몫**. "초안 B로 임시 저장" 요청 시 클로드가 **Gmail 임시 보관함에 초안 저장**.
- **답변 템플릿**: "템플릿" 폴더에 열 가지 상황별 답장 예시 파일을 만들어 두면 매번 메일이 달라질 불확실성을 줄이고 일관된 응답 가능. 언제든 수정 가능.

### 기능 ③ 관리자 페이지 (대시보드)
- 취지: 스프레드시트로도 보이지만 **시인성 좋게 한눈에** 보기 위함. 화자: "관리자 대시보드는 외주 견적에서 비싼 항목 중 하나"([의견]/미검증).
- 요청 구성: 요약 카드(이번 주 문의 건수·미응대 수·체크인 예정 팀 수), 문의 목록, 문의 상태 데이터(미응대 방지), 최근 문의 추이 그래프, 이번 주 요약.
- **서버 없는 로컬 전용**(로그인/회원가입 없음). 클로드가 보안상 **어드민 키(admin key)** 지정을 요구 → 화자는 "테스트1" 사용, `코드.gs`와 관리자 페이지 양쪽에 **같은 키 값** 입력.
- 배포: `코드.gs` 교체·저장 → 배포 관리에서 새 버전 배포 → 클로드가 만든 `어드민.html`(admin.html) 로컬 실행. 문의 목록 체크 후 새로고침하면 "완료" 상태로 전환. 홈페이지 최종 문의 시 시트·관리자 페이지 동시 반영 확인.

### 리스크·주의 사항
- 배포 시 매번 뜨는 "**구글 미확인 앱**" 경고 → 좌측 하단 "고급" 클릭 후 승인해야 진행.
- 화자·클로드 모두 언급: **실제 예약을 받을 거라면 여러 보안 요소를 붙이는 것을 추천**(현재는 테스트 수준).
- 재고·답장 판단 자동화, 로그인/DB는 미구현 — **다음 3탄**으로 이월.

### 확장 가능성 (화자 전망)
- [전망] 데이터베이스 + **재고 관리 에이전트**를 붙이면 A/B 답장 판단까지 자동화 가능.
- [전망] 클로드 코드 **루틴 기능**으로 매일 아침/정각 등 원하는 시간에 새 문의 확인 및 자동 답장 시스템 구성 가능(요청 있으면 별도로 시연 예고).

### 세일즈 구조 (1회 기록)
- **데키랩 AI 자동화 강의** 홍보: 데키랩이 실제 쓰는 워크플로를 처음~끝까지 만드는 강의, 출시 1주 만에 100명+ 수강(화자 주장/미검증), 수강생 커뮤니티에서 개인 프로젝트 질문 가능. 자세한 내용은 영상 설명란 링크.

## 3줄 오리엔테이션
- 1탄에서 만든 숙박업소 웹사이트에 "예약 문의 폼 → 구글 스프레드시트 저장 → 자동 알림 메일 → 자동 답장 → 관리자 대시보드"를 코드 없이 클로드로 붙이는 실습편.
- 데이터베이스/서버 대신 구글 스프레드시트 + 구글 앱스크립트를 백엔드로 쓰고, 앱스크립트 코드는 전부 클로드가 작성해 준다. 사용자는 시키는 대로 복붙·배포·권한 승인만 한다.
- 답장 자동화는 Gmail 커넥터 + 클로드 데스크톱으로 초안 작성/임시저장, 상황별 답변 템플릿 파일까지 만들어 일관성을 확보. 로그인·데이터베이스는 다음 3탄으로 넘긴다.

## 전문 — 시간순 워크스루

### [00:00–00:53] 영상 개요 — 오늘 만들 3가지 기능
지난 편에서 클로드 코드로 12분 만에 여러 웹사이트 디자인을 만들었고, 이번 편은 그 웹사이트를 "본격적으로 활용"하기 위해 기능을 붙이는 실습편이다. 개발 지식 없이 클로드만으로 만들 기능은 크게 세 가지: ① 홈페이지에 들어온 고객이 예약 문의를 넣으면 그 내용이 **구글 스프레드시트에 자동으로 쌓이게** 하고, ② 문의 고객에게 알맞은 응대를 하는 시스템을 만들고, ③ 이 모두를 한 화면에서 보는 **관리자 페이지**를 만든다. 관리자 페이지에는 이번 주 문의 개수·문의 추이·고객 목록이 담긴다.

> "이 기능들은 수백만 원짜리 웹사이트 안에 꼭 들어 있는 기능들인데요. 이걸 오늘 전부 무료로 만들어 보도록 하겠습니다." [00:46] (비용 비교는 화자 주장/미검증)

### [00:53–01:17] 적용 범위 — 문의가 필요한 모든 업종
예시는 숙박업소지만, 미용실·과일 판매·필라테스 등 **고객 문의가 필요한 웹사이트라면** 같은 방법으로 발전시킬 수 있다고 한다. 영상이 끝날 때쯤이면 "문의를 대신 받아주는 AI 직원 한 명"과 관리자 페이지가 생겨 있을 거라고 예고한다. [의견] "AI 직원 한 명을 뽑은 셈"이라는 표현은 화자의 비유.

### [01:17–01:51] 시작 환경 — 지난 편 프로젝트 폴더 이어받기
지난 편에서 웹사이트를 만든 클로드 코드 프로젝트 폴더에서 이어서 작업한다. 해당 폴더가 없어도 실습은 가능하지만, 똑같은 상황에서 하고 싶으면 **지난 영상에서 만든 프로젝트 폴더와 사용한 프롬프트들을 정리해 둔 링크가 영상 설명란에 있으니** 다운로드받으라고 안내한다. 그 상태로 웹사이트를 실행하면 하단에 예약 문의 입력 탭이 보인다.

### [01:51–02:32] 예약 폼 손보기 — 필드 추가
지난 편은 디자인 중심이라 "예약 요청 보내기" 버튼이 아직 제대로 작동하지 않는다. 그래서 이 웹사이트를 방문한 사용자가 예약 폼을 입력하면 그 내용이 내 구글 스프레드시트에 쌓이도록 프로젝트 폴더를 수정한다. 먼저 예약 폼 자체를 손보는데, 기존 기본 정보에 더해 **이메일과 아동 동반 여부**를 폼에 포함시켜 달라고 요청한다.

### [02:32–03:07] 수정된 폼 확인
클로드에게 요청한 폼 항목은 이름·연락처·이메일·사용 기간·(성인/아동으로 나눈) 인원수·객실 타입·추가 요청 사항이며, **필수 사항은 별도 표시**해 달라고 요청했다. 클로드가 기존 웹사이트를 확인하고 폼을 수정해 주며, 로컬 페이지를 새로고침하면 예약자 정보 → 숙박 정보 → 요청 사항 구조로 폼이 바뀐 것을 확인할 수 있다.

### [03:07–03:30] 왜 서버/DB가 견적을 뛰게 하는가
수정된 폼으로 작성한 데이터를 웹사이트 주인(화자)이 확인하려면, 사용자가 작성한 데이터를 모아둘 공간 — 즉 **서버와 데이터베이스**가 필요하다. 화자는 "이 부분은 확실히 개발자의 영역이고, 따라서 웹사이트 견적이 확 뛰기 시작하는 지점"이라고 설명한다. [의견] 견적 상승 지점에 대한 화자의 실무 관점.

### [03:30–04:00] 대안 — 구글 스프레드시트를 DB로
이번엔 더 간단하게 가기 위해, 평소 엑셀처럼 자주 쓰는 **구글 스프레드시트를 데이터베이스 대신** 사용해 홈페이지에서 폼을 보내면 스프레드시트에 쌓이도록 워크플로를 구성한다. 막막할 수 있지만, 해야 할 일은 코드 작성이 아니라 "지금 뭘 하고 싶은지 클로드에게 이야기만 해 주는 것"이라고 강조한다.

### [04:00–04:31] 알아둘 개념 — 구글 앱스크립트
대신 **구글 앱스크립트**라는 개념 하나만 알아두면 된다. 앱스크립트는 구글 스프레드시트나 Gmail 같은 구글 서비스에서 쓰는 간단한 프로그래밍 언어로, **구글 서비스들끼리 서로 연결하려면 이런 언어가 필요하다** 정도만 이해하면 된다. 앱스크립트에 들어갈 코드 내용은 전부 클로드가 작성해 주므로 걱정하지 않아도 된다.

### [04:31–05:04] 클로드에게 스프레드시트 연동 요청
클로드에게 "방금 만든 예약 폼을 제출하면 구글 스프레드시트에 자동으로 쌓이게 만들고 싶다"고 요청한다. 구체적으로는 **구글 앱스크립트를 활용하고, 폼에 있는 내용들을 시트에 한 줄씩 기록**되게 만들어 달라고 했다. 또한 이를 위한 앱스크립트 코드를 짜주고, 내가 직접 해야 하는 것이 있으면 순서대로 하나씩 알려달라고 요청한다.

### [05:04–05:24] 클로드의 절차 안내 ① 스프레드시트 생성
클로드가 앱스크립트에서 해야 할 것을 자세히 안내한다. 첫 단계는 스프레드시트 만들기. 클로드가 제안한 스프레드시트 링크로 들어가면 새 스프레드시트가 생성되고, 이름만 간단히 "예약 문의"로 저장한다.

### [05:24–05:52] 절차 ② 앱스크립트 편집기에 코드 붙여넣기
다음은 앱스크립트 편집기 열기. 스프레드시트 상단의 **확장 프로그램 → 앱스크립트**를 클릭하면 `코드.gs` 파일이 보인다. 기존에 있던 코드는 지우고, 클로드가 만들어 준 `코드.gs` 내용을 그대로 복사해 이 파일에 붙여넣은 뒤 Ctrl+S로 저장한다.

### [05:52–06:25] 절차 ③ 테스트 실행 + 권한 승인
앱스크립트가 잘 작동하는지 테스트한다. 상단에서 실행할 함수를 클로드가 제안한 함수(자막 원문 "테스트 업펜드", `testAppend` 계열로 추정)로 골라 실행 버튼을 누른다. 그러면 승인이 필요하다는 권한 검토 메시지가 뜨는데, **구글이 확인하지 않은 개인 앱**이라 확인이 필요하다는 경고가 나온다. 이때 좌측 하단 "고급" 버튼을 클릭하고 권한을 승인한 뒤 "계속"을 눌러 테스트를 이어간다.

### [06:25–06:53] 테스트 성공 — 시트에 데이터가 쌓임
테스트가 실행되고 완료되면, 방금 만든 스프레드시트로 돌아가 데이터가 잘 들어간 것을 확인한다. 화자는 "개발 지식 없이 클로드에게 원하는 것을 요청하고 시키는 대로 했을 뿐인데 이제 구글 스프레드시트를 데이터베이스로 사용하기 시작한 것"이라고 정리한다.

### [06:53–07:24] 절차 ④ 웹 앱으로 배포
이제 웹사이트의 연락 폼과 스프레드시트를 연결하려면 앱스크립트를 **배포**해야 한다. 앱스크립트에서 배포 버튼 → 새 배포 버튼을 누르고, 유형은 "웹 앱", 설명은 "예약 사이트", **인증 정보는 "나", 액세스 권한이 있는 사용자는 "모든 사용자"**를 선택한다(이 값들도 클로드가 안내한 것).

### [07:24–07:44] 배포 권한 승인 + 웹 URL 확보
배포 버튼을 누르고 액세스 승인을 하면 다시 "승인되지 않은 앱" 경고가 뜨는데, 마찬가지로 좌측 하단 "고급(advanced)"을 클릭해 권한을 한 번 더 승인한다. 그러면 앱스크립트 코드가 배포되고 하단에 **웹 앱 URL**이 나온다.

### [07:44–08:16] 클로드가 폼↔시트 연결 + 자동 테스트
이 웹 앱 URL을 복사해 클로드에게 전달하면, **클로드가 직접 웹사이트와 스프레드시트를 연결하고 작동까지 확인**해 준다. 잠시 기다리면 클로드가 테스트를 진행하고, 결과적으로 요청한 테스트가 전부 구글 스프레드시트에 들어온 것을 확인할 수 있다. 이 테스트 행들은 지워준다. 또한 앞으로 `코드.gs`를 수정할 때마다 **새 버전으로 배포를 거쳐야** 반영이 완성된다고 일러둔다.

### [08:16–08:51] 실제 폼 제출 테스트
클로드는 테스트용이 아니라 실제 예약을 받을 거라면 **여러 보안 요소를 붙이는 것을 추천**한다. 이제 웹사이트에서 실제로 예약 폼을 채워 "예약 요청 보내기"를 누르면 요청이 넘어갔다는 표시가 뜨고, 스프레드시트를 확인하면 사용자가 입력한 데이터가 그대로 쌓인 것을 볼 수 있다. 잘 안 되면 새로고침 후 다시 시도하면 된다.

### [08:51–09:41] 다음 기능 ② 자동 알림 메일 요청
손님이 문의를 넣으면 손님과 주인(화자) 모두에게 알림을 보내야 한다. 이런 자동 알림 메일은 보통 유료 솔루션을 붙여 매달 돈을 내야 하는 기능인데(화자 주장/미검증), 여기서는 클로드 코드에서 프롬프트 하나로 만든다. 클로드에게 "문의가 접수되면 **손님에게는 예약 문의가 접수되었다는 메시지**를, **나에게는 Gmail을 활용해 새 예약 문의가 왔다는 내용**을 보내도록 앱스크립트에 들어갈 내용을 작성해 달라"고 요청한다.

### [09:41–10:11] 알림 메일용 코드 교체 + 테스트
클로드가 `코드.gs` 파일을 수정해 주면, 그 내용을 그대로 복사해 스프레드시트 → 앱스크립트로 가서 기존 코드를 새 코드로 교체·저장한다. 그다음 "테스트 메일 보내기"류 테스트 함수(자막 "테스트 메일 온")를 실행하고, 실행 권한도 승인한다.

### [10:11–10:37] 알림 메일 수신 확인
메일함을 확인하면 예약을 문의한 사용자에게 갈 메일과 웹사이트 주인(나)에게 올 메일이 모두 도착한 것을 확인할 수 있다. 화자는 "이 작업으로 예약 문의를 담당하는 **AI 직원 하나를 뽑은 셈**"이라고 표현한다([의견]). 다만 이 테스트는 두 메일 모두 나에게 보내도록 설계된 것이고, 실제로는 사용자와 나에게 각각 전송된다.

### [10:37–11:16] 새 버전 배포 후 실제 문의 테스트
테스트가 확인되었으니 새로 배포하는데, 이때는 "새 배포"가 아니라 **"배포 관리"에서 새 버전으로** 배포한다(클로드가 요청한 방식). 배포 후 웹사이트에서 "데키랩"이라는 이름과 이메일로 실제 문의를 넣으면, 주인인 나에게는 "새 예약 문의 접수" 메일이, 사용자에게는 "예약 문의 접수" 메일이 전송되고 스프레드시트에도 데이터가 정상 입력된다.

### [11:16–11:50] 한계 — 확인 메일일 뿐 답변은 아님
지금 발송되는 메일들은 그저 **접수 확인 메일**로, 고객이 실제로 물어본 내용에는 답하지 않는다. 무엇을 물어보든 "예약이 완료되었다"는 식의 문자만 간다. 따라서 사람의 판단이 필요한 답장을 보내기 위해 추가 기능을 구현한다. 물론 한 건씩 직접 써도 되지만, **답변이 어느 정도 정형화되어 있다면 이것도 자동화**할 수 있다.

### [11:50–12:23] 답장 자동화 준비 — Gmail 커넥터 연결
클로드를 활용해 답장을 자동화하는데, 이때 **Gmail 커넥터**를 쓴다. 커넥터 연결을 위해 **클로드 데스크톱 앱**을 켜고, 좌측의 사용자 지정 → 커넥터 버튼에서 Gmail을 찾아 클로드와 Gmail 커넥터를 연결한다. 도구 권한은 "항상 허용"으로 두고 테스트를 진행한다.

### [12:23–12:57] Gmail 연동 확인 + 답장 초안 요청
클로드 코드로 넘어와 Gmail이 잘 연동됐는지 확인한다. "제 계정에서(자막 '제 주일에서') 오늘 들어온 새 예약 문의 알림 메일들을 찾아 문의들을 분류하고, 손님께 보낼 **답장 초안을 존댓말로** 작성해 달라"고 요청한다. 그러면 클로드는 현재 객실 상황을 아는 나에게 판단을 넘기기 위해 **두 가지 예시 메일**을 제시한다.

### [12:57–13:20] 초안 A/B — 재고 판단은 사람 몫
클로드가 제시한 두 초안: 당일 예약 상황에서 **당일 예약이 가능하면 초안 A**로, 그렇지 않으면 **예약이 조금 어렵다는 초안 B**로 보내면 된다. 현재는 웹사이트에 데이터베이스를 붙이지 않았고 재고 데이터가 사용자(나)에게만 있어서, 이런 판단을 하나하나 직접 처리해야 한다.

### [13:20–13:42] 확장 가능성 — 재고 에이전트 + 루틴
[의견/전망] 추후 데이터베이스를 붙이고 **재고를 관리하는 에이전트**를 붙이면 이 판단 부분마저 자동화할 수 있다. 나아가 클로드 코드의 **루틴 기능**을 활용해 매일 아침이나 정각마다 원하는 시간에 새 문의를 확인하고 원하는 답장으로 고객에게 응답하는 자동화 시스템도 만들 수 있다. 원하는 사람이 있으면 그 단계까지 발전시키는 모습을 보여주겠다고 예고하지만, 이번 편은 메일 자동화 수준까지만 다룬다.

### [13:42–14:02] 답장 임시저장(초안 보관)
"초안 B로 임시 저장 메시지 작성해 줘"라고 요청하면, 클로드가 **Gmail 임시 보관함에 메일을 저장**한다. 실제로 확인하면 바로 답장할 수 있도록 임시저장 메일함에 초안이 작성된 것을 볼 수 있다.

### [14:02–14:41] 답변 템플릿 파일 만들기
매번 초안이 새로 작성되는 게 신경 쓰이고 답변을 지정해 두고 싶다면, 미리 **답변 템플릿**을 만들어 두면 좋다. 클로드에게 "템플릿"이라는 폴더를 만들어 예상 답변들을 모은 답변 템플릿 파일을 만들어 달라고 요청할 수 있다. 예로 **열 가지 상황**에 대한 답장 예시를 정리해 미리 템플릿으로 만들어 달라고 요청한다.

### [14:41–14:54] 템플릿 효과 — 일관성
템플릿 문서를 확인하면 각 상황별 메시지 템플릿들이 생성되어 있다. 이렇게 메일을 템플릿화해 두면 **매번 다른 메일이 생성될 불확실성을 줄이고 항상 일관된 메일**을 보낼 수 있다. 원하면 언제든 이 템플릿 메일들을 수정할 수 있다.

### [14:54–15:37] 강의 홍보 — 데키랩 AI 자동화 강의
관리자 페이지 제작에 앞서, 실습을 따라오다 막히는 사람들을 위해 새로 출시된 **데키랩의 AI 자동화 강의**를 소개한다. 데키랩이 실제로 쓰는 워크플로를 처음부터 끝까지 함께 만드는 강의로, "유튜브 영상만으로는 부족하다"는 사람에게 맞다고 한다. 정식 출시 후 일주일 만에 100명이 넘게 수강 중이며(화자 주장/미검증), 강의 내용뿐 아니라 개인 프로젝트까지 수강생 커뮤니티에서 질문하며 성장할 수 있다고 안내한다. 자세한 내용은 영상 설명란 링크 참고. (세일즈 장치 — 정보로 1회 기록)

### [15:37–16:14] 마지막 기능 ③ 관리자 페이지 취지
현재 상황: 사용자가 예약 문의를 넣으면 나와 사용자에게 도착 알림이 오고, 자주 묻는 질문은 답장 자동화까지 되어 있다. 여기에 문의들을 한눈에 확인할 **관리자 페이지**를 추가한다. 구글 스프레드시트에서도 확인할 수 있지만, **시인성 좋게 한눈에** 보기 위함이다. 화자는 "이런 관리자 대시보드가 웹사이트 외주 견적에서 꽤나 비싼 항목 중 하나"라고 언급한다(비용 주장/미검증).

### [16:14–17:01] 관리자 페이지 요청 내용
클로드에게 "구글 스프레드시트에 있는 예약 문의 데이터를 읽어서 보여주는 관리자 페이지"를 만들어 달라고 요청한다. 넣을 내용은 자유롭게 적으면 되는데, 화자는 **이번 주 문의 건수·미응대 문의 수·체크인 예정 팀 수**의 요약 카드, **문의 목록**, 미응대 방지를 위한 **문의 상태 데이터**, **최근 문의 추이 그래프**와 이번 주 요약 등을 한눈에 볼 수 있게 요청했다.

### [17:01–17:24] 서버 없는 로컬 전용 관리자 페이지
현재 서버·데이터베이스를 쓰지 않아 **로그인이나 회원가입은 되지 않는 상황**이다. 지금 기능 수준에서는 서버 없이 로컬에서만 돌리는 가벼운 형태도 큰 제약이 없으므로, **서버 없이 로컬에서만 데이터를 받아오는** 관리자 페이지로 만든다.

### [17:24–18:06] 관리자 키 설정 + 배포
프롬프트를 넣으면 클로드가 관리자 페이지를 생성하는데, 확인 전 반영할 사항이 있다고 한다. `코드.gs` 파일 안에 **어드민 키(admin key) 값**을 하나 정하라고 보안상 요구한다. 화자는 "테스트1"이라고 간단히 적고, 배포 전에 관리자 페이지의 어드민 키에도 **같은 키 값**을 넣어 저장한다. 그다음 `코드.gs`를 복사해 스프레드시트 → 확장 프로그램 → 앱스크립트의 `코드.gs`에 새로 붙여넣고 저장한 뒤, "배포 관리"에서 새 버전으로 배포한다.

### [18:06–18:32] 관리자 페이지 실행 확인
완료 버튼을 누른 뒤 클로드가 만들어 준 `어드민.html`(admin.html) 로컬 파일을 실행하면 예약 문의 기반 관리자 페이지가 뜬다. 이번 주 문의 건수·미응대 건수·이번 주 예정 체크인이 정리돼 있고, 최근 일주일 문의 내용이 정리돼 있다. 문의 목록에서 체크한 뒤 새로고침하면 **"완료" 상태로 바뀌는 것**을 확인할 수 있다.

### [18:32–18:57] 최종 통합 테스트
관리자 페이지가 연결됐으니 홈페이지에서 최종 문의를 넣어 보면, **구글 스프레드시트는 물론 관리자 페이지에도 새로운 문의 목록이 생성**되는 것을 확인할 수 있다. 한눈에 들어오는 문의 내용을 볼 수 있고, 원하면 클로드와 대화로 언제든 관리자 페이지를 원하는 내용으로 바꿀 수 있어 편리하다.

### [18:57–19:39] 마무리 + 다음 편 예고
오늘처럼 클로드에게 자연어로 원하는 것만 요청하고 클로드가 제안하는 대로 따라오다 보니 실전적인 기능들을 완성할 수 있었고, **클로드 이외에는 전부 무료로** 구현했다(화자 주장). 다만 지금 웹사이트는 간단히 배포된 상태이고 관리자 페이지는 로컬로 돌린다. 따라서 **다음(3탄)에는 홈페이지를 본격 배포하고 데이터베이스도 붙여** 더 다양한 기능을 구현하겠다고 예고한다. 궁금한 점은 댓글로 남겨달라며 구독·좋아요를 부탁하고 마무리한다.
