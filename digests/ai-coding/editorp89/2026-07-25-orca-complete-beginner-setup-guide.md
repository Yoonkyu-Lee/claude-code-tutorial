## 요약 (주제별)

### 영상 목적과 화자의 오르카 평가
- Orca(오르카) 완전 초보용 세팅·입문 가이드. 설치부터 복잡한 화면에서 어떤 버튼만 눌러 쓰면 되는지를 초보 관점에서 천천히 함께 해보는 구성.
- 화자는 오르카를 7일 정도 사용. [의견] 솔직히 **안 써도 아무 일 안 생긴다** — 필수도 아니고 없다고 생산성이 떨어지는 것도 아님.
- [의견] 다만 앱이 세련됐고, 시먹스(tmux 계열 추정, `[불명확]`)·와프(Warp) 등 다른 터미널 프로그램에서 A는 있는데 B가 없는 식으로 아쉬웠던 기능들이 오르카에는 "좌우지간 다 있어서" 계속 쓴다. 특별한 비법 없이 기본으로 깔고 가는 프로그램처럼 사용.

### 핵심 경고 — 오르카는 "토큰을 빨리 태우는 아궁이"
- 오르카는 **토큰을 빠르게 소모하도록 최적화된 툴**. 비유: 장작을 빨리 태우는 아궁이. [의견] 유저가 토큰을 빨리 써야 에이전트 업체가 돈을 버니 업체가 좋아할 프로그램.
- 이유는 오르카의 핵심이 **워크트리(worktree) 기반 멀티 에이전트 병렬 실행**이라는 데 있음(아래 참조). 워크를 여러 개 만들어 병렬로 돌리면 좋은 후보를 골라오기 좋지만 **토큰을 N배(예: 4배)로 쓴다**.
- [의견] 화자의 구독자 대부분은 월 100~200달러씩 여러 에이전트를 쓰는 사람이 아니라 **제일 좋은 것 하나만 쓰는 사람**이라, 워크트리 방식은 이들에게 부적합. 그래서 온보딩(멀티 에이전트를 종용하는 설정)을 끄라고 권한다.

### 설치와 첫 화면
- "오르카"로 검색 → onorca.dev 계열 데브 사이트(자막상 도메인 표기 불명확, `[불명확]`)에서 OS별 다운로드 → 실행하면 설치 진행(쉬움).
- 첫 실행 시 **온보딩 가이드**가 뜸(설치된 에이전트를 감지해 편하게 쓰게 해주겠다는 안내). [의견] **"프로젝트 설정으로 건너뛰기"로 넘기고 설정하지 말 것을 추천** — 순수하게 쓰는 걸 권함. 온보딩은 은근히 멀티 에이전트/토큰 소모 방향을 종용하는 설정이기 때문.

### 화면 구성 — 왼쪽 폴더 라인업 / 오른쪽 파일 탐색기
- 왼쪽: 에이전트를 띄울 때마다 추가되는 **폴더별 라인업**. 에이전트는 **폴더별로 따로 소환돼 그 폴더 안에서만 동작**. PC 전체에 띄우면 전체를 잡아버려 안 좋으니 **폴더 위에서 띄우는 게 정석**. (왼쪽 "제거"는 목록에서 빼는 것이지 실제 폴더 삭제가 아님.)
- 오른쪽: **파일 탐색기**. 개발 중 생기는 파일·보안 파일(`.env` 등)까지 바로 확인. 이미지 등을 **드래그 앤 드롭**으로 에이전트에 바로 첨부 가능. [의견] 화자는 이 사소한 기능(드래그 앤 드롭이 부드럽게 됨) 때문에 오르카로 넘어왔다고 함.

### 워크트리(worktree) 개념과 트레이드오프
- 오르카를 쓴다 = 워크트리를 쓴다. **한 폴더에서 에이전트 여러 개가 하나뿐인 공용 파일을 동시에 수정하면 충돌**이 남. 워크트리는 그 **폴더(코딩 책상)를 복제**해, 서브 책상에서 서로 다른 에이전트(예: 코덱스 vs 클로드 코드)가 병렬 작업 후, 더 잘된 것을 메인에 **병합(merge)**하는 전략.
- 레포지토리(폴더) 추가 후 **플러스(+)를 누르면 복제된 워크트리가 만들어짐** — 사용자가 인지하지 못한 채 복제되는 구조. 병렬 후보 선택엔 좋지만 토큰을 배수로 소모(위 "핵심 경고" 참조).

### 폴더 두 개 병행 실습 (워크트리와 별개)
- "테스트 오르카 1번/2번" 두 폴더를 만들어 각각 다른 작업(웹 개발 vs 문서 개발 등)을 병행하는 예시 — **이건 워크트리가 아니라 그냥 폴더 두 개 병행**.
- 각 폴더에 터미널이 살아 있고 접었다 폈다 가능. 클로드 코드·코덱스는 각자 사전 설치 필요(설치법은 화자 이전 영상).
- 실습: 1번 폴더 터미널에 **클로드 코드**(`--dangerously-skip-permissions`) → 모델 **오퍼스 5**, 리즈닝(에포트) **하이**. 2번 폴더 터미널에 **코덱스** → 모델 **GPT-5.6("쏘"/Sol 계열 추정, `[불명확]`)**, 리즈닝 **하이**.
- 터미널 상태 표시: **초록불 = 에이전트 실행 중**, **idle = 대기 상태**. 계층 구조는 폴더 → 터미널 → 에이전트 순으로 얹힘.
- 작업 지시: 양쪽에 "유명 엔터테인먼트 소속사 랜딩 페이지 만들기"를 병렬로 시켜, 왼쪽 라인업의 빙빙 도는 아이콘으로 진행 상태를 한눈에 확인.

### 편의 기능 — 알림 / 새 터미널 / 새 브라우저 탭
- **알림**: 설정에서 켜면 작업 완료 시 소리로 알림. [의견] 요즘 작업이 5분+ 기본이라 대기가 힘든데 유용.
- **새 터미널(+)**: 워크트리와 달리 **같은 책상(폴더)에 다른 에이전트를 추가 소환**. 예: 코덱스로 시키고 클로드로 평가하는 식.
- **새 브라우저 탭(+)**: 오르카 내장 웹 브라우저. 처음엔 크롬 로그인 기록 미공유라 재로그인 필요하지만, **"가져오기(import)"로 크롬·사파리 설정을 한꺼번에 가져올 수 있음**.

### 오르카 내장 브라우저의 핵심 3기능 (초보용 웹 개발)
- **말풍선(페이지 요소의 주석 달기)**: 화면의 임의 요소를 클릭해 잡고, 그 요소에 대한 질문 프롬프트를 에이전트에 전송. **브라우저·탭·화면 크기·선택 요소 정보**가 함께 담겨 넘어가 답변 퀄리티가 올라감. (질문 대상 에이전트는 온보딩에서 설정했거나 "보내기" 시 선택.)
- **위치 복사(Copy)**: 클릭 한 번으로 요소의 **위치 주소 + 그 자리 정보**를 클립보드에 복사 → 붙여넣어 질문. 말풍선과 유사하나, 말풍선=질문 동반, 복사=위치만 복사.
- **변경(수정) 모드**: 요소를 선택해 실제 변경을 지시("빨간색으로 바꿔 줘", "한글로 바꿔 줘", "글자색 바꿔 줘" 등)하고 일괄로 작업 중 에이전트에게 전송 → 해당 부분만 수정. [의견] 남의 서버(예: 네이버)는 실제로 못 바꾸고 화자에게만 보이는 임시 변경으로 표시.

### 실전 결과 — 코덱스 vs 오퍼스 5 랜딩 페이지
- 코덱스: **이미지까지 잘 만들어** 멋진 소속사 사이트 완성. 변경 모드로 "녹턴"을 한글로, 글자색 변경 등을 일괄 적용해 반영 확인.
- 오퍼스 5(클로드): [의견] **이미지 생성을 못 해** 이미지가 빠졌지만 구성 자체는 훌륭. 이미지 유무로 평가하지 말고 구성을 볼 것. (웹브라우저 자동 표시가 잘 안 돼 화자가 직접 브라우저 탭으로 확인.)
- 파일 드래그 앤 드롭 재강조: 복사·붙여넣기 없이 이미지를 넘길 수 있고, [의견] 오르카가 이를 훨씬 부드럽게 처리.

### 마무리와 후속 예고
- [의견] 병렬 사용은 오르카에서 많이들 헷갈려하는 부분이라 초보용으로 정리. 오르카로 처음 에이전트에 입문하는 사람에게 가이드가 되기를 바람.
- 오르카 **모바일**과 **에뮬레이터**는 안 다룸 — 반응 보고 원하면 두 번째 영상으로 예고.

## 전문 — 시간순 워크스루

### [00:00–00:28] 오프닝 — 오르카 완전 초보 세팅 가이드
오르카(Orca) 완전 초보 세팅 가이드 영상을 준비해 왔다고 소개하며 시작한다. 유튜브에 검색하면 다른 유튜버들이 오르카를 통차게(통째로) 잘 소개하는 영상이 많은데, 오늘 화자가 소개할 내용은 자기도 똑같이 생각하는 내용을 간단히 말하는 것이라고 함. 어쨌든 오르카를 설치한 다음, 설치부터 그 복잡한 화면에서 어떤 버튼만 눌러서 사용하는 게 입문자 입장에서 좋은지를 천천히 같이 해보는 시간을 갖겠다고 예고한다.

### [00:28–00:45] 오르카 솔직 평가 — 없어도 아무 일 안 생김
먼저 오르카 소개를 한다. 화자는 오르카를 7일 정도 써 보고 있다고 밝힌다. [의견] 솔직하게 말하면 이걸 안 쓴다고 해서 아무 일도 안 생긴다고 함 — 꼭 필수고 최고고 이거 없으면 생산성이 떨어져 뒤쳐질 것 같은, 그런 문제는 없다는 것.

### [00:45–01:05] 오르카가 좋은 점 — 세련됨 + 기능 통합
[의견] 다만 화자가 봤을 때 앱이 좀 세련됐다는 생각이 든다고 함. 시먹스(Cimux/시먹스 — 자막상 표기 불명확)나 와프(Warp) 같은 다양한 프로그램을 쓰는데, 그런 것들과 비교하면 화자가 아쉬웠던 기능이 조금씩 있었다는 것. 예를 들어 시먹스에는 A 기능이 있는데 B가 없고, 와프에는 B가 있는데 A가 없어서 불편했는데, 오르카는 좌우지간 다 있으니 그런 점이 좋다고 평가한다. 그래서 자기도 오르카를 계속 쓰고 있다고 함. [불명확: "시먹స"는 자막상 표기가 불분명 — 문맥상 tmux 또는 유사 터미널 멀티플렉서 프로그램으로 추정되나 확정 불가]

### [01:05–01:18] 오르카를 쓰는 태도 — 특별한 비법 없이 기본 깔개
[의견] 화자는 오르카를 자기만의 비법이 있어 특별하게 쓰는 건 거의 없고, 일반적인 평범한 작업을 할 때 그냥 기본으로 깔고 가는 프로그램처럼 쓰자는 생각으로 쓰고 있다고 함.

### [01:18–01:44] 핵심 성격 — 토큰을 빠르게 소모하도록 최적화된 툴
오르카는 기본적으로 **토큰을 빠르게 소모하는 데 최적화된 툴**이라고 규정한다(뒤에서 상세 설명 예고). [의견] 화자는 굳이 그렇게까지 쓸 필요가 있을까 생각하지만 소개는 해주겠다고 함. 쉽게 말하면 오르카는 **장작을 빨리 태우는 아궁이 같은 녀석**이라는 비유. 그래서 에이전트 제공 업체는 참 좋아할 프로그램일 것 같다고 함 — 유저들이 토큰을 빨리 써야 업체가 돈을 많이 벌기 때문. [의견] 업체가 좋아할 것 같다는 관측.

### [01:44–02:13] 오르카 다운로드 — 클린 상태로 설치 시작
이제 오르카를 설치해 본다. 화자는 오르카를 한창 쓰다가 자기 세팅을 다 갖다 버리고, 시청자와 함께 설치해 보려고 완전히 클린한(플린한) 상태로 준비했다고 함. 오르카는 검색하면 되고, "오르카"라고 검색하면 **onorca.dev**(자막상 "온오르카.de데" — 도메인 표기 불명확)라는 데브 사이트가 나온다. 접속한 다음 그 사이트의 다운로드 버튼에서 자기 운영체제에 맞춰 버튼을 눌러 프로그램을 다운로드하면 된다. [불명확: 다운로드 사이트 도메인이 자막상 "온오르카.de데"로 표기돼 정확한 주소(onorca.dev 등) 확정 불가]

### [02:13–02:27] 설치 파일 실행
그러면 설치 파일이 다운로드되고, 다운로드가 다 되면 실행한다. 실행하면 바로 설치가 진행되는 것을 볼 수 있고, 설치는 그렇게 어렵지 않다고 함.

### [02:27–02:47] 첫 실행 — 온보딩 가이드
설치 후 오르카를 실행하면 가장 먼저 뜨는 것이 **온보딩 가이드**다. 온보딩 가이드를 보면, 마치 시스템에 설치된 다양한 에이전트를 오르카가 감지해서 "내가 이걸 편하게 쓸 수 있게 해줄게"라고 얘기해 주는 모습이 있다.

### [02:47–03:00] 온보딩 건너뛰기 추천
[의견] 화자는 이걸 **그냥 "프로젝트 설정으로 건너뛰기"로 넘기고 설정하지 않는 것을 추천**한다 — 그냥 순수하게 쓰는 것을 권한다. 프로젝트 추가가 나오면 끄고(다시 볼 수 있음), 오른쪽 아래의 "온보딩 완료" 버튼을 눌러 그냥 닫아주면 된다.

### [03:00–03:03] 메인 화면 진입
이게 시청자가 보게 되는 오르카의 메인 화면이라고 소개한다.

### [03:03–03:20] 왼쪽 패널 — 폴더별 에이전트, PC 구조 비유
왼쪽에 있는 것은 에이전트를 띄울 때마다 추가되는 영역이다. **폴더별로 따로따로 에이전트를 구동**하는 구조. 화자가 이전 영상들에서 설명한 대로, 이 "에이전트"라는 녀석은 우리 PC 안에서 동작하는데, PC 안에 여러 폴더가 존재하고 그 **폴더별로 에이전트가 따로 소환돼서 도는 방식**으로 구동한다고 다시 설명한다.

### [03:20–03:37] 에이전트는 폴더 위에서 띄우는 게 정석
에이전트를 구동할 때 주의할 점은, **에이전트가 어떤 폴더 안에서 실행되는지에 따라 그 폴더 안에서만 논다**는 것. 에이전트를 PC 전체에 띄워버리면 전체를 잡아버려 안 좋으므로, **보통은 폴더 위에다 띄워서 보는 게 좋다**고 강조. 이 폴더들을 여기서 띄워 하나씩 볼 수 있다고 함.

### [03:37–03:57] 오른쪽 패널 — 파일 탐색기(만족했던 기능)
오른쪽은 화자가 만족했던 기능 중 하나인 **폴더 안 파일 탐색기** 기능이다. [의견] 에이전트를 쓸 때 제일 불편한 게, 이미지 같은 어떤 파일을 에이전트 창에 드래그 앤 드롭으로 올리고 싶은데 그게 안 되던 점이었다. 오르카는 파일 탐색기가 있어 그게 된다. [의견] 화자도 이 사소한 기능 때문에 오르카로 넘어왔다고 밝힌다. 설치 후 화면은 그대로 두겠다고 함.

### [03:57–04:06] 오르카의 핵심 — 워크트리를 쓴다는 것
이제 오르카의 핵심을 얘기해야 한다며, 오르카를 쓴다는 건 곧 **워크트리(worktree)를 쓰겠다는 것**이라고 규정한다. 오르카가 "워크트리"라는 용어를 자꾸 얘기한다는 점을 지적.

### [04:06–04:30] 워크트리 만들기 시연 — 레포지토리(폴더) 추가
워크트리가 무엇인지 시연한다. 화면의 버튼을 누르면 호스트가 있고, 레포지토리(repository)를 추가하겠다며 폴더를 추가한다. 아무 폴더나 선택하면 그 폴더를 열어주고, 그 안에서 플러스(+)를 누르면 오르카가 **워크 트리를 만들려고 한다**. 그렇게 작업 트리를 만들어 본다.

### [04:30–05:18] 워크트리가 필요한 이유 — 한 폴더에서 여러 에이전트가 충돌
워크트리가 왜 필요한지 설명한다. 폴더를 하나 띄운 상태에서, 원래는 한 폴더에서 에이전트 하나만 쓴다. 그런데 **한 폴더 안에서 다수의 작업을 하고 싶으면** 문제가 생긴다 — 폴더 안 파일들은 공용이라 하나뿐인데, 이 파일을 **에이전트 두 개가 동시에 수정하려 들면 충돌(꽝)이 난다**. A는 이렇게 치고 싶고 B는 저렇게 치고 싶은데, 하나의 파일을 동시에 고칠 수 없다는 것이 문제.

### [05:18–05:34] 워크트리 = 폴더(코딩 책상)를 복제
그래서 **워크트리란 그 폴더를 복제하는 것**이다. 폴더를 복제해서 동일한 "복제된 코딩 책상"을 하나 더 만든다. 그다음 "너는 여기 수정해, 난 복제된 데서 할게" 식으로 나누고, 나중에 더 잘된 사람 것을 다시 합쳐 하나로 만든다 — 이런 전략을 갖는 것이 워크트리를 쓴다는 것.

### [05:34–06:03] 메인 책상 + 서브 책상 → 병합 전략
메인 책상이 있고, 서브 코딩 책상들이 있는데, 서브 책상에서 원래 있던 파일을 각자 복제해 따로 가져간 다음 각자 작업을 진행한다. 한쪽은 이렇게 되고 다른 쪽은 아예 다른 방향으로 됐는데 그쪽이 조금 더 좋다면, 메인으로 합칠 때 그 좋은 것을 가지고 들어온다. 그렇게 합쳐서 진행할 수 있으니 좋아 보인다고 함.

### [06:03–06:15] 병렬 실행 = 효율 (코덱스 vs 클로드 코드 비교)
복제된 책상에서 서로 다른 에이전트들이 동작하니, **에이전트가 병렬로 진행되면서 굉장히 효율적**이라고 함. 예를 들어 여기서는 코덱스가 똑같은 파일로 해보고, 여기는 클로드 코드가 해보고, 둘 중 어느 쪽이 더 잘했나 비교해서 더 잘한 것을 합쳐 이후 작업을 이어갈 수 있다는 것. 이것이 워크트리를 쓴다는 의미.

### [06:15–06:27] 오르카는 인지 못 한 채 워크트리를 만든다
그런데 오르카는 사용자가 인지하지 못한 상태에서 그냥 플러스만 누르면 복제된 책상을 만들어 작업을 진행하게 된다는 점을 지적한다. 이것이 워크스페이스/워크트리의 개념이다.

### [06:27–06:42] 워크트리의 이면 — 토큰을 N배로 소모
워크트리를 한다는 건 에이전트가 복제된 책상에서 동시에 작업을 진행하는 것이라, 모르고 쓰면 좋다고 느낄 수 있다. 워크를 많이 만들어 돌리면 가장 좋은 후보를 골라오기 좋기 때문. 예를 들어 사이트 디자인이 마음에 안 들 때 네 개를 동시에 시켜 "제일 좋은 걸 내가 고를 테니 각자 갖고 와봐" 하면 일단 좋아 보인다. **하지만 토큰을 4배로 쓴다**는 것이 핵심.

### [06:42–07:07] 오르카의 핵심 = 토큰 소모 유도 (초보에게는 부적합)
[의견] 오르카는 그 **토큰 소모를 유도하는 방향의 기능을 핵심으로 가지고 있다**는 것. 온보딩에서 에이전트를 선택·추가하게 하는 이유도 아마 이것이라고 추정. 화자가 이걸 안 좋다고 하는 이유는, 자기 영상을 보는 대부분의 구독자는 화자처럼 에이전트 여러 개에 월 100~200달러씩 쓰는 사람이 아니라 **제일 좋은 것 하나만 쓰는 사람**이 많기 때문. 그런 입장에서는 워크를 쓴다는 게 그렇게 좋지 않다는 것.

### [07:07–07:34] 온보딩을 끄라고 한 이유 재확인 + 오늘의 목표
[의견] 그래서 화자가 온보딩을 하지 말자고 했던 것이다 — 온보딩 과정은 은근히 그 방향(멀티 에이전트/토큰 소모)을 종용·강요하는 설정이기 때문. 오늘 오르카를 쓰는 방법은 (1) 기본 설치가 끝난 뒤 가장 현실적이고 무난한 세팅, (2) 화자가 주관적으로 꼽은 주요 기능들을 소개하고, (3) 클로드 코드와 코덱스를 각각 띄워 써보는 흐름이라고 안내한다.

### [07:34–08:12] 화면 구성 설명 시작 — 폴더 추가/제거
화면 UI를 줌으로 크게 만들어 설명한다. 왼쪽의 플러스/폴더 버튼을 누르면 작업하는 폴더를 추가할 수 있다. 화자는 기존 것을 다 꺼버리는데, **여기서 "제거"는 목록에서 지우는 것이지 실제 폴더를 지우는 게 아니라고** 명확히 한다.

### [08:12–08:38] 테스트용 폴더 두 개 생성
새 작업을 위해 새 폴더를 만든다. 원하는 위치에 "테스트"라는 폴더를 만들고, 그 안에 **테스트 오르카 1번**과 **테스트 오르카 2번** 두 개를 만든다.

### [08:38–08:55] 두 폴더를 오르카에 추가
플러스 버튼 → 폴더 찾아보기 → "테스트" 폴더 안의 "테스트 오르카 1번"을 열고, 이어서 폴더를 하나 더 연다. 두 개의 폴더에서 동시에 작업하는 예시를 보여주기 위한 것.

### [08:55–09:07] 이건 워크트리가 아니라 그냥 두 폴더 병행
[의견] 이것은 **워크트리와 상관없이** 그냥 폴더를 두 개 만들어, 예를 들어 한쪽에서는 웹 개발, 한쪽에서는 문서 개발을 하고 싶은 사람을 위한 예시라고 명확히 구분한다.

### [09:07–09:07] 각 폴더에 살아 있는 터미널
각 폴더에는 터미널이 살아 있다. 폴더를 누르면 터미널이 접혔다 펴졌다 하고, 2번 터미널과 1번 터미널을 왔다 갔다 할 수 있다.

### [09:07–09:24] 클로드 코드·코덱스 사전 설치 안내
이제 클로드 코드와 코덱스를 둘 다 써보면 좋은데, 둘 다 설치돼 있어야 한다. 클로드 코드와 코덱스는 각자 설치해 와야 하고, 설치 방법은 화자의 이전 영상에 나와 있으니 진행하라고 안내.

### [09:24–09:57] 폴더 상태 그림 설명 — 아직 에이전트 미실행
화자가 화면에 그림을 그리며 설명한다. "테스트 오르카 1번" 폴더가 있고, 지금 비어 있는 상태로 어떤 에이전트도 띄우지 않았으며 터미널만 떠 있는 상태다. 여기가 2번이고, 폴더를 두 개만 만들었으니 이런 상황을 가정한다. 위치를 옮겨 보기 편하게 정리해, 두 폴더가 있고 에이전트는 아직 안 띄운 상태라고 정리.

### [09:57–10:12] 테스트 오르카 1번에 클로드 코드 실행 (danger 권한)
"테스트 오르카 1번"에 **클로드를 실행**한다. 화자는 클로드를 "데인저러스 퍼미션스"(`--dangerously-skip-permissions`)로 띄운다.

### [10:12–10:18] 터미널 상태 표시 — 초록불 + 아이들(idle)
띄우면 이 터미널에 **초록색 불**이 떠 있는데, 이는 현재 이 터미널에서 클로드 코드를 실행한 상태라는 뜻이고, "아이들(idle)"은 대기(배기) 상태라는 뜻이라고 설명한다. 테스트 오르카 1번의 터미널에서 클로드 코드를 띄운 상태.

### [10:18–10:37] 폴더 위 터미널 위 클로드 코드 — 구조 그림
회색 지대는 폴더 구조, 그 위에 검정색 터미널 화면을 띄웠고, 그 터미널 위에 비로소 클로드 코드를 띄운 것이라고 계층 구조를 그림으로 정리한다. 즉 폴더 → 터미널 → 클로드 코드 순으로 얹혀 있는 구조.

### [10:37–10:56] 테스트 오르카 2번에 코덱스 실행
두 번째로, 2번 폴더의 터미널로 이동한다. 터미널만 떠 있는 상태에서 **코덱스를 띄운다**. 코덱스는 업데이트도 좀 해주고, 화자는 코덱스를 실행해 시작한다.

### [10:56–11:13] 1번=클로드, 2번=코덱스 정리
정리하면 1번 폴더 터미널에는 클로드 코드, 2번 폴더 터미널에는 코덱스가 떠 있는 상태다. 각자의 코덱스와 클로드 코드가 떠 있는 상태.

### [11:13–11:20] 아이콘 차이 — 기본이 클로드라서
한쪽엔 아이콘이 있고 한쪽엔 없는데, 이는 오르카가 기본을 클로드 코드로 잡고 있어서 그런 것이며 중요하지 않다고 함.

### [11:20–11:31] 양쪽 폴더에서 각각 작업 시작
이제 양쪽 폴더에 서로 다른 에이전트를 띄운 상태에서 작업을 진행하면 된다. 이 폴더에서는 이 작업, 저 폴더에서는 저 작업. 터미널은 안 보이게 접어 두고 떠 있다고 가정하고 진행한다.

### [11:31–11:41] 클로드에 오퍼스 5 모델 선택
각자 다른 작업을 시켜본다. 한쪽(클로드)에서는 **오퍼스 5(Opus 5)**를 쓴다 — 오퍼스가 새로 나왔다며 오퍼스 5번을 쓰겠다고 함. `/model`(슬래시 모델)로 모델 설정을 할 수 있고, 이것도 이전 영상에서 다 설명했다고 함.

### [11:41–11:53] 리즈닝(에포트) 좌우키로 선택 → 하이 에포트
그 상태에서 키보드 좌우키로 선택해 둔 상태에서 엔터를 누르지 말고 좌/우로 움직이면 **모델의 에포트(effort/리즈닝)**를 결정할 수 있다. 화자는 **하이 에포트(high effort)**를 놓고 작업을 진행한다.

### [11:53–12:04] 코덱스도 슬래시 모델 → GPT-5.6 + 하이 리즈닝
코덱스도 마찬가지로 `/model`(슬래시 모델)로 모델을 고를 수 있다. 화자는 **GPT-5.6에 "쏘"(Sol/솔라 추정)**를 쓰고, 엔터를 누르면 리즈닝 레벨을 고를 수 있는데 **하이(high)**로 한다. 둘 다 똑같은 상태(하이)로 놓고 작업을 진행한다. [불명확: "쏘"는 GPT-5.6의 등급명(솔라/Sol 계열 추정)이나 자막상 표기가 불분명]

### [12:04–12:18] 작업 지시 — 오퍼스 5에게 랜딩 페이지
판비(창)를 줄이고, 작업은 아무거나 시켜본다. 오퍼스 5가 나왔으니 얘한테 간단한 랜딩 페이지를 만들어 보라고 하면 재밌을 것 같다고 함. 랜딩 페이지는 좀 지겹지만, 화자가 늘 만드는 예시로 **유명 엔터테인먼트 소속사의 멋진 랜딩 페이지**를 만들어 보라고 지시한다.

### [12:18–12:34] 클로드에 지시 전송 + 코덱스에도 작업 지시
"유명 엔터테인먼트 소속사의 랜딩 페이지를 만들어 봐"라고 오퍼스(클로드)에게 지시하고("페이파을 엔터테임먼트 사이트" — 자막상 지시문 표기 일부 불명확), 코덱스에게도 같은 작업을 진행시킨다.

### [12:34–12:52] 양쪽 병렬 진행 + 왼쪽 진행 상태 표시
그러면 둘 다 돌면서 작업이 진행되는 것을 볼 수 있다. 빙빙 도는 아이콘으로 진행 상태를 볼 수 있어, **왼쪽을 보면 각 에이전트가 지금 뭘 하고 있는지 볼 수 있어 편리**하다고 함.

### [12:52–13:09] 오르카 장점 — 알림 설정
[의견] 오르카의 장점 중 하나로 **알림(notification)** 기능을 소개한다. 설정에 알림 항목이 있고, 켜면 작업이 완료됐을 때 소리로 알려준다. 설정에서 알림을 활성화한다.

### [13:09–13:27] 알림이 유용한 이유 — 긴 작업 대기
켜면 작업이 완료됐을 때 "뿅" 하고 소리와 함께 알림이 뜬다. [의견] 요즘 에이전트 작업 길이가 굉장히 길어져 5분 기다리는 게 기본인 상황이라, 이런 걸 기다리기가 힘드니 알림을 띄워 주는 것이 좋다는 것. 이런 걸 통합해 놓은 게 좋다고 평가.

### [13:27–13:50] 오르카 장점 2 — 오른쪽 파일 탐색기
두 번째로 오른쪽의 **파일 탐색기**를 소개한다. 지금은 파일을 안 만들고 있어 아무것도 안 보이지만, 곧 파일들이 주르륵 생길 것. 예전에는 파일 위치를 보려면 탐색기를 따로 열어 확인해야 했는데, 이제는 오른쪽에 파일들이 바로 보인다. **보안 파일(예: `.env` — "점 인바이런먼트")까지 한꺼번에 볼 수 있어** 편리하다고 함.

### [13:50–14:04] 파일 탐색기 + 드래그 앤 드롭
[의견] 여기에 이미지 파일이 있으면 드래그 앤 드롭으로 잘 들어가고, 이미지 복사·붙여넣기가 안 되는 스트레스도 여기서는 쉽게 해결된다. 오른쪽에 파일 탐색기가 있는 것이 큰 장점 중 하나라고 강조.

### [14:04–14:18] 코딩 진행 중 산출물 확인 예고
에이전트들이 코딩을 진행하며 여러 작업을 할 것이고, 완성되면 볼 수 있을 거라고 함.

### [14:18–14:40] 플러스 버튼 — 새 터미널(같은 책상에 다른 에이전트)
플러스를 누르면 **새 터미널**을 만들 수 있다. 이는 "테스트 오르카 2번" 폴더에 새 터미널을 띄우겠다는 뜻으로, **워크트리와는 다른 것** — 그냥 같은 책상에 다른 에이전트를 또 소환하는 것이라고 구분한다. 예를 들어 여기에 클로드를 띄우면 같은 책상에 에이전트 두 개가 뜬 것.

### [14:40–15:00] 같은 책상 두 에이전트 활용 예 — 작업 후 평가
같은 책상에서 두 에이전트를 동시에 작업시킬 수 있다. 물론 그렇게 하면 별로 안 좋지만, **코덱스로 시켜보고 클로드로 평가**해 보고 싶은 사람이 있는데, 그럴 때 이렇게 쓰면 된다. 같은 책상 위에 두 에이전트가 올라와 있고, 한쪽이 먼저 작업한 뒤 다른 쪽에게 "평가해"라고 시킬 때 창을 왔다 갔다 하기 편하다. 화자는 안 할 거라 꺼버린다.

### [15:00–15:26] 플러스 버튼 — 새 브라우저 탭
플러스를 누르면 볼 수 있는 또 하나는 **새 브라우저 탭**이다. 클릭하면 오르카 안에 웹 브라우저가 나와 여기서 웹 브라우저를 쓸 수 있다. 이 웹 브라우저에 정말 유용한 기능이 하나 있다고 예고. 단, 처음엔 크롬과 검색 기록·로그인 등이 공유돼 있지 않아, 로그인 시 비밀번호를 처음부터 다시 입력해야 한다 — 오르카가 기본적으로 로그인 기록을 공유하지 않기 때문.

### [15:26–16:03] 브라우저 설정 가져오기 (크롬·사파리)
그런데 "가져오기(import)"가 있어, 이를 누르면 **크롬과 사파리의 설정을 한꺼번에 가져올 수 있다**. 그러면 이후 로그인도 편하고, 원래 쓰던 브라우저 환경을 그대로 쓸 수 있으니 사용자가 편하게 선택하면 된다고 안내.

### [16:03–16:23] 웹 개발 핵심 기능 — 요소 선택 말풍선
화자가 소개하려던 핵심 기능을 설명한다. 웹 개발할 때 "여기 이거 좀 수정해 줘"가 어려운데, 그게 오르카에 있다. **말풍선을 클릭하면 화면의 어떤 요소든 잡히고**, 그 요소를 잡은 다음 그 부분에 대한 프롬프트를 에이전트에게 날릴 수 있다("이게 뭐야?" 식으로).

### [16:23–16:52] 질문이 누구에게 가나 — 온보딩에서 설정한 에이전트
그러면 이 질문은 누구에게 가는가? **아까 온보딩에서 클로드 코드를 설정하지 않았는데, 거기서 설정하면 그 에이전트에게 질문이 넘어간다**. 추가해 보고 "보내기"를 하면 "누구에게 보낼 거냐"가 뜬다. 지금 코덱스가 일하고 있으니 클로드에게 보내면, 터미널을 열어 그 에이전트에게 질문을 알아서 날려준다.

### [16:52–17:01] 전송되는 컨텍스트 — 브라우저·탭·화면크기·선택 요소
질문을 보낼 때, **어떤 웹브라우저의 무슨 탭인지, 화면 크기가 얼마인지, 사용자가 선택한 버튼이 무엇인지**를 함께 담은 메시지를 보내준다. 그러면 에이전트가 그에 답해준다.

### [17:01–17:19] 실시간 웹 질문 — 초보에게 유용
[의견] 웹브라우저 화면을 보면서 실시간으로 에이전트에게 질문할 때 편하게 물을 수 있다는 것. 개발을 아는 사람은 이렇게 안 해도 되지만, 초보자에게는 이 방식이 유용하다.

### [17:19–17:34] 요소 지정 크롤링 질문 예시
예를 들어 "여기에는 어떤 내용이 있고, 이걸 가져오려면(크롤링하려면) 어떻게 해야 해?"라고 특정 요소를 지정해 질문할 수 있다.

### [17:34–17:53] 질문 여러 개 넘어감 → 필요 없는 것 삭제
보내기를 하면 앞서 했던 것과 함께 두 개의 질문이 다 넘어간다. 필요 없는 질문(첫 번째)은 지워버리고, 원하는 질문(두 번째 크롤링 질문)만 남기면 된다.

### [17:53–18:05] 요소 지정 답변 = 퀄리티 상승
"이 부분을 어떻게 크롤링해야 하냐"고 요소를 지정해 물으면, 에이전트가 해당 부분을 확인하고 그에 맞는 답을 그대로 해주기 때문에 **답변의 퀄리티가 올라간다**. 웹브라우저 요소에 대해 질답하고 싶을 때는 **말풍선(페이지 요소의 주석 달기)** 기능을 쓰면 된다.

### [18:05–18:24] 두 번째 버튼 — 요소 위치 복사(Copy)
그다음 버튼은 클릭 한 번으로 끝난다 — "카피드(copied)"라고 뜬다. 이는 화면으로 보는 **버튼/구성 요소의 위치를 클립보드에 복사**해 주는 기능. 예를 들어 로그인 버튼의 위치를 알고 싶으면 클릭하면 그 위치를 카피해 준다.

### [18:24–18:42] 복사한 요소 붙여넣어 질문
복사한 것을 그냥 붙여넣어 "이게 뭐지?"라고 물으면, 앞서 말풍선으로 질문한 것과 같은 내용이 된다. **복사된 내용에는 눈으로 보는 해당 위치의 주소와 그 자리의 정보들이 함께 담겨** 넘어간다.

### [18:42–18:54] 두 버튼 정리 — 질문 vs 위치 복사
정리하면 두 버튼은 유사하지만, **말풍선은 질문을 한꺼번에 할 수 있는 것**, **복사 버튼은 그 요소에 대한 위치만 복사해 오는 것**이다. 둘 다 굉장히 유용하다.

### [18:54–19:11] 세 번째 기능 — 변경(수정) 모드
랜딩 페이지를 만든 뒤 다시 볼 것을 예고하며, "스크린샷에 그리기" 버튼(그림 그려 설명)과 **"수정하기(변경)"** 버튼을 소개한다. 앞의 말풍선은 요소를 선택해 **질문**하는 것이었다면, **변경 모드는 웹 개발 중 해당 위치를 실제로 바꾸도록 지시**하는 것.

### [19:11–19:22] 변경 예시 — 색을 빨간색으로
웹 개발 중 해당 위치의 색깔만 빨간색으로 바꾸고 싶으면, 그 요소에 "빨간색으로 변경해 줘"라고 추가하면 그 부분을 보내 빨간색으로 바꿀 수 있다는 것.

### [19:22–19:33] 네이버 예시 — 남의 서버는 임시 변경만
[의견] 단, 화자는 (예시로 든) 네이버 서버의 주인이 아니므로, 바꾸라고 해도 실제로는 못 바꾸거나 **임시로(화자에게만 보이는 형태로) 바꾼 모습만** 보여준다. 그래도 이런 방식으로 웹 개발을 편하게 할 수 있다고 함.

### [19:33–19:53] 오른쪽 파일 확인 + 코덱스로만 작업
오른쪽에서 개발 중 생겨난 파일들을 다 볼 수 있다. 화자는 (프로젝트 제거가 아니라) 한쪽 에이전트를 꺼버리고 코덱스로만 작업하겠다고 한다. 코덱스가 작업 완료를 알린다.

### [19:53–20:18] 웹브라우저로 결과 띄우기 지시
코덱스에게 "웹브라우저로 띄워 봐"라고 한다. 그러면 오르카 안 웹브라우저에 띄워 보여주거나 크롬을 열어줄 수 있다("뭐든 상관없다"). 양쪽 에이전트에 다 "다 되면 웹브라우저에서 보여줘"라고 지시해 병렬 진행한다.

### [20:18–20:33] "이네 브라우저" = 오르카 내장 브라우저
코덱스가 "이네 브라우저에서 열겠다"고 하는데, 그 "이네 브라우저"가 바로 오르카 내장 브라우저를 뜻한다. 코덱스가 그 내장 브라우저를 열어 결과를 보여주려 한다.

### [20:33–20:47] 주소를 직접 브라우저 탭에 열기
편하게 하기 위해 화자가 직접 플러스 → 브라우저 탭에서 그 주소를 눌러 띄워 본다. 웹 브라우저로 **멋있는 소속사 사이트**가 나온다. 코덱스가 멋있게 만들어줬다고 감탄.

### [20:47–20:59] 코덱스 결과 감상 — 이미지까지 잘 만듦
[의견] 다른 창은 꺼버리고 코덱스 결과를 보며 얘기한다. 역시 코덱스라서 **이미지를 잘 만들어줘** 이런 걸 잘한다고 평가.

### [20:59–21:17] 변경 모드 실전 — "녹턴"을 한글로
수정을 해본다. 예를 들어 "녹턴"이라는 부분을 한글로 수정하고 싶어졌다. 요소를 누른 다음 선택하고 "이걸 한글로 바꿔 줘"라고 한 뒤, **변경 모드**로 추가한다. 여러 수정 사항을 마음대로 고를 수 있다.

### [21:17–21:37] 변경 모드 — 글자색 변경 추가 + 일괄 전송
예를 들어 "이 글자색을 흰색 말고 다른 걸로 해 줘"를 추가한다. 원하는 수정들을 다 요청한 뒤 "보내기"를 눌러 지금 작업 중인 **코덱스에게 메모를 보낸다**. 그러면 해당 부분에 대한 수정만 진행된다. 이것이 **페이지 요소의 주석 달기(변경 모드)** 사용법.

### [21:37–21:58] 수정 결과 반영 확인
클로드(오퍼스) 쪽은 랜딩 페이지를 띄우라고 했으니 띄울 때까지 작업하고, 코덱스 쪽은 요청대로 해당 부분이 한글로 바뀌고 색깔도 바뀐다. 잠시 기다리자 사이트가 한글로 바뀌고 색깔도 바뀐 것을 확인.

### [21:58–22:11] 웹 수정 기능 정리 + 오퍼스 5 결과 기대
[의견] 이런 방식으로 웹 개발 시 내 사이트에서 마음에 안 드는 부분을 수정하는 기능이 이 녀석(변경 모드)이라고 정리. 오퍼스 5가 랜딩 페이지를 얼마나 잘하는지 보고 싶다고 함. 다만 클로드(오퍼스 5)는 **이미지를 만들 줄 몰라** 코덱스처럼 이미지를 추가해 넣지 못했을 것이라, 더 안 좋아 보일 수 있는데 그것으로 평가하지 말고 **구성**을 보고 평가하자고 함.

### [22:11–22:34] 오퍼스 결과 평가 + 추가 변경 요청
[의견] 오퍼스 결과도 예쁘게 잘 만들었다고 함. 음악 재생하는 것처럼 나왔지만 실제 음악은 없다. 바꾸라고 한 부분의 위치 색깔만 바꿔줬다. 메모 기능을 더 써서, 예를 들어 "한국인만 오는 사이트라 이건 필요 없어"라고 특정 요소에 메모를 추가해 코덱스에게 보낸다.

### [22:34–22:58] 클로드가 웹브라우저에 못 띄우는 문제
[의견] 클로드(오퍼스) 쪽이 왜 웹브라우저에 못 띄우는지 모르겠다며, "너 왜 웹 브라우저에 안 띄우니?"라고 물어본다(반영이 다 안 돼서 그런 건지 확인차). 그러자 이제 오르카 내장 브라우저("우리 카이브"?—오르카 지칭)에서 띄운다.

### [22:58–23:11] 오퍼스 결과도 브라우저로 확인 — 준수함
플러스 → 새 브라우저 탭으로 오퍼스 결과도 띄워 본다. 오퍼스도 잘 만들어줬고, 이미지가 없어서 그렇지 그 정도도 굉장히 훌륭하다고 평가.

### [23:11–23:25] 오퍼스 결과도 한글 변경 지시
오퍼스가 "오르카"라는 폴더 이름을 무슨 엔터테인먼트 회사 이름으로 생각했나 보다고 함. 마찬가지로 특정 요소를 선택해 "한글로 바꿔 달라"고 하고 보내기 → 클로드에게 보낸다. 이런 식으로 할 수 있어 초보자에게 굉장히 유용할 것이라고 봄.

### [23:25–23:47] 파일 드래그 앤 드롭 재강조
오르카의 기본 내용은 다 설명했다며, 오른쪽 아웃풋 파일 등을 바로 첨부할 수 있다는 점을 재차 보여준다. 드래그로 빼면 이미지가 넘어가, **복사·붙여넣기 고생 없이** 이미지를 넘길 수 있다. 다른 데 있는 이미지(예: 화자의 딸 사진)도 드래그로 넘길 수 있다. [의견] 물론 이건 오르카에서만 되는 건 아니지만, **오르카가 이걸 훨씬 부드럽고 잘 처리**한다 — 드래그 앤 드롭이 안 되는 데도 있고 되는 데도 있는데 오르카는 만족스럽게 잘 된다고 함.

### [23:47–24:08] 마무리 — 입문자 대상 병렬 사용 가이드
[의견] 이런 방식으로 쓰는 것이 입문자가 꼭 알아야 하는 기본이고, 병렬로 쓰는 것을 오르카에서 많이들 헷갈려하는 것 같아 소개했다고 함. 잘 아는 사람에게는 너무 기본적일 수 있지만, 세상에는 다양한 사람과 입문하려는 사람이 많아 이런 영상도 필요하다고 함. 초보자가 오르카를 통해 처음으로 에이전트에 입문하려 할 때 가이드가 되기를 바란다고 함.

### [24:08–24:26] 후속 예고 + 클로징
[의견] 오르카 모바일과 오르카가 띄워주는 에뮬레이터는 안 써봐서 못 다뤘는데, 반응을 보고 원하면 두 번째 영상으로 준비해 올리겠다고 예고. 오늘 오르카 영상은 여기까지이며, 정말 기본 중의 기본이고 초보자라면 다 이렇게 쓰는 게 기본인 영상이라고 정리. 다음 영상에서 유용한 내용으로 돌아오겠다며 마무리한다.
