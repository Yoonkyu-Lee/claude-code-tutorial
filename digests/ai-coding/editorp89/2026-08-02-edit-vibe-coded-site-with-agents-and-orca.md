# [시즌 03] 바이브 코딩으로 만든 사이트에이전트와 수정하기 + 오르카(Orca)

## 요약 (주제별)

### 이 영상의 목표·범위
- 지난 편에서 바이브 코딩으로 만든 "애플 스토어" 샘플 사이트를 소재로, 이번 편은 그 사이트를 **에이전트로 수정하고 다시 배포**하는 방법을 다룬다. 사이트 만들기 → 배포 → 수정까지 두 영상으로 이어지는 실습 시리즈.
- 수정 방법을 **어려운 버전(브라우저 개발자 도구)** 과 **쉬운 버전(오르카)** 두 가지로 제시하며, 화자는 근본 원리를 알리려 어려운 버전을 먼저 설명한다.

### 핵심 원리 — 로컬 호스트에서 수정하고 배포는 나중에
- 정석은 배포본을 직접 고치는 게 아니라, 내 PC에 **로컬 호스트 서버(localhost:3000)** 를 띄워 거기서 빠르게 수정한 뒤 배포 위치로 옮기는 것.
- 프로젝트 폴더의 모든 파일이 localhost:3000으로 들어가 PC에서 즉시 실행되므로, **코드가 수정되면 로컬 호스트에 바로 반영**된다. 반면 배포는 원격 서버 업로드를 거쳐 결과 확인이 느리다. 그래서 빠른 수정 확인용으로 로컬을 쓴다.
- 에이전트에게 "로컬 호스트 3000에 이 사이트를 띄워 줘"라고 요청해 시작한다.
- [불명확] 작업 폴더명은 자막에 "스터디 최지T 워크 01번"으로 음차돼 있어 정확 표기 불확실(ChatGPT/코워크 관련 폴더로 보임).

### 어려운 버전 — 브라우저 개발자 도구로 요소 지정
- **F12**로 개발자 도구를 연다. "토글 디바이스 툴바" 버튼으로 모바일/데스크톱 화면 전환 가능.
- **요소 선택 버튼(네모 박스+화살표)** 을 누르고 화면에 마우스를 올리면 해당 영역이 하이라이트되고, 오른쪽에 그 요소를 구현한 코드 위치가 잡힌다.
- 그 코드 부분을 **우클릭 → Copy → Copy selector** 하면 "해당 위치의 주소" 역할을 하는 문자열이 만들어진다. 이 주소 + 자연어 요청("여기 버튼이 잘려 있어" 등)을 에이전트에 전달하면 그 위치만 정확히 수정한다.
- 시연한 수정 예: 잘린 동그란 버튼 → 동그랗게, 겹쳐 보이는 폰트(줄 간격) 교정, 형광색 배색을 "과일 가게에 안 어울려 맛없어 보인다"로 요청해 변경. 지정한 곳만 바뀌고 나머지는 그대로.

### 쉬운 버전 — 오르카(Orca)의 화면 코멘트
- 오르카 설치는 지난 영상에서 다뤘으므로 생략(이번엔 버그로 강제 종료 후 재실행하는 장면 있음).
- **프로젝트 추가 → 폴더 찾아보기**로 ChatGPT/코워크로 작업하던 폴더를 그대로 연다. 한 폴더를 오르카·ChatGPT 코워크가 함께 볼 수 있어 병행에 유리하다는 [의견].
- 오르카에서 **+ → 새 브라우저 탭 → localhost:3000** 입력으로 같은 사이트를 띄운다.
- **말풍선(코멘트)** 으로 수정할 화면 요소마다 메모를 단다(예: 형광색 지점마다 "맛이 없어 보인다"). 코멘트 묶음을 **원하는 에이전트로 전송(화자는 코덱스 선택)** 하면 그 에이전트가 수정을 알아서 진행한다.
- 원리는 어려운 버전과 동일하며, 오르카는 "요소 위치 전달"을 쉽게 바꿔 준 것뿐이다.

### 배포(deploy) 마무리
- 배포는 **코워크(ChatGPT의 코워크)** 에서 "배포해"로 실행. 수정된 로컬 호스트 내용을 실제 웹사이트 주소(애플 스토어 배포본)로 내보낸다.
- 배포 전에는 로컬은 반영·배포본은 미적용 상태이므로, 로컬 주소와 배포 주소를 나란히 열어 비교하며 대기한다.
- 진행 상태(버전 저장·배포 등)가 표시되고 "공개 배포할까요?"에 승인하면 마무리. **배포에 약 3분** 걸릴 수 있다.

### 화자의 권고·태도 [의견]
- 원리(요소를 정확히 클릭 → 위치를 에이전트에 전달 → 수정)를 알면 어떤 도구·환경에서도 원하는 작업을 할 수 있으므로, **어려운 방식(개발자 도구)을 꼭 먼저 해 보라**고 강권한다.
- DB 등이 없는 정적 사이트는 어렵게 갈 필요 없이, 업체를 거치지 않고 에이전트로 쉽게 만들어 배포하면 된다.
- 로컬 호스트/포트 개념이 낯설면 자기 책 『바로바로 바이브 코딩』을 보거나 검색해 공부해 오길 권한다(오늘은 실습편이라 개념 설명은 생략).

## 3줄 오리엔테이션
- 지난 영상에서 바이브 코딩으로 만든 "애플 스토어" 샘플 사이트를, 배포본이 아니라 **로컬 호스트(localhost:3000)** 에 띄워 놓고 에이전트로 수정한 뒤 다시 배포하는 실습 영상이다.
- 수정 방법을 **어려운 버전(브라우저 개발자 도구 F12 → 요소 선택 → Copy selector로 위치 주소를 에이전트에 전달)** 과 **쉬운 버전(오르카의 화면 요소 코멘트 기능으로 클릭 후 코덱스에 전송)** 두 가지로 나눠 보여 준다.
- 화자 [의견]: 두 방식의 원리는 "수정할 요소의 위치를 정확히 지정해 에이전트에 전달"로 동일하며, 오르카는 그 전달을 쉽게 해 줄 뿐이니 원리 이해를 위해 어려운 버전을 먼저 해 보라고 권한다.

## 전문 — 시간순 워크스루

### [00:00–00:21] 오늘 영상의 위치 — 저번에 만든 사이트 "수정하기" 편
지난 영상에서 바이브 코딩으로 만든 "애플 스토어"라는 사이트를 소재로 이어 간다. 화자는 그때 "이 사이트를 수정할 방법이 있다"고만 언급하고 "다음에 설명하겠다"며 넘어갔었는데, 오늘 그 수정 방법을 다룬다고 한다. (이 사이트 자체는 이전 영상을 보면 만들 수 있다고 전제.)

### [00:22–00:46] 어려운 버전을 먼저 하는 이유
오늘 설명은 **어려운 버전과 쉬운 버전 두 가지**가 있으며, 화자는 어려운 버전을 먼저 얘기하겠다고 한다.
- [의견] 어려운 버전은 "굳이 알기 싫은 근본적인 내용까지" 설명해야 하는 것인데, 알기 싫고 어려운 것이 대개 근본적인 것들이라, 그 근본을 먼저 짚으면 사이트 수정 시 무엇을 알아야 하는지가 드러난다는 논리다.

### [00:46–01:11] 정석 — 배포본이 아니라 로컬 호스트에서 수정
사이트를 배포한 상태를 전제로, 가장 먼저 준비할 것은 **배포된 사이트를 직접 고치는 게 아니라 내 컴퓨터에 로컬 호스트 서버를 띄워 거기서 수정**하는 것이라고 설명한다. 로컬에서 빠르게 수정을 마친 뒤, 그 결과물을 내 컴퓨터에서 배포 위치로 옮기는 과정이 "정석"이라고 한다.

### [01:11–01:31] localhost:3000에 사이트 띄우기
에이전트에게 "로컬 호스트 3000에 이 사이트를 띄워 줘"라고 요청하는 것으로 시작한다.
- [의견/안내] 이 과정이 잘 이해되지 않으면 화자의 책 『바로바로 바이브 코딩』을 보거나, "로컬 호스트 서버가 무엇인가", "포트 번호는 무엇인가"를 검색해 공부해 오길 추천한다. 오늘은 실습 영상이라 그 부분까지 다 설명하진 않는다고 한다.

### [01:31–01:48] "띄워도 되냐" 확인 후 실행 → 애플 스토어가 뜸
에이전트가 "여기다 띄울 거냐"고 물었고, 화자는 이미 다른 게 띄워져 있어 "띄워도 되냐"는 되물음에 "그렇게 해라"고 답한다. 그러면 에이전트가 사용자 PC의 localhost:3000 주소에 만들어 둔 애플 스토어 사이트를 띄운다. 잠시 기다린 뒤 주소를 입력하면 애플 스토어가 뜨는 것을 확인한다.

### [01:48–02:20] 로컬 호스트가 무엇인지 — 즉시 반영의 원리
화자가 "도대체 뭔지 궁금하다"는 시청자를 위해 상황을 간단히 설명한다.
> "여러분들 PC에다가 이 폴더 있던 이 저번에 우리가 작업했던 스터디 [최지T 워크] 01번이라는 이 폴더에 있는 이 모든 파일의 내용이 여기에 이제 뭉쳐져 가지고 여기로 들어가는 거예요." [01:54]

즉 이전에 작업하던 프로젝트 폴더(자막 원문 "스터디 최지T 워크 01번" — [불명확: ChatGPT/코워크 관련 폴더명을 음차한 것으로 보이나 정확 표기 불확실])의 파일 전부가 localhost:3000으로 들어가고, PC에서 즉시 실행 중이라 **코드가 수정되면 바로 여기에 반영**된다. 반면 배포는 수정 후 원격 서버에 파일을 업로드하는 과정을 거쳐 결과물을 보는 시간이 느려지므로, 빠른 수정 확인을 위해 로컬 호스트로 하는 것이 정석이라고 강조한다.

### [02:20–02:42] 수정 위치 찾기 — F12 개발자 도구
가장 먼저 할 일은 수정할 위치를 찾는 것이다. **F12**를 누르면 개발자 도구(자막 "개발자 사이트")가 열리며 화면이 바뀐다. 자세한 설명은 생략하되, "토글 디바이스 툴바" 버튼이 파랗게 선택돼 있어 이를 눌렀다 껐다 하면 모바일 화면과 일반 데스크톱 화면이 전환된다고 짚는다.

### [02:42–03:04] 요소 선택 도구(화살표 버튼)로 위치 지정
개발자 도구에서 수정하고 싶은 위치를 에이전트에게 전달할 수 있어야 한다. 그 방법으로 **네모 박스에 화살표가 있는 아주 작은 버튼(요소 선택/inspect 버튼)** 을 소개한다. 이 버튼을 누른 뒤 화면에 마우스를 올리면, 마우스 위치의 영역이 하이라이트되어 어떤 영역이 선택되는지 볼 수 있다.

### [03:04–03:14] 예시 1 — 잘려 보이는 동그란 버튼
화자가 "동그란 버튼이 잘려 있는 게 마음에 안 든다"며 이를 수정 대상으로 삼는다. 정확히 마우스 오버하면 그 부분만 선택되고, 오른쪽에서 그 버튼을 구현한 실제 코드 위치가 하이라이트된다.

### [03:14–03:40] Copy selector로 "주소" 만들어 에이전트에 전달 → 수정
하이라이트된 코드 부분을 **우클릭 → Copy → Copy selector** 하면, 해당 코드 위치를 에이전트에 전송할 수 있는 문자열이 만들어진다.
- [의견/비유] 이 selector를 "해당 위치의 주소"라고 보면 된다고 설명한다. 그 주소와 함께 "여기 버튼의 모양이 잘려 있어"라고 요청하면, 화면에서 "여기쯤"이라고 막연히 생각하던 위치를 정확한 주소로 전달했기 때문에 에이전트가 그 위치만 정확히 수정한다. 결과적으로 버튼이 동그랗게 바뀐다.

### [03:40–04:07] 예시 2 — 겹쳐 보이는 폰트(줄 간격)
같은 방식을 한 번 더 시연한다. "줄이 너무 붙어 있어 폰트가 보기 불편한" 부분을 최대한 정확히 선택 → Copy selector → "폰트가 겹쳐져 있는 것 같아"라고만 요청한다. 그러면 오른쪽(에이전트)이 바로 그 부분을 수정하고, localhost:3000이므로 즉시 반영되어 보인다.

### [04:07–04:37] 예시 3~ — 형광색 배색, 반복 적용
과일 사이트인데 형광색이 "먹음직스럽지 않다"는 지점도 최대한 넓게 선택 → Copy selector → "과일 가게인데 이런 색은 좀 맛이 없어 보여"라고 요청하면 된다고 시연한다. 다른 곳들도 같은 식(요소 선택 → Copy selector → 전달 → "폰트가 겹쳐 보여" 등)으로 반복 수정한다. 특정 위치만 지정했기 때문에 다른 곳은 하나도 바뀌지 않고 지정한 곳만 수정된다는 점을 강조한다. 여기까지가 "어려운 방식"이다.

### [04:41–04:55] 쉬운 방식 — 오르카(Orca) 사용, 버그로 강제 종료 후 재실행
이제 쉬운 방식으로 넘어간다. **오르카를 설치**하면 된다. 오르카 설치 과정은 지난 영상에서 이미 설명했으므로 다시 다루지 않는다고 한다. (오르카가 버그로 강제 종료되어 다시 켠다.)

### [04:55–05:22] 오르카에 프로젝트 폴더 추가
오르카에서 먼저 **프로젝트(폴더)를 추가**해야 한다. 오르카도 ChatGPT(자막 "채피pt")에서 작업 중인 그 폴더를 볼 수 있다. **프로젝트 추가 → 폴더 찾아보기** 버튼을 눌러, ChatGPT/코워크로 작업하던 그 폴더를 그대로 찾아 열면 된다.
- [의견] 이렇게 한 폴더에서 작업하면 오르카도, ChatGPT의 코워크(자막 "최지T … 워크")도 같은 폴더를 볼 수 있어서 함께 쓰기 좋다며, 도구를 같이 써 보길 권한다.

### [05:22–05:40] 오르카에서 새 브라우저 탭으로 localhost:3000 열기
폴더를 열면, 여기서 할 일은 하나뿐이라고 한다. (열린 것 중 하나는 꺼 버리고) 해당 버튼을 누른 뒤, 무언가는 무시하고 **플러스(+) → 새 브라우저 탭**을 누른다. 그다음 아까 복사했던 주소 **로컬 호스트 3000**을 입력하면, 오르카 안에서도 똑같은 웹사이트가 나온다.

### [05:40–06:13] 쉬운 버전 — 말풍선(코멘트)으로 화면 요소에 메모 달기
오르카에는 **말풍선(코멘트)** 기능이 있다. 원리는 어려운 버전과 똑같다 — 수정하고 싶은 위치를 고른 뒤 수정 요청을 하는데, 오르카에서는 **요청 대상(어느 에이전트로 보낼지)** 을 선택할 수 있다. 화자는 형광색이 마음에 안 드는 여러 곳에 대해 "과일 가게 사이트인데 형광색이라 맛이 없어 보인다"는 문장을 복사해 각 위치에 코멘트로 붙여 나간다("여기도 추가", "여기도 코멘트 추가"). 형광색인 부분들에 전부 메모(코멘트)를 달았다.

### [06:13–06:26] 코멘트 묶음을 에이전트(코덱스)로 전송 → 수정
형광색 관련 코멘트를 다 남겼으니, 이 메모들을 원하는 에이전트에게 보내면 된다. 화자는 **코덱스**에 보내 작업을 시킨다. 그러면 코덱스가 열려 해당 부분에 대한 수정 요청을 알아서 진행한다.

### [06:26–06:52] 로컬 호스트 즉시 반영 → 완료 후 배포
localhost에서 수정되므로 오르카에서 보고 있어도, 또는 같은 주소를 연 다른 창에서도 바로 반영된다. 앞서 말한 원리대로, 코드가 수정되면 로컬 호스트는 바로 반영되므로, 수정이 끝날 때까지 기다렸다가 완료되면 다시 배포하면 된다.

### [06:52–07:20] 배포 위치 — 코워크(ChatGPT)에서, 두 방식 정리
"배포해서 마무리해 줘"라고 하면 되는데, **배포는 코워크(자막 "최지T 워크" = ChatGPT의 코워크)** 에서 한다. 수정 방법을 여기(개발자 도구)에서 하는 법도, 오르카를 쓰는 법도 보여 줬는데, 오르카는 화면 요소에 채팅(코멘트)을 넣을 수 있어 쉽게 할 수 있는 방법이라고 정리한다.

### [07:20–07:41] [의견] 원리는 같다 — 어려운 버전을 꼭 해 보라
[의견] 쉽게 하려면 도구를 왔다 갔다 하며 배워야 하는데, 방금 봤듯 원리는 똑같다.
> "해당 위치 요소를 정확하게 클릭을 하고 해당 요소의 위치를 전달해서 수정을 하는 건데 이 오르카는 그 전달하는 방식을 조금 쉽게 바꿔 준 것뿐이에요." [07:22]

원리를 알고 진행하면 무엇을 하든 원하는 작업을 원하는 환경에서 마음대로 할 능력이 생기므로, 일단 **어려운 방식으로 해 보길 꼭 추천**한다고 한다.

### [07:41–08:12] 배포 실행 — 로컬은 반영, 배포본은 아직 미적용
수정이 끝나 localhost:3000에는 잘 반영되어 있지만, 배포했던 사이트는 여전히 적용 전 상태(형광색·겹친 폰트 그대로)다. 이를 위해 "배포해"라고 하면, 수정된 로컬 호스트의 내용을 애플 스토어가 올라가 있는 웹사이트 주소로 내보낼 수 있다는 뜻이라고 설명한다. 에이전트가 배포를 알아서 진행하고, 배포가 다 되면 그 사이트 주소로 들어가 보면 된다.

### [08:12–08:38] 로컬 vs 배포본 비교하며 대기
브라우저에서 열기를 누르면 주소가 나오는데, 한쪽에는 로컬 호스트, 한쪽에는 배포된 주소를 띄워 양쪽을 비교하면 된다. 아직 배포가 완료되지 않아 배포본은 적용 전이고(로컬 호스트는 당연히 반영돼 보임), 새로고침하며 대기하면 배포가 끝났을 때 배포본도 원하는 대로 수정되어 있을 것이다.

### [08:38–09:04] 배포 진행 — 확인·저장·공개
배포가 진행되며 "배포 절차를 사용하고 있고 … 사이트 버전 저장함, 배포함" 식의 진행 상태가 뜬다. 배포는 3분 정도 걸릴 수 있다. 에이전트가 "공개 배포할까요?"라고 물으면 "그래라"고 답해 배포를 마무리한다.

### [09:02–09:18] [의견] 정적 사이트는 어렵게 갈 필요 없다
[의견] 데이터베이스 등이 들어가지 않는 사이트는 아주 어렵게 할 필요가 없다. 업체를 거칠 필요도 없이 쉽게 만들어 배포하면 되니, 에이전트를 이용하는 김에 이렇게 해 보면 좋겠다고 한다.

### [09:18–09:34] 마무리 — 반영 완료
배포가 완료되어 다 반영된 것을 확인한다. 사이트 만들기·배포·수정까지 두 개의 영상으로 잘 해 보길 권하며, 다음 영상에서 유용한 소식으로 돌아오겠다고 마무리한다.
