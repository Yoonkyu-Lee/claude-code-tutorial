# [시즌 3] Orca로 다수의 에이전트 조율하기 with 워크트리

## 요약 (주제별)

### 핵심 결론 (무엇을 하는 영상인가)
- Orca(오르카)의 "오케스트레이션 스킬" + git worktree를 결합해, 하나의 프로젝트 폴더에서 Claude Code·Codex 같은 여러 에이전트에게 동시에 서로 다른 작업을 시키는 방법을 실습한다.
- 예제: 온열 매트 기업 랜딩 페이지를 메인에서 만든 뒤, 디자인1(20대 감성)·디자인2(50대 감성) 두 갈래로 복제해 서로 다른 에이전트에게 병렬로 디자인 개편을 시키고, 마음에 드는 것(디자인2)을 메인으로 머지한다.
- [의견] 여러 에이전트를 구독한 사람에게 특히 유용하고, 입문자에게는 "분산 → 합치기 → 다시 분산"의 반복 워크플로가 가장 좋은 사용법이라고 본다.

### git·worktree 개념 (비유로 설명)
- **커밋 = 사진 찍기**: git은 프로젝트 폴더의 형상(파일·폴더 구조)을 특정 시점에 사진으로 찍어 관리하는 "사진 관리사". 세이브를 안 했어도 과거 사진으로 되돌릴 수 있다.
- **HEAD = 최신 사진 표식 / 타임머신**: git이 최신 커밋을 HEAD에 자동으로 꽂아 둔다. HEAD를 과거 사진으로 옮기면 그 시점이 재연된다.
- **worktree = HEAD를 여러 개로 / 책상 복제**: HEAD가 하나면 한 방향으로만 진행되지만, worktree는 HEAD를 별도로 둬서 한 폴더에서 서로 다른 두 방향으로 동시에 진행하게 한다. "현재 작업하던 책상 상태를 복제해 실험실처럼 여러 시도"를 하는 것.
- 전제: worktree는 git 기반이라 git init이 돼 있어야 하고, worktree 생성 전에 **최소 한 번의 커밋(초기 커밋)**이 있어야 한다(사진 없이 책상 복제 불가).

### 실전 절차 (설치 → 생성 → 지시 → 머지)
1. 빈 폴더에 메인 에이전트(Claude Code)를 dangerously skip permissions로 실행하고 "git 초기화해줘"로 git init.
2. Orca 설정 → 오케스트레이션 스킬 Install → 터미널 명령어 엔터 → additional agent에서 Claude Code만 켜고 엔터 → 설치 방식 기본값(symlink) 엔터.
3. Orca에서 해당 프로젝트를 인식시키면 + 버튼이 "워크스페이스"에서 "작업 트리(worktree) 만들기"로 바뀐다. + 로 디자인1(하청=Claude), 디자인2(하청=Codex) worktree 생성.
4. 프롬프트로 "메인에서 랜딩 페이지 제작 → 디자인1은 20대 감성, 디자인2는 50대 감성으로 디자인만 변경 후 각각 브라우저에 띄우기"를 한 번에 지시.
5. 마음에 드는 것을 "이 worktree를 머지해서 앞으로 메인으로 삼겠다"고 하면 메인 작업을 치우고 그 갈래를 가져가며, 나머지 갈래는 정리한다.

### 오케스트레이션 동작 원리
- 메인 책상(작업 반장)이 하위 worktree(하청 인부)에게 Orca를 통해 메시지를 전송해 각각 작업을 시킨다. 외부에서 보면 "메인 에이전트가 하위 인부들을 부린다"는 그림.
- 메인이 먼저 진행된 뒤 Orca가 디자인1·2에 지시 내용을 메시지로 자동 전달해, 총 세 군데에서 병렬 작업이 진행된다.

### 실전 함정·주의
- **위임(delegation) 필수**: 에이전트는 "worktree를 쓰라"고 하면 자기가 아는 git worktree를 혼자 쓰려는 경향이 있어 메시지 전송을 안 한다. Orca에 worktree 조작 권한을 위임시키고 "메시지를 전송해 봐라"라고 명시해야 병렬 조율이 작동한다(화자가 실제로 겪은 함정).
- **합치기는 이상적일 뿐**: 완전히 다른 결과물을 합치라고 하면 충돌 등으로 잘 안 된다. 합치기를 못 해도 "동시에 여러 개 시도 + 마음에 드는 루트만 이어가기"의 시간 절약 효과가 크다는 게 실질 이점.
- **worktree 생성 버그**: 프로젝트를 처음 인식시킬 때 + 버튼이 워크스페이스로 뜨거나 "기본 브랜치를 찾을 수 없다"는 에러가 날 수 있음 → 프로젝트를 Orca에서 제거 후 재추가, 그리고 초기 커밋으로 해결.

### 도구·에이전트 특성 (화자 의견)
- [의견] Codex는 이미지 리소스를 잘 만든다. 다만 메인을 Claude Code로 만들면 처음에 이미지를 안 넣고 기하학 문양을 코드로만 그리는 경향이 있어, 명시적으로 "이미지 넣어라"라고 해야 한다.
- [의견] 간단한 랜딩 페이지 제작은 Codex가 더 잘할 것. 사이트에 리소스가 없으면 휑해 보인다.
- **칸반 보드(숨은 꿀 기능)**: 작업 카드를 To Do / In Progress / In Review / Done으로 드래그해 상태를 관리. 실제 작업엔 영향 없고 표시만 관리하지만, 여러 에이전트 작업을 조망하기 좋다.
- **부분 수정 팁**: 말풍선을 눌러 수정할 영역만 고른 뒤 "이 부분을 수정 요청한다"고 해야 그 부분만 바뀐다(이전 영상에서 설명한 방식).

### 대상·비용 한정
- [한정] 이 기능은 여러 에이전트 서비스를 구독한 사람에게 의미가 있다. Claude Code 20달러 하나만 구독한 경우 병렬로 쓰면 토큰을 너무 빨리 소진하므로 실습보다 청취용.
- [의견] 화자는 이전에 "worktree는 굳이 하지 말라"고 했으나 시청자 요청으로 다뤘고, 본인은 Orca 홍보 대사가 아니라며 후속(Orca 모바일)은 댓글 반응을 보고 결정하겠다고 밝힘.

## 3줄 오리엔테이션
- Orca(오르카)의 "오케스트레이션 스킬"과 git worktree를 결합해, 하나의 프로젝트 폴더에서 여러 AI 코딩 에이전트(Claude Code·Codex)에게 동시에 다른 작업을 시키는 방법을 보여준다.
- 전반부는 git commit·HEAD·worktree 개념을 "책상 복제 / 사진 관리사" 비유로 비전공자용으로 설명하고, 후반부는 온열 매트 랜딩 페이지를 예제로 메인·디자인1·디자인2 세 갈래 병렬 작업을 실습한다.
- 화자의 핵심 메시지: worktree로 여러 시도를 동시에 돌려 보고 마음에 드는 것만 골라 메인으로 머지하는 것이, 특히 여러 에이전트를 구독한 사람에게 유용하다는 것. (합치기는 이상적일 뿐 항상 잘 되지는 않음을 명시)

## 전문 — 시간순 워크스루

### [00:00–00:57] 도입 — 왜 이번엔 worktree를 다루는가
오늘 주제는 Orca로 다수의 에이전트를 조율하는 것이다. 화자는 이전에 "worktree는 굳이 하지 말라"고 말했지만, 시청자들이 Orca의 핵심 기능인데 안 다루면 어떡하냐고 요청해서 다루게 됐다고 밝힌다. 본인도 개념을 명확히 설명하려고 공부·리서치·정리·확인을 거쳤으니 "거의 정확한 정보일 것"이라고 말한다.
> "제가 워크트리 굳이 하지 말라고 말씀을 드렸는데 또 많은 분들이 그래도 오르카의 핵심 기능인데 안 다뤄주면 어떡하냐 이러셔 가지고 다루게 됐고요." [00:04]

### [00:22–00:57] 대상 시청자와 목표 그림
이번 설명은 고수용이 아니라, 이 분야를 전혀 몰라도 "에이전트가 똑똑하다는데 나는 Codex랑 Claude Code 둘 다 구독 중이고 큰 작업을 두 녀석에게 동시에 시켜서 잘한 것만 받고 싶다"는 사람을 겨냥한다. 에이전트를 쓴다는 건 하청을 주는 것이고, 하청 업체가 둘이면 둘에게 동시에 일을 시키고 싶을 수 있는데 그걸 Orca가 편하게 해준다는 관점으로 보라고 안내한다. 화자는 미리 그려둔 그림(Orca로 다수 에이전트를 부려 세 개 작업을 동시에 하는 모습)을 제시한다.

### [00:57–01:41] 실습 전제와 대상 한정
Orca가 여러 에이전트를 조종할 수 있는지 화자가 직접 확인했고 된다고 한다. 오늘은 함께 Orca의 worktree를 사용해 볼 것인데, 이는 Orca에 있는 "오케스트레이션 스킬"을 설치하지 않으면 진행되지 않으므로 그 스킬 설치까지 함께 한다. worktree 개념이 이해 안 되면 그냥 넘어가도 되지만 이해하면 재미있게 쓸 수 있다고 한다.
- [의견/한정] 이 기능은 여러 에이전트 서비스를 구독한 사람에게만 의미가 있다. Claude Code를 20달러 하나만 구독하는 경우 병렬로 쓰면 토큰을 너무 빨리 소진하므로, 20달러 유저는 실습은 못 하고 듣기만 해야 할 것이라고 미리 안내한다.

### [01:42–03:31] worktree 비유 (1) — 책상 복제
worktree는 "내 프로젝트 폴더에서 동시에 여러 일을 효율적으로 (에이전트에게) 시키고 싶을 때" 쓰는 것이라고 정의한다. 프로젝트 폴더는 이전 영상들에서 "에이전트가 활동하는 책상"으로 비유했던 것이고, 에이전트가 그 책상에서 파일·폴더를 만들고 지운다. 책상이 하나면 보통 한 작업만 할 수 있어 불편한데, 이 책상(현재 작업 상태 그대로)을 복제할 수 있다면 어떨까가 worktree의 시작점이다.
예시로 웹사이트 화면이 어느 정도 완성된 상태에서 디자인 베리에이션을 두 방향으로 동시에 시험하고 싶은 경우를 든다. 웹 화면 변경은 원래 있던 화면을 통째로 바꾸는 것이라 "동시에 두 개"라는 개념이 없다. 그래서 책상을 복제하면 같은 상태에서 각자 다른 디자인 작업을 시킨 뒤 마음에 드는 쪽을 골라 계속 진행할 수 있다는 것이 worktree의 장점이다. 화자는 이를 "실험실 같은 작업"이라고 표현한다.

### [03:31–04:44] git 기반이라는 전제 + git 비유 (2) — 사진 관리사와 커밋
worktree는 git 기반이므로 이해하려면 git을 이해해야 한다. 오늘 git 강의는 아니고 worktree 이해에 필요한 기본만 설명한다. git은 "내 프로젝트의 형태(형상)를 관리해 주는 녀석"이다. 프로젝트 폴더 안의 파일·폴더 구조가 작업하면서 계속 변하는데, git은 관리자가 와서 "지금 상태 사진 찍겠습니다" 하고 그 시점의 상태를 사진으로 찍어 보관하는 사진 관리사에 해당한다.
- 프로젝트가 진행되며 폴더·파일 형태가 바뀔 때마다 git이 다시 사진을 찍어 여러 스냅샷을 관리한다.
- 세이브를 안 했어도 git이 옛날 사진을 알고 있으므로, 작업이 망가지면 "그저께 찍은 사진으로 돌아갈 수 있냐"고 부탁해 이전 상태로 되돌릴 수 있다.
> "그 사진을 찰칵 찍는 거를 커밋이라고 부릅니다." [06:30]

### [06:37–08:03] git 비유 (3) — HEAD와 타임머신
git은 사진(커밋)만 관리하는 게 아니라, "최신 사진이 뭔지"를 바로 알려주는 HEAD라는 공간에 최신 커밋을 꽂아 둔다. 우리가 신경 쓰지 않아도 최신 사진이 자동으로 HEAD에 업데이트된다. 사진을 쭉 찍으면 가장 마지막 것이 HEAD가 된다. 다만 "첫날로 돌아가고 싶다"고 하면 HEAD를 그 과거 사진으로 옮겨서 그 시점을 최신처럼 취급한다. 즉 HEAD가 옮겨 다니며 프로젝트의 형상을 바꾸고, 이것이 타임머신처럼 과거 시점으로 이동하게 해 주는 원리다. HEAD가 가리키는 사진의 모습대로 프로젝트가 재연된다.

### [08:16–09:12] worktree = HEAD를 여러 개로
HEAD가 하나뿐이면 프로젝트 형태를 관리하는 주체가 하나라 한 방향으로만 진행된다. worktree는 HEAD가 별도로 존재하게 해서 "지금부터 HEAD는 두 개"가 되게 한다. 각 HEAD가 서로 다른 진행 상황을 따로 기록하므로, 한 폴더(한 갈래)에서 시작했더라도 서로 다른 두 방향으로 프로젝트를 동시에 진행할 수 있다. 이것이 worktree다.
> "지금부터는 한 폴더에서 작업을 해도 서로 다른 두 개의 방향으로 프로젝트를 진행할 수 있다는 거예요. 이게 워크틀입니다." [08:44]

### [09:12–10:44] 에이전트와 결합했을 때의 효율 + 합치기의 한계
worktree를 에이전트와 묶으면 효율적이 된다는 게 Orca의 발상이다. Claude Code 하나와 Codex 하나를 쓰는데 프로젝트는 하나일 때, worktree로 책상을 복제하고 사진 관리자를 두 개 둔 뒤 "Claude Code는 A 루트, Codex는 B 루트"로 서로 다른 작업을 시킬 수 있다. 예: 웹 프로젝트 디자인을 A 스타일·B 스타일로 동시에 진행. 나중에 관리하다가 마음에 드는 것만 골라 합칠 수 있고, 에이전트들끼리 알아서 조율하게 하는 것이 Orca 핵심 기능 중 하나다.
- [의견/주의] 합치기는 어디까지나 이상적인 생각이라 충돌 등으로 항상 잘 되지는 않는다. 완전히 다른 두 사이트를 만들어 놓고 합치라고 하면 잘 안 합쳐진다. 합치기를 못 하더라도 동시에 여러 개를 시킬 수 있는 것, 마음에 드는 루트로만 계속 갈 수 있는 것 자체가 시간 절약이라는 큰 장점이라고 정리한다.

### [10:44–11:01] 실습 개요
이제 Orca로 이동해, 오케스트레이션 스킬을 이용해 Claude Code를 메인 관리자로 두고 하위 하청으로 Claude Code와 Codex에게 서로 다른 디자인 작업을 따로 시키는 프로젝트를 진행한다. 이 흐름이 이해되면 성공한 것이라고 말한다.

### [11:01–11:42] git 초기화 (필수 전제)
빈 폴더 "테스트 오르카 워크트리"를 만들어 두고, 메인 에이전트로 Claude Code를 "dangerously skip permissions"로 실행한다. 하청을 줘서 여러 작업을 하려면 git이 필요하므로 폴더가 git 초기화된 상태여야 한다. 현재 폴더는 아무것도 없고 git도 없는 클린 상태라, "git 초기화해줘"라고 시켜 git init을 먼저 한다.

### [11:42–13:17] 오케스트레이션 스킬 설치
Orca 설정에 들어가면 "오케스트레이션"이라는 AI 기능이 있고, 설치/업데이트 버튼을 누르면 명령어가 나오는데 엔터로 실행해 설치한다. 이때 이 스킬이 적용될 에이전트 범위(Claude, Codex 등 PC에 설치된 에이전트)가 표시되고 거기에 적용된다. 화자는 시청자와 동일한 클린 상태를 재현하려고 기존 오케스트레이션 스킬을 일부러 삭제한 뒤 다시 설치 과정을 보여준다.
- 설치 절차: Install 클릭 → 터미널에 명령어가 나오면 엔터 → additional agent 선택 화면에서 스페이스바로 Claude Code만 켜고 엔터 → 설치 방식은 기본값(symlink, recommended)으로 엔터 → 설치 후 재확인하면 "오케스트레이션 스킬이 설치됐다"고 표시됨 → 앱으로 돌아가기.

### [13:17–13:40] 상태 확인 — .git 폴더
Claude Code를 clear로 초기화한다. 이제 폴더에는 git만 들어와 있는 상태다. macOS 유저는 Command+Shift+.으로 숨김 폴더를 토글해 .git이 보이면 "테스트 오르카 워크트리" 폴더가 git으로 잘 초기화된 것이다.

### [13:40–15:08] worktree 생성 시도 중 버그와 원인
"테스트 오르카 워크트리"에 대해 워크스페이스 만들기 + 버튼을 누른다. 처음엔 "워크스페이스 이름"이 뜨는데 뭔가 잘못된 것 같아, "현재 git은 잘 초기화됐나"를 확인한다(잘 돼 있어야 함). 이는 약간의 프로그램 버그라 확인을 잘 해야 한다고 말한다. 프로젝트 제거(폴더 삭제가 아니라 Orca 목록에서만 제거) 후 프로젝트를 다시 추가하니, 이제 + 버튼이 "작업 워크스페이스"가 아니라 "작업 트리(worktree) 만들기"로 바뀐다 — Orca가 이 폴더를 git 관련으로 인식하게 된 것이다.
- 첫 worktree 생성 시도(디자인 1번, 담당 에이전트 Claude)에서 "기본 브랜치를 찾을 수 없다"는 에러가 반복된다. 껐다 켜도 안 된다.

### [15:08–15:49] 원인 = 커밋 부재, 초기 커밋으로 해결
Claude Code에게 원인을 물으니 "아무것도 커밋하지 않아서 그럴 수 있다"고 한다. 화자는 이를 "사진을 찍은 적도 없는데 책상을 복사하려고 하니 안 된다고 한 것"으로 비유한다. 그래서 아무거나 초기화 커밋(initial commit)을 하나 만들어(메인 책상에서 사진 하나를 찍어) 문제를 해결한다.
> "사진을 찍은 적도 없는데 책상을 복사하려고 하니까 얘가 이제 안 된다라고 한 거예요." [15:36]

### [15:49–16:29] worktree 두 개 생성 — 디자인1(Claude), 디자인2(Codex)
초기 커밋 후 + 버튼으로 "디자인 1번" worktree를 만들고 하청 업체를 Claude로 지정하니 정상 생성된다. 메인에서는 이름이 "메인"이었는데, 이 갈래는 "디자인 1번"으로 이름이 바뀌고 가지(branch)처럼 표시된다. 즉 초기 커밋 시점 이후부터 책상을 복제해 디자인 1번 책상을 만든 것이다. 이어 + 버튼으로 "디자인 2번" 책상을 만들고 이번엔 하청 업체를 Codex로 지정한다. 실제 폴더에도 "디자인 2번"이 생기는데 이 부분 설명은 생략한다.

### [16:29–17:44] 병렬 작업 지시 프롬프트
화자는 "현재 폴더를 Orca로 관리 중이고 초기화 커밋된 상태에서 다음 작업을 시켜 보려 한다"며 다음을 한 번에 지시한다.
- 메인(메인 책상)에서 먼저 간단한 기업의 랜딩 페이지를 만든다(디자인은 자유).
- 그다음 디자인 1번으로 가서 그 랜딩 페이지 디자인을 "20대 감성"으로 디자인만 바꾸고 웹 브라우저에 띄운다.
- 디자인 2번에서는 같은 랜딩 페이지 디자인을 "50대 감성"으로 디자인만 바꾸고 웹 브라우저에 띄운다.
순서: 사이트가 아직 없으니 메인 책상에서 랜딩 페이지를 자유롭게 만든 뒤, 디자인1·디자인2에서 각각 20대·50대 감성으로 바꾸고 각각 브라우저에 띄운다.

### [17:44–19:00] 실행 동작 — 오케스트레이션 시도
작업을 시키면 Orca 스킬을 이용해 각 worktree의 에이전트를 오케스트레이션하려고 시도한다. 에이전트는 "worktree가 이미 있네, 일단 메인에 랜딩 페이지 만들고 그다음 여기서 할게"라는 식으로 진행한다. 메인 책상에서 작업하다 분기가 생겼고 동시에 다른 녀석에게 시키고 싶을 때, Orca가 오케스트레이션 스킬로 두 녀석을 조율해 메시지를 전달할 수 있게 시스템을 만들어 뒀고, 그걸 가져다 쓰는 것이다. 원리는 git worktree지만 외부에서 보면 "메인(작업 반장)이 하위 하청 인부들을 부린다"는 그림이다.

### [19:00–20:03] 메인 완료 후 하위로 메시지 전송
메인에서 랜딩 페이지 작업이 끝나면 이제 worktree가 "와리가리(왔다갔다)"하는 모습이 보인다. 원래는 메인 책상이 worktree에 메시지를 전송해 각각의 디자인 작업을 시켜야 한다. 화자가 따로 입력하지 않았는데도 Orca가 디자인 1번·2번 worktree에 방금 전 지시 내용을 각각 메시지로 전달한다. 이것이 Orca worktree를 쓰는 이유다.

### [20:03–20:48] 위임(delegation)이 필요하다는 중요한 함정
- [실전 주의] 스킬로 구성돼 있어도, 에이전트는 "그냥 (git) worktree를 쓰라"고 이해해서 자기가 알던 git worktree를 혼자 쓰려는 경향이 있다. 그래서 Orca에 worktree 조작 권한을 위임시켜 "메시지를 전송해 봐라"라고 명시해야 한다.
- 실제로 화자가 처음 "worktree에서 작업하라"고만 했을 때 에이전트가 혼자 worktree만 만지고 메시지 전송을 안 했다. "왜 메시지를 worktree에 전송하는 모습이 안 보이냐"고 묻자 "Orca에 worktree 조작을 위임하지 않아서"라고 답했고, Orca에 위임시키자 그제야 메시지를 보냈다. 그 결과 메인은 먼저 진행되고, 2번·1번에 Orca가 메시지를 전달해 세 군데에서 병렬 작업이 진행된다.

### [20:48–21:19] 각 갈래의 작업 내용 확인
디자인 2번(Codex)은 50대 감성, 디자인 1번(Claude 계열)은 20대 감성으로 디자인만 다시 입힌다. 메인에서 만든 사이트는 주제를 안 줬는데도 에이전트가 "온열 매트 제조사" 사이트로 만들었다. 각 갈래가 서로 다른 작업을 진행 중이고, 작업이 끝나면 브라우저에 띄워 달라고 했으므로 2번·1번이 각각 완료되면 사이트를 보여줄 것이다.

### [21:19–22:20] 전체 구조 재정리 (그림)
- 메인: 온열 매트사 랜딩 페이지를 Claude Code로 제작. Orca가 이 상태를 지켜보다 책상을 두 개 복제해 디자인1·디자인2 책상을 만든다(랜딩 페이지 완성 상태를 복제했으니 처음엔 셋이 동일).
- Orca에게 시켜 각 책상에 메시지 전송: 디자인2(Codex)=50대 타깃, 디자인1=20대 타깃으로 디자인만 개편.
- 즉 동시에 세 개 작업이 진행되고, 각각 웹 브라우저를 따로 띄우게 했다.

### [22:20–23:16] 결과 확인 — 메인, 디자인2
메인 내장 브라우저를 띄우니 스크롤 내려가며 온도가 따뜻해지는 연출의 온열 매트사 랜딩 페이지가 나온다. 디자인이 마음에 안 들면 2번·1번으로 따로 가겠다는 취지다. 디자인 2번(Codex, 50대 대상)은 50대 스타일로, 화자가 "마음에 안 든다"는 손톱(네일) 디자인이 들어간 형태로 나온다. 마음에 안 들면 그 사이트를 띄운 상태에서 계속 수정 작업을 시키면 된다.

### [23:16–23:52] 디자인2에 이미지 추가 지시 + Codex 특성
디자인 2번에 "이미지도 만들 줄 알면서 왜 이미지를 포함 안 시켰냐, 이미지 포함해라"고 지시한다. 그러면 2번 책상에서 이미지를 추가한 웹사이트를 만들려 한다.
- [의견] Codex는 이미지를 잘 만드는데 사이트에 적용을 안 한 게 아쉽다. 그 이유는 메인을 Claude Code로 만들었기 때문에 처음에 이미지를 생각 안 해서 기하학적 문양을 코드로만 그려준 것. 그래서 그냥 이미지를 넣어 버리라고 지시한다.

### [23:52–24:33] 숨은 꿀 기능 — 칸반 보드
작업 중인 상태를 드래그해 오른쪽으로 올리면 To Do / In Progress / In Review / Done 식으로 작업 위치를 옮길 수 있다. 예: 디자인 2번을 리뷰 중이면 Review로, 1번·메인도 리뷰로 옮기고, 마음에 드는 게 나오면 Done으로 옮겨 완료 표시. 실제 작업에 영향은 없고 보여지는 칸반 보드만 관리하는 것이지만, 에이전트들이 작업 중인 상태를 조망할 수 있어 좋은 기능이라고 평한다.

### [24:33–26:31] 진행 상황과 반복 워크플로 정리
2번은 이미지 삽입 작업이 한창이고, 1번은 여전히 사이트를 만드는 중이다. 디자인 1번은 20대 감성이라 밝은 감성으로, 메인 레이아웃은 거의 그대로 유지된다.
- 병렬 작업이 필요할 때는 Orca 오케스트레이션 스킬 + worktree로 병렬 작업을 시키고 메인에서 나머지로 메시지를 날리는 방식으로 쓰면 된다.
- 마음에 드는 것을 옮기려면 메인 책상에 "디자인 2번 worktree가 마음에 드니 지금부터 이걸 머지해서 앞으로 메인으로 칠게"라고 하면, 메인에서 하던 작업을 싹 치우고 디자인 2번을 가져간다.
- [의견] 입문자에게는 이렇게 분산에서 시켰다가 합쳐 메인으로 불러들이고, 또 분산에서 시키다 합치는 방식이 가장 좋은 사용법이다. 서로 다른 같은 작업을 서로 다른 에이전트에게 시킬 수 있는 것도 좋은 점이다.

### [26:31–27:26] 부분 수정 팁 + 마무리 안내
리소스(이미지)를 만들어 넣는 코덱스의 강점을 언급하며, 간단한 랜딩 페이지 제작은 Codex가 더 잘할 거라고 본다([의견]). 사이트에 리소스가 하나도 없으면 휑해 보인다. 더 세밀히 수정하려면 저번 시간에 설명한 대로 말풍선을 누른 뒤 원하는 영역만 골라 "이 부분에 대해 수정 요청한다"고 해야 그 부분만 수정된다. 이미지 삽입이 완료돼 50대 감성 온열 매트 사이트가 만들어진 것을 확인한다.
오늘 영상은 Orca의 worktree와 오케스트레이션 스킬을 한꺼번에 다뤘고, Orca 팬들의 요청으로 준비했다. 다음 영상은 요청이 있던 "Orca 모바일" 설명이 될 수도 있지만, 본인이 Orca 홍보 대사는 아니므로 계속 다루긴 어렵고 원하는 사람이 많으면 댓글을 보고 결정하겠다고 한다.

### [27:26–27:49] 최종 — 디자인2를 메인으로 머지
메인 책상에서 디자인 2번을 선택해 가져가려 하므로, 1번을 다 사진 찍어 확인한 뒤 프로젝트를 정리하고 책상을 정리하는 모습이 보인다. 디자인 2번을 메인으로 가져와 메인에서 띄우는 것이 디자인 2번이 되는 흐름으로 마무리된다. 화자는 다음 영상에서 또 유용한 소식으로 찾아오겠다고 끝맺는다.
