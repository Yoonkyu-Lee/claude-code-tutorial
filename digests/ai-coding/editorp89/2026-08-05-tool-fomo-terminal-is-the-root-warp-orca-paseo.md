## 요약 (주제별)

### 영상의 성격·목적
- Paseo가 새로 나와 써 볼까 고민하다 거의 안 써 본 채로 만든, 화자 스스로 "리뷰 아닌 이상한 영상"이라 규정한 편. 메인 주제는 Paseo 소개가 아니라 도구 포모(FOMO)에 대한 메시지이고, Paseo는 개념만 곁들여 소개한다. 채널에 초보자가 많다는 점을 전제로 함.

### 핵심 메시지 — 포모(FOMO) 경계
- [의견] 포모 = "나만 모르는 것 같아 불안한 증세". 다들 쓴다는데 나만 안 쓰는 것 같아 이 도구 저 도구 갈아타는 사람이 많을 거라 봄.
- [의견] 도구를 바꿔 봤자 인생에서 달라지는 건 없다. 도구는 "자기 문제 해결"에 의미가 있다. 순수 호기심 공부는 좋지만, "요즘은 뭘 쓴다던데 나는 구닥다리다" 하는 불안(포모) 때문이라면 도움이 안 됨.
- [의견] 유행을 쫓지 말고, 자기 상황이 호기심인지 아니면 불안한 마음만 달래려는 건지 돌아보라. 그래야 빠르게 바뀌는 시대를 건강하게 살 수 있음.

### 핵심 비유 — "터미널이 근본, 나머지는 예쁜 껍데기(아종)"
- [의견] Warp·Orca·Paseo·VS Code 확장·Claude Desktop 코드(Cowork)·tmux 계열 등 에이전트 도구는 모두 **터미널**이라는 근본 위에 예쁜 껍데기(옷)를 씌운 "아종"에 불과. Claude와 엔터로 대화하는 상태를 예쁘게 만든 것뿐이라 터미널을 쓰는 것과 차이가 거의 없고, 버튼이 있어 유저 친화적일 뿐.
- [의견] 초보자는 "내 Claude Code와 남의 Claude Code가 달라 보일" 수 있지만 결국 "무슨 옷을 입혔냐"의 차이.
- UI가 예뻐서(VS Code의 Claude, Claude Desktop 등) 거기서 못 벗어나는 사람이 많다는 관찰.

### 권장 학습 태도 — 터미널에 나를 최적화하라
- [의견] Claude Code 입문자는 터미널에서 시작하기를 권장. 터미널의 불편함(버튼 없음, 파일 탐색기 없음 등)을 스스로 느낄 때 껍데기 프로그램으로 옮겨 가는 게 맞고, "남이 쓴다고" 옮기는 건 좋지 않음.
- [의견] 도구가 쏟아질 때는 "터미널을 7일만 써 보라" — 그러면 뭐가 나와도 적응 가능.
- [의견] 도구에 나를 최적화하지 말 것. 예: 무료인 Orca에 최적화됐는데 서비스가 종료되면 버려진 신세. 근본(터미널)에 자기를 맞추고, 껍데기는 "어떤 옷을 입어 볼까"로 접근.

### Paseo — 정체와 핵심 개념(데몬)
- Orca와 UI 형태는 비슷하나 지향이 다른 "터미널의 아종". 화자는 설치만 하고 거의 안 써 봄, 가이드 영상도 안 찍겠다고 함(원하면 찍을 수 있으나 가치가 낮다는 판단).
- **세션(=채팅방)**: Claude Code를 터미널에서 실행하면 대화가 오가는 창.
- **데몬(daemon)**: 악마가 아니라 그리스 신화 다이몬(daimon)에서 온 말. 눈에 안 보이지만 백그라운드에서 계속 일하는 무언가. PC를 켜면 보이지 않게 돌아가는 프로세스라는 컨셉으로 이해하면 됨.
- Paseo 설치 시 데몬이 하나 생겨 채팅방들을 "물고" 있음 → 데몬이 죽지 않으면(=PC를 안 끄면) 채팅방(세션)이 사실상 계속 살아 있음. Claude Code 창을 X로 닫으면 맥락이 사라지던 문제를 해결하는 컨셉.

### Paseo — 진짜 목적(멀티 기기)과 유리한 시나리오
- 데몬(대문)에 여러 기기(스마트폰, 회사 맥북 에어 등)를 붙일 수 있음. 기기에서 에이전트를 직접 돌리는 게 아니라, 데몬에 떠 있는 채팅방을 기기가 가져다 씀 → 여러 기기가 같은 채팅창을 공유. 이게 Paseo의 진짜 목적.
- [의견] 유리한 시나리오: 집 PC를 24시간 켜 데몬·채팅창을 유지하고, 외부에서 스마트폰이나 다른 맥북으로 그 채팅창에 붙어 조작·작업하고 싶은 경우.

### Orca vs Paseo 선택 가이드
- [의견] PC 하나를 갖고 다니며 그 PC를 켜서 작업하는 걸 선호 → **Orca**. Claude Code를 띄운 PC는 집에 두고 다른 데서 붙고 싶다 → **Paseo**가 유리.
- Orca 단점: 프로그램(PC)이 꺼지면 끝. Paseo는 데몬을 죽이지 않는 한 유지. 단 "Paseo 종료 시 데몬도 죽는지"는 화자 미확인.
- 기능 성격: Orca는 멀티에이전트 작업(폴더 여러 개에 Claude Code·Codex 각각 구동, 워크트리 기반 병렬 구동, 여러 에이전트 조율=오케스트레이션)에 좋음. Paseo도 공식 문서상 오케스트레이션은 있으나 핵심 기능은 아닌 것 같다는 (미사용 상태의) 판단.
- [의견] 성숙도: Paseo는 아직 1.0 미만이라 버그가 많을 것이고 **한글 미지원**. Orca는 이미 1.0을 넘겨 더 성숙. → Orca를 잘 쓰는 사람이 Paseo로 넘어갈 이유는 없어 보임(단 "Paseo가 후지다"는 뜻은 아님).

### 곁가지 코멘트 — "Claude Code로 영상 편집" 유행
- [의견] Claude Code로 영상 편집을 하려면 최소 수백 번 프롬프팅 + 월 100달러(≈14만 원 이상) 비용. 반면 화자가 전에 소개한 **브루(Vrew)**는 무음 구간·오탈자를 잘 잡아 주고, 스탠더드 연 22만 원(월로 나누면 얼마 안 됨, 가격은 "10만→20만 원 정도"로 정정 언급). 영상 편집이 주력이면 굳이 Claude Code로 할 이유를 모르겠다는 입장(업로드까지 자동화면 여지). 관건은 "한 달에 영상을 몇 개나 찍느냐" — 가치·문제 상황을 따지라는 것.

### 또 다른 요청 도구
- "양 모양 아이콘" 도구(리뷰 요청 다수)를 언급하나 이름을 떠올리지 못함. [불명확: 자막이 "허더"로 반복 표기 — 화자 묘사("양 모양 아이콘")로 미루어 Ghostty 터미널일 가능성이 있으나 자막만으로는 확정 불가]. 터미널을 아주 좋아하는 사람용이라 버튼을 많이 제공하지 않는다고 하며 리뷰를 보류(원하면 하겠다고 함).

### 마무리 조언
- [의견] 유행에 집착 말고 기본기를 닦아라. 나중에 와도 문제없고, 그때는 그 프로그램들이 유행이 지나 안 쓰일 수도 있음. 에이전트 시대의 핵심은 "뭘 써 보는 것" — Claude Code나 Codex부터. 프로그램을 정 쓰고 싶으면 한 개만 골라 해 보되 이왕이면 터미널이 좋다. "즐거운 공부·자동화·바이브 코딩"을 하라는 당부.

## 3줄 오리엔테이션
- 새 도구가 쏟아지며 "나만 안 쓰는 것 같아 불안한" 포모(FOMO)를 느끼는 시청자를 향해, 도구를 바꿔도 인생은 안 달라지니 유행이 아니라 자기 문제 해결에 초점을 맞추라는 메시지가 영상의 축이다.
- 핵심 논지: Warp·Orca·Paseo·VS Code 확장·Claude Desktop 등 에이전트 도구는 결국 모두 "터미널"이라는 근본 위에 예쁜 껍데기(옷)를 씌운 아종이므로, 도구가 아니라 터미널에 자기를 최적화하라는 것.
- 그 위에서 새로 나온 Paseo를 (거의 안 써 본 채) 개념만 소개한다 — 데몬(daemon)이 세션(채팅방)을 물고 있어 PC를 켜 두면 스마트폰·다른 맥북에서 같은 채팅방에 붙을 수 있는 것이 핵심이며, Orca와 언제 갈릴지도 정리한다.

## 전문 — 시간순 워크스루

### [00:00–00:27] 도입 — "안 써 보고" 만든 Paseo 리뷰 아닌 영상
Paseo라는 도구가 또 나와서 써 볼까 말까 고민하다가, 결국 거의 안 써 보고 영상을 준비했다고 화자가 밝힌다. 리뷰 영상은 아니라고 선을 긋는다. 이런 도구들이 쏟아지는 요즘 포모를 느끼는 사람이 많을 것 같아 그 얘기를 먼저 하고, Paseo가 뭔지는 설명해 주는 게 맞을 것 같아 대충 써 보고(사실상 거의 안 써 보고) 준비한, 좀 이상한 영상이라고 스스로 규정한다. 제목은 "도구에 미쳐버린 사람들, Warp부터 Orca, Paseo까지".

### [00:27–00:50] 포모(FOMO)란 무엇인가
"도구까지 포모를 만드는 지금"이라며 포모의 뜻을 푼다. [의견] 포모(FOMO)는 "나만 모르는 것 같아서 불안한 증세"라고 화자는 설명한다. 이 영상을 보는 사람 중에도 "나만 이걸 모르는 것 같아 두렵고, 다들 쓴다는데 나만 안 쓰는 것 같아 힘든" 포모가 있어서 보는 사람이 있을 거라고 본다. 그래서 이거 썼다 저거 썼다 하는 사람이 많을 거라는 생각이 든다고 한다.

### [00:50–01:48] 도구를 바꿔도 인생은 안 달라진다 — 문제 해결에 초점
Claude Code든 Codex든 Orca든, Visual Studio Code든 다 싸잡아 하는 얘기인데, [의견] 도구를 바꾼다고 해서 인생에서 달라지는 일은 없다고 단언한다. 도구를 쓰는 이유는 결국 자기 문제를 해결해야 의미가 있다는 것. 순수하게 호기심으로 공부하는 거라면 공부에만 뜻을 두면 되지만, 호기심을 넘어 "요즘은 뭘 쓴다던데 나는 아직 이걸 쓰네, 구닥다리다" 하는 불안(포모) 때문이라면 그건 별 도움이 안 된다고 한다. 유행을 쫓지 말고, 자기 상황이 호기심인지 아니면 진짜 해결하고 싶은 문제 없이 유행을 쫓는 불안한 마음만 해결하려는 것인지 다시 생각해 보라고 권한다. 그래야 빠르게 바뀌는 이 시대를 건강하게 살 수 있다는 것.

> "여러분들이 도구를 바꾸신다고 해서 인생에서 달라지는 게 일도 없습니다." [01:04]

### [01:48–02:09] 호기심은 좋지만 포모는 안 된다
앞의 얘기를 다시 정리한다. [의견] 호기심은 좋은 것이고 나무라려는 게 아니지만, 포모는 안 된다는 것. 호기심을 해결하기 위해서라면 언제든 즐거운 마음으로 뛰어들면 좋지만, 문제를 해결하는 게 훨씬 더 중요하다고 강조한다. 자신이 지금 문제를 해결하고 있는 상황인지 다시 한번 돌아보는 시간을 가지면 좋겠다고 한다.

### [02:09–03:15] 곁가지 사례 — "Claude Code로 영상 편집" 유행에 대한 코멘트
최근 Claude Code 같은 걸로 영상 편집을 해결하려는 사람들이 유행처럼 번지고 있다고 짚는다. [의견] 그런데 Claude Code로 영상 편집을 하려면 최소 수백 번 프롬프팅을 해야 하고, 비용도 월 100달러(하나에 14만 원이 넘는다고 언급)를 지불해야 한다는 것. 반면 화자가 전에 소개했던 **브루(Vrew)**라는 오래된 영상 편집 도구는 무음 구간·오탈자 등을 아주 잘 잡아 주는데, 화자는 스탠더드를 22만 원(연 기준)에 쓰고 있고 12로 나누면 월 얼마 안 한다고 한다(가격을 "10만 원이었는데 20만 원 정도"라고 정정하며 언급). 영상을 주력으로 해서 녹음하고 자막 깔고 하고 싶은 사람이라면 굳이 Claude Code로 해야 하는지 모르겠다는 입장. 다만 영상 업로드까지 자동화해야 한다면 그럴 수도 있겠다고 여지를 둔다. [의견] 핵심은 "당신은 한 달에 영상을 몇 개나 찍느냐" — 문제 상황과 가치를 따져 보라는 것. 호기심이라면 오케이지만, 자동화로 편해지려면 일단 영상을 많이 찍어야 성립한다고 짚는다.

### [03:15–04:12] 에이전트 도구 나열 — 다 "껍데기"들이다
다시 에이전트 도구 얘기로 돌아온다. "에이전트를 쓴다"는 건 Claude Code나 Codex 같은 걸 생각하면 되고, 그런 걸 쓰는 도구들의 "껍데기"가 굉장히 많다고 한다. VS Code 확장 프로그램도 있고(Visual Studio Code에서 Claude Code를 버튼으로 예쁘게 쓰는 UI를 보여 준다), 기본적으로 Claude Desktop의 코드(Cowork/Claude Code)도 있는데 그것도 결국 Claude Code라고 한다. [의견] 이 UI가 예뻐서 못 벗어나는 사람이 많다는 것. Warp도 그렇고, mux 계열(tmux 같은 터미널 멀티플렉서)도, 최근 소개한 Orca도, 오늘 나온 Paseo도 다 마찬가지라고 한다.

### [04:12–05:18] 핵심 비유 — 터미널이 근본, 나머지는 예쁜 껍데기(아종)
결국 이 도구들은 명령어를 입력하는 수단인 **터미널** 위에서 동작한다고 설명한다. 화자가 늘 강조하는 터미널의 중요성을 다시 꺼내며, 단순해 보이는 터미널이 에이전트가 동작하는 아주 기본적인 "토양"이라고 한다. 그 토양 위에 껍데기를 씌운 것이 나머지 전부라는 것 — 기본 터미널, Orca, VS Code의 Claude 등 모든 것이 "터미널을 예쁘게 껍데기 씌운 것에 불과하다"고 표현한다. 정확히는 Claude와 명령을 주고받는 상태(엔터로 대화하는 상태)를 예쁘게 만든 것뿐이라, 터미널을 쓰는 것과 차이가 거의 없고 그냥 버튼이 있어 유저 친화적일 뿐이라는 것. 초보자는 "내가 쓰는 Claude Code와 남이 쓰는 Claude Code가 달라 보일" 수 있지만, 결국 "가면(옷)을 뭘 입혔냐"의 차이일 뿐인 **아종**이라고 정리한다.

> "이 모든 것들이 얘를 그냥 이쁘게 껍데기를 씌운 거에 불과합니다." [04:52]

### [05:18–06:09] 그래서 터미널에서 시작하라 — 이동은 "내 불편함"이 기준
[의견] 그래서 Claude Code를 제대로 공부하려면 터미널에서 시작하다가, 터미널이 주는 불편함(버튼이 없음, 추가 기능이 없음 — 예컨대 파일 탐색기가 없음)을 스스로 느낄 때 그런 걸 제공하는 프로그램으로 옮겨 가는 게 맞다고 한다. 내가 불편함을 느껴서 옮기는 것이지, "남이 쓴다고" 옮기는 건 좋은 게 아니라는 것. 모든 도구는 터미널의 기본 형태를 예쁘게 바꿔 주는 것에 불과하므로, 처음 입문자에게는 터미널에서 시작하기를 권장한다고 반복한다.

### [06:09–06:56] 무엇이 중요한가 — "터미널 7일만 써 보라", 도구에 나를 최적화하지 말라
[의견] 도구가 쏟아질 때는 그냥 터미널을 7일만 써 보라고 권한다. 그러면 뭐가 나와도 적응할 수 있다는 것. 도구를 쫓아 자신을 도구에 맞추지 말라며 예를 든다 — 자신이 Orca(무료)에 최적화된 사람이라 치자, 그런데 어느 날 Orca가 서비스를 종료해 사라지면 버려진 사람 같은 처지가 된다는 것. 그러니 도구에 나를 최적화하지 말고, 근본인 터미널에 나를 맞추고 "Claude Code는 터미널에서 돌아가는 에이전트 도구구나"를 이해한 다음, "터미널의 껍데기 버전이 좋은 게 많네, 어떤 옷을 입어 볼까" 하는 식으로 접근하라고 한다. "요즘 다 Orca 쓴다니까 Orca에 특화된 방식으로 공부해야지"는 아니라는 것.

### [06:56–07:12] Paseo는 소개만, 가이드 영상은 안 찍는다
[의견] 그래서 Paseo는 소개만 하고 가이드 영상은 찍지 않겠다고 한다. 너무 원하면 찍긴 하겠지만 그렇게 가치가 없다는 입장. 설치는 했지만 아무것도 안 해 봤다고 다시 밝힌다.

### [07:12–08:24] Paseo란 무엇인가 (1) — 데몬(daemon) 개념 풀이
Paseo는 화면(loading feel/UI)을 보면 Orca와 비슷한 형태를 취하지만 지향하는 관점이 조금 다르다며, 핵심 하나만 설명하겠다고 한다. 우선 "채팅창"부터 정의한다 — Claude Code를 터미널에서 실행하면 대화가 오가는 그 채팅창을 **세션(session)**이라 부르는데, 여기서는 그냥 "채팅방"이라 부르겠다고 한다. Paseo는 이 세션(채팅방)을 **데몬(daemon)**이라는 곳에서 관리하게 해 주는 것이 목적인 "터미널의 아종"이라고 규정한다.

이어 데몬 개념을 비유로 설명한다. 데몬은 악마가 아니라 그리스 신화의 다이몬(daimon)에서 온 말로, 사람 눈에는 안 보이지만 뒤에서 끊임없이 일을 처리하는 정령을 뜻한다고 한다. 그래서 데몬은 "터미널이 아니라 뭔가 백그라운드에서 계속 일을 하는 무언가"라는 컨셉으로 이해하면 된다는 것. 정확히 이해하려면 복잡해지지만, PC를 켜면 눈에 보이는 실행 프로그램 말고도 뒤에서 안 보이게 계속 일하는 무언가가 있는데 그게 데몬이라고 정리한다. "눈에 안 보인다"가 핵심이라고 한다.

> "데몬은 악마가 아니고요. 그리스 신화 (…) 다이몬이라는 녀석은 (…) 사람의 눈에는 안 보이거든요. 근데 뒤에서 끊임없이 일을 처리하는 정령을 얘기를 합니다." [08:38]

### [08:24–09:39] Paseo란 무엇인가 (2) — 데몬이 채팅방을 "물고" 있어 세션이 안 죽는다
Paseo가 설치되는 순간 이 프로그램의 데몬이 하나 생기고, 그 데몬이 사용자의 채팅방들을 다 "물고" 있다고 설명한다. 데몬이 죽지 않으면 그 채팅방들이 다 살아 있다는 것. 화자는 이 개념이 시청자의 기존 고민과 닿는다고 짚는다 — Claude Code와 즐겁게 세팅하고 "추억"(대화·맥락)을 쌓았는데 X(닫기)를 누르면 그게 다 사라져서, 켜 놓고 다니고 싶었다는 것. Paseo에서는 데몬이 채팅방들을 물고 있고 데몬은 보이지 않는 채 계속 살아 일하므로, 컴퓨터를 끄지 않는 한 데몬이 살아 있고, 따라서 채팅방도 사실상 살아 있게 된다. 이렇게 세션을 유지시켜 주겠다는 것이 Paseo의 기본 컨셉이라고 정리한다.

### [09:39–10:34] Paseo란 무엇인가 (3) — 데몬(대문)에 여러 기기를 붙인다 = 진짜 목적
그런데 여기서 끝이 아니라, Paseo는 그 "대문"(데몬) 위에 기기를 붙일 수 있다고 한다. 구조는 이렇다 — Paseo를 설치하면 모든 채팅창을 데몬에 물려 놓고, 그 데몬에 붙을 수 있는 기기들의 연결을 제공한다. 예를 들어 스마트폰으로 이 대문에 붙을 수 있고, 회사의 맥북 에어로도 이 대문에 붙을 수 있다. 이때 스마트폰에서 에이전트를 직접 돌리는 게 아니라, Paseo 데몬에 떠 있는 채팅방을 스마트폰이 가져다 쓰는 것이라 한다. 그래서 여러 기기가 데몬 위에 붙어 같은 채팅창을 볼 수 있고, 스마트폰이 보는 채팅창과 맥북이 보는 채팅창이 동일해질 수 있다는 것 — 이걸 제공하는 게 Paseo의 진짜 목적이라고 한다.

### [10:34–10:55] Paseo가 유리한 사용 시나리오
[의견] Paseo를 써야 한다면, 한 PC(집 PC 등)에서 데몬과 채팅창을 유지하면서, 외부에 나가 스마트폰으로 그 채팅창을 조작하거나 회사의 맥북 에어로 붙어 작업하고 싶은 경우라고 정리한다. 집 PC를 24시간 켜 두고 접속하면 되므로 그 용도에 특화된 녀석이라는 것.

### [10:55–11:48] Orca와의 비교 — 언제 갈리나, 그리고 "핵심 기능이 뭔가"
Orca에도 모바일 기능이 있어, 그것만 놓고 보면 비슷할 수 있다고 인정한다. 다만 [의견] Orca의 단점은 Orca 프로그램(PC)이 꺼지면 끝난다는 것이고, Paseo는 데몬을 물고 있어 데몬을 죽이지 않으면 유지된다는 차이라고 한다. 단, 화자가 확인 안 해 본 것은 "Paseo를 종료하면 데몬도 죽는지" 여부라고 솔직히 밝힌다(어쨌든 Paseo 측 설명은 그렇다고). 비교하자면, [의견] Orca를 잘 쓰는 사람이 굳이 Paseo까지 넘어올 필요는 없어 보인다고 한다. Paseo가 주장하는 강점은 "데몬을 띄워 다수 기기로 세션 채팅을 날릴 수 있다"는 것이고, Orca는 그건 없는 대신 멀티에이전트 작업(폴더 여러 개 띄워 Claude Code·Codex를 각각 돌리고, 워크트리로 다수 에이전트를 병렬 구동하거나, 하나의 작업을 여러 에이전트가 조율하는 오케스트레이션)에 좋다고 한다. Paseo도 오케스트레이션을 공식 문서상 제공하긴 하는데, 그게 핵심으로 나온 것 같지는 않다는 게 (안 써 본 채의) 화자 판단이다. 써 본 사람이 "그거 아니다"라고 하면 그게 정답이라고 여지를 남긴다.

### [11:48–12:11] 요약 선택 가이드 — Orca vs Paseo
설명이 어려워 "그래서 뭘 쓰라는 거냐" 하는 사람을 위해 단순화한다. [의견] PC 하나를 갖고 다니며 그 PC를 켜서 작업하는 걸 선호한다면 **Orca**를 쓰면 되고, Claude Code를 띄워 둔 PC는 집에 있고 나는 다른 데서 붙어 작업하고 싶다면 **Paseo**가 더 유리할 것 같다고 정리한다. 화자 본인은 Paseo를 선호할 만한 작업을 하지 않는다고 덧붙인다.

### [12:11–12:34] Paseo 성숙도 — 아직 1.0 미만, 한글 미지원
Paseo가 후지다는 게 아니라고 먼저 못 박은 뒤, 평가를 내려야 한다면 이렇게 말한다. [의견] Paseo는 아직 버전이 1.0도 안 됐고, Orca는 이미 1.0을 넘겨 훨씬 성숙한 도구라는 것. 이제 막 만들어진 Paseo는 버그가 많을 것이고, 심지어 한글 지원도 안 한다고 한다. 이런 점을 따지면 Orca를 잘 쓰는 사람이 Paseo로 넘어갈 이유는 없어 보인다고 정리한다.

### [12:34–13:09] 요청 많던 또 다른 도구 — Ghostty(양 모양 아이콘)
"양 모양(헤드?) 아이콘"이 있는 도구도 리뷰해 달라는 요청이 많았다며 이름을 떠올리려 애쓴다("카였나?" 등). 결국 **허더/Ghostty로 추정되는 도구**를 가리키며 "이거 맞다"고 한다. [불명확: 자막이 "허더"로 반복 표기 — 화자가 "양 모양 아이콘"이라 묘사한 점으로 미루어 Ghostty 터미널일 가능성이 있으나 자막만으로는 확정 불가]. 요청한 사람이 정말 많았지만, 화자가 아는 바로는 이건 "터미널을 너무 좋아하는 사람들이 쓰기 좋은 툴"이라 버튼을 많이 제공하지 않는다고 한다. 그래서 리뷰를 하려다 멈췄고, 원하면 리뷰하겠으나 자기가 도구에 집착하는 사람이 아니어서 안 했다며, 원하면 그것까지 하겠다고 한다.

### [13:09–14:11] 마무리 — 유행 말고 기본기, "뭘 써 보는 게" 중요
오늘 Paseo를 메인으로 한 게 아니라, 도구 관련 포모를 느끼는 사람이 많은 것 같아 영상을 올린 것이라고 한다. 채널에 초보자가 많은데, "남들이 안 쓰는 프로그램을 나는 써야 앞서 가는 거 아니냐"는 포모가 있었다면, 오늘 영상을 통해 그런 건 그렇게 중요하지 않다고 전한다. [의견] 차분히 기본기를 닦다가 나중에 와도 문제없고, 나중에 오면 그런 프로그램들은 유행이 지나 아무도 안 쓰고 있을 수도 있다는 것. 잠깐 치고 지나가는 유행에 집착하지 말라고 한다. 에이전트 시대에 중요한 건 "뭘 써 보는 것" — Claude Code나 Codex(자막의 "코스"는 Codex로 교정)를 써 보는 게 중요하니 그것에 먼저 집중하고, 프로그램을 정 쓰고 싶으면 한 개만 골라 해 보되 이왕이면 터미널이면 좋다고 권한다. 공부한 다음 나중에 옮겨도 전혀 문제없으니 포모를 느끼지 말고 "즐거운 공부, 즐거운 자동화, 즐거운 바이브 코딩"을 하라며 마친다. 또 유용한 영상으로 돌아오겠다고 인사한다.

> "잠깐 치고 지나가는 유행에 너무 집착하지 마시고요. (…) 에이전트 시대에는 뭘 써 보는 게 중요하죠? (…) 클로드 코드나 코덱스 써 보는 게 중요하니까." [13:38]
