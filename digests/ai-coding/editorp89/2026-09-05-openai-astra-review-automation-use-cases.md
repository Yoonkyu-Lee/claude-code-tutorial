> editorp89 · 2026-09-05 · 조회수 8,164 · 길이 22:28 · [영상 링크](https://youtu.be/Ct0o3RqdkhI)
> 정리 방식: 시간순 심층 워크스루 (paraphrase) + 주제별 상세 요약
> 검증 배너: 수익 주장이 없는 신규 모델 리뷰 영상이다. 다만 화자 스스로 "출시 당일 오전에 알게 되어 영상 촬영 포함 세 시간 남짓 써 본 것이 전부"라고 경험치 한계를 명시하므로, 성능·속도에 대한 평가는 전부 **개인 체감(화자 주장, 미검증)**이다. 가격·문서 관련 서술은 화자가 화면에 띄운 공식 문서를 읽으며 말한 것이지만 이 정리는 자막만을 소스로 하므로 수치 확인이 필요하다. 제품·라이브러리 명칭은 자동자막 음차를 문맥으로 복원한 근사치이며, 복원이 불확실한 항목은 `[불명확]`으로 남겼다.

## 요약 (주제별)

### 아스트라 출시 맥락과 화자의 프레이밍
- 오픈AI가 신규 모델 **아스트라(Astra)** 를 예상(약 일주일 뒤)보다 빨리, 발표 당일 바로 공개했다. 화자는 이를 경쟁사 **페이블 5.1** 발표를 강하게 의식한 조치로 본다([의견]).
- 문서의 가격 설정에서도 페이블 5.1을 경쟁 타깃으로 두고 있음이 "노골적으로 느껴졌다"는 것이 화자의 첫인상([의견]).
- 화자가 보는 에이전트의 방향성은 **기본 사무 업무 대행 = 사무 자동화**이며, 오픈AI가 보는 방향도 그쪽이라고 판단한다([의견]).
- 이 영상 자체는 출시 당일 오전에 알게 되어 촬영 포함 **세 시간 남짓** 써 본 개인 테스트다. 화자 스스로 경험치 한계를 명시하고, "이렇게 쓰면 더 좋다"는 반론이 있으면 그게 정답이라고 선을 긋는다.

### 문서·커뮤니티에서 전해지는 아스트라의 특징 (전언, 미검증)
- **컴퓨터 유즈를 더 적극적으로 사용**하는 경향 → 문서·PPT 등 사무직 업무 자동화가 강화된 느낌.
- **속도 향상.** 예전에 오픈AI가 "컴퓨터 유즈를 더 빠르게 하겠다"고 예고했었는데 실제로 빨라졌다는 체감.
- **장기 작업 성능 향상 = 하네스 강화.**
- **지난 컨텍스트 윈도우까지 참조.** 이전에는 컨텍스트가 압축·재생성되면 소실이 컸는데, 아스트라부터 이전 컨텍스트를 참조하는 하네스로 강화됐다고 한다 — 단, 화자도 "어디서 봤는지 기억이 안 난다"고 출처를 명시하지 못한다.
- 화자 본인은 엔지니어가 아니라 4번은 문서로만 확인. 다만 직접 만든 애플리케이션의 개선안을 논의하고 "끝까지 드라이브해 봐라"라고 시켰을 때 매우 잘해 준다는 체감은 있었다([의견]).

### 가격 비교 (화자가 화면 문서를 읽으며 말한 값, 미검증)
- 클로드 페이블: 컨텍스트 윈도우 100만 토큰, 입력 **10달러** / 출력 **50달러**, 캐시 라이트 **12.5달러**(5분 캐시 기준, 1시간 캐시는 더 비쌈).
- 아스트라: 입력 **10달러** / 출력 **50달러**, 캐시 라이트 **12.5달러** — 캐시 가격까지 동일하게 맞췄다.
- 아스트라는 캐시 유지 시간에 따른 가격 차이를 두지 않는 것으로 보인다(화자도 확신 없음).
- 아스트라에는 별도 **패스트 모드**가 있으나, 클로드 쪽은 패스트 모드 전용 가격제를 공개하지 않아 비교 불가.
- 화자 해석: 캐시까지 똑같이 맞춘 가격표에서 "우리랑 부딪쳐 볼 수 있냐"는 도발이 읽힌다([의견]).

### 커뮤니티 반응 vs 이 영상의 초점
- 커뮤니티 화제는 **3D 쪽**에 쏠려 있다 — **Three.js** 기반 3D 게임, 3D 컨셉 자기소개 포트폴리오 사이트, 블렌더 작업 등. 전반적으로 3D·볼륨감 있는 인터랙션 작업을 빠르고 잘한다는 결과물이 쏟아진다(출처 계정은 `[불명확: 원문 "코이 오픈에 AI"]`).
- 화자는 그 흐름 대신 **컴퓨터 유즈 = 사무 업무 자동화**만 파고드는 것이 이 영상의 핵심이라고 못 박는다.
- 코딩 성능은 언급하지 않겠다고 선언 — "코딩은 워낙 상향 평준화돼서 누렁소나 검정소나 잘한다"([의견], [05:04]).

### 오픈AI 공식 발표 자료에서 읽히는 방향성
- 오프닝 영상의 핵심은 **말로 시켜서 컴퓨터를 조작**하는 것: 그림판 작업을 음성으로 지시 → 끝나면 블렌더로 옮겨 3D 모델링, 파워포인트 작업도 말로 지시.
- **마우스 커서 표시**가 컴퓨터 유즈 동작 중이라는 시각적 신호.
- 성능 비교 섹션은 "좋다"는 홍보로 넘기되, **소요 시간을 강조**하는 대목("우리 좀 빨라요")이 눈에 띈다.
- 코딩만이 아니라 **서치 작업** 등 실제 사용자가 원하는 자동화 시나리오가 많다는 점을 강조. 왼쪽에 레퍼런스 슬라이드를 주면 오른쪽에 확장해 만들어 주는 예시도 있음.
- 설계도 기반 모델링 → 실제 기판 시뮬레이션 사례도 포함.

### 실전 1 — 웹 문서를 구글 독스로 "양식까지" 복제하기
- 상정 상황: **서치한 내용을 문서화하는 일상 업무.** 왼쪽 = 오픈AI 개발자 문서의 모델 프라이싱 페이지, 오른쪽 = 구글 독스(워드도 잘될 것이라 봄).
- 실행 경로: 챗GPT 앱 → 채팅 → **코덱스 모드로 바꿀 필요 없이 챗GPT 모드에서 워크(work)** 진입.
- 프롬프트 요지(원문 [10:01–10:29]): "컴퓨터 유즈를 사용해서 왼쪽 브라우저의 GPT 아스트라 소식을 오른쪽 구글 독스에 최대한 양식을 살려 옮기되, 제출용으로 쓸 수 있도록 문서 양식을 창의적으로 스스로 개선해 보기 좋게 만들어 보자." **핵심은 "컴퓨터 유즈를 쓰라"고 명시하는 것.**
- 초반 사고: 모델이 예전에 설치해 둔 **오르카(Orca)** 를 실행하려 해서, 화자가 "오르카 말고 챗GPT의 컴퓨터 유즈를 쓰라"고 교정. 이후 어느 창을 봐야 할지 몰라 브라우저를 여러 개 띄워 보다가 다른 창에 있던 대상을 제대로 찾아냈다.
- 모델의 계획 서술: 원문을 "짙은 우주색 배경 + 큰 제목 + 성능 그래프 + 활용 사례"로 읽고, "남색·파란색 제목과 비교표로 분위기를 살리고 원문의 장 순서에 맞춰 한국어로 재구성하겠다".
- **스스로 자기 평가**를 수행(왼쪽을 얼마나 똑같이 복제했는가). 화자가 "레이아웃·배치를 맞춰 보라", "테마와 배치를 복제하는 느낌이 있으면 좋겠다"고 추가 요청.
- 모델이 **직접 페이지 설정 메뉴에 진입**해 페이지 색상을 검정으로 바꾸고 흰색 본문 + 파란색 강조로 맞춤. 별표 장식으로 "우주적인 느낌"을 표현하고 중앙 정렬까지 조정.
- 화자가 "페이지가 뚝뚝 끊긴다"고 하자 그 표현을 이해하고 **'페이지 없음' 모드로 전환**, 요청하지 않은 **텍스트 너비**까지 원문 비율에 맞춰 수정(어떤 옵션인지는 화자도 미확인).
- 소요 시간: 1차 **3분 15초**, 레이아웃 보완 **2분 38초** — 약 **5분**에 완성. 앞선 1·2회차 실험도 **3~4분**대. 예전에는 컴퓨터 유즈가 너무 느려 이런 작업이 아예 불가능했다는 것이 비교 기준.
- 파생 활용 팁: 새 뉴스가 나오면 그냥 이렇게 문서로 복제해서 읽으라([의견]).

### 실전 2 — 피그마를 직접 조작해 발표 자료 만들기
- 지시 요지([17:23–17:42]): "피그마 앱 펴놨으니 네가 이용해서, 빈 페이지에 **내가 즐겨 쓰는 슬라이드 타입을 보고 복제해서** 발표 자료를 만들어 줘."
- 모델이 컴퓨터 유즈로 피그마에 들어가 화자가 만들어 둔 **기존 발표 자료를 하나씩 훑어 스타일을 파악**한 뒤 복제·제목 변경·장표 수정을 진행.
- 겪은 문제와 자율 해결: 프레임이 위아래로 겹치자 붙여넣기 후 **계층을 확인**하고, "복제한 다음 레이어 바깥으로 빼야지"라고 스스로 판단해 분리에 성공 → 화자가 시킬 필요가 없었다.
- 화자의 추가 요청 두 건: (1) "새로 만들어지는 프레임을 순서대로 잘 이어서 보기 좋게 나열해 줘" (2) 캔버스 구석구석에 흩어진 프레임을 **순서대로 정리**. 모델이 배치 작업까지 수행. 화자는 "처음부터 배치 위치를 지정하고 수정하라고 했어도 됐겠다"고 회고.
- 내용 채우기: 앞서 만든 보고서 내용을 바탕으로 각 프레임을 파악해 화자의 **목록 형식 장표**에 맞춰 입력.
- 시사점: 피그마로 무언가를 만드는 사람은 **이미 만들어 둔 자산을 그대로 재료로 주면** 잘 시킬 수 있다([의견]). 모션이 필요 없다면 굳이 `[불명확: 원문 "하이퍼프레임즈"]` 기반으로 슬라이드를 만들 이유가 있나 싶을 정도.

### 실전 3 — RPG 웹게임 (결과만 공유)
- 소요 시간 **약 25분**(에셋·파일 작업 포함), 동물 컨셉 리메이크는 **25~30분**.
- 화면 구성을 CSS 선 작업으로 때운 게 아니라 **모서리 장식을 포함한 에셋 이미지 전부를 모델이 생성**. 에셋 제작 속도가 크게 빨라졌다는 평가.
- 구현된 것: 자동 사냥, 몬스터 처치, 쿨타임(요청 반영), 도토리 상점, **9-슬라이스 방식**으로 잘라 만든 인터페이스 요소.
- 특히 인상적이었던 것은 **모션 품질** — 예전엔 어색했던 피격 모션·타격 액션 모션이 잘 만들어졌다([의견]). 일부 에셋이 잘려 어색한 부분은 인정. 자동 장착 기능은 없음.
- 총평: 웹 게임 = 웹 애플리케이션 하나를 만든 셈이고, **아이디어만 있으면 금방 만들 수 있겠다**([의견]).

### 화자가 체감한 질적 변화 — "화면을 진짜로 본다"
- 예전 모델은 수정 요청을 받으면 내부적으로 코드·텍스트를 짜고 텍스트 비교를 하는 식으로 동작했는데, 아스트라는 **화면을 본다.** 눈에 보이는 것 기반 작업이 더 매끄럽다([의견]).
- 사람이 하는 작업 순서(원문 관찰 → 스타일 계획 → 실행 → 자기 평가 → 메뉴 진입 수정)를 그대로 따라간다는 점을 반복해 강조.
- 속도가 결정적이다: 예전엔 "아휴 그냥 내가 하고 말지" 하고 포기하거나 프로그래밍으로 우회했는데, 이제는 **시켜 놓고 다른 작업을 하고 와도 되는** 수준. 화자는 PC 두 대로 한쪽은 바이브 코딩, 한쪽은 유튜브 슬라이드 초벌 작업을 돌리는 활용을 구상한다([의견]).
- 다만 "더 빨라지면 좋겠다"는 아쉬움은 계속 붙인다.

### 비용·한계·주의사항
- **커서 제어권을 빼앗기는 불편함**이 실사용의 큰 마찰. 자동화를 걸어 놓고도 제어권을 뺏기면 다른 작업을 못 한다. 코드팩토리 님이 소개한 `[불명확: 원문 "에고"]` 서비스를 대안으로 고려 중이나, 이번 시연은 순수 크롬 브라우저 기반으로 진행.
- **토큰 소모가 크다.** 컴퓨터 유즈는 화면을 보고 해석한 뒤 진행하므로 토큰을 더 쓸 것이라는 추정(화자 추정, 미검증). 실제로 주간 사용량 한도를 평소 안 쓰던 수준으로 소모했고, "얼마 쓰지도 않았는데 25% 썼다"고 [21:44] 언급.
- **사용 한도 초기화 크레딧**(`[불명확: 원문 "초기아이 초기권"]`)에는 **만료일**이 있으므로 미리미리 소진하는 것이 중요하다는 조언.
- 요금제 현실: 이 정도로 쓰려면 **20달러 요금제로는 불가능하고 100달러 또는 200달러 플랜**이 필요하다.

### 화자의 전망과 마무리
- 오픈AI의 지향은 **내가 원래 하던 업무 방식은 그대로 두고, 모델이 그 "행위"를 대신하게 만드는 것**으로 읽힌다([의견]).
- 컴퓨터 유즈가 잘 되면 **스레드(Threads)** 같은 SNS 운영도 자동화할 수 있겠다는 확장 가능성(`[불명확: 원문 "슬레드"]`). 다만 토큰 단가가 내려가야 한다는 단서.
- 오픈AI와 **앤트로픽**의 경쟁이 잘 붙어 유저에게 이점으로 남기를 바란다([의견]).
- 바이브 코딩·프로그래밍 성능 평가는 더 써 본 뒤로 미뤘고, 주목할 새 소식이 나오면 후속 영상을 찍겠다고 예고.

## 3줄 오리엔테이션
- 오픈AI가 신규 모델 **아스트라(Astra)**를 예상보다 빨리 공개했고, 토큰 가격을 경쟁 모델(클로드 페이블 5.1)과 동일하게 맞춘 것에서 노골적인 경쟁 의도가 읽힌다는 것이 화자의 출발점이다.
- 커뮤니티는 3D·게임 결과물에 열광하지만, 화자는 **컴퓨터 유즈(computer use)** 하나에 초점을 맞춰 "문서 옮기기"와 "피그마 슬라이드 만들기"라는 사무 업무 자동화를 실시간으로 시연한다.
- 결론은 성능보다 **속도**다. 예전엔 느려서 못 쓰던 컴퓨터 유즈가 3~5분대로 끝나면서 "그냥 시켜 놓고 딴 일 하면 되는" 영역에 들어왔다는 것. 대신 토큰을 많이 먹어 20달러 요금제로는 불가능하다는 단서를 단다.

## 전문 — 시간순 워크스루

### [00:00–01:03] 예상보다 빠른 공개, 그리고 이 영상의 성격
오픈AI가 아스트라 모델을 매우 빨리 공개했다. 화자는 "한 일주일 뒤면 나오겠다"는 것이 정설이라 생각하고 있었는데 당일 바로 풀린 것을 보고, 경쟁사 **페이블 5.1** 발표를 강하게 의식한 조치로 판단한다([의견]). 문서에 적힌 가격 설정에서도 페이블 5.1을 경쟁 타깃으로 두고 있음이 "노골적으로 느껴졌다"고 말한다.

당일 오전에 일어나 아이 밥을 먹이고 이것저것 테스트해 본 결과 느껴지는 특징이 있어 영상을 찍게 됐다고 밝힌다. 화자가 보는 에이전트의 방향성은 결국 **기본적인 사무 업무를 대신 해 주는 사무 자동화**이며, 오픈AI가 보고 있는 방향도 그쪽이라는 생각이 들었다([의견]). 커뮤니티는 3D 모델링 쪽을 많이 조명하지만, 자신은 일반적인 사무 업무를 시켜 보며 어느 수준까지 해 주는지, 자신은 어떤 방식으로 썼는지를 공유하겠다고 예고한다.

> "당연히 개인적인 테스트니까 여러분들이 생각하셨을 때 '이렇게 쓰면 안 되나요? 전 이게 더 좋던데요'라고 하면은 예, 그게 정답입니다." [01:00]

### [01:04–02:12] 문서·커뮤니티에서 얻은 다섯 가지 인상
화자가 문서와 커뮤니티에서 주워들은 내용을 다섯 가지로 정리한다(모두 화자가 전하는 인상·전언이며 미검증).

1. **문서·PPT 등 사무직 업무 자동화가 강화된 느낌.** 그렇게 될 수 있는 이유는 아스트라 모델이 **컴퓨터 유즈를 더 적극적으로 쓰는 경향**을 보이기 때문이다.
2. **왠지 모르게 더 빨라졌다.** 예전에 오픈AI가 "컴퓨터 유즈를 더 빠르게 하겠다"고 얘기했었는데 진짜로 빨라졌다.
3. **장기 작업을 시켰을 때 매우 잘한다** — 하네스가 강화됐음이 느껴진다.
4. **지난 컨텍스트 윈도우까지 참조**한다. 원래는 장기 작업 중 컨텍스트 윈도우가 압축되거나 새로 만들어지면 소실되는 게 많았는데, 아스트라로 넘어오면서 이전 컨텍스트까지 참조할 수 있는 형태로 하네스를 강화했다고 한다(출처는 화자도 "어디서 봤는지 기억이 안 난다"고 명시).
5. **가격이 페이블 5.1과 동일**하고 캐시 가격까지 맞췄다.

화자 자신은 엔지니어가 아니라서 4번은 문서로만 봤다고 선을 긋는다. 다만 직접 시켜 봤을 때, 예전에 어렵지 않게 만들어 둔 애플리케이션들의 개선 방안을 논의하고 "네가 끝까지 한번 드라이브해 봐라"라고 했을 때 매우 잘해 준다는 느낌을 받았다고 한다([의견]). 가격을 캐시까지 똑같이 맞춘 것에서는 "진짜로 너네 우리랑 부딪쳤을 때 맞다이 뜰 수 있냐" 같은 도발이 느껴지는 새로운 가격표라고 평한다([의견]).

### [02:13–02:57] 커뮤니티 분위기는 3D, 이 영상은 컴퓨터 유즈
현재 커뮤니티에서는 3D 모델링 쪽 성과 발표가 많다. 화자가 정보를 볼 때 자주 본다는 한 계정([불명확: 원문 "코이 오픈에 AI"])에서 "아스트라의 사용자 결과물이 쏟아지고 있다"며 사례를 모아 주고 있는데, **Three.js(3js)** 라이브러리 기반 3D 게임, 특이한 컨셉의 자기소개 포트폴리오 사이트, 블렌더 작업 등이 보인다. 전반적으로 3D 느낌이 나거나 애플리케이션 인터랙션에 볼륨감이 들어가는 작업을 훨씬 빨리, 잘 해 준다는 결과물들이 올라오고 있다.

화자는 그쪽 대신 **컴퓨터 유즈에 초점을 맞춰 리뷰하는 것이 오늘 영상의 핵심**이라고 못 박는다.

### [02:58–03:45] 가격표 뜯어보기 — 페이블과 정확히 동일
클로드 페이블은 컨텍스트 윈도우 100만 토큰에 입력 10달러 / 출력 50달러다. 아스트라도 동일하게 **10달러 / 50달러**이고, 캐시 라이트가 **12.5달러**인데 페이블도 12.5달러다. 화자는 페이블 쪽 가격표에서 "5분 캐시 쓰기 12.5달러, 한 시간 캐시 쓰기는 조금 더 비쌈" 구조를 짚으면서, 아스트라는 캐시 유지 시간에 따른 가격 차이를 두고 있지 않은 것 같다고 관찰한다(화자 본인도 확신 없이 "그런 것 같다"고 말함).

아스트라에는 **패스트 모드**가 별도로 있는데, 클로드 쪽은 기능으로는 있는 것으로 알지만 패스트 모드에 맞춘 가격제를 공개하지 않아 비교가 어렵다고 한다. 결론은 "가격이 굉장히 비슷하다" 정도로 정리한다.

### [03:45–05:13] 오픈AI 발표 문서 — 말로 시키는 그림판·블렌더·PPT
가격은 같지만 아스트라만의 독특한 방향성을 보여 주는 문서들이 있다며 오픈AI 발표 자료를 연다([불명확: 원문 "발표시 PT6"]). 오프닝 영상부터 "굉장히 노골적"인데, 핵심은 **말로 시켜서 작업을 시키는 것**이다. 그림판 작업을 음성 지시로 조작하고, 그림판 작업이 끝나면 블렌더로 옮겨 3D 모델링을 해 보라고 역시 말로 시킨다. 화면에 나타나는 **마우스 커서 표시**가 컴퓨터 유즈가 동작 중이라는 신호다. 파워포인트 작업도 말로 시킨다.

화자는 이 영상에서 힌트를 얻어 "얘네가 이쪽에 굉장히 집중했구나"를 느꼈고 그래서 오늘 같은 테스트를 하게 됐다고 설명한다. 문서의 성능 비교 항목들은 "좋다"는 홍보라며 빠르게 넘기고, 설계도에 맞춰 모델링해 실제 기판을 시뮬레이션했다는 사례, 애플리케이션 구현 사례를 언급한다. 특히 **소요 시간**을 강조하는 대목이 눈에 띈다고 짚는다 — "우리 좀 빨라요"를 강조하고 있다는 것.

또한 코딩만이 아니라 **서치 작업** 등 실제 사용자가 원하는 자동화 시나리오가 많다는 점을 강조하고 있고, 왼쪽에 예전에 만든 슬라이드(레퍼런스 파일)를 주면 오른쪽에 아스트라가 더 확장해서 만들어 준다는 예시도 있다. 코딩 관련 결과물([불명확: 원문 "익스필드"])에 대해서는 언급하지 않겠다고 한다.

> "코딩 이런 거는 이제 여러분들 뭐 워낙 상향 평준화 돼 있기 때문에 이거나 저거나 어 누렁소나 검정소나 잘합니다." [05:04]

### [05:13–05:57] 화자의 체감 — 화면을 진짜로 본다, 그리고 빠르다
사용 경험은 세 시간 남짓(영상을 찍으면서 두 시간 정도 더)이 전부라, "더 할 수 있는데 왜 저 사람 모르지"라는 반응이 나올 수 있음을 미리 인정한다. 그 범위 안에서 느낀 것은 두 가지다.

첫째, 문서에서 본 것처럼 **컴퓨터 유즈를 적극적으로 써서 자동화를 하려 한다.** 예전에는 뭘 수정해 달라고 하면 내부적으로 코드나 텍스트를 짜고 텍스트 비교를 하는 식으로 동작했는데, 아스트라는 **화면을 본다.** 진짜로 화면을 잘 보고, 눈에 보이는 것 기반 작업이 더 매끄럽게 느껴진다([의견]). 둘째, **엄청나게 빠른데 왜 빠른지는 모르겠다**고 솔직히 말한다.

### [05:57–07:07] 예고편 1 — 프라이싱 문서를 구글 독스로 복제
먼저 해 본 작업을 미리 보여 준다. 왼쪽은 웹 브라우저로 열어 둔 오픈AI 개발자 문서의 **모델 프라이싱 페이지**, 오른쪽은 **구글 독스**. 이 문서를 양식 그대로 옮겨 적어 보라고 시킨 것이 1회차다. 화자가 양식이 마음에 안 든다며 "좀 최대한 맞춰 봐"라고 했더니 다시 맞춰서 작업해 준 것이 2회차다.

여기서 흥미로운 지점: 구글 문서에는 **'페이지 있음'과 '페이지 없음' 옵션**이 있는데, 모델이 "페이지 안에서 작업하면 양식을 못 맞추겠다"고 스스로 판단해 커서를 움직여 메뉴를 눌러 **페이지 없음 모드로 전환**했다. 스탠더드·배치·플렉스·패스트 모드 같은 표 항목도 최대한 맞추려 노력했다. 예전에는 이런 작업이 1~2회차 수준에서 되지도 않았고 컴퓨터 유즈가 너무 느려 쓸 수 없을 정도였는데, 이 정도 작업이 **3~4분**밖에 안 걸렸다는 것이 화자가 강조하는 변화다.

### [07:07–07:41] 예고편 2 — 피그마를 직접 조작해 슬라이드 만들기
PPT 작업도 되나 싶어 독특한 방식으로 시켜 봤다. 슬라이드 스타일을 PNG 파일로 주고 **피그마 자체를 조작해서** 만들어 보라고 한 것이다. 화자는 컴퓨터 유즈의 의미를 "내 컴퓨터에 있는 애플리케이션을 쓴다는 것"이라고 정의한다. 실제로 원래 발표 자료를 그대로 복제해 문서 작업을 한 뒤, 그 문서 내용이 컨텍스트에 남아 있으니 이를 바탕으로 슬라이드를 만들어 보라고 했더니 만들어 줬다. 다만 슬라이드 위치가 다 틀어져 어디로 날아가는지 모르는 상태에서 화자가 중단시켰고, 뒤에서 정렬을 다시 맞춰 볼 것이라고 예고한다.

메뉴를 클릭하고 이동하고 살펴보는 과정이 매우 빠르게 보여 사용자 입장에서 좋다고 평가하며, 모션이 필요 없다면 굳이 [불명확: 원문 "하이퍼프레임즈"] 같은 도구 기반으로 슬라이드를 만들어야 하나 싶을 정도였다고 덧붙인다([의견]).

### [07:41–09:16] 예고편 3 — RPG 웹게임, 25~30분 만에
게임 만들기는 오래 걸려서 결과만 공유한다. 이 게임 작업에 **약 25분**(들어가는 에셋과 파일 작업 포함)이 걸렸다. 핵심은 화면 구성을 CSS 선 작업으로 끝낸 게 아니라, 화면 모서리 장식을 포함한 **에셋 이미지들도 전부 모델이 만들게 했다**는 점이다.

RPG 게임을 만들어 보라고 했더니 자동 사냥, 몬스터 처치가 돌아가고 "쿨타임이 있었으면 좋겠다" 같은 요청도 알아서 반영했다. 이어 **동물 컨셉**으로 다시 만들어 보라고 했더니 25~30분 정도에 매우 잘해 줬다(일부 에셋이 잘려 어색한 부분은 인정). 에셋 만드는 속도가 매우 빨라졌고, 인터페이스에 필요한 부분을 **9-슬라이스 방식**으로 잘라 구성해 보라는 요청도 잘 수행했다.

모션 품질에 대해서도 놀라움을 표한다 — 예전에는 모션을 구성하면 어색했는데, **피격 모션·타격 액션 모션**이 잘 만들어져 있어 신기했다는 것. 도토리 상점 같은 상점 구현도 모델이 알아서 했다. 다만 자동 장착 기능은 없다. 결론적으로 웹 게임 = 웹 애플리케이션 하나를 만든 셈이며, **아이디어만 있으면 금방 만들 수 있지 않겠냐**는 소감을 남긴다([의견]).

### [09:16–10:37] 본 실험 세팅과 프롬프트 전문
이제부터가 "진짜 도움이 될" 문서 쓰기와 PPT 작업이다. 화자가 상정한 상황은 **서치를 한 다음 서치한 내용을 문서화하는 일**이며, 그 흐름대로 시연한다. 오른쪽에 구글 독스를 열어 두지만 워드를 켜도 잘할 것 같다고 덧붙인다. 앞서 만든 문서는 지우고 처음부터 시작한다.

애플리케이션(챗GPT 앱)을 켜고 채팅을 연 뒤, **챗GPT 모드에서 코덱스 모드로 굳이 바꿀 필요 없이** 그 상태에서 **워크(work)** 로 들어간다. 그리고 다음과 같이 지시한다.

> "컴퓨터 유즈를 사용해서 웹브라우저 왼쪽에 있는 GPT 아스트라 소식을 오른쪽에 열려 있는 웹브라우저의 구글 독스에 최대한 양식을 살려서 옮기는 작업을 해보자. 이때 제출용으로 쓸 수 있도록 양식을 최대한 GPT 아스트라 소식에 맞추되, 문서 양식을 상의적으로(창의적으로) 네가 스스로 개선해서 보기 좋도록 만들어 보자." [10:01–10:29]

포인트는 **"컴퓨터 유즈를 쓰라"고 명시**하는 것이다.

### [10:37–11:26] 실행 초반 — 오르카가 아니라 챗GPT의 컴퓨터 유즈
모델이 "양쪽 브라우저의 내용을 확인하겠다"고 하며 컴퓨터 유즈를 실행하려 하는데, 화자가 예전에 설치해 둔 **오르카(Orca)** 를 실행하려는 정황이 보인다. 화자는 즉시 "오르카 말고 그냥 챗GPT의 컴퓨터 유즈 쓰면 돼"라고 교정 지시를 넣는다.

브라우저를 띄우면 화면 왼쪽에 **"봇이 보고 있다"는 표시**가 뜬다. 어느 브라우저를 봐야 할지 모르니 모델이 창을 이것저것 띄워 확인하는데, 다른 창에 띄워 둔 것을 제대로 찾아온다. 이후 양쪽 브라우저를 오가며 왼쪽 내용을 오른쪽으로 옮기기 시작한다.

### [11:26–12:10] 원문 파악과 스타일 계획 수립
왼쪽 내용을 빠르게 파악한 모델이 계획을 말로 서술한다 — 원문이 "짙은 우주색 배경의 큰 제목, 성능 그래프, 활용 사례를 배치한 것 같다"고 읽고, 문서에는 "남색·파란색 제목과 비교표로 그 분위기를 살리고 원문의 장 순서에 맞춰 한국어로 재구성하겠다"고 한다. 화자는 이것이 실제로 사람이 하는 작업 순서 그대로라고 평한다. 이어 컴퓨터 유즈 커서가 뜨면서 제목을 입력하기 시작한다.

### [12:10–13:26] 커서 제어권 문제와 1차 결과
작업이 진행되는 동안 화자는 **커서 제어권을 빼앗기는 불편함**을 지적한다. 자동화를 걸어 놓고도 제어권을 뺏기면 다른 작업을 못 하기 때문이다. 이 문제 때문에 코드팩토리 님이 소개했던 [불명확: 원문 "에고"]라는 서비스를 써 볼 생각이지만, 이번 시연은 순수하게 크롬 브라우저 기반 자동화로 그대로 두고 본다.

모델은 제목 설정 후 왼쪽 브라우저에서 내용을 파악해 한꺼번에 본문을 적고, 이어 **스스로 평가**를 진행한다(왼쪽을 오른쪽에 얼마나 똑같이 복제했는가). 화자는 지금 상태도 보기는 좋지만 레이아웃·배치가 동일하다고 보긴 어려워 "레이아웃과 배치를 좀 맞춰 보라"고 요청한다. 여기서 화자는 문서 옮기기 자체는 원래도 잘 됐지만 **컴퓨터 유즈를 쓰니 더 잘해 주는 느낌**이라는 점에 초점을 맞추고 있다고 다시 밝힌다. 예전에는 번역하고 어쩌고 했었는데 이제는 문서를 이렇게 옮긴 뒤 문서로 봐도 될 것 같다는 활용법도 제안한다([의견]).

> "테마랑 어 레이아웃 배치를 복제하는 느낌이 좀 있으면 좋겠는데" [13:15–13:23]

### [13:26–15:11] 페이지 설정·배경색·중앙 정렬 — 총 5분대
모델이 "보고서 느낌이 너무 강하니 원문의 짙은 우주색, 큰 제목, 넓은 여백, 파란색 성능 강조를 문서에 더 적극적으로 반영하겠다"고 답한다. 그리고 **스스로 페이지 설정 메뉴에 들어간다.** 페이지 색상을 먼저 바꾸고, 그에 맞춰 텍스트 색을 수정한다 — "배경을 검정으로 바꾸고 흰색 본문과 파란색 강조를 맞추고 있다"고 진행 상황을 보고한다. 이어 핵심 목차를 구성하고 본문을 원문처럼 배치하겠다고 한다.

화자는 소요 시간을 계속 추적한다. 첫 작업은 **3분 15초**, 이번 수정은 **2분 38초** 정도로, "거의 5분 만에 이런 문서를 만들었다"는 것이 요지다. 결과물에는 중간중간 별표 같은 것을 넣어 우주적인 느낌을 표현했고, 중앙 정렬 스타일도 맞췄다.

> "이제 문서 작업이 그냥 거의, 제가 봤을 때는 이 자동화를 한다라는 게 어디까지 왔는가를 좀 볼 수 있는 거 같습니다." [15:04–15:11]

### [15:11–16:31] 속도가 핵심 — "페이지가 뚝뚝 끊긴다"
화자가 강조하는 것은 **속도**다. 예전에는 컴퓨터 유즈를 쓰려다가 "아휴 그냥 내가 하고 말지" 하거나 다른 방법(프로그래밍)을 찾았는데, 이제 이 과정이 금방 된다는 것.

결과물에서 아쉬운 점으로 "페이지가 뚝뚝 끊긴다"를 지적하며, 모델이 이 표현을 이해할 수 있을지 실험한다. 스크롤을 쭉 내리면서 보는 게 좋다는 의미인데, 모델은 이를 이해하고 **연속 경계 레이아웃을 없애기 위해 페이지 설정 메뉴로 들어가 '페이지 없음'으로 전환**한다. 나아가 요청하지 않은 **텍스트 너비**까지 수정한다 — 원문의 너비가 적절히 보기 좋게 되어 있으니 이것도 중요하게 판단한 것 같다는 화자의 해석이다(무슨 옵션을 골랐는지는 화자도 확인 못 함).

여기서 화자는 일반 시청자용 활용 팁을 던진다 — 새로운 뉴스가 나오면 그냥 이런 식으로 문서로 복제해서 보라는 것([의견]).

### [16:31–17:21] 좌우 비교와 오픈AI의 방향성
좌우를 비교하니 복제 수준이 상당히 비슷해졌다고 평가한다. 화자는 이 지점에서 **오픈AI가 무엇을 지향하는지**를 묻는다. AI에게 아예 자동화 작업을 시키되, **내가 원래 하던 업무 방식은 그대로 두고 모델이 그 "행위"를 대신하도록** 맞추려는 것 같다는 해석이다([의견]).

문서를 내려가며 보면 앞부분 소개 부분부터 내용을 맞춰 준 것이 확인되는데, 모든 내용을 다 반영한 것 같지는 않고 새 보고서 양식으로 만드느라 일부 개선이 들어간 것 같다고 관찰한다.

### [17:21–18:20] 피그마 미션 — 내가 쓰는 슬라이드 타입을 보고 복제해라
문서 작업을 하다 보니 "이걸 피그마에도 자동화할 수 있겠는데"라는 생각이 들었고, 조사한 내용을 자기 슬라이드에 그냥 집어넣으면 되는 것 아니냐는 발상으로 이어진다. 지시는 이렇다.

> "지금 보고서 보기 좋아. 근데 피그마 앱 지금 펴놨거든. 이거 네가 이용해서 지금 빈 페이지 하나 있는데 거기에 내 슬라이드 타입 잘 보고 복제해서 발표 자료 좀 만들어 주면 안 돼. (…) 페이지에 보면 내가 즐겨 쓰는 슬라이드 타입이 있어." [17:23–17:42]

모델은 "피그마 페이지 1에서 자주 쓰는 슬라이드 스타일을 보겠다"며 바로 컴퓨터 유즈로 들어가, 커서로 화면을 훑으며 화자가 만들어 둔 발표 자료를 하나씩 본다. 화자는 이 과정을 "아 요런 거 좋아하는구나 하고 파악하는 중"이라고 중계한다.

### [18:20–19:31] 프레임 복제·겹침·분리로 씨름하는 구간
파악이 끝난 모델이 슬라이드를 복제하고 제목을 바꾸며 장표를 수정하기 시작한다(화자는 모델이 "장표"라는 개념을 이해할지 궁금해한다). 이미지도 모델이 직접 만들어 넣을 수 있으면 좋겠다는 바람을 덧붙이면서, 앞으로 자신이 슬라이드를 손으로 입력할 일이 있겠냐고 되묻는다. 시청자에게는 "제가 인공지능을 어디까지 써서 만들었는지 의심하면서 보면 재밌을 것"이라는 농담도 던진다.

속도에 대해서는 **더 빨라지면 좋겠지만 지금 수준으로도 충분히 좋다**는 평가다. 이 정도 속도면 시켜 놓고 잠깐 다른 작업을 하고 와도 되기 때문이다. 화자 본인은 PC가 두 대라 한쪽에서 바이브 코딩을 돌리고 다른 쪽에서 유튜브에 올릴 슬라이드 초벌 작업을 시켜 두면 편할 것 같다고 구상한다([의견]).

실제 진행에서는 프레임이 위아래로 왔다 갔다 하며 겹치는 문제가 발생한다. 모델은 프레임 붙여넣기 후 계층을 확인하고, 슬라이드가 한 장만 있는 상태를 이상하게 여기며 "복제한 다음 레이어 바깥으로 빼야지"라고 판단해 **분리 작업을 스스로 해낸다.** 화자는 "굳이 제가 이 작업을 시킬 필요가 없다"고 평한다.

### [19:31–20:22] 배치 정렬 요청과 내용 채우기
포지션을 수정해 슬라이드 위치를 붙여 주는데 위치가 이상해지자, 화자가 "새로 만들어지는 프레임을 순서대로 잘 이어서 보기 좋게 나열도 해 줘"라는 요청을 추가로 넣는다. 그러자 모델은 슬라이드를 하나씩 수정하며, 조사한 내용을 바탕으로 각 프레임을 파악하고 내용을 입력해 나간다.

화자는 여기서 시청자가 힌트를 많이 얻을 것이라고 말한다 — 피그마로 무언가를 만드는 사람이라면 **이미 만들어 둔 것을 그대로 이용해 모델에게 시키면 잘하겠구나**라는 발상이다. 화자 본인은 목록 형식 장표를 쓰기 때문에 모델이 그 형식에 맞춰 내용을 채워 준다. 속도만 조금 더 빨라지면 좋겠다는 단서를 다시 붙인다.

### [20:22–21:10] 토큰 사용량과 "초기화 크레딧 만료일"
화자가 초점을 맞춘 것은 컴퓨터 유즈 쪽이고, 바이브 코딩·프로그래밍 쪽은 더 써 보고 말하겠다며 미룬다. 대신 재미있는 관찰을 하나 공유한다 — **사용량을 많이 쓰고 있다**는 것. 주간 사용량 한도를 이렇게 많이 쓴 적이 없는데, 컴퓨터 유즈를 쓰면 화면을 보고 해석한 뒤 진행하기 때문에 토큰을 더 많이 쓸 것 같다는 추정이다(화자 추정, 미검증).

그래서 **사용 한도 초기화 크레딧**([불명확: 원문 "초기아이 초기권"])을 영리하게 써야 한다고 조언한다. 이 초기화 크레딧에는 **만료일**이 있으므로, 그 점을 감안해 미리미리 소진하는 것이 중요하다는 것이다.

### [21:10–21:55] 프레임 정리와 자동화 확장 가능성, 그리고 토큰 값
슬라이드가 세 장쯤 만들어졌는데 어디에 있는지 모를 정도로 피그마 캔버스가 광활해, "새로 만들어지는 프레임을 순서대로 이어서 보기 좋게 정리하라"고 시킨다. 모델이 구석구석에서 만든 것을 찾아 이동시키며 **배치 작업까지 해 준다.** 화자는 처음부터 이쪽에 배치해 놓고 수정하라고 했어도 됐을 것 같다고 회고하면서, 어쨌든 이런 식으로 자동화 작업이 된다고 정리한다.

컴퓨터 유즈가 잘 되니 확장 가능성도 언급한다 — 시청자들이 관심 있어 하는 **스레드(Threads)** 같은 것도([불명확: 원문 "슬레드"]) 다 자동화할 수 있겠다는 것. 다만 토큰이 더 싸지면 좋겠는데 지금은 비싸다는 단서를 단다.

> "제가 지금 뭐 얼마 쓰지도 않았는데 뭐 한 25% 쓴 거 보니까 더럽게 많이 쓰긴 해요." [21:44–21:48]

### [21:55–22:25] 마무리 — 경쟁이 유저에게 이점이 되기를
그래도 이 정도면 자동화 업무에서 편해지는 것들이 몇 가지는 생길 것 같다는 것이 화자의 평가다. 오픈AI와 **앤트로픽**이 계속 경쟁하고 있는데, 그 경쟁이 잘 붙어 유저에게 이점으로 남는 부분이 있었으면 좋겠다는 바람을 덧붙인다([의견]).

현실적인 단서도 명확히 붙인다 — **이 정도로 쓰려면 일반적인 20달러 요금제로는 불가능하고 100달러나 200달러 플랜을 써야 한다.** 마지막으로 주목할 만한 새 소식이 나오면 영상을 추가로 찍겠다, 일반적인 사용 방법이 궁금할 테니 참고가 될 만한 것들을 계속 올리겠다고 예고하며 마무리한다.
