## 요약 (주제별)

### Paseo란 무엇인가 — 위치와 정의
- Paseo는 **에이전트 도구 중 하나**로, 이미 구독 중인 Claude·Codex(ChatGPT) 같은 것을 꽂아 **껍데기만 바꿔 보기 좋게 쓰는 도구**다([01:26~]). 자체 모델을 파는 게 아니라 기존 **구독을 공유하는 시스템**([05:53]).
- 인터페이스는 직관적이며 폴더 지정란과 **호스트(PC) 지정 드롭다운**이 핵심 축. 모델·추론(사고)·권한·속도가 전부 버튼으로 제공된다.
- 사람들이 Orca/Paseo/Warp 같은 GUI를 쓰는 이유: ① 모바일 연결 등 부가 기능, ② PC 간 호스트 연결, ③ [의견] "터미널에서만 쓰자니 좀 역하다"는 정서적 이유([02:23]).

### Orca → Paseo 이동 이유 (화자 [의견])
- 이전 소개 때는 "Orca로도 충분할 것 같다"고 했으나, 써 보니 Orca가 **개인적으로 되게 무겁다**고 느꼈고 무거운 도구를 굳이 계속 쓸 필요는 없다고 판단.
- Paseo는 **가볍고 라이트**하며 자신에게 필요한 기능이 다 있어 갈아탔다. 특히 **호스트 연결 기능이 좋아서** 넘어왔다고 재차 밝힘([18:43~]).

### 윈도우 설치 — 순서가 전부 (칠판 정리, [07:33~])
1. **Claude Code 또는 Codex 설치**
2. **계정 로그인 완료**
3. **Git 설치 완료**
4. **Paseo 설치**
- 이 순서를 지켜야 매끄럽다. 화자 본인이 Paseo부터 먼저 설치했다가 **모델 선택에서 오류**가 났고(자막상 오류명 [불명확]), Paseo를 껐다 켜서 해결([08:52~]).
- Claude Code: 공식 문서 **Advanced setup**에서 Windows PowerShell 명령어 복사 → PowerShell 붙여넣기 실행. 설치 후 "native installation exists" 안내가 나오면 **환경 변수(PATH)에 설치 경로를 등록**하고 PowerShell을 껐다 켜야 `claude`가 동작한다([05:12~]).
- Codex: "Codex CLI install" 검색 → **Install Codex** → PowerShell 명령어 동일 방식.
- **Git 미설치 시 아예 진행이 안 된다** — "필수 중의 필수". Windows 탭에서 받아 Next만 누르면 됨.
- 설치 파일 다운로드 시 브라우저 경고가 뜨는데 화자는 "유지"를 눌러 진행하며 위험하지 않다고 함(화자 주장).
- macOS 설치는 파일 받아 **드래그 앤 드롭**뿐, 나머지는 동일([18:37~]).

### 기본 사용법 — 폴더·모델·권한 설정
- Claude Code/Codex는 **작업 폴더 중심**이라 Paseo에서도 `Browse(프로젝트 추가)`로 폴더를 지정해야 한다. 바탕화면에 `Paseo Study 01` 같은 **빈 폴더**를 만들고, **폴더명에 한글은 웬만하면 쓰지 말 것**.
- 설정 → **호스트**는 "지금 Paseo가 실행 중인 PC"에 대한 설정이며, 그 안 **에이전트 옵션**으로 이 PC에 깔린 에이전트를 관리한다.
- 설정 → **프로바이더**에서 안 쓰는 것은 전부 비활성화, Cursor·Gemini 등 쓰는 것만 추가하면 채팅창에서 바로 쓸 수 있다(화자는 macOS에서 Cursor를 추가).
- 실행 옵션: **사고 모드는 보통 high**, 권한은 오토 대신 **바이패스 모드**(확인 질문 없이 전권 위임), **번개 모드(빠른 실행)는 토큰을 1.5~2배 쓰기 때문에 권장하지 않음**(수치는 화자 주장, 미검증).

### Paseo 부가 기능
- **사이드 패널 파일 탐색기**: 지정 폴더 내부 파일을 Paseo 안에서 확인. 단 **새로고침을 눌러야** 새로 생성된 파일이 보이는 경우가 있음.
- **MD 뷰어**: 파일 클릭만으로 마크다운을 렌더링 미리보기/소스 전환해 볼 수 있음.
- **내장 브라우저 + 요소 주석(마우스 커서 버튼)**: 브라우징 화면에서 특정 요소를 찍어 "여기를 수정해 줘"라고 채팅에 첨부. [의견] Orca에서 좋아하던 기능과 동일.
- **Paseo 도구 활성화 → 일정 관리**: 몇 시 몇 분에 PC가 켜져 있으면 명령을 실행하는 방식. Claude의 "예정됨"과 완전히 동일하고, 원래 **크론잡**으로 되던 일을 좀 더 편하게 해 주는 정도([의견] "특별한 건 아니다").
- **오케스트레이션 스킬**: Orca에 있던 것과 동일. 에이전트 하나를 중심에 두고 다른 에이전트를 조율 — 예) Claude는 이미지 생성 도구가 없으니 "Codex 쪽에 부탁해 이미지 에셋을 받아오라"고 시키면 조율해서 가져온다. [의견] "스킬도 뭐 이렇게 대단한 건 아니라고 생각".
- **사용량 화면**: Claude·Codex·Cursor 등 사용량을 한꺼번에 볼 수 있는 점을 좋게 평가([의견]).

### 호스트 연결 (PC↔PC) — 이 영상의 킥
- 개념: 집에 켜 둔 맥미니의 Paseo를 밖의/다른 PC의 Paseo에서 그대로 조작. "PC 다른 쪽에 있는 에이전트를 우리가 부릴 수 있다. 이게 핵심"([03:20]).
- 절차: ① **양쪽에 Paseo 설치** → ② 호스트가 될 쪽에서 설정 → **기기 페어링** → 페어링 링크 생성 → ③ 붙을 쪽에서 **Host → Add Host** → 링크 붙여넣기 → 페어링.
- **페어링 링크는 비밀번호처럼 취급**하라고 앱이 안내한다([13:20]).
- 링크를 준 쪽이 **주인(호스트)**, 붙는 쪽이 **클라이언트**. Paseo는 이 연결들을 관리하는 **중앙 관리자 역할**.
- 붙는 즉시 상대 쪽 **프로젝트 폴더·작업 상태·채팅 기록이 전부 공유**되고, 실행되는 Claude Code는 맥미니에 있는 그것이다. 한쪽에서 지우면 다른 쪽에서도 지워지고, 탭을 끄면 저쪽 탭도 꺼진다.
- 결과적으로 **윈도우 화면에서 macOS를 쓰는 것처럼** 여러 OS·여러 PC를 한 화면에서 조작하는 상태가 된다.

### 모바일 연결
- 모바일에 Paseo를 설치하고, 호스트 쪽 설정 → 기기 페어링에서 뜬 **QR코드를 스캔**하면 끝(링크 대신 QR).
- 페어링 즉시 맥미니의 채팅 기록이 모바일에 그대로 보이고, 모바일에서 보낸 채팅이 맥미니 세션에 바로 들어간다. 관점은 "**켜져 있는 세션에 채팅을 날려 주는 역할**"([17:25]).
- 화자는 최근 안드로이드(갤럭시 폴드 계열)로 바꿨고, 모바일 화면 미러링(퀵타임)에 실패해 **구글 Meet로 급히 우회**해 시연했다([15:03~16:20]).

### 한계·주의 (화자가 직접 인정한 것)
- **윈도우는 각종 버그가 있어 안 될 수 있고, 에이전트 쓰는 환경으로는 그렇게 추천하지 않는다**([의견], [07:07~]). 그럼에도 윈도우 유저가 있으니 설치를 도와주는 것이라는 입장.
- 모바일은 **반응이 살짝 느리고**, **텍스트 지우기가 잘 안 되는** 문제가 있음 — 개발사가 고쳐야 할 부분([의견]).
- 설치 순서를 어기면 인증이 꼬여 모델 목록이 안 뜨는 실제 사례가 영상 중 발생.
- 사이드 패널은 새로고침을 안 하면 파일이 안 보이는 일이 있음.

### 채널 근황 (본론 외)
- 8월 말 강의가 많았고 **허리 이슈**로 영상 업로드가 중단됐었으며, 유튜브 운영 방침을 고민하며 쉬었다고 밝힘. 그동안 게시판으로만 소통.
- [의견] "영상 되게 쉽게 올린다고 생각하시지만… 사실 영상 찍는 데 시간이 굉장히 많이 든다"([00:24]).
- 원래 macOS 유저용으로 기획했으나 **Paseo가 윈도우도 지원한다는 걸 촬영 중 확인**하고 제목을 윈도우 포함으로 수정했다고 현장에서 언급.

## 3줄 오리엔테이션
- Paseo(파세오)는 이미 구독 중인 에이전트(Claude Code, Codex 등)를 "껍데기만 바꿔" 보기 좋게 쓰는 가벼운 GUI 도구이고, 화자는 Orca가 무겁다고 느껴 Paseo로 옮겨 왔다([의견]).
- 윈도우 설치는 순서가 전부다 — Claude Code 또는 Codex 설치 → 계정 로그인 → Git 설치 → 그다음 Paseo. 순서를 어기면 모델 목록이 안 뜨는 등 인증 문제가 생긴다.
- Paseo의 킥은 "호스트 연결"로, 페어링 링크(또는 QR)만 붙여 넣으면 집의 맥미니 세션을 윈도우 PC에서도 모바일에서도 그대로 이어 받아 조작할 수 있다.

## 전문 — 시간순 워크스루

### [00:00–00:33] 오랜만의 인사 — 영상 공백의 이유
화자는 오랜만이라며, 8월 말쯤 강의가 굉장히 많았고 거기에 허리 이슈까지 겹쳐 영상을 못 올리고 있었다고 밝힌다. 그동안 유튜브 운영 방침 등을 고민하면서 잘 쉬고 왔고, 쉬는 중에도 어떻게든 연락은 드리고 싶어 게시판 글만 줄줄이 올렸다며 기다려 준 사람들에게 감사를 전한다. 아무것도 안 한 건 아니고 하는 일은 많았는데 영상을 못 찍었을 뿐이라고 한다.

> "여러분들은 제가 영상 되게 쉽게 쉽게 올린다라고 생각하시지만 제가 뭐 표현만 그렇게 안 하지 사실 영상 찍는데 시간이 굉장히 많이 들어요." [00:24]

### [00:33–01:02] 오늘 주제 — Paseo 입문 가이드, 그리고 Orca를 떠난 이유
오늘은 macOS 유저를 위한 Paseo 입문 가이드를 준비했다고 말한다. 이전에 Paseo를 한 번 소개했을 때는 "Orca로도 충분할 것 같다"고 말했지만, Orca는 쓰다 보니 개인적으로 **되게 무겁다**는 생각이 많이 들었고 무거운 도구를 굳이 계속 쓸 필요는 없겠다는 판단이 들어 Paseo를 건드려 봤다고 한다([의견]). 대충 알아보니 Paseo는 가볍고 라이트한 툴인 데다 자신에게 필요한 기능이 다 있어서, 지금은 Paseo를 설치해 쓰고 있다고 밝힌다. 설치부터 처음 하는 사람이 굉장히 많을 것이라 아예 설치부터 생으로 진행하겠다고 예고한다.

### [01:02–01:26] 윈도우 지원 확인 — 제목을 그 자리에서 수정
"윈도우 유저는 왜 무시하냐"는 반응을 의식해, 자신은 항상 윈도우 유저도 고려해 준비한다고 말한다. Paseo를 검색해 설치 페이지에 들어가 보니 **윈도우 버전도 제공**하고 있어서, 윈도우 버전도 같이 설치해 보겠다고 한다(어차피 설치 과정은 동일하다는 이유). 원래 윈도우 지원을 안 하는 줄 알았는데 다 지원하니 영상 제목을 "윈도우, macOS 유저를 위한 Paseo 입문 가이드"로 수정하겠다고 현장에서 말한다([01:44] 부근에서도 재언급).

### [01:26–01:43] Paseo가 무엇인가 — 구독제 에이전트의 껍데기
Paseo가 뭔지 아직 궁금한 사람을 위해, 그냥 **에이전트 도구 중 하나**라고 정의한다. 사용자가 이미 구독제로 쓰고 있는 Claude나 Codex(ChatGPT) 같은 것들을 꽂아서, **껍데기만 바꿔 보기 좋게 쓰는 도구**라고 보면 된다는 설명이다.

### [01:43–02:13] 이런 도구를 쓰는 이유 (1) — 모바일 연결과 PC 간 호스트 연결
이런 도구를 쓰는 사람들은 보통 앱이 제공하는 추가 기능을 노린다고 말한다. 예를 들어 모바일을 붙일 수 있는 편의 기능, 그리고 오늘 다룰 **PC 간 호스트 연결**이 그것이다. 호스트 연결이 뭐냐면, 집에 맥미니를 인터넷에 꽂아 따로 운영하면서 항상 켜 두는 사람이 밖에 나와서도 그 PC에서 뭔가 작업하고 싶을 때가 있는데, 그럴 때 Paseo로 호스트를 붙이는 게 굉장히 쉽다는 것. 화자는 이게 편리해서 이쪽으로 넘어왔다고 말한다([의견]).

### [02:13–02:47] 이런 도구를 쓰는 이유 (2) — 터미널만 쓰기 싫은 욕구
Orca든 Paseo든 [불명확: 원문 "시스"]든 Warp든, 이런 걸 왜 쓰냐고 되묻는다. 코드 인터페이스가 제공하는 화면을 **터미널에서만 쓰자니 좀 역하다**는 것이고, 그래서 덜 역한 프로그램을 쓰고 싶은 욕구가 계속 있는 것 같다고 말한다([의견]). 입문한 사람이 많으니 그 요구는 당연히 있고, 터미널을 벗어나 다양한 도구를 같이 써 보고 싶은 사람에게 Paseo가 굉장히 좋아 보인다고 한다. 자신은 집에서 맥미니 서버를 따로 운용 중이라, 오늘은 그 맥미니 서버 상황도 보여 주면서 Paseo를 붙이는 방법까지 소개하겠다고 예고한다.

### [02:47–03:32] 인터페이스 미리보기 — 폴더 지정과 호스트 드롭다운이 핵심
Paseo는 인터페이스가 굉장히 직관적이라고 말한다. 사용자들이 아는 [불명확: 원문 "HJPT 문법"]으로 돼 있는 인터페이스이며, 폴더를 지정하는 곳이 있고 특이하게 **호스트(PC)를 지정할 수 있는** 자리가 있다. 이게 무슨 말이냐면, 지금 쓰고 있는 맥스튜디오에서 Paseo를 켜 두고, 맥미니에도 Paseo를 설치해 활성화한 뒤 화면만 꺼 두면, 맥스튜디오의 Paseo에서 **PC 드롭다운만 바꿔** 맥미니의 Paseo를 조작해 에이전트를 부릴 수 있다는 것이다.

> "PC를 다른 쪽에 있는 에이전트를 우리가 부릴 수 있다. 이게 핵심이라고 보시면 될 것 같습니다." [03:20]

모델 지정, 추론(사고) 지정, 권한 지정, 속도 지정이 전부 버튼으로 되는 점도 편하다고 덧붙이고, 호스트 설정이 킥이지만 그건 설치 이후에 진행하겠다고 미룬다.

### [03:32–04:11] 윈도우에 Paseo 설치 — 다운로드와 브라우저 경고
설치는 크롬이든 윈도우든 동일하다고 보지만 윈도우 유저가 많으니 윈도우에서 먼저 진행하겠다고 한다. 다운로드(Windows)를 누르면 Paseo 셋업 파일을 받게 되는데, 브라우저가 신뢰 어쩌고 하며 경고를 띄울 것이라 안내한다. 화자는 이를 안전한 것으로 보고 "유지"를 눌러 계속 진행해 설치를 완료하며, **절대 위험한 프로그램이 아니라고** 말한다(주장). 설치는 그냥 "다음"만 눌러 기본 설치로 진행하면 되고 별로 어려울 게 없다고 한다.

### [04:11–05:00] 중요한 선행 조건 — 에이전트가 먼저 깔려 있어야 한다
설치할 때 중요한 게 하나 있다며, 쓰려는 **인공지능 도구(에이전트)가 미리 설치돼 있어야 한다**고 강조한다. 자기 윈도우 PC에는 Claude가 설치돼 있지 않은 것 같다며 확인 후 설치를 같이 해 보자고 한다. Paseo 설치는 완료됐고, 윈도우에서 완전히 처음부터 진행한다는 가정으로 Claude부터 쭉 설치한다. Claude Code 설치는 "Claude Code install"로 검색해 들어가 **Advanced setup**에서 윈도우 PowerShell용 명령어를 복사한 뒤, PowerShell에 붙여 넣고 엔터를 눌러 설치하면 된다고 안내한다.

### [05:00–05:36] 윈도우 환경 변수(PATH) 설정
오늘 작업이 길 것이라고 예고하면서, 기본 세팅 후 모바일까지 다룰 것이고 자신은 최근 안드로이드 폰(**갤럭시 폴드 계열**, 자막 표기 흔들림)으로 바꿨는데 상당히 괜찮다고 곁들인다. 설치 후 셋업 노트에 "native installation exists" 류의 안내가 나오는데, 이는 설치는 됐지만 **설치 위치를 윈도우가 모르고 있다**는 뜻이므로 안내된 경로를 그대로 복사해야 한다고 설명한다. 윈도우에서 "환경 변수"를 검색해 설치 위치를 윈도우에 알려 주는 방식으로 붙여 넣고 확인하면 Claude Code가 요구하는 사항을 다 맞춘 것이며, 그다음 **PowerShell을 껐다 켜서** `claude`를 입력하면 정상 실행되는 걸 볼 수 있다고 한다.

### [05:36–06:11] Claude 구독 로그인 — Paseo는 구독을 공유하는 시스템
화자는 구독제 로그인까지 마치고 진행하겠다며, 링크가 나오면 Ctrl+클릭으로 로그인 화면에 진입해 쓰는 Claude Code 계정으로 로그인하라고 안내한다. **Paseo는 (기존 도구의) 구독을 공유하는 시스템**이기 때문에, PC에 미리 Claude를 설치하고 로그인해 두는 것을 권장한다고 말한다. 마음이 급해 Paseo부터 설치하면 연결 과정을 다시 거쳐야 하니 미리 Claude Code 설치를 진행하라는 것.

### [06:11–06:48] 인증 완료, 그리고 Codex CLI 설치
인증 코드를 붙여 넣고 엔터를 누르면 "Login successful"이 뜨며 Claude Code가 실행되고, 실행 확인 후 종료한다. Codex도 마찬가지라며 "Codex CLI install"로 검색해 나오는 화면에서 **Install Codex**를 누르면 명령어가 나오고, PowerShell 명령어를 복사해 동일하게 실행하면 된다고 시연한다. Codex는 별다른 내용 없이 잘 설치된다고 말한다.

### [06:48–07:33] Git 설치는 필수 — 그리고 윈도우 환경에 대한 경고
윈도우에서 처음 에이전트를 쓰는 사람이 깜짝 놀라는 게 하나 있는데, **Git을 설치하지 않으면 진행이 안 된다**는 점이라고 짚는다. 그래서 Codex 세팅 후 Git 설치도 같이 진행하겠다고 한다. 여기서 화자는 미리 말해 두는데, 윈도우는 각종 버그가 있어서 안 될 수가 있고 사실 **에이전트를 쓰는 환경으로 그렇게 추천하지는 않는다**고 밝힌다([의견]). 그래도 윈도우 쓰는 사람이 있으니 설치를 도와주는 것이라며, Git도 검색해 Windows 탭에서 다운로드하고 Next만 눌러 설치하면 문제없이 진행된다고 안내한다. Git은 "필수 중의 필수"라 반드시 설치해야 한다고 강조한다.

### [07:33–07:57] 정리 — 윈도우 설치 조건 4단계 (칠판)
여기까지 한 것을 화이트보드("칠판")를 켜서 순서대로 정리한다. 윈도우 설치 조건은 ① **Claude Code 또는 Codex 설치** → ② **계정 로그인 완료** → ③ **Git 설치 완료** → ④ **Paseo 설치**. 이 순서대로 해야 매끄럽게 설치를 진행할 수 있다고 못 박는다. 릴리즈 노트 보기 창은 끄고 Finish를 누른다.

### [07:57–08:11] Paseo 첫 실행 — 오프닝 화면
설치와 로그인이 다 끝난 상태에서 Paseo를 실행하면 아주 심플한 오프닝 화면이 나온다고 하며, 여기서부터 인터페이스를 하나씩 살펴보겠다고 한다.

### [08:11–08:52] 작업 폴더 지정 — Paseo Study 01 만들기
에이전트를 쓰는 사람은 다 알겠지만 Claude Code와 Codex는 기본적으로 **폴더를 지정해야** 그 폴더 중심으로 작업을 시작한다고 설명한다. Claude Desktop처럼 켜자마자 채팅창에 냅다 채팅하는 방식이 아니라 작업 폴더를 정해 줘야 하므로, 빈 폴더를 하나 만들면 된다는 것. Paseo의 **Browse(프로젝트 추가)**는 Paseo가 관리할 폴더를 추가하겠다는 뜻이므로, Browse를 눌러 파인더/탐색기가 뜨면 원하는 위치(보통 바탕화면)에 `Paseo Study 01` 같은 폴더를 하나 만들라고 안내한다. **폴더명을 한글로는 웬만하면 만들지 말라**고 덧붙인다. 폴더를 선택하면 그 폴더에서 작업할 준비가 된다.

### [08:52–09:21] 모델 선택 오류 — 순서를 어긴 대가, 껐다 켜기
모델 선택을 누르면 오류 표시가 뜨는데([불명확: 자막 원문 "오류 5오류"]), 이게 바로 **로그인을 한 다음에 Paseo를 설치해야 하는데 자신이 Paseo부터 냅다 설치해서** 생긴 문제라고 설명한다. 껐다 켜면 인증이 깔끔하게 끝난 상태에서 다시 로딩해 줄 것이라며, 이런 경우 Paseo를 껐다 켜 보면 된다고 안내한다. 다시 켜면 빈 폴더인 Paseo Study가 남아 있고, 그 상태에서 `+`를 눌러 모델을 선택하면 Claude와 Codex가 로그인돼 있으므로 모델 선택 화면이 정상적으로 나온다.

### [09:21–10:08] 설정 → 호스트와 프로바이더
설정으로 넘어가면 메뉴가 엄청나게 많은데, 봐야 하는 건 **호스트**라고 짚는다. 호스트란 **지금 Paseo가 실행되고 있는 PC**에 대한 이야기이므로, 지금은 이 윈도우 PC에 대한 설정을 하는 것이다. 여기에 **에이전트 옵션**이 있어 이 PC에 설치된 에이전트를 관리할 수 있다. 모델이 보이는 곳을 찾아 메뉴를 하나씩 눌러 보다가 **프로바이더(Provider)** 항목을 찾아내고, 프로바이더는 모델을 공급하는 곳이라 그렇게 이름이 붙은 것 같다고 말한다. 여기서 **쓰지 않을 것은 다 비활성화**하고, Cursor를 쓰면 Cursor를 추가해 채팅창에서 쓸 수 있으며 Gemini를 쓰면 Gemini를 추가하면 된다고 안내한다. 자신은 일단 두 가지(Claude·Codex)만 가지고 진행한다.

### [10:08–10:36] 모델·사고 모드·바이패스 모드·번개 모드
프로바이더 설정이 끝나면 모델 선택에서 쓰는 모델들이 나오고, 원하는 모델을 고른 뒤 **사고 모드는 보통 high를 많이 쓴다**고 말한다. 권한은 오토 모드 말고 **바이패스 모드**를 쓰는데, Claude Code 실행 시 자꾸 "할까요, 말까요?"를 묻지 않게 하는 것이 바이패스 모드이며 이걸 켜면 **모든 전권을 에이전트에게 주게 된다**고 설명한다. **번개 모드**는 빨리 실행/느리게 실행을 고르는 것인데, 빨리 실행은 보통 **토큰을 1.5배에서 두 배까지** 쓰기 때문에 그렇게 권장하지는 않는다고 한다(수치는 화자 주장, 미검증).

### [10:36–11:31] 채팅 테스트와 사이드 패널 파일 탐색기
현재 Paseo Study 01 폴더에서 작업이 진행되고 있으므로 "하이", "일기 아무거나 써 봐" 같은 걸 시키면 파일도 만든다고 시연한다. 보통 만들어진 파일을 보려면 파일 탐색기로 바탕화면을 타고 들어가야 하는데, 오른쪽 위의 **사이드 패널 토글**을 누르면 그 폴더 안의 파일들을 보여 주는 파일 탐색기를 Paseo가 제공한다고 소개한다. "파일로 저장할까요?"에 "해라"고 답해 저장시키고, 오른쪽에서 **새로고침**을 눌러야 저장된 파일이 보인다고 알려 준다(새로고침을 안 하면 안 보이는 일도 있었다고 함). 결과적으로 Paseo Study 01 폴더 아래에 다이어리 폴더가 만들어지고 그 안에 파일이 생성된다.

### [11:31–12:20] MD 렌더링과 내장 브라우저·요소 주석 기능
만들어진 파일은 클릭만 하면 Paseo 안에서 MD 파일로 볼 수 있고, 미리 보기를 하면 예쁘게 렌더링되며 소스로 보면 원래 마크다운 형태가 보인다고 시연한다([의견] "저는 이걸 이쁘다라고 하는데"). 다시 `+`를 누르면 **Paseo 내부에 자체 브라우저**도 있어 브라우징을 진행할 수 있는데, 브라우징이 된다는 건 곧 그 화면을 두고 에이전트에게 작업을 시킬 수 있다는 뜻이라고 설명한다. **요소에 주석 달기(마우스 커서 버튼)**를 짚으며, 이건 Orca에서 좋아했던 기능 — 사이트를 바이브 코딩한 뒤 특정 부분을 지정해 "여기를 수정해 줘"라고 메시지를 보내는 그것 — 과 같다고 말한다. 요소를 첨부하면 그 내용이 채팅창으로 그대로 들어간다. 오늘은 웹사이트 전용 영상이 아니라 기본 설정·입문 가이드이므로 이 정도로만 간단히 설명하겠다고 한다.

### [12:20–13:33] 호스트 연결 준비 — 기기 페어링 링크는 비밀번호처럼
Paseo에서 주로 쓰는 인터페이스(기본 채팅창, 모델 설정, 웹 브라우저, 에이전트, 파일 수정 내용 보기)는 다 설명했다고 정리한 뒤, 아직 이야기하지 않은 하나 — **원격 PC의 Paseo를 지금 윈도우의 Paseo와 붙이는 법** — 으로 넘어간다. 화자는 맥미니를 켜 둔 상태이고 **크롬 원격 데스크톱**으로 맥미니에 붙어 있는 상태라며 화면을 공유한다. 맥미니에도 동일하게 Paseo를 실행해 둔 상태이고, 이 맥미니 호스트와 윈도우 호스트를 붙일 수 있으면 굉장히 편리하겠다는 것이 동기다. 양쪽에 Paseo가 설치돼 있어야 하며, 설정의 **기기 페어링**을 누르면 Paseo 링크가 하나 나온다. 이 **페어링 링크는 비밀번호처럼 취급하라고 안내돼 있다**고 짚는다. 모바일로 연결할 거면 모바일에 Paseo를 설치하고 **QR코드를 찍고**, PC에서 붙을 거면 **이 링크를 복사**하면 된다.

### [13:33–14:16] 윈도우에서 Add Host — 붙자마자 프로젝트와 작업 상태가 공유됨
윈도우로 돌아와, 서버처럼 생긴 **호스트 버튼**을 누르면 **Add Host**로 호스트를 추가할 수 있다고 안내한다. 여기에 페어링 링크를 붙여 넣고 페어링을 누르면 Paseo가 자동으로 붙으면서 인터넷 연결 상태를 보여 준다. 그 즉시 **상대방(맥미니)에 있던 프로젝트 폴더가 벌써 보이기 시작한다**. 맥미니 Paseo에서 딱 하나의 폴더를 열어 작업 중이었는데 윈도우 쪽에도 그게 보이고, **작업 상태도 동일하게 공유**되어 맥미니에서 개발 서버를 재시작한 그 채팅 내용까지 완벽하게 공유된다고 시연한다.

### [14:16–15:03] 맥미니의 Claude Code를 윈도우에서 실행 — 양방향 채팅 공유
이때부터 할 수 있는 일은, 윈도우를 쓰고 있지만 맥미니의 Paseo와 호스트 연결이 됐기 때문에 **윈도우 화면에서 macOS를 쓰는 것처럼** 작업하는 것이라고 정리한다. Claude Code를 누르면 실행되는데, 이 Claude Code는 **맥미니에 있는 Claude Code**다. 채팅창은 서로 공유되므로 여기서 "하이"라고 인사하면 저쪽에도 기록이 남는다며 시연하고(처음엔 안 보이다가 이내 반영), 이런 방식으로 Paseo는 호스트 세션들을 간단히 연결해 **여러 OS·여러 PC를 화면 한 군데서 다 조작할 수 있는 상태**를 만들어 준다고 요약한다.

### [15:03–16:20] 모바일 시연 — 화면 미러링 실패와 우회
이번엔 쓰고 있는 갤럭시(폴드)에서도 그 작업이 되는지 같이 보겠다며, 화면이 바로 공유될지 모르겠다고 하면서 **퀵타임 플레이어**로 갤럭시 화면 공유를 시도한다. 잘 되지 않아 "안 되면 캡처해서 보여 드려야겠다"며 여러 번 시도하지만 결국 화면 미러링이 되지 않는다. 결국 화면 공유 방법을 찾다가 **구글 Meet를 급하게 열어** 모바일 화면을 보여 주는 방식으로 우회한다.

### [16:20–17:08] 모바일 페어링 — QR 스캔 한 번으로 맥미니 세션 연결
그 상태에서 모바일 Paseo를 실행하면 **QR코드 스캔**을 할 수 있다고 설명한다. 갤럭시(모바일) 쪽에서 QR코드 스캔을 눌러 **맥미니에 붙일 것**이며, 맥미니 쪽에서는 설정 → **기기 페어링**을 눌러 QR을 띄우고 모바일로 스캔한다. 그러면 아주 간단하게 Paseo가 바로 열리고, **맥미니에 있는 채팅 기록이 그대로 보이는 것**을 확인할 수 있다. 이 상태에서 바로 작업을 진행할 수 있어 굉장히 편하다고 말한다([의견]).

### [17:08–17:53] 모바일에서 채팅 전송 — 느림과 지우기 버그
화자는 모바일 상태에서도 "화장실에서 응가를 하면서 바이브 코딩을 할 수 있다"고 농담하며, "안녕"이라고 채팅을 넘겨 본다. **살짝 느린 건 어쩔 수 없고**, 텍스트 **지우기도 잘 안 된다**며 이런 건 개발사가 고쳐 줘야 할 부분 같다고 지적한다([의견]). 엔터로 채팅을 넘기면 실제로 채팅이 넘어가고, 이 상황은 맥미니에서 실제로 진행 중인 상황이라고 강조한다. 즉 **켜져 있는 세션에 채팅을 날려 주는 역할**이라는 관점으로 접근하면 된다는 것. 완벽하지는 않다고 인정하면서도, 모바일에서 입력하는 채팅이 맥미니 쪽에 바로 들어가는 걸 보여 준다.

### [17:53–18:37] 정리 — 호스트=주인, 클라이언트, 중앙 관리자 역할
다시 정리한다. 윈도우즈에서 Paseo를 설치했고 맥미니의 Paseo에 붙고 싶다면, **양쪽에 설치가 다 되어 있어야 하고**, 붙이는 쪽에서 **Add Host** 후 상대에게서 받은 **링크를 넣어 주면** 된다. 그러면 링크를 준 쪽이 **주인(호스트)**, 붙는 쪽이 **클라이언트**가 된다. 이후 입력하는 채팅은 즉시 양쪽에 공유되고, **여기서 지우면 저기서도 지워진다**. Paseo가 그런 연결 상태들을 관리해 주는 **중앙 관리자 역할**을 한다고 보면 된다는 정리다. 급하게 멀리서 서버에 있는 파일로 작업해야 하는 경우 굉장히 유용한 툴이라 생각하며, 자신도 이 기능이 좋아서 Paseo로 넘어왔다고 말한다([의견]). 윈도우 쪽에서 탭을 끄니 맥미니 쪽 탭도 꺼지는 걸 보여 주며 "실제로 이 PC가 그냥 여기 있는 거"라고 표현한다.

### [18:37–19:10] macOS 설치 — 드래그 앤 드롭
이제 macOS에서도 똑같이 진행해 보겠다며, 자신은 macOS에서 Paseo를 클린하게 삭제해 뒀기 때문에 이것도 해 보겠다고 한다. macOS 설치도 동일해서 설치 파일을 다운로드하고, 다운로드 완료 후 클릭해 **드래그 앤 드롭**으로 Paseo 설치를 진행하면 된다고 안내한다.

### [19:10–19:58] macOS에서 프로바이더 설정과 맥미니 호스트 페어링
macOS(맥스튜디오)에서 Paseo를 열면, Claude Code와 Codex가 이미 설정돼 있어 그대로 들어와 있다. Copilot과 OpenCode는 쓰지 않을 것이고, 자신은 여기서 **Cursor를 쓰기 때문에** Cursor를 눌러 설치까지 진행한다(로그인이 필요하면 로그인하라고 뜨지만 이미 로그인돼 있어 별 어려움 없이 된다). 지금은 맥미니 호스트에 붙어 있지 않으므로 **Host → Add Host**로 맥미니에서 받았던 링크를 붙여 넣고 페어링하면, 동일하게 맥미니의 호스트 세션이 들어와 있는 걸 볼 수 있다. **연결이 엄청나게 간단하다**고 강조한다.

### [19:58–20:32] Paseo 도구 활성화 — 일정 관리(크론잡과 같은 것)
Paseo에는 이 외에도 설정이 굉장히 많은데, 자신이 다 써 본 것도 아니니 써 본 것 중 유용하다 싶은 것과 지금 테스트 중인 것만 말하겠다고 한다. **에이전트 메뉴의 "Paseo 도구 활성화"**를 누르면 일정 관리 같은 걸 할 수 있는데, 사실 특별한 건 아니고 **몇 시 몇 분에 PC가 켜져 있으면 그 명령을 실행하는 방식**이라고 설명한다. Claude의 "예정됨(scheduled)" 기능과 완전히 동일하며, 이런 걸 켜지 않더라도 특정 시간에 뭔가를 하는 건 원래 **크론잡(cron job)**으로 할 수 있는 일이지만 Paseo가 그걸 좀 더 편하게 해 준다는 것. 쓰고 싶으면 켜면 된다고 한다.

### [20:32–21:41] 오케스트레이션 스킬 — Orca에 있던 것과 동일
그다음은 **오케스트레이션 스킬**인데, 이건 Orca에 있던 것과 동일한 것이라고 말한다. 이 스킬을 설치하면, 예컨대 맥미니에 있는 상태에서 프로젝트를 추가할 때 **호스트 표시를 맥스튜디오로 클릭**해 그쪽 폴더 중심으로 작업할 수 있다. 화자는 자신이 계속 개발 중인 캡처 도구 프로젝트([불명확: 자막 원문 "오마이 오픈스텝쪽"])를 맥스튜디오에서 개발 중이라고 예로 든다. 이 상태에서 이미지 생성이 하고 싶어졌는데 모델을 Claude로 해 두면 Claude는 이미지 생성 도구가 없다. 그럴 때 오케스트레이션 스킬을 설치해 둔 상태에서 "**Codex 쪽에 부탁해 이미지 에셋을 받아오고, 그걸 Paseo의 오케스트레이션 스킬로 네가 알아서 조율하라**"고 시키면, Claude가 못 만드는 이미지를 Codex 쪽에 만들게 해 받아올 수 있다는 설명이다. 즉 에이전트 하나를 중심에 놓고 나머지 에이전트를 조작하는 기능인데, [의견] 화자는 "스킬도 뭐 이렇게 대단한 건 아니라고 생각한다"고 평가한다.

### [21:41–22:12] 사용량 보기와 터미널 정리
나머지 기본적인 것으로 **사용량** 화면을 짚는데, 이렇게 누르면 사용량이 한꺼번에 보이는 것도 굉장히 좋다고 말한다([의견]). Codex는 오늘 쓰지 않아 비어 있고, Claude는 세션을 쓰는 상태가 보이며, Cursor는 아직 안 써서 그렇게 보인다고 설명한다. 다른 것도 연결하면 당연히 보일 것이라고 한다. 이어 안 쓰는 터미널은 그냥 날려 버리겠다며 정리하고, 터미널 에이전트 북스 류는 켜 두면 좋지만 자신은 기본적인 것만 쓰겠다고 한다.

### [22:12–22:32] 마무리
이 정도면 Paseo에 입문하는 사람들에게 충분한 가이드가 됐다고 생각한다고 말한다. 보통 윈도우 가이드 영상이 많이 안 올라오는데, 윈도우에서 하는 사람들에게 **모바일 설정까지** 잘 가이드가 되었기를 바란다고 마무리한다. 오늘부터 다시 힘을 내서 좋은 영상으로 계속 인사드리겠다며 다음 영상을 예고한다.
