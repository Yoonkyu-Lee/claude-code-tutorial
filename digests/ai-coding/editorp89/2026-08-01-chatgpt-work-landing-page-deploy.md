## 요약 (주제별)

### 1. 핵심 주장 — Chat이 아니라 Work를 써야 하는 이유
- ChatGPT 데스크톱 앱에는 상단에 GPT/Codex 선택과 Chat/Work 선택이 있다. 왼쪽 위는 GPT 모드 그대로 두고, 가운데는 **Work**를 추천.
- **Chat**은 웹브라우저 기반이라 에이전트의 활동 범위가 채팅창 안에 갇힌다. 채팅창 밖으로 나가 작업을 못 한다.
- **Work**는 에이전트가 채팅창을 벗어나 사용자 PC의 파일·폴더에 직접 접근·편집한다. 그래서 "웹사이트를 만들어 배포"하는 이 실습은 Chat이 아니라 Work에서만 가능하다.

### 2. 준비물·환경 설정
- 준비물: ChatGPT 애플리케이션. 구글에서 "앱 다운로드" 검색 → 다운로드 사이트에서 Mac/Windows 버전 설치.
- [의견] **Windows 버전은 버그가 엄청나게 많다** → 화자는 Mac으로 진행. Windows 유저는 알아서 해결해 따라오라고 당부(미검증, 화자 강의 경험 기반).
- 모델·추론 강도 선택: 모델은 [불명확: 원문 "솔"], 추론 강도는 "높음". 모델은 위로 갈수록 좋아지지만 토큰을 빨리 소모 → 조절 필요.
- 추론 강도 = 자동차 기어 비유. 높을수록 "속도"가 아니라 **결과물이 좋아질 확률**이 올라감. "울트라(매우 높음)"는 토큰을 많이 쓰고 거의 쓸 일 없다(공식 문서 근거라고 화자 주장) — 일상 작업은 "높음"으로 충분.
- "빠름" 옵션: 표준 vs 1.5배 속도(결과 나오는 속도 차이). 화자는 "빠름" 켜고 사용.

### 3. 프로젝트 만들기 — 폴더를 활동 범위로 지정
- "프로젝트 선택 → 새 프로젝트 → 읽고 편집할 수 있는 폴더 추가"로 폴더를 지정하면, ChatGPT가 그 폴더를 읽고 편집할 수 있다.
- 화자는 먼저 데스크톱을 지정해 확인. "여기 뭐가 있지?"라고만 물어도 에이전트가 **지정 폴더(바탕화면)** 내용을 확인하려 든다 → 영역을 지정하면 그 영역에서 에이전트가 동작.
- 실습 본편은 빈 폴더(`스터디-ChatGPT-워크-01`)를 새 프로젝트로 열어 진행. 지정 폴더 안에서 실제로 파일들이 생성되는지 확인 가능.

### 4. 실전 절차 — 랜딩 페이지 제작 프롬프트
- `$` 입력 후 "사이트" 검색 → **"사이트" 스킬** 사용. 이 스킬이 사이트 제작 + 배포까지 진행해 준다.
- 오늘 목표: 게시판·회원가입 없는 간단한 **사업장 소개 랜딩 페이지**.
- 컨셉: 참고 사이트([불명확: 원문 "체지 오버뷰"])의 구조와 **스크롤 인터랙션** 특징을 복제 → 과일 판매 업체 랜딩 페이지.
- 프롬프트 요구사항: 가게 이름 "애플스토어", 계절 과일을 신선하게 판매, 프리미엄만 취급, 배송 1~3일 이내로 빠름, "당도 떨어지는 것은 절대 안 판다"가 원칙. 줄바꿈은 Shift+Enter.
- 에이전트는 뼈대 생성 → 내용 확인 → 재작업 등 자율 흐름으로 다수 파일을 매우 빠르게 생성. [의견] 사이트 제작 자체는 요즘 흔해서 대단한 일이 아니라고 화자가 반복 강조.

### 5. 진짜 강점 — 배포까지 원스톱
- ChatGPT Work의 핵심 강점: 사이트 제작 후 **배포까지 완료**해 준다. 보통 웹사이트는 내 PC에서만 보이고 공개하려면 도메인이 필요한데, 그것까지 처리.
- 흔한 바이브 코딩 배포 절차(Vercel/GitHub에 올리기, Vercel CLI·GitHub CLI 설치 등) 없이 **"만들어서 배포해"** 한마디로 배포. 공짜 배포가 큰 장점.
- 도메인 주소는 약간 랜덤하게 생성되지만 남이 접속 가능한 주소를 만들어 줌. 현재는 유통기한 없이 유지 가능(정책 변동 가능성은 화자도 인정). — 주소 랜덤/유지 정책은 화자 리서치 기반 주장/미검증.
- 활용: 랜딩 페이지를 초기에 배포해 **유저 반응 테스트**, 주소 변경은 나중 문제로. 테스트·MVP에 좋은 기능이라는 게 화자 평가.

### 6. 배포 실무 — 명령, 상태, 공유 설정
- 사이트를 만든 것만으로는 목록에 안 뜬다. **"배포해"** 명령을 내려야 배포 큐에 걸리고, 진행 중이던 테스트 과정이 끝나면 배포됨(테스트는 휴지통으로 꺼도 됨).
- 배포는 우선 **"온리(only, 나만 보기)"** 상태로 됨. "사이트 버전 저장 중"이 뜬 뒤 목록에 등장.
- 배포물 확인 위치: `chatgpt.com/sites`(계정에 배포된 사이트 목록). 앱 안 "사이트"에서도 확인.
- 공유 설정: 설정 → 공유에서 "나만 보기" → **"모두에게 공개 / 인터넷 사용 · 누구나"**로 변경 후 게시하면 누구나 접속 가능. 사이트 이름은 바꿀 수 있으나 URL 자체는 못 바꾸고 **도메인 앞부분만** 일부 수정 가능.
- 배포 직후엔 반영에 시간이 걸려(만든 지 2분 미만이면) 설정 변경 시 로딩이 뜰 수 있음 → 잠시 기다릴 것. 관리에서 사이트 삭제도 가능.

### 7. 결과물 품질과 보완 팁
- 완성물은 로컬 호스트([불명확: 원문 "3,1"], 본인만 보는 주소)에 먼저 뜸. 요청한 **스크롤 인터랙션**(구간별로 한쪽만 진행 / 좌→우 진행 등)이 반영돼 프리미엄 과일 업체 느낌이 남.
- 에이전트가 **모바일과 일반 화면을 다르게 구현**(반응형)한 점을 긍정 평가.
- [의견] 코드로 도형을 그리다 보면 에셋이 조잡할 수 있음 → **이미지로 보완**("덕테이프")하면 좋다. "당도" 표시·스티커 모양 등은 아쉬워 수정하면 좋음.
- **화면 수정법과 맞춤 도메인 추가는 다음 영상**으로 미룸.

### 8. 세일즈·배경 언급
- 로컬 호스트 개념은 화자의 책 **"바로바로 바이브 코딩"**에 자세히 설명돼 있다며 안내(도서 언급).
- 배경: 지난주·지지난주 한양대 [불명확: "에디카"] 및 [불명확: "플라"]에서 ChatGPT Work 중심 실습 강의를 했고 반응 좋았던 것을 영상화.
- [의견] 마무리 권고: ChatGPT가 크게 발전 중이지만 Claude·Claude Code도 좋은 도구이니 **여러 도구를 골고루 써 보고 자신에게 맞는 것**을 찾으라.

## 3줄 오리엔테이션
- ChatGPT 데스크톱 앱의 "Work" 모드를 켜면 에이전트가 채팅창을 벗어나 내 PC의 지정 폴더(파일·폴더)를 직접 읽고 편집할 수 있고, 그 덕에 웹사이트를 만들어 **배포**까지 한 번에 할 수 있다는 게 이 영상의 핵심.
- 실습: 빈 폴더를 프로젝트로 지정 → `$사이트` 스킬을 불러 "과일 가게(애플스토어) 랜딩 페이지"를 만들게 하고 → "배포해" 명령 한 번으로 온라인 주소를 받아 공유 설정을 "모두에게 공개"로 바꾸는 흐름.
- 화자는 "사이트 만들기 자체는 흔하다, 진짜 강점은 Vercel·GitHub CLI 없이 그냥 배포까지 공짜로 해 주는 것"이라고 강조. 화면 수정법·맞춤 도메인은 다음 영상으로 미룸.

## 전문 — 시간순 워크스루

### [00:00–00:24] 인사와 영상 배경
화자는 ChatGPT "Work"가 궁금한 시청자를 위해 이 영상을 올린다고 시작한다. 지난주·지지난주에 한양대 [불명확: 원문 "에디카"] 및 [불명확: 원문 "플라는 곳"]에서 강의를 하며 ChatGPT Work를 중심으로 여러 실습을 해 봤는데, 그중 반응이 괜찮았던 것 하나를 잡아 영상으로 만들었다고 한다. 슬라이드는 따로 없고 그냥 따라 하는 편안한 강의라고 안내한다.

### [00:24–01:03] 준비물과 앱 설치 — Windows 버전 경고
준비물은 ChatGPT 애플리케이션 설치다. 구글에서 "앱 다운로드"로 검색하면 ChatGPT 다운로드 사이트가 나오고, 거기서 Mac 버전 또는 Windows 버전 중 하나를 설치하면 된다. 화자는 여러 번 강의하며 알게 된 점으로 **Windows 버전은 버그가 엄청나게 많다**고 지적하고, 자신은 Mac 버전으로 진행하겠다고 밝힌다.
> "윈도우즈 버전은 버그가 엄청나게 많습니다." [00:45]

Windows 버그로 생기는 문제는 상황이 제각각이라 일일이 답변하기 어렵다는 것을 알게 됐다며, Windows 유저는 어떻게든 해결해서 따라오시면 좋겠고 미리 참고하라고 당부한다. [의견] 화자의 사용 경험에 근거한 권고이며, Windows 버전이 실제로 얼마나 버그가 많은지는 미검증.

### [01:03–01:22] 기본 인터페이스 — GPT/Codex, Chat/Work 선택
앱을 설치하면 인터페이스를 설명한다. 왼쪽 위에서 "GPT로 할 거냐, Codex로 할 거냐"를 고를 수 있는데, 여기서는 GPT 모드 그대로 두고 진행하면 된다. 가운데에는 "Chat으로 할 거냐, Work로 할 거냐"가 있고, 화자는 **Work로 하는 것을 추천**한다.

### [01:22–01:47] Chat vs Work — 에이전트의 활동 범위 차이
왜 Work인지에 대한 설명. 여러 번 영상에서 다뤘던 것인데, **Chat은 웹브라우저에서 하는 것이라 에이전트의 활동 범위를 채팅창 안에 가둬 버린다**. 채팅창 바깥으로 나가 이런저런 작업을 할 수 없다는 것이다. 즉 오늘 하려는, 나만의 웹사이트를 만들어 배포하는 실습은 Chat에서는 할 수 없으므로 Work에서 진행해야 한다고 강조한다.
> "이 챗은요, 여러분들 웹브라우저에서 하는 거기 때문에 이 에이전트가 동작하는 그 활동 범위를 이 채팅창 안으로 가둬 버립니다." [01:27]

### [01:47–02:03] Work 모드가 PC 폴더에 접근하는 원리
Work로 오면 에이전트가 채팅창을 벗어나 사용자의 PC(파인더/데스크톱)에 접근한다. 예를 들어 데스크톱을 Work의 활동 범위로 지정해 놓으면, 그 데스크톱 위치에 있는 파일과 폴더들을 ChatGPT Work가 살펴볼 수 있다는 것. 정말 그런지 직접 확인해 보겠다고 한다.

### [02:03–02:25] 프로젝트 생성 — 읽고 편집할 폴더 추가
왼쪽에서 "프로젝트 선택 → 새 프로젝트"를 눌러 "읽고 편집할 수 있는 폴더 추가"를 한다. 이는 지정한 폴더를 ChatGPT가 읽고 편집할 수 있게 해 주는 것. 클릭하면 원하는 폴더를 고를 수 있는데, 화자는 데스크톱을 선택한다. 선택하면 소스 폴더에 "데스크톱" 폴더가 추가된다. 폴더는 더 추가해도 되지만 일단 하나만 추가해 프로젝트 만들기를 한다.

### [02:25–02:47] 모델과 추론(리즈닝) 강도 선택
프로젝트를 만든 뒤 상황에 맞게 모델과 모델 리즈닝을 선택해야 한다. 화자는 모델은 [불명확: 원문 "솔"] 을 쓰고, 추론 강도는 중간에 있는 "높음"을 쓴다고 밝힌다. 모델은 위로 올라갈수록 좋아지지만 그만큼 토큰을 빨리 소모하므로 잘 조절해서 쓰라고 한다. "한(도)에는 (다른 모델)이 차라리 낫다"는 사람들도 있으니 그건 검색해 보고 고르라고 덧붙인다. [불명확: 모델명 음차 여러 곳 — 원문 "솔", "테라"]

### [02:47–03:14] 추론 강도 = 자동차 기어 비유, 울트라는 거의 불필요
추론 강도를 자동차 기어에 비유한다. 기어가 높을수록 속도가 빠른 것처럼 보이지만, 여기서는 속도가 빨라진다기보다 **추론 강도가 좋아지면서 결과물이 좋아질 확률이 올라간다**는 뜻이라고 정정한다. "울트라"는 토큰을 엄청 많이 쓴다. 공식 문서에서 본 걸로는 "매우 높음"(울트라)은 사실 거의 쓸 일이 없고, 아주 희귀한 상황(예: 추론 강도를 크게 올려 매우 어려운 문제를 풀어야 할 때)에만 쓴다고 한다. 일상 작업은 "높음"이어도 충분히 좋은 결과가 나오니 "높음"을 추천한다.

### [03:14–03:24] "빠름" 옵션 — 표준 vs 1.5배 속도
"빠름"은 켰다 껐다 할 수 있는 옵션이다. 표준은 기본 속도, 빠름은 1.5배 속도로, 결과가 진짜 빨리 나오냐 느리게 나오냐의 차이라고 설명한다. 화자는 "빠름"을 켜고 쓰겠다고 한다.

### [03:24–03:53] 활동 범위 확인 — "여기 뭐가 있지?"
데스크톱이 정말 활동 범위로 지정됐는지, ChatGPT가 데스크톱을 어떻게 다룰 수 있는지 확인하는 좋은 방법은 "여기에 뭐가 있냐"고 물어보는 것이다. 화자는 "여기에 뭐가 있지"라고만 질문했지 "데스크톱/바탕화면에 뭐가 있는지"를 콕 집어 묻지는 않았는데, 에이전트는 이미 바탕화면 폴더의 내용을 확인하려 든다. 즉 앞서 지정한 폴더를 중심으로 파일·폴더가 뭐가 있는지 보려 한다. 영역을 지정해 주면 그 영역에서 에이전트가 동작하려 한다는 것.

### [03:53–04:09] 왜 Work를 쓰는가 — PC 파일·폴더에 관여
그래서 Work를 쓰는 이유는, 내 PC에 있는 파일과 폴더에 에이전트가 다 접근해 관여할 수 있기 때문이다. 그렇게 에이전트에게 내 컴퓨터의 작업을 시킬 수 있고, 그걸 위해 Work를 쓰는 것이라는 개념을 잡고 들어가면 좋다고 정리한다.

### [04:09–04:29] 오늘의 실습 예고 — 나만의 사이트 만들어 배포
ChatGPT Work로 할 수 있는 오늘 작업으로, 나만의 사이트를 만들어 배포하고 싶은 사람이 분명히 있을 거라고 한다. 사이트 제작은 "바이브 코딩"이니 뭐니 너무 흔한 주제지만, ChatGPT Work를 쓰면 굉장히 단축되는 영역이 있어 소개한다는 것.

### [04:29–04:49] 빈 폴더로 새 프로젝트 만들기
"새 채팅"을 누르고, 새 프로젝트로 아무 빈 폴더나 하나 만들어 두라고 한다. 화자는 스터디 폴더 안에 새 폴더 `스터디-ChatGPT-워크-01`(원문 "스터디, 채, GPT, 워크 01")을 만들어 열기를 한다. 빈 폴더이므로 "여기에 뭐가 있냐"고 물으면 "아무것도 없다"고 답할 것이라며, 실제로 물어보라고 한다.

### [04:49–05:03] 스킬(Skill) 개념 — `$사이트`
이제 사이트를 만들라고 할 건데, 그냥 "사이트 만들라"고 해도 되지만 **스킬 개념**을 안다면 달러 기호(`$`)를 누르고 "사이트"로 검색하면 "사이트"라는 스킬이 있다고 소개한다. 이 스킬은 **ChatGPT Work로 사이트를 만들고 배포까지 진행해 주는 기능**이라고 설명한다.

### [05:03–05:29] 오늘 만들 것 — 사업장 소개 랜딩 페이지
사이트를 배포하려면 여러 가지를 고려해야 하지만, 오늘은 사업장을 소개하는 간단한 랜딩 페이지를 만든다. 게시판이나 회원가입 같은 것 없이, ChatGPT Work로 그냥 사이트를 써 보는 아주 간단한 예제다. 만든 뒤 관리하는 법까지 다루겠다고 예고한다.

### [05:29–06:02] 참고 사이트 복제 컨셉 — 스크롤 인터랙션 따라 하기
화자는 [불명확: 원문 "체지 오버뷰"] 라는 사이트의 느낌이 좋아 그것을 그대로 복제해, 자신이 과일 장사를 한다고 가정하고 "과일을 판매하는 업체를 소개하는 랜딩 페이지"를 만들려 한다. 이 사이트의 구조와, 스크롤을 내렸을 때 표현되는 **인터랙션**(스크롤바를 내릴 때 나오는 효과)의 특징을 잘 복사해서 과일 가게 랜딩 페이지를 만들라고 지시할 것이라고 한다. 과일 가게 이름은 직접 만들어 보라고 하고, 디테일한 내용을 적어 주겠다고 한다.

### [06:02–06:52] 프롬프트 요구사항 — "애플스토어" 과일 가게 컨셉
줄바꿈은 Shift+Enter로 하며 추가 요구사항을 입력한다. 화자가 넣은 설정: 과일 가게 이름은 "애플스토어"(진짜 가게 이름이라고 함), 컨셉은 계절 과일을 신선하게 판매, 프리미엄 과일만 취급, 배송은 1~3일 이내로 매우 빠름, "절대로 당도가 떨어지는 것을 팔지 않는다"가 가게 원칙. 좀 웃긴 컨셉이지만 이걸로 사이트를 만들어 보라고 바로 프롬프트를 집어넣는다.

### [06:52–07:17] 지정 폴더에서 실제로 작업이 일어나는지 확인
이해해야 할 점은, 앞서 지정한 폴더에서 진짜로 사이트 제작 작업이 이루어지는지 봐야 한다는 것. `스터디-ChatGPT-워크-01` 폴더에 들어가 잠깐 기다려 보면, 에이전트가 사이트를 만들기 위해 엄청나게 많은 파일을 매우 빠르게 만들어 주는 걸 볼 수 있다. 화자는 이것이 요즘 너무 흔한 일이라 대단한 게 아니고, 요즘은 다 기본적으로 이렇게 한다고 짚는다.

### [07:17–07:43] 에이전트의 자율 작업 흐름
에이전트는 사이트를 만들기 위해 여러 작업을 한다 — 실제로 들어가 사이트 뼈대를 띄우고, 내용을 살펴보고, 어떻더라 판단하고, 이렇게 작업하겠다고 하고, 만들고 나서 확인해 보니 제대로 안 된 것 같아 다시 만들겠다는 등 여러 이야기를 해 준다. 그 작업들이 다 진행되면 사이트가 만들어진다. 다만 사이트가 만들어지는 것까지는 요즘 아무나 하는 거라 대단한 게 아니라고 다시 강조한다.

### [07:43–08:20] ChatGPT Work의 진짜 강점 — 배포까지 해 준다
ChatGPT Work의 진짜 능력은, 사이트를 만든 뒤 **배포까지 완료해 준다**는 것이다. 보통 웹사이트를 개발하면 내 컴퓨터에서만 볼 수 있고, 남들이 보게 하려면 도메인 주소 같은 것이 필요하다. 그것까지 해 주는 게 ChatGPT Work 사이트 기능의 특징이다.
> "그것까지 얘가 완료를 해 준다라는 게 이 [ChatGPT] 워크에 있는 이 사이트의 특징입니다." [07:57]

화자가 리서치해 보니 도메인 주소는 약간 랜덤하게 만들어 주긴 하지만, 어쨌든 다른 사람이 접속할 수 있는 주소를 만들어 준다. 그 주소는 (정책이 어떻게 바뀔지는 모르나) 지금은 딱히 유통기한 없이 계속 배포·유지할 수 있다고 한다. (주소 랜덤 여부·유지 정책은 화자의 리서치 기반 주장/미검증.)

### [08:20–08:48] 활용 시나리오와 배포의 장점
초기에 랜딩 페이지를 만들어 배포해 놓고 유저 반응을 본다든가, 주소를 바꾸는 건 나중 문제로 두고, 테스트를 한다든가 할 때 굉장히 좋은 기능이라고 본다. 공짜로 배포할 수 있게 해 주는 것이 큰 장점이다. 흔히 바이브 코딩을 배운 뒤 배포하려면 "Vercel에 올려라, GitHub에 올려라, Vercel CLI를 설치해라, GitHub CLI도 있어야 한다" 같은 얘기를 하는데, ChatGPT Work는 그런 것 없이 "만들어서 배포해"라고만 하면 배포를 해 준다는 게 큰 장점이라고 한다.
> "얘는 그런 거 없이 그냥 만들어서 배포해 하면 좌우지간 배포를 해 준다라는 게 굉장히 큰 장점입니다." [08:44]

### [08:48–09:10] 배포한 사이트 확인 위치 — chatgpt.com/sites
요즘 에이전트가 사이트를 만들어 준다고 하면 배포까지 해 주는 게 거의 기본이 되어 가는 것 같다고 덧붙인다. 배포한 결과물은 `chatgpt.com` 끝에 `/sites`(원문 "슬사이트")를 붙여 접속하면, 로그인한 계정에 배포된 사이트 목록이 나온다. 앱 안에서도 "사이트"를 눌러 볼 수 있다.

### [09:10–09:37] 공유 설정 — 나만 보기 / 누구나 보기
사이트 목록에서 공유 대상이 "모든 사용자"로 되어 있으면, 공유 설정을 수정할 수 있다. 화자가 실제로 수정을 시도하는데 "편집" 항목은 아니고 설정으로 들어가야 한다. 설정에 들어가면 사이트 이름을 정하고(URL 자체는 못 바꾸지만 도메인 앞부분은 조금 바꿀 수 있음), 공유에서 "나만 보기"와 "누구나 보기"를 고를 수 있다. "누구나 보기"로 하고 "방문하기"를 누르면 만든 사이트를 바로 배포된 상태로 볼 수 있다.

### [09:37–09:56] 앞 주소도 나쁘지 않다 / 배포 관리
배포 주소 앞부분도 그렇게 나쁘지 않아 테스트하기엔 충분해 보인다고 한다. [불명확: 원문 "플레이"] 에서 수업할 때 "그냥 한번 대충 만들어 봐라" 해서 만든 것도 이렇게 배포됐다며, 배포가 굉장히 쉬워졌다고 한다. 배포 관리에서 지우고 싶으면 만든 것을 삭제하면 된다.

### [09:56–10:24] 방금 시킨 작업이 완료되면 — "나만 보기"로 배포
방금 시킨 작업이 다 완료되면 그 결과물이 "사이트"라는 곳에 올라가 우선 "나만 보기"로 배포된다. 그다음 설정만 수정하면 남들도 볼 수 있는 사이트가 된다. ChatGPT Work에서 작업하기 때문에, 접속해 봤을 때 에셋(원문 "에센")이 조금 허접할 수 있다 — 코드로 도형들을 만들어 표현하려다 보면 약간 조잡한 것들이 생긴다.

### [10:24–10:35] 이미지로 보완하기 (덕테이프)
그런 조잡한 부분은 "덕테이프"처럼 **이미지로 보완**해 넣으면 굉장히 좋다고 한다. ChatGPT Work를 활용해 사이트를 만들고 배포하면 굉장히 쉽게 만들 수 있으며, 다 만든 다음 다시 살펴보며 배포까지 천천히 설명하겠다고 한다. [의견] "이미지로 보완하면 좋다"는 화자 팁.

### [10:35–11:11] 완성된 사이트 확인 — 로컬 호스트에 뜬 결과물
다행히 에이전트가 과일 사이트를 만들어 로컬 호스트에 띄웠다. 화자는 로컬 호스트를 이해하려면 자신의 책 "바로바로 바이브 코딩"을 보라며 거기에 자세히 설명해 뒀다고 안내한다(세일즈 언급). 로컬 호스트 [불명확: 원문 "3,1"] 주소는 지금 화자 본인만 볼 수 있는 주소다. 내려서 보니 사이트를 굉장히 잘 만들어 줬다고 평가한다.

### [11:11–11:20] 요청한 스크롤 인터랙션 구현 확인
스크롤할 때 인터랙션이 있으면 좋겠다고 요청한 것이 반영됐다. 스크롤바를 내릴 때 단순히 화면이 내려가는 게 아니라, 어떤 구간은 한쪽만 진행되고 그다음 구간은 왼쪽에서 오른쪽으로 진행되는 방식을 채택해 잘 만들어 줬다고 한다.

### [11:20–11:28] 프리미엄 과일 업체 느낌 / 다음 영상 예고
이 정도면 프리미엄 과일을 취급하는 업체 느낌은 충분히 난다고 평가한다. 마음에 안 드는 것을 수정해 진행하면 되는데, 화면을 수정하고 싶다면 수정하는 법을 알아야 하고 그건 **다음 영상**에서 설명하겠다고 미룬다.

### [11:28–11:50] 배포 명령 — "야 이제 배포해"
사이트를 만들었으니 이제 배포해야 한다. 배포하려면 "사이트"로 들어가면 되는데, 새로고침해도 아직 목록에 없다. 그건 배포하라고 아직 말하지 않았기 때문이다. 그래서 "야 이제 배포해"라고 명령한다. 그러면 배포하라는 명령이 큐에 걸리고, 지금 진행 중인 테스트 과정이 끝나면 배포까지 진행해 준다.
> "야 이제 배포해." [11:37]

### [11:50–12:10] 배포 = 우선 "나만 보기"(온리 상태)로
배포한다는 것은 남들이 다 볼 수 있게 하는 게 아니라, 우선 나만 볼 수 있는 "온리(only)" 상태로 배포해 준다는 뜻이다. 배포된 뒤 설정만 바꿔 "모두 공개"로 하면 된다. 테스트 과정이 귀찮으면 그냥 진행하면 되는데, 에이전트가 "공유 가능한 사이트로 게시하는 마지막 단계로 넘어가겠다"고 하고 있어, 화자는 (테스트를) 휴지통을 눌러 꺼 버리고 에이전트가 배포까지 다 해 줄 것 같다고 한다.

### [12:10–12:34] 모바일도 고려한 구현 / 아쉬운 부분
재밌는 점으로, 사이트를 보니 에이전트가 **모바일도 고려**해 모바일 상태와 일반 상태를 다르게 구현한 것 같다고 한다. 이런 사이트는 아무나 못 만든다고 하며, 다만 "당도" 표시나 스티커 모양 같은 부분은 조금 아쉬워 수정하면 좋다고 한다. 수정법은 다음 영상에서 소개할 테니 일단 배포까지만 가자고 한다.

### [12:34–12:52] 배포 완료 목록에 등장 — 온리 상태
"공유 가능한 사이트로 게시하는 마지막 단계로 넘어간다"는 말이 안 나온 사람은 그냥 "배포해"라고 명령만 내리면 에이전트가 배포해 준다. "사이트 버전 저장 중"이 잠깐 떴다 지나가면, 목록에 올라와 있을 것이라고 한다. 실제로 목록에 올라왔고, 배포된 상태이며 지금은 "온리(나만 보기)" 상태다.

### [12:52–13:26] 공유 설정 변경 — "모두에게 공개"
목록의 사이트를 눌러 설정에서 "온리" 상태를 바꾼다. 그러면 아무나 볼 수 있는 웹사이트로 바뀐다. 웹사이트를 간단히 만들어 배포하는 걸 너무 어려워하지 말고, 누구나 할 수 있으니 시도해 보면 재밌을 거라고 한다. 사이트를 만든다는 건 결국 나의 브랜드를 알리기 위해 뭔가를 만들어 보는 것이니, 그럴 때 돈을 너무 많이 들이지 말고 이렇게 해 보면 좋다고 권한다.

### [13:26–13:40] 도메인 앞부분 수정 시도 — 안 됨
공유 설정에서 "나만 보기"를 "모두에게 공개"로 바꿔 잡으면 쉽게 끝난다. 도메인 앞부분(원문 "애플스토 시as")만 수정할 수 있는데, 화자가 시도하니 지금은 수정이 안 된다. 맞춤 도메인 항목도 안 되는 듯해 아까는 됐던 것 같다며 새로고침을 한 번 더 해 본다.

### [13:40–14:08] 배포 직후 로딩 — 시간이 필요
공유 설정은 공유 설정을 누른 다음 "나만"에서 "모두에게"로 바꾸면 된다. 다만 배포하고 나서 시간이 좀 필요한데, 만든 지 2분도 안 돼 바로 하려니 계속 로딩이 뜬다. 그러니 조금 기다렸다가 하면 된다고 안내한다.

### [14:08–14:30] 사이트 관리에서 "인터넷 사용 · 누구나"로 게시
공유 설정은 여기서 해도 되고, "사이트 → 해당 부분 설정 → 관리"로 들어가 "인터넷 사용 · 누구나"로 게시하면 된다. 그러면 그 주소로 누구나 접속할 수 있는, [불명확: 원문 "애플 스토어 시저널이라는 K989"] 의 ChatGPT 사이트가 만들어진다. 맞춤 도메인 추가도 할 수 있는데, 그건 필요하다면 다음에 설명하겠다고 미룬다.

### [14:30–14:39] 배포 완료 — 누구나 접속 가능
이제 사이트가 배포됐으니, 배포된 주소로 접속하면 누구나 들어가 볼 수 있다. 누구나 이런 사이트를 만들 수 있다고 정리한다.
