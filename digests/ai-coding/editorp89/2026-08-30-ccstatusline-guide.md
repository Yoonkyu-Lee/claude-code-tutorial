# [시즌 3] 내 클로드 코드에 계기판을 달아주고 싶다면? ccstatusline 가이드

> editorp89 · 2026-08-30 · 조회수 5,795 · 길이 9:07 · [영상 링크](https://youtu.be/PdQbF4_BE_o)
> 정리 방식: 시간순 심층 워크스루 (paraphrase) + 주제별 상세 요약
> 검증 배너: 수익 주장이 없는 도구 소개(토막 팁) 영상이다. 다만 화자 스스로 "메뉴를 완전히 정확하게 설명했는지 명확하지 않다"고 인정하고 GitHub 문서를 보라고 안내하므로, 아래 메뉴 명칭은 자동자막 음차를 문맥으로 복원한 근사치다. 복원이 불확실한 항목은 `[불명확]`으로 남겼다. 후반부는 도구 설명이 아니라 채널 운영 계획에 대한 화자의 고민([의견])이다.

## 요약 (주제별)

### ccstatusline이 무엇이고 무엇을 보여 주는가
- 터미널에서 클로드 코드를 실행했을 때 화면 아래쪽에 상태 정보를 띄워 주는 도구. 화자는 이것을 "계기판"이라고 부른다.
- 표시 항목 예시: 현재 쓰는 모델, 컨텍스트 윈도우 크기, 현재 git 브랜치, 이번 주에 남은 Opus 사용량.
- 제작 동기는 순수하게 "왜 여태 소개 안 했지?"이다. 설정법을 알면서 소개하지 않는 게 치사한 것 같아 찍었다고 밝힌다([의견]).

### 추천 대상과 화자의 현재 사용 상태
- 기본 터미널을 쓰는 사람에게 "꿀템". 별도 도구가 싫고 무거운 것이 부담스러운 사람, 기본기에 충실하고 싶은 사람에게 강력 추천([의견]).
- 반대로 화자 본인은 Paseo·Orca 같은 다른 도구를 주로 써서 이 도구를 잠깐 잊고 있었다. 아주 옛날에 세팅해 쓰다가 이것저것 바꾸는 과정에서, 터미널로는 기본 작업만 하며 이런 정보를 안 보는 일이 많아져 지금은 설치하지 않은 상태였다고 인정한다.

### 설치 절차
- github.com에서 `ccstatusline` 저장소를 찾는다. 검색은 "클로드 코드 ccstatusline"으로 하면 맨 위에 나온다. 저장소 소유자 계정명은 자막 음차가 뭉개져 `[불명확: 원문 "Sirlock / Sir멜록"]`.
- README의 긴 설명은 다 읽을 필요 없고 링크만 복사하면 된다.
- 클로드 코드 채팅에 그 링크를 붙이고 "요거를 설치해 줘"라고 하면 설치가 가볍게 끝난다. 설치 파트는 이것이 전부다.

### 설정 진입과 Powerline 모드
- 설정하려면 먼저 Ctrl+C를 두 번 연달아 눌러 클로드 코드를 종료한 뒤, 명령어 `ccstatusline`을 입력한다. 다소 당황스러운 메뉴 창이 뜬다.
- 메뉴는 방향키로 이동하며, 연두색으로 볼록볼록 움직이는 항목이 현재 선택 위치다. 메뉴 위쪽 영역은 해당 옵션 선택 시의 변화를 보여 주는 미리보기다.
- 가장 먼저 할 일은 Powerline setup. 들어가서 엔터 → 처음엔 꺼져 있으므로 `T`로 토글한다. Powerline이 꺼지면 "못생겨지고" 켜면 "약간 이뻐진다"는 것이 화자의 비교([의견]).
- 실전 함정: 한글 입력 상태에서 T를 누르면 "ㅅ"이 입력되어 토글이 안 된다. 반드시 영문으로 전환 후 T.
- 나머지 부가 옵션(자막상 `[불명확: 원문 "언라인 위젯", "컨티뉴 띵"]`)은 하면 좋지만 화자는 기본만 하고 Back 또는 ESC로 빠져나온다.

### Lines 메뉴 — 줄과 위젯 구성
- 표시 정보를 바꾸는 곳은 Lines 메뉴. line 1과 line 2가 있고, 화자 설정에서는 각각 위젯 네 개씩 떠 있다.
- line 1 구성: 1번 모델 / 2번 Context Length / git branch / git changes. 엔터를 누르면 위치 변경 모드가 되어 순서를 옮길 수 있지만, 화자는 "1번 라인은 건드릴 게 없으니 그냥 두라"고 권한다([의견]).
- line 2는 처음에 비어 있다(자막상 `[불명확: 원문 "MT"]`, 문맥상 empty 표시). 엔터로 들어가 `A`를 누르면 추가할 위젯 종류를 고르는 메뉴가 열린다.
- 삭제는 `D`(delete). 요약 절차: A로 위젯 종류 선택 → 추가, D로 제거, ESC로 상위 복귀.
- line 3에도 원하는 것을 설정할 수 있다.

### 화자가 추천하는 위젯
- **usage 계열**: weekly `[불명확: 원문 "페이블"]` usage, weekly Opus usage, weekly reset timer. 이걸 넣으면 주간 한도와 리셋 타이머를 다 체크할 수 있다. 리셋 타이머 표시 예 — "위클리 리셋 하루하고도 12시간 30분 남았다".
- 화자 본인은 weekly Opus usage 정도만 추가해 뒀고, Opus를 많이 쓸 테니 Opus usage를 우선 추천한다([의견]).
- **Session usage**: 현재 세션을 얼마나 썼는지 표시("현재 세션 20% 정도 썼다"). 3번 위치에 배치했고 "되게 유용할 것 같다"고 평가.
- **토큰 계열**: input/output/total 토큰 수 관련 위젯(자막 "토큰스 토큰 인풋 나브 토크 토탈" — 세부 명칭 `[불명확]`).
- **Context**: 현재 컨텍스트를 얼마나 썼는지 "Context Used" 형태로 표시.
- 화자가 **뺀** 것: weekly usage는 굳이 필요 없어서 삭제, Context Window는 "현재 컨텍스트 윈도우가 얼마냐"만 알려 줘서 주요 정보가 아니라고 보고 삭제([의견]). Context가 중복 추가돼 있어 하나 정리.

### 저장과 실제 동작 확인
- ESC로 상위 복귀 후 Save and Exit을 하면 설정이 끝난다. 이후 클로드 코드를 실행하면 화면 아래에 선택한 정보들이 나온다.
- 실행 직후 이미 "세션을 4% 잡아먹은" 상태였고, "하이"라고 인사 한마디만 보내도 상태 표시가 갱신된다고 안내.
- 변화 실험: "멋진 웹사이트 랜딩 페이지를 만들어 봐"를 시키면 토큰을 쓰면서 세션 사용량과 Context Used가 금방 올라갈 것이라는 예상.
- 실제로는 처음 4% 이후 값이 잘 안 변했고, 토큰이 773 토큰에서 멈춘 듯해 "지금 좀 느려진 것 같다"고 현장 관찰만 남긴다(원인 미확인, `[불명확]`). 지켜보는 동안 "약간 바보가 된 것 같은 느낌"이라는 농담도 붙는다.
- 요점은 수치가 바뀌는 것을 보면서 "지금 내가 무슨 짓을 하고 있는지"를 파악할 수 있다는 것.

### 설명의 한계 — 스스로 붙인 단서
- 메뉴를 완전히 정확하게 설명했는지 본인도 명확하지 않다고 인정하고, 정보는 GitHub 저장소에 다 있으니 그걸 보라고 안내한다.
- Powerline을 켜 놓은 다음에는 클로드 코드에게 옵션 수정을 시켜도 해 주는 것으로 "알고 있다"고 말한다(주장/미검증, 확신 유보).

### 채널 운영 계획 — 후반부 고민 (도구와 무관)
- 앞으로의 영상 방향: 기본적인 건 이미 다 찍었으므로, "멋있는 걸 한 번에 만들면서 짠" 하는 전형적 바이브 코딩 영상보다, 진지하게 목표를 하나 두고 필요한 프로그램을 만드는 과정이 힌트가 되는 영상을 준비할까 고민 중([의견]). 원하는 주제가 있으면 댓글로 남겨 달라고 요청.
- 유튜브의 구조적 한계: 영상을 다 올려도 뒤섞여서, 순서대로 봐야 할 영상들을 재생 목록으로도 관리하기 어렵다. 그래서 기본 가이드 영상은 별도 트랙을 만들어 멤버십 쪽에 따로 관리할까 고민 중([의견], 유료·멤버십 유입 구조에 대한 언급).
- 무료 공개에 대한 갈등: 처음엔 야심 차게 올리겠다고 했지만 "후원자에게만 줘야 하나" 고민하다 결국 다 무료로 올리다 보니 "약간 가치 없게 뿌려지는" 면도 있는 것 같아, 다시 갈무리해 진지하게 올릴까 생각 중([의견]).

### 집필 중인 클로드 코드 입문서
- 화자가 클로드 코드 입문서를 작성 중이며, 단독이 아니라 채널의 오랜 선배인 **코드팩토리**와 공저다.
- 기본 중의 기본이 될 만한 내용, "클로드 코드에서 이건 꼭 알아야 한다" 싶은 것을 추려 원고를 쓰고 있다.
- 최대 난점은 클로드 코드가 업데이트되며 내용이 계속 바뀐다는 점. 독자들이 업데이트 때문에 스트레스를 받는다고 해서, 웬만하면 변하지 않을 것들만 담으려고 노력 중이라고 밝힌다.
- 여기에 맞춰 영상을 하나 준비해 볼까 하는 고민도 함께 언급([의견]).

## 3줄 오리엔테이션
- 터미널에서 클로드 코드를 쓸 때 화면 아래에 현재 모델·컨텍스트 사용량·git 브랜치·주간 Opus 잔여량 같은 "계기판"을 띄워 주는 `ccstatusline` 설치·설정 가이드다.
- 설치는 GitHub 링크를 클로드 코드에 던져 "설치해 줘"로 끝내고, 설정은 클로드 코드를 종료한 뒤 `ccstatusline` 명령으로 들어가 Powerline 모드를 켜고 Lines 메뉴에서 위젯을 A(추가)/D(삭제)로 고르는 방식이다.
- 마지막 2분은 도구와 무관하게, 앞으로 영상을 어떤 방향으로 만들지·유튜브의 순서 관리 한계·멤버십 분리 고민·코드팩토리와 공저 중인 클로드 코드 입문서 이야기다.

## 전문 — 시간순 워크스루

### [00:00–00:26] 왜 이제야 소개하는가
화자는 오늘 영상을 "약간 토막 팁"이라고 소개하면서, 이걸 왜 여태 소개하지 않았는지 스스로도 모르겠다며 "나 이거 왜 소개 안 했지?" 하면서 찍는 영상이라고 밝힌다. 본인은 요즘 Paseo나 Orca 같은 다른 도구를 많이 쓰다 보니 가볍게 터미널을 쓸 때 이 도구를 잠깐 잊고 있었다고 한다. 설정법을 알면서 시청자에게 소개하지 않는 건 "좀 치사한 것 같아서" 영상을 찍게 됐다는 것이 제작 동기다([의견]).

### [00:26–00:47] 이 도구가 보여 주는 것 — 아래쪽 계기판
목표를 보면 알겠지만, 터미널에서 클로드 코드를 실행했을 때 화면 아래쪽에 정보가 뜨는 그것이라고 설명한다. 표시되는 항목으로는 현재 쓰는 모델이 무엇인지, 컨텍스트 윈도우는 얼마짜리를 쓰는지, 현재 브랜치는 어디인지, 이번 주에 사용할 수 있는 Opus의 양이 얼마나 남았는지 같은 것들을 든다. 화자는 이것을 "계기판"이라고 부르며, 가볍게 쓰고 싶은 사람에게 추천하겠다고 말한다.

### [00:47–00:59] 추천 대상 — 기본 터미널파, 무거운 도구가 싫은 사람
이걸 왜 가이드하지 않았는지 모르겠다고 다시 한 번 사과하듯 덧붙이면서, 기본 터미널을 쓰는 사람에게는 "꿀템"이라고 정리한다. 별도 도구가 싫고 무거운 것이 부담스러운 사람, 기본기에 충실하고 싶은 사람에게 강력 추천한다는 것이다([의견]). 그러고는 짧게 바로 가이드로 들어간다.

### [00:59–01:31] 설치 (1) — GitHub에서 `ccstatusline` 찾기
설치하려면 github.com의 `ccstatusline` 저장소 링크를 그대로 입력하면 된다고 안내한다. 귀찮으면 "클로드 코드 ccstatusline"으로 검색하면 맨 위에 저장소가 나오는데, 만든 사람 이름은 자막상 `[불명확: 원문 "Sirlock / Sir멜록"]`으로 뭉개져 있다(문맥상 저장소 소유자 계정명이다). 저장소에는 "ccstatusline을 설치하는 순간 클로드 코드의 상태가 아주 예뻐진다"는 식의 아주 긴 설명이 있는데, 그걸 다 읽어 볼 필요는 당연히 없고 링크만 그대로 복사하면 된다고 말한다.

### [01:31–01:40] 설치 (2) — 클로드 코드에 "요거 설치해 줘"
화자 본인은 이미 설정이 끝나 있는 상태라 화면을 넘어온 것이라고 밝히고, 시연을 위해 화면을 클리어한 뒤 채팅을 처음 시작하는 상황을 가정한다. 복사한 링크를 붙여 놓고 "요거를 설치해 줘"라고 하면 설치가 가볍게 끝난다는 것이 설치 절차의 전부다.

### [01:40–01:55] 설정 진입 — Ctrl+C 두 번으로 종료 후 `ccstatusline` 실행
설치가 끝난 다음 설정을 하려면 먼저 클로드 코드를 종료해야 한다. Ctrl+C를 두 번 연달아 눌러 클로드 코드를 종료하고, 그 상태에서 명령어 `ccstatusline`을 그대로 입력해 엔터를 치면 된다. 그러면 "좀 당황스러운" 메뉴 창이 뜬다고 예고한다.

### [01:55–02:09] 메뉴 조작법과 첫 단계 — Powerline setup
메뉴에서는 연두색으로 볼록볼록 움직이는 항목이 현재 선택 위치이며, 키보드 방향키로 메뉴를 고르는 방식이라고 설명한다. 가장 먼저 해야 할 것은 Powerline setup(자막 "파워라인 셋업")이다. 이걸 켜야 화면이 "이쁘게 휘황찬란하게", 무지개 빛깔로 나오는데, 그런 모양을 쓰고 싶다면 Powerline setup을 켜야 한다는 것이다.

### [02:09–02:24] Powerline 토글 — T 키, 한/영 상태 주의
해당 항목에 들어가 엔터를 누르면 Powerline 모드가 처음에는 꺼져 있을 것이고, 화면에 "press T to toggle" 안내가 있으니 T를 눌러 토글하면 된다. 여기서 실용적인 주의사항을 하나 붙인다 — 한글 입력 상태에서 T를 누르면 당연히 토글이 안 되고 "ㅅ"이 입력되니, 한/영 상태를 확인하고 영문으로 전환한 뒤 T를 눌러야 껐다 켰다 할 수 있다는 것이다.

### [02:24–02:45] 미리보기 영역, 나머지 옵션은 건너뛰고 ESC
메뉴 위쪽에 보이는 것은 그 옵션을 선택했을 때 어떤 변화가 생기는지 보여 주는 미리보기다. Powerline 모드가 꺼지면 "이렇게 못생겨지고" 켜면 "약간 이뻐진다"고 비교하며, 얼마나 이뻐졌냐 하면 "이거보다 이게 낫잖아요" 정도라고 가볍게 넘긴다([의견]). 그 밖에 자막에 `[불명확: 원문 "언라인 위젯", "컨티뉴 띵"]`으로 남은 부가 옵션들도 하면 좋지만, 본인은 기본적인 것만 하고 싶어서 이 정도만 하고 돌아가겠다고 한다. 되돌아갈 때는 Back을 누르거나 ESC를 누르면 된다.

### [02:45–03:10] Lines 메뉴 — 화면에 뜨는 줄 구성
사람마다 표시되는 정보가 다를 텐데, 그것을 바꾸는 곳이 Lines 메뉴(자막 "에 라인")라고 안내한다. Lines에 들어가면 line 1과 line 2가 있고, 지금 화자의 설정에서는 line 1에 위젯 네 개(하나, 둘, 셋, 넷), line 2에도 위젯 네 개가 떠 있는 상태라고 짚어 준다.

### [03:10–03:23] line 1의 위젯 4종과 위치 변경
line 1에 들어가면 원하는 항목을 켰다 껐다 할 수 있다. 메뉴를 고르면 1번이 모델, 2번이 Context Length(자막 "컨텍스트 랭스"), 그다음이 git branch, 그다음이 git changes(자막 "기체인지")라고 각각 대응시킨다. 엔터를 누르면 위치를 바꾸는 모드가 되어 순서를 이리저리 옮길 수도 있다. 다만 화자는 "여기서 사실 건드릴 거 없습니다"라며 1번 라인은 그냥 두라고 권한다([의견]).

### [03:23–03:38] line 2 — 비어 있는 줄에 위젯 추가하기(A)
2번 라인으로 가면 처음에는 자막상 `[불명확: 원문 "MT"]`(문맥상 비어 있음을 뜻하는 empty 표시로 읽힌다)로 되어 있을 것이다. 엔터로 들어가면 처음엔 아무것도 없고, 화면에 위젯 추가 안내(자막 "애드 be아피커" — 문맥상 A 키로 위젯을 추가하라는 안내)가 보인다. A를 누르면 메뉴가 열려서 여기에 추가할 위젯을 고를 수 있다.

### [03:38–03:58] 추천 위젯 (1) — usage 계열과 리셋 타이머
화자가 추천하는 첫 번째 계열은 usage(자막 "유제지"), 즉 얼마나 썼는지 보는 위젯이다. 구체적으로는 weekly `[불명확: 원문 "페이블"]` usage, weekly Opus usage, weekly reset timer 같은 것들을 추가하면 주간 한도를 다 체크할 수 있고 리셋 타이머도 확인할 수 있다고 설명한다. 본인은 weekly Opus usage 정도만 추가해 뒀는데, 리셋 타임을 추가하면 "위클리 리셋 하루하고도 12시간 30분 남았다" 같은 표시를 얻을 수 있다고 시연한다.

### [03:58–04:12] 삭제(D)와 추가 절차 정리
지우고 싶으면 화면에 보이는 대로 D를 누르면 delete가 되면서 항목이 지워진다. 절차를 다시 정리하면, A를 눌러 위젯 종류를 먼저 고르고 그다음 추가하면 된다는 것이다. 추천은 usage 안에 있는 Opus usage — 아무래도 Opus를 많이 쓸 테니 — 또는 `[불명확: 원문 "페이블 유제지"]` 쪽이라고 다시 짚는다.

### [04:12–04:25] 추천 위젯 (2) — Session usage
Session usage는 현재 세션을 얼마나 썼는지 보여 주는 위젯이라 이것도 추가해 주면 좋다고 한다. 화면에서는 3번 위치에 들어갔고, "현재 세션을 20% 정도 썼다"는 식으로 표시된다. 이 정도만 추가해 줘도 되게 유용할 것 같다는 평가다([의견]). 다 골랐으면 ESC를 누르면 된다.

### [04:25–04:47] 추천 위젯 (3) — 토큰 계열과 Context
원하는 것을 하나씩 추가하면 되는데, 화자가 추가해 둔 예로는 토큰 관련 위젯(자막 "토큰스 토큰 인풋 나브 토크 토탈" — 문맥상 input/output/total 토큰 수 계열, 세부 명칭은 `[불명확]`)을 든다. 그리고 하나를 더 추가해 놓고 이름을 까먹었다가 "토큰 스피드가 아니고… 아 그렇죠, Context"라고 떠올린다. Context 위젯을 넣으면 지금 컨텍스트를 얼마나 썼는지가 나온다는 설명이다.

### [04:47–05:08] 중복 정리 — 무엇을 지웠고 왜 지웠나
화면에서 Context가 이미 2번에 들어가 있어 두 개가 중복된 상태라 하나를 지운다. 표시는 "Context Used"(자막 "컨텍스트 유즈드") 형태로 얼마나 썼는지 보여 준다. 이어서 본인 기준의 취사선택을 밝힌다 — weekly usage는 굳이 필요 없어서 지우고, Context Window는 "현재 컨텍스트 윈도우가 얼마냐"를 보여 주는 것이라 그렇게 주요한 정보가 아니어서 지운다([의견]). 이런 식으로 필요한 것만 자유롭게 설정하면 되고, line 3에도 원하는 것을 설정하면 된다고 덧붙인다.

### [05:08–05:29] 저장 — Save and Exit, 그리고 실행 결과
설정이 끝나면 ESC를 눌러 상위로 돌아온 다음 Save and Exit(자막 "세이브 앤 엑시")를 하면 끝낼 수 있다. 그때부터 클로드 코드를 실행하면 화면 아래에 원하는 정보들이 싹 나온다. 화자는 실행하자마자 "세션을 벌써 4%나 잡아먹었다"고 지적하고, 여기서 "하이"라고 인사 한마디만 보내도 상태가 표시될 것이라고 안내한다.

### [05:29–05:55] 수치가 실시간으로 변하는지 확인
Context Used가 4%로 표시된 것을 확인하고, 계속 대화하면 값이 변하는지 보자고 한다. "멋진 웹사이트 랜딩 페이지를 만들어 봐"라고 시키면 에이전트가 토큰을 쓰면서 세션 사용량도 올라가고 Context Used도 올라갈 것이라는 예상이다. 엄청 쓰고 있기 때문에 금방금방 올라갈 것이라며, 그냥 대충 만들라고만 해도 아랫부분 수치가 바뀌면서 "여러분들이 지금 무슨 짓을 하고 있는지"를 볼 수 있다는 것이 이 도구의 요점이라고 정리한다.

### [05:55–06:12] 본인은 왜 안 쓰고 있었나
화자는 이걸 아주 옛날에 세팅해 쓰다가 이것저것 바꾸는 과정에서, 터미널은 기본적인 작업만 하면서 이런 정보를 안 보는 일이 많아졌다고 털어놓는다. 그래서 최근에는 설치하지 않은 상태였지만, 시청자가 원한다면 이렇게 하면 된다는 것이다([의견]).

### [06:12–06:24] 메뉴 설명의 한계 — GitHub에 다 있다, 옵션 수정은 클로드 코드에 시켜도 됨
본인이 메뉴를 완전히 정확하게 설명했는지가 지금 명확하지 않다고 스스로 단서를 달면서, 사실 GitHub 저장소에 정보가 다 있으니 그걸 보고 하면 된다고 안내한다. 또 Powerline을 켜 놓은 다음에는 클로드 코드에게 옵션을 수정해 달라고 해도 해 주는 것으로 알고 있다고 말한다(단, "제가 알고 있는데"라는 표현으로 확신은 유보 — 주장/미검증). 기본적인 사용법은 알려 줬으니 나머지는 자유롭게 쓰면 될 것 같다는 마무리다.

### [06:24–06:47] 지켜보는 동안 수치가 안 변한다
설정 후 사용량이 줄어드는 게 보일 거라며 화면을 지켜보는데, 처음 4%를 먹은 이후 변화가 없다. 가만히 보고 있으니 "제가 약간 바보가 된 것 같은 느낌이 든다"고 농담하면서도, 되고는 있는 것 같다고 말한다. 다만 토큰이 773 토큰을 쓴 뒤 더 안 쓰는 것 같아 뭐 하는 건가 싶다며, 지금 좀 느려진 것 같다고 관찰을 남긴다(현장 관찰이며 원인은 확인되지 않음 — `[불명확]`). 어쨌든 안 변하는 것 같지만 이렇게 원하는 정보를 골라 쓰면 된다는 말로 도구 파트를 닫는다.

### [06:47–07:23] 앞으로의 영상 방향 고민 — "멋있는 것 한 방"보다 목표 지향 과정
영상은 여기까지이고 간단한 소개를 했으니 다음에 다른 영상으로 돌아오겠다고 인사한 뒤, 이후 올릴 영상을 어떤 방식으로 준비할지 고민 중이라고 밝힌다. 기본적인 건 이미 다 찍었기 때문에, 바이브 코딩하는 과정을 여러 가지로 준비해야 하나 생각 중이라는 것이다. 바이브 코딩 영상이라고 하면 보통 멋있는 걸 한 번에 만들면서 "짠" 하는 걸 원하는 사람이 많은데, 본인은 그보다 진지하게 목표를 하나 두고 시청자가 필요로 하는 어떤 프로그램을 만드는 과정이 힌트가 되도록 영상을 준비하는 게 어떤가 생각하고 있다고 말한다([의견]).

### [07:23–07:35] 시청자 요청 접수
준비가 되면 그런 방향으로 영상을 잡아 올리려 한다면서, 영상을 보는 사람 중 원하는 것이 있으면 댓글을 남겨 주면 참고해서 영상을 올려 보겠다고 한다.

### [07:35–07:57] 유튜브의 순서 문제와 멤버십 분리 고민
기본 가이드 영상은 따로 트랙을 만들어 별도로 제공해 볼까 하고 있다고 밝힌다. 이유는 유튜브의 단점 때문인데 — 이건 그냥 본인의 고민이라고 전제를 달면서 — 영상을 다 올려도 결국 영상이 뒤섞여 버린다는 점이다. 순서대로 봐야 할 영상들이 있는데 재생 목록으로 해도 관리하기가 쉽지 않아서, 이걸 멤버십 쪽에 따로 관리할까 하는 생각을 하고 있다고 말한다([의견]. 유료·멤버십 유입 구조에 대한 언급이므로 정보로서 기록).

### [07:57–08:16] 무료로 다 뿌리는 것에 대한 갈등
처음에는 야심 차게 올리겠다고 했는데, 결국 "이 영상은 꼭 후원하는 분들에게만 줘야 하나" 같은 고민을 하다가 그냥 다 무료로 올리다 보니 약간 가치 없게 뿌려지는 면도 있는 것 같아 고민 중이라고 털어놓는다([의견]). 어차피 무료로는 다 올라가 있으니, 다시 갈무리해서 좀 더 진지하게 올리는 걸 해야 하나 하는 생각이라는 것이다.

### [08:16–09:00] 클로드 코드 입문서 집필 — 코드팩토리와 공저
그리고 현재 클로드 코드 입문서를 열심히 작성하고 있다고 알린다. 혼자 쓰는 것은 아니고, 채널의 오랜 선배인 코드팩토리와 함께 책을 집필 중이다. 기본 중의 기본이 될 만한 내용을 추려서 "클로드 코드에서 이건 꼭 알아야 된다" 싶은 것들로 원고를 쓰고 있다고 한다. 문제는 클로드 코드가 업데이트되면서 내용이 자꾸 바뀐다는 점이라, 최대한 그런 것들을 피해 가면서 작업하려 한다는 것. 독자들이 업데이트 때문에 스트레스를 받는다고 해서, 웬만하면 변하지 않을 것 같은 것들만 담으려고 굉장히 많이 노력하고 있다고 밝힌다. 여기에 맞춰 영상을 하나 준비해 볼까 하는 고민도 하고 있다고 덧붙인다([의견]).

### [09:00–09:05] 클로징
영상은 여기까지이고, 다음 영상에서 또 유용한 소식으로 찾아오겠다는 인사로 끝난다.
