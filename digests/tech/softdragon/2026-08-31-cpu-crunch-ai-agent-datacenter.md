## 요약 (주제별)

### 1. 핵심 논지 — AI 병목의 다음 순번은 CPU
- 수요 이동 순서를 GPU → 메모리 → **CPU**로 제시한다. CPU는 AI 시대에서 소외돼 있었으나 최근 급격히 주목받고 있으며, 젠슨 황도 컨퍼런스마다 CPU를 강조한다는 것(화자 주장).
- 전환의 원인은 워크로드 성격 변화다. 1세대 생성 AI가 "사람 → GPU 추론 → 답변"이었다면, AI 에이전트는 "사람 → GPU 생각 → CPU 작업 → GPU 생각 → CPU 작업"의 반복이다. AI가 "생각만 하는 기계"에서 "컴퓨터를 직접 쓰는 노동자"가 되면서 시대가 바뀌었다는 정리.
- 파급 범위는 칩을 넘어선다 — 데이터센터의 물리적 구조와 아키텍처를 통째로 새로 지어야 할 수도 있다는 이야기까지 나온다(주장·미검증).

### 2. 시장에서 이미 관측된다는 신호들 (모두 화자 전달, 미검증)
- 인텔: 올해 만든 서버형 CPU를 연말 물량까지 이미 완판(솔드아웃).
- AWS: CPU 서버 대기 시간이 폭증해 내부 엔지니어들에게 CPU 사용량을 아끼라는 지시까지 내림.
- AMD: 데이터센터 CPU 주문이 급등 중(화자 측의 AMD 관계자 인터뷰 근거). 서버 CPU 전망치를 두 배로 상향.
- 인텔·AMD 주가는 연초 대비 급등한 상태. ARM과 퀄컴도 에이전트용 CPU를 만들겠다고 발표.
- 한 매체[불명확: 원문 "I리플리"]는 "CPU 크런치는 이제 시작에 불과할지 모른다"고 평.

### 3. 근거 ① 조지아텍 연구 — CPU 코어만 늘려도 최대 5.15배
- 엔비디아 H100 GPU를 2대 혹은 8대로 구성해 LRM(대규모 추론 모델)을 실행한 실험. GPU 구성은 그대로 두고 CPU 코어 수만 증가시킴.
- 결과: 모델마다 차이는 있으나 응답 생성 시간이 **최소 1.47배 ~ 최대 5.15배** 개선.
- 의의: CPU가 제때 일을 나눠주지 못해 GPU가 유휴 상태였다는 점이 과학적으로 확인됨. 화자에 따르면 박사급 연구자들조차 이를 몰랐고, "CPU는 한두 대면 충분하다"는 전제로 대학에 자원을 신청해 왔다(주장).

### 4. 근거 ② 인텔(+조지아텍) 연구 — 실행 시간의 대부분이 CPU
- 인텔·조지아텍 연구: 에이전트가 중간중간 CPU에 시키는 일이 **전체 실행 시간의 89%**를 차지.
- 인텔 단독 연구 설계: AI 서버 2대(하나는 GPU 성능이 상대적으로 낮은 구성, 다른 하나는 H200 등 최상급 구성)에 코드·문서 검색·웹 요약·계산기 호출·화학 연구 등 여러 에이전트를 돌려 소요 시간을 측정. "에이전트가 쓰는 시간을 CPU 관점에서 처음부터 끝까지 쟀다"고 연구가 스스로 밝힘.
- 대표 결과: 가장 무거운 작업인 분자 구조 계산은 총 34초 중 **29~30초가 CPU 몫**(전체의 약 80~90%가 CPU 병목).
- 예외: 코딩 작업은 CPU와 GPU가 둘 다 중요했다. 그 외 대부분의 에이전트 작업에서 CPU 중요성이 연구자·기업의 예상을 넘었다.
- AMD 측 분석(마두 랑가라잔 부사장[불명확: 원문 "마두랑 안가라"]): 현실적인 AI 에이전트 작업을 8단계로 쪼개 실행했더니 **7단계가 전적으로 CPU에서** 실행.

### 5. 비용 비대칭 — 1.5%짜리 부품이 나머지를 놀린다
- H100 GPU 8장 서버 이용료: 시간당 **55.04달러**.
- CPU 코어 16개 추가 비용: 시간당 **0.80달러(80센트)** — 전체 서버 가격의 **약 1.5%**[자막은 "80달러"로 들리나 비율 계산상 80센트로 교정].
- 함의: "그랜저 값"짜리 GPU들이 전체 비용의 1.5%에 불과한 CPU가 부족해서 놀고 있었다. GPU를 무작정 늘리는 것보다 상대적으로 저렴한 CPU를 균형 있게 갖추는 편이 경제적이고 성능도 좋다는 것이 CPU 수요 폭증의 이유.

### 6. 왜 병목이 생기는가 (메커니즘)
- 일반적인 AI 서버에서 CPU는 일감을 정리해 "이걸 계산해라"는 명령을 계속 만들어 GPU에 밀어줘야 한다.
- 화자의 예시: GPU가 1초 만에 계산을 끝냈는데 CPU가 다음 작업 준비에 3초가 걸리면, GPU는 "계산 끝났는데요" 하고 대기하고 CPU는 "잠깐만, 파일 읽고 있어"라고 답하는 상태 → 비싼 GPU가 유휴.
- 에이전트에서 CPU의 구체 역할: AI 출력 해석 → 어떤 도구를 부를지 결정 → 도구 실행 → 결과를 다시 AI에 반환. 계산·검색·시뮬레이션·재사고를 수십 번 반복하는 구조라 "머리"인 CPU가 중심이 된다.

### 7. 메모리·국내 종목으로의 연결고리
- 엔비디아가 공개한 서버용 CPU **'베라(Vera)'**의 소개 문구가 "AI 에이전트를 위해 만들어진 CPU".
- GPU 옆 메모리는 HBM → HBM 최강자 SK하이닉스가 급등한 배경. 반면 **CPU 옆에 꽂히는 것은 HBM이 아니라 일반 서버용 DRAM**이고, 이 영역은 삼성전자·SK하이닉스가 장악.
- 따라서 CPU 수요 증가 → 일반 서버 DRAM 수요 동반 증가 → AMD·인텔 CPU 성장세가 확인되면 삼성전자의 서버 메모리 출하도 늘어난다는 전망([의견]). 화자는 이를 "거스를 수 없는 기술의 흐름"이라 표현.

### 8. 인용된 업계 발언 (모두 화자 전달, 원문 미확인)
- 인텔 CEO 립부 탄[자막 "리프타"], 지난 6월 대만 컴퓨텍스: "엄청나게 많은 CEO가 나한테 직접 전화해서 더 많은 CPU 공급 확보를 희망했다" [08:27].
- AMD 리사 수: "지금까지 GPU와 CPU의 비율이 1대 4나 1대 8이었는데, AI 에이전트로 인해 1대 1로 CPU 수요가 폭증하고 있다. 아니, CPU가 GPU보다 많아질지도 모르겠다" [08:57].

### 9. 삽입 코너 — 채널 자체의 AI 에이전트 운영 공개 (1:41~3:04)
- 화자는 구독자 92만 기술 채널이 AI를 실제로 어떻게 쓰는지 "세계 최초로" 공개한다며 자사 파이프라인을 소개한다(내부 프로세스라 검증 불가).
- 성공 사례 자동 기록: 한 달 전 테슬라 건식 배터리 영상이 잘 되자 에이전트들이 성공 사례로 자동 기록하고 스크립트[불명확: "예스크래프트"]의 특징을 함께 저장.
- A/B 테스트: 제목·썸네일을 각 3개씩 투입해 시청 지속률이 높은 것을 AI가 선택. 결과가 나오면 어떤 조합이 왜 이겼는지를 조회수·시청 지속률·CTR·좋아요 비율과 함께 DB에 기록.
- 소재 추천: 이 DB들을 바탕으로 에이전트가 주요 언론사·논문 저널·'하이젠버그'의 연구를 수집 → 채널(SOD)의 성공 사례와의 근접도를 판단 → 성공 가능성이 높으면 텔레그램으로 기획안 보고.
- 실패 학습 사례: 테슬라 성공을 근거로 에이전트가 추천한 현대차 영상은 실패했고, 그 교훈으로 다른 모빌리티 주제를 추천해 성공했다고 밝힘[불명확: 원문 "선망을 하였죠"]. 보안상 축약·생략했다는 단서 있음.

### 10. 배경 개념 — CPU vs GPU 비유
- GPU = "평범한 병사들"(하나하나는 의미 없지만 모이면 강력), CPU = "천재 엘리트"(느리지만 정확, 하나씩 처리).
- 챗봇 질의 흐름: 사용자가 질문 → CPU가 "이 질문 계산해라"고 GPU에 전달 → 수많은 GPU가 거대한 행렬 계산 수행 → 결과 반환. GPU는 수십억 개 숫자를 동시에 곱하고 더하므로 연산량을 크게 잡아먹는 "노가다" 담당.

## 3줄 오리엔테이션
- AI 수요가 GPU → 메모리로 번졌고, 화자는 그다음 병목이 **CPU**라고 주장한다.
- 근거는 "AI 에이전트 워크로드는 대부분의 단계가 CPU에서 실행되며, GPU를 그대로 두고 CPU 코어만 늘려도 최대 5배 이상 빨라졌다"는 최근 연구들(인텔·조지아텍 등, 화자 전달).
- 파급 시나리오: 인텔·AMD의 서버 CPU 수요 급증 → CPU 옆에 꽂히는 일반 서버용 DRAM 수요 증가 → 삼성전자·SK하이닉스로 연결, 데이터센터 구성비 자체가 바뀐다.

### [00:00–00:47] 오프닝 — GPU, 메모리 다음은 CPU
AI 때문에 GPU 수요가 급증했고 그다음 메모리 수요가 급증했는데, 화자는 "그다음은 무엇인가"를 묻고 답으로 CPU를 제시한다. 젠슨 황도 각종 컨퍼런스에서 CPU를 강조하고 있으며, CPU는 지금까지 AI 시대에서 소외돼 있었지만 최근 엄청난 주목을 받고 있다는 것(주장). 근거로 세 가지를 먼저 던진다 — 인텔은 올해 만든 서버형 CPU를 연말 물량까지 이미 다 팔았고, AWS는 CPU 서버 대기 시간이 폭증해 내부 엔지니어들에게 CPU 사용량을 아끼라는 지시까지 내렸으며, 데이터센터의 물리적 구조와 아키텍처를 통째로 새로 지어야 할 수도 있다는 이야기까지 나온다(모두 화자 주장·미검증).

### [00:51–01:41] 배경 — CPU와 GPU의 역할 비유
화자는 GPU를 "평범한 병사들", CPU를 "천재 엘리트"로 비유한다. 하나씩 쏘는 쪽(느리지만 정확)이 CPU, 하나하나는 의미 없지만 모이면 강력한 쪽이 GPU이며, 게임도 AI도 모두 이 구조로 돌아간다. ChatGPT에 "삼성전자 전망 알려줘"라고 검색하면 CPU가 "GPU야, 이 질문 계산해라"라고 넘기고, 수많은 GPU가 거대한 행렬 계산을 끝낸 뒤 결과를 돌려주면 끝나는 흐름이라고 설명한다. GPU는 수십억 개의 숫자를 동시에 곱하고 더하는 연산이라 연산량을 미친 듯이 잡아먹는 노가다 담당이라는 것.

### [01:41–02:14] 삽입 코너 — 채널 운영에 쓰는 AI 에이전트 (1) 성공 사례 기록과 A/B 테스트
화자는 자신을 "과학기술 유튜버 중 에이전트를 가장 좋아하는 사람 중 하나"라고 소개하며, 구독자 92만 규모의 기술 전문 유튜브 채널이 실제로 AI를 어떻게 쓰는지 "세계 최초로" 공개하겠다고 한다. 한 달 전 올린 테슬라 건식 배터리 영상이 조회수가 잘 나오자 여러 에이전트가 이를 성공 사례로 자동 기록하고, 그 스크립트[불명확: 원문 "예스크래프트"]의 특징을 따서 함께 기록해 둔다는 것. 또 제목과 썸네일을 각각 세 개씩 넣어 시청 지속률이 높은 것을 AI가 고르도록 설계했고, 결과가 나오면 AI가 어떤 조합이 이겼는지·왜 이겼는지를 추측해 조회수·시청 지속률·CTR·좋아요 비율과 함께 DB에 기록한다(화자 주장, 내부 프로세스라 검증 불가).

### [02:14–03:04] 삽입 코너 (2) — 소재 추천 파이프라인과 실패 학습
이 데이터들과 여러 다른 DB를 바탕으로, 에이전트가 주요 언론사·주요 논문 저널, 그리고 '하이젠버그'에 올라오는 연구들을 수집한다. 그다음 그 소재가 채널(SOD)의 성공 사례와 얼마나 가까운지를 판단해 성공 가능성이 높으면 텔레그램으로 "이 소재로 이런 식으로 만들면 잘 될 겁니다"라고 화자에게 보고한다. 실패도 있는데, 얼마 전 올린 현대차 영상은 테슬라의 성공 사례를 보고 에이전트가 추천한 주제였으나 실패했고, 에이전트는 그 실패에서 교훈을 얻어 다른 모빌리티 주제를 추천했고 그건 성공했다고 말한다[불명확: 원문 "선망을 하였죠"]. 보안상 축약·생략했다는 단서를 붙인다.

### [03:04–03:33] 왜 에이전트는 CPU 중심인가
화자는 이 과정에서 AI가 답변만 하고 끝나는 게 아니라 직접 계산하고, 찾아보고, 결과를 돌리고, 시뮬레이션을 돌리고, 다시 생각하는 과정을 수십 번 반복한다는 점을 강조한다. 어떤 걸 GPU에 계산시키고 어떻게 배분할지 정하는 "머리" 역할이 중요하기 때문에 에이전트는 CPU가 중심이라는 것. 구체적으로 CPU는 AI의 출력을 해석하고, 어떤 도구를 부를지 정하고, 그 도구를 실행하고, 결과를 다시 AI에게 돌려주는 역할을 맡는다.

### [03:33–04:00] AMD 측 분석 — 에이전트 8단계 중 7단계가 CPU
AMD의 마두 랑가라잔 부사장[불명확: 원문 "마두랑 안가라 부사장"]이 분석한 바로는, 현실적인 AI 에이전트 작업을 여덟 단계로 쪼개 전부 돌려봤더니 그중 무려 일곱 단계가 전적으로 CPU에서 실행됐다고 한다(화자 전달, 미검증). 현재 인텔과 AMD 주가는 연초 대비 급등한 상태이고, 화자 측이 AMD 관계자[불명확: 원문 "AMD원분"]를 인터뷰한 결과 AMD의 데이터센터 CPU 주문도 엄청나게 급등하고 있다고 한다(주장).

### [04:00–04:27] 연구 결과 요약 — 실행 시간의 89%, 최대 5.15배
결론부터 제시하는 구간이다. 인텔과 조지아텍[자막 원문 "조자텍/조재 택"]에서 나온 연구에 따르면 에이전트가 중간중간 CPU에게 일을 시키는데 이것이 전체 실행 시간의 89%를 차지했다. 조지아텍의 다른 연구에서는 GPU는 그대로 두고 CPU 코어만 늘렸더니 답변이 나오기까지의 시간이 최대 5.15배 빨라졌다(모두 화자 전달, 원 논문 미확인).

### [04:27–04:58] 원인 — GPU가 CPU를 기다리며 논다
왜 이런 결과가 나오는가. 지금 쓰는 일반적인 AI 서버에서 CPU는 일감을 정리해 "이거 계산해라"는 명령을 계속 만들어 GPU에 밀어줘야 한다. 화자의 예시로, GPU가 계산을 1초 만에 끝냈는데 CPU가 다음 작업을 준비하는 데 3초가 걸린다고 하면, GPU는 "계산 끝났는데요" 하고 서 있고 CPU는 "잠깐만, 그 파일 읽고 있어"라고 답하는 상황이 된다. 결국 그 비싼 GPU가 CPU를 기다리며 노는 것이다.

### [04:58–05:26] 조지아텍 실험 조건과 결과 폭
조지아텍 연구진이 엔비디아 GPU H100을 2대 혹은 8대 구성으로 LRM(대규모 추론 모델)을 돌려본 실험이다. 그래프에서 파란색에서 빨간색으로 갈수록 CPU 코어 수가 늘어났다는 뜻이며, 그렇게 하니 모델마다 차이는 있지만 최소 1.47배에서 최대 5.15배 개선됐다. 더 재미있는 건 실제로 CPU가 제때 일을 나눠주지 못해 GPU가 놀고 있었다는 사실이 과학적으로 확인됐다는 점이라고 강조한다.

### [05:26–05:50] 연구자들도 몰랐다 — 비용 비대칭
화자에 따르면 박사급 연구자들조차 이 사실을 몰랐는데, 다들 "우리는 CPU가 한두 대만 있어도 충분할 것 같다"는 식으로 대학에 (자원을) 신청해 왔기 때문이다(주장). 그런데 CPU 코어만 적절히 늘려도 성능이 최대 다섯 배 가까이 늘어난다면, 한 대에 그랜저 값인 GPU를 무작정 늘리는 것보다 상대적으로 저렴한 CPU를 균형 있게 갖추는 편이 훨씬 경제적이고 성능도 좋다는 결론이 된다.

### [05:50–06:15] 숫자로 본 비대칭 — 1.5%짜리 병목
구체 수치가 제시된다. H100 GPU 여덟 장이 들어간 서버의 이용료는 시간당 55.04달러인 반면, CPU 코어 16개를 추가하는 비용은 시간당 0.80달러, 즉 80센트다[자막 원문은 "80달러요"이나 문맥·비율상 80센트로 교정]. 이는 전체 서버 가격의 1.5%에 불과하다. 그랜저 값짜리 GPU들이 전체 비용의 1.5%밖에 안 되는 CPU가 부족해서 놀고 있었다는 것이고, 화자는 이것이 지금 업계에서 CPU 수요가 폭증한 이유라고 정리한다.

### [06:15–06:48] 인텔 연구 — 두 대의 서버, 다섯 종류의 에이전트 작업
인텔이 발표한 연구는 AI 에이전트가 쓰는 시간을 CPU 관점에서 처음부터 끝까지 재봤다고 스스로 밝힌 연구다(화자 전달). 연구진은 AI 서버 두 대를 준비했는데, 한 대는 GPU 성능이 상대적으로 낮은 구성이고 다른 한 대는 현재 데이터센터에 들어가는 최상급 칩인 H200 등 좋은 부품을 쓴 구성이다. 여기에 코드, 문서 검색, 웹 요약, 계산기 호출, 화학 연구까지 여러 종류의 AI 에이전트를 돌리면서 걸린 시간을 측정했다.

### [06:48–07:17] 인텔 연구 결과 — 34초 중 29~30초가 CPU
복잡한 결과 중 가장 쉬운 것만 소개하는데, 그래프 제일 오른쪽의 무거운 작업, 즉 분자 구조를 계산하는 작업이다. 총 작업 시간이 34초였는데 그중 무려 29~30초 정도가 CPU의 몫이었고, 전체 시간의 거의 80~90%가 CPU 때문에 병목이 걸린 셈이다. 코딩의 경우에는 CPU와 GPU가 둘 다 중요했지만, 대부분의 에이전트 작업에서 CPU의 중요성은 연구자들과 기업들이 생각하는 것 이상이었다는 것이 결론이다.

### [07:17–07:43] 패러다임 정리 — 1세대 생성 AI vs 에이전트
화자는 세대 차이를 이렇게 정리한다. 1세대 생성 AI가 "사람 → GPU 추론 → 답변"이었다면, AI 에이전트는 "사람 → GPU 생각 → CPU 작업 → GPU 생각 → CPU 작업"의 반복에 가깝다. [의견] 에이전트가 에이전트를 만들고 그 에이전트들이 각자 검색하고 코드를 돌리기 시작하면, 그 검색과 실행을 맡아줄 인텔·AMD의 CPU 수요는 더욱 폭증하게 될 것이라고 전망한다.

### [07:43–08:14] 엔비디아 Vera와 메모리 연결고리
참고로 최근 엔비디아가 공개한 서버용 CPU '베라(Vera)'가 있는데, 소개 문구가 "AI 에이전트를 위해 만들어진 CPU"라고 한다. 화자는 여기서 메모리로 논지를 잇는다 — GPU 옆에 붙는 메모리는 HBM이고, 그래서 HBM 최강자인 SK하이닉스가 엄청나게 급등했다. 반면 CPU 옆에 꽂혀 있는 것은 HBM이 아니라 일반 서버용 DRAM이며, 이 시장은 삼성전자와 SK하이닉스가 꽉 잡고 있다. 따라서 CPU 수요가 늘수록 이 메모리 수요도 함께 커지게 될 것이며, "이건 거스를 수 없는 기술의 흐름"이라고 말한다([의견]·전망).

### [08:14–08:32] 인텔 CEO 발언과 국내 메모리 연결
AMD·인텔의 CPU 성장세가 확인된다면 서버에 들어가는 삼성전자의 메모리 출하[불명확: 원문 "섬전의 메모리 성향"]도 같이 늘어나게 될 것이라는 전망이다. 근거로 지난 6월 대만 컴퓨텍스에서 인텔 CEO 립부 탄[자막 원문 "리프타"]이 한 발언을 든다.

> "엄청나게 많은 CEO가 나한테 직접 전화해서 더 많은 CPU 공급 확보를 희망했다" [08:27] (화자가 전달한 인용, 원문 미확인)

### [08:32–09:08] 마무리 — CPU 크런치와 리사 수의 비율 발언
AI가 그냥 생각만 하는 기계일 때는 GPU가 가장 중요했지만, AI가 컴퓨터를 직접 사용하는 "노동자"가 되면서 시대가 완전히 바뀌고 있다는 것이 화자의 정리다. 한 매체[불명확: 원문 "I리플리"]에서는 CPU 크런치가 이제 시작에 불과할지도 모른다고 했고, AMD는 서버 CPU 전망을 두 배로 늘렸으며, 인텔은 이미 솔드아웃, ARM과 퀄컴도 에이전트용 CPU를 만들겠다고 발표했다(모두 화자 전달, 미검증). 마지막으로 AMD 리사 수의 발언을 인용하며 끝난다.

> "지금까지 GPU와 CPU의 비율이 1대 4나 1대 8이었는데, AI 에이전트로 인해서 1대 1로 CPU 수요가 폭증하고 있다. 아니, CPU가 GPU보다 많아질지도 모르겠다." [08:57] (화자가 전달한 인용, 원문 미확인)
