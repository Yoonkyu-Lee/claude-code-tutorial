## 요약 (주제별)

### TeamPCP는 누구이며 왜 핫한가
- 스스로를 "생계에 어려움을 겪는 10대·젊은 성인의 느슨한 조직, 돈을 위해 활동하는 해킹 그룹"이라 소개한 범죄 수익형 그룹(화자 인용, 인터뷰 매체명 [불명확: 원문 "호브스"]).
- 다른 범죄 수익형 그룹과 차별화되는 특기가 "공급망 공격"이라 전 세계 보안 업계가 주목하고 범죄자 사이에서도 "핫스타"가 됐다.

### 공급망 공격의 개념 (화자 비유)
- 개발자는 코드를 100% 직접 짜지 않고 남이 만든 라이브러리·패키지를 가져다 쓴다("Don't reinvent the wheel"). TeamPCP는 그 "바퀴 공장"을 턴다.
- 코드가 모인 저장소 NPM·PyPI를 "곡간"에 비유 — 여기에 독을 타면 그 재료로 만든 모든 결과물이 오염된다. 보안 도구가 CI/CD에서 자동 실행되므로 한 번 감염되면 개발자가 저장을 누르는 순간 악성 코드가 자동 실행·확산된다.

### 감염 연쇄 타임라인 (화자 인용 사건·수치)
- 2026-03-19: Trivy(보안 스캐너, GitHub Actions/CI/CD에서 자동 실행) 해킹 → 개발자 해킹으로 저장소에 독 주입, 4시간 내 수천 파이프라인 도달.
- Trivy 독은 크리덴셜(ID·비밀번호·토큰) 수집 → Checkmarx KICS로 확산(KICS도 CI/CD 자동 실행 도구라 투트랙화).
- LiteLLM(AI 모델 연결 라이브러리) 감염 → 메타·오픈AI 라벨링 파트너 Mercor[원문 "머코어"] 해킹, Telnyx[원문 "텔닉스"]도 개발자 토큰 경유로 감염.
- 유럽 집행위 클라우드, Cisco(Trivy 사용)도 이 공급망 공격으로 피해.
- Checkmarx 재해킹(도발): 저장소명 "Checkmarx TeamPCP", 설명란 "비밀번호 바꾸는 거 깜빡했나 봐요. 사랑을 담아서 팀 PCP" + 악성 코드 재삽입 → Bitwarden CLI 버전까지 감염.
- 2026-05-11: TanStack[원문 "10스택"]에 웜 투하, 5시간 만에 172개 패키지·400+ 악성 버전 확산 → Mistral AI, Nx 토큰 탈취.

### 자가복제 웜 "미니 샤이 훌루드"
- 단순 악성 코드가 아니라 "자격 증명 탈취 + 자체 확산형 웜". 웜은 바이러스(기생형)와 달리 독립 프로그램으로 스스로 자가복제·확산.
- 이름은 듄(Dune)의 모래벌레 "샤이 훌루드"에서 따온 것으로 TeamPCP가 명명. 작년 샤이 훌루드의 개량판이 미니 샤이 훌루드.
- 동작: 감염 PC의 크리덴셜을 훑어 저장소 접근용(NPM·PyPI 등)이 나오면 그 저장소에 자기 자신을 복제·주입 → 주입 자동화.
- 사용 기법(TanStack 주입): Pull Request 공격 + GitHub Actions Poisoning + 런타임 메모리 갈취 3종 조합(자막 오인식 교정, 세부 명칭에 [불명확] 여지). 화자는 상세 설명을 다음 영상으로 예고.

### GitHub 대형 유출과 도발
- 악성 Nx Console(VS Code 확장)은 게시 18분 만에 삭제됐으나 6천 건 다운로드. 그중 GitHub 직원 PC가 있어 GitHub 내부 저장소 3,800개 소스 코드 유출(화자 인용).
- TeamPCP가 GitHub 데이터 판매 글 게시 → GitHub는 "약 3,800개 저장소 유출 규모는 조사 결과와 대체로 일치"라고 확인(주체 해석에 [불명확] 여지).
- BreachForums[원문 "브릿치 포럼"]와 콜라보 공모전: 샤이 훌루드 오픈소스 공개 + 최대 규모 공급망 공격자에게 1,000달러(약 150만 원) 지급.
- 유통 구조: TeamPCP는 해킹만 하고 랜섬웨어 그룹[원문 "벡트/벡터"]을 유통사로 지정. 대어를 낚으면 직접 판매글도 올림(Mistral AI 등).

### 화자의 보안 교훈 (일반 사용자·개발자용)
- 타겟 전환: 해커가 일반인에서 개발자로 목표를 옮김.
- 확장 프로그램(VS Code 확장·브라우저 확장·AI 도구)이 새 위험 지점 — 개발자가 악의 없이 만든 정상 프로그램도 공급망 공격으로 오염될 수 있음.
- 자동 업데이트는 위험 요소지만 끊지 말 것 — 보안 업데이트는 꼬박꼬박.
- 바이브 코딩 주의: AI가 만든 코드가 어떤 라이브러리·패키지·버전을 쓰는지 모르는 경우가 많음 → 사용 버전 리스트를 직접 관리하고 취약점을 그때그때 확인해야 함(AI가 자동으로 챙겨주지 않음).
- 보안은 "뚫리고 막고"의 반복이라 끝나지 않는다.

### [의견] 방어 투자의 딜레마
- 보안 예산은 성과가 "사고가 안 남"이라 정당화가 어렵다. 작년 1억으로 해킹이 없었다면 올해 2억은 못 쓰고, 오히려 "8천만 원으로도 되지 않을까"로 줄이게 됨. 충분해서 안 났는지 아슬아슬해서 안 났는지 알 수 없어 예산을 줄이다 결국 당한다 — 이것이 정보보안의 근본적 어려움.

## 3줄 오리엔테이션
- TeamPCP는 돈을 노리는 해킹 그룹으로, 개발자들이 공통으로 가져다 쓰는 라이브러리·보안 도구(공급망)에 악성 코드를 심어 한 번에 광범위하게 감염시키는 "공급망 공격"을 주특기로 한다.
- 보안 스캐너 Trivy 해킹(2026-03-19)을 시작으로 KICS·LiteLLM·Bitwarden·TanStack·Nx 등으로 독이 연쇄 확산됐고, 자가복제 웜 "미니 샤이 훌루드"까지 등장해 Mercor·Mistral AI·GitHub 등 대형 피해자가 나왔다.
- 화자의 결론: 해커의 타겟이 일반인에서 개발자로 옮겨갔으며, 확장 프로그램·자동 업데이트·바이브 코딩이 새 위험 지점이고 보안은 결코 "끝낼 수 있는" 일이 아니다.

## 전문 — 시간순 워크스루

### [00:00–00:25] 정상 프로그램이 좀비로 돌변한다는 도입
늘 쓰던 프로그램이 사실 악성 코드였다면, 업데이트를 하는 순간 내 프로그램이 좀비로 바뀐다는 문제 제기로 문을 연다. 오늘의 주인공은 "팀 PCP(TeamPCP)"로, 이름만 들으면 PC방 같지만 현재 전 세계 사이버 보안 업계가 주목하는 핫한 해킹 그룹이라고 소개한다.

> "우리가 늘 쓰고 있었던 프로그램이 악성 코드라면 업데이트를 하니까 좀비로 바뀌는 거예요." [00:00]

### [00:25–01:05] TeamPCP의 정체 — 돈을 노리는 범죄 수익형 그룹
TeamPCP의 일원 한 명이 한 매체와 인터뷰에서 스스로를 "생계 유지에 어려움을 겪는 10대와 젊은 성인들로 구성된 느슨한 조직"이며 "돈을 위해 활동하는 해킹 그룹"이라고 소개했다고 전한다(화자 인용). 전형적인 범죄 수익형 해킹 그룹이라는 것. 그런데 이런 그룹이 이들만 있는 것도 아닌데 왜 유독 뜨거워졌느냐 하면, 이들이 특별히 잘하는 게 있기 때문 — 바로 공급망 공격이다.
- 인터뷰 상대 매체명은 자막이 "호브스"로 들려 [불명확: 원문 "호브스"]로 남긴다.

### [01:05–02:28] 공급망 공격이란 — "바퀴 공장을 턴다"
공급망 공격을 라면 스프에 비유한다. 프로그래머도 처음부터 모든 코드를 100% 짜지 않고, 남이 만들어 둔 코드 조각(라이브러리·패키지)을 가져다 쓴다. 예로 웹사이트에 지도를 넣을 때 구글 맵 SDK 같은 라이브러리를 그대로 가져온다. 개발자 모토 중 하나가 "Don't reinvent the wheel(바퀴를 다시 만들지 마라)"인데, TeamPCP는 바로 그 "바퀴 공장"을 털어버린 것이 공급망 공격이다. 이런 코드가 모인 곳(저장소)의 대표가 NPM과 PyPI이며, 화자는 이를 재료를 저장해 두는 "곡간"에 비유한다 — 여기에 독을 타면 그 재료로 만든 모든 요리가 독이 된다.

> "이 팀 PCP는 바퀴 공장을 턴 겁니다. 이게 바로 공급망 공격인 거예요." [01:48]

### [02:28–04:07] 첫 사건 — Trivy 해킹(2026-03-19)과 4시간 내 확산
2026년 3월 19일, TeamPCP가 Trivy(트리비)를 해킹한다. Trivy는 취약점을 찾아주는 보안 스캐너 도구인데, 문제는 이 도구가 GitHub Actions 등 CI/CD 파이프라인에서 자동으로 많이 쓰인다는 점이다. 개발자가 코드를 수정해 저장소(곡간)에 넣을 때 잘못된 부분이 없는지 자동 검사하는 과정(CI/CD)에서 Trivy가 자동 실행되는데, 그 Trivy에 독이 타지면 개발자가 저장을 누르는 순간 그 개발자 컴퓨터에서 악성 코드가 자동 실행된다. TeamPCP는 Trivy 개발자를 해킹해 Trivy 저장소에 독을 풀었고, 그 결과 4시간 이내에 수천 개의 파이프라인에 도달했다고 한다(화자 인용).

### [04:07–05:00] 크리덴셜 탈취와 Checkmarx KICS로의 확산
Trivy 독 버전이 실행되면 "자격 증명 수집" 코드가 돈다. 크리덴셜(아이디·비밀번호, 로그인 시 발급되는 토큰·티켓 같은 인증 정보)을 몰래 훔쳐가는 것이라, Trivy로 자동 관리하던 개발자들이 다 털렸다. 그중 하나가 Checkmarx(체크막스)의 KICS라는 도구였고, KICS의 인증 정보까지 TeamPCP가 얻어갔다. 문제는 KICS도 Trivy처럼 CI/CD에서 자동 실행되게 많이 쓰이는 도구라, TeamPCP는 KICS에도 독을 풀어 공격을 "투트랙"으로 확장했다.
- KICS = Checkmarx가 만든 IaC(코드형 인프라) 보안 스캐너. 자막의 "킥스"를 문맥 교정.

### [05:00–06:10] LiteLLM·Mercor·Telnyx로 이어지는 연쇄
다음 희생자는 LiteLLM(라이트LLM) — ChatGPT·Claude 같은 여러 AI 모델을 연결해 주는 라이브러리로, AI 개발자라면 모를 수 없고 AI 프로그램이 내부에서 많이 쓴다. Trivy에 독을 탔더니 KICS와 LiteLLM 둘의 토큰까지 덩달아 "자진 납세"로 떨어졌다는 표현. 그 여파로 메타와 오픈AI의 라벨링 파트너인 Mercor(머코어)가 해킹당해 AI 업계에 비상이 걸렸다는 기사가 났다. 여기에 LiteLLM을 쓰던 Telnyx(텔닉스) 개발자도 해킹당해, 그 개발자의 토큰이 털리면서 Telnyx에도 독이 들어갔다.
- 라벨링 파트너명 자막 "머코어"를 Mercor로 교정(문맥 근거). 확정 불가하면 원문 병기: Mercor[원문 "머코어"].

### [06:10–07:03] EU 집행위·Cisco 피해와 Vext 랜섬웨어 파트너십
독은 계속 퍼져, 유럽 집행위(European Commission) 클라우드가 해킹당했던 기사도 이 TeamPCP의 공급망 공격이었고, Cisco(시스코)도 Trivy를 썼기 때문에 털렸다. "한 번 독을 제대로 타면 알아서 퍼진다"는 것이 공급망 공격의 위력. 데이터가 너무 많이 쏟아지자 TeamPCP는 전략을 세워, 한 랜섬웨어 그룹과 파트너십을 체결한다. 상대 그룹이 "TeamPCP와 파트너십을 체결했다"고 발표했는데, 즉 TeamPCP는 해킹만 하고 그 랜섬웨어 그룹을 "유통사"로 지정한 구조다.
- 파트너 랜섬웨어 그룹명은 자막이 "벡트/벡터"로 흔들려 [불명확: 원문 "벡트/벡터"]로 남긴다.

### [07:03–08:23] Checkmarx 재해킹 도발과 Bitwarden CLI 감염
본격적으로 "제대로 털어보자"며, 앞서 해킹했던 Checkmarx에 TeamPCP가 다시 들어가 재해킹한다. 이번엔 도발적으로, 깃 저장소 이름을 "Checkmarx TeamPCP"로 바꾸고 설명란을 "비밀번호 바꾸는 거 깜빡했나 봐요. 사랑을 담아서 팀 PCP"로 고쳤다. 이름만 바꾼 게 아니라 악성 코드까지 심어두고 나갔다. 그런데 이 플러그인을 쓰던 개발자 중에 Bitwarden(비트워든, 비밀번호 관리 프로그램) 개발자가 있어 그도 당했고, TeamPCP는 Bitwarden의 CLI 버전에 악성 코드를 심어 뿌린다. 그래서 Bitwarden CLI 버전 사용자는 해킹당했을 가능성도 있다는 것.

> "비밀번호 바꾸는 거 깜빡했나 봐요. 사랑을 담아서 팀 PCP" [07:38]

### [08:23–09:26] TanStack 공격 — 세 가지 기법 조합
공급망 공격에 "맛을 본" TeamPCP의 다음 표적은 TanStack(자막 "10스택")이다. NPM에 관리되던 라이브러리(패키지)로, 웹 서버 개발에 많이 쓰는 리액트 프레임워크 중 하나라 사용자가 매우 많다. 여기엔 기존 기술 세 가지 — Pull Request 공격, GitHub Actions Poisoning, 런타임 메모리 갈취 — 를 조합해 악성 코드를 주입했다. 화자는 이 기법들이 딥하다며 다음 기회에 쉽게 설명하겠다고 예고한다.
- 프레임워크명 자막 "10스택"을 TanStack으로 교정(NPM·리액트 프레임워크라는 문맥 근거).
- 세 기법 명칭은 자막 오인식("폰 리퀘스트", "갈치 총")을 문맥 교정한 것으로, Pull Request/런타임 메모리 갈취 표기에 [불명확] 여지 있음.

### [09:26–10:28] 자가복제 웜 등장 — 미니 샤이 훌루드
TanStack에 푼 독은 단순 악성 코드가 아니라 "자격 증명 탈취 악성 코드이자 자체 확산형 웜"이었다. 화자는 웜과 바이러스 차이를 설명한다 — 바이러스는 다른 프로그램·프로세스에 기생해 실행되는 악성 코드, 웜은 독립 프로그램으로 스스로 자가복제·확산하는 "살아 있는 벌레" 같은 것. 이 웜의 이름이 "미니 샤이 훌루드(Mini Shai-Hulud)"로, 듄(Dune)에 나오는 거대한 모래벌레를 뜻하며 "패키지들을 먹어치우며 퍼진다"는 의미로 TeamPCP가 직접 붙였다. 작년에 나온 "샤이 훌루드"를 이번에 개량한 버전이 미니 샤이 훌루드다.
- 자막 "균에서 나오는 거대한 모래벌레"는 "듄(Dune)에서 나오는"의 오인식으로 교정.

### [10:28–11:27] 웜의 자동화 동작 원리
악성 코드가 실행되면 그 컴퓨터의 크리덴셜을 싹 훑고, 그중 저장소 접근용 크리덴셜(NPM·PyPI 등)이 나오면 그 저장소에 자기 자신을 복제·주입까지 한다. 즉 "악성 코드 주입"을 자동화한 것 — 이전까지는 직접 주입하고, 새 표적이 오면 또 주입하는 게 번거로웠는데, 해커들도 이를 자동화한 셈이다.

### [11:27–12:38] 5월 11일 투하 — 172개 패키지·400+ 버전, Mistral AI·Nx
미니 샤이 훌루드는 2026년 5월 11일 투하됐고, 다섯 시간 만에 172개의 서로 다른 패키지에 걸쳐 400개 이상의 악성 코드 버전을 뿌렸다(화자 인용). 이렇게 털린 곳 중 하나가 Mistral AI다 — 원래 유통은 협력사가 맡되, 가끔 "대어"를 낚으면 TeamPCP가 직접 나와 "미스트랄 AI 우리 판이다"라고 판매 글을 올린다. 더 무서운 건, TanStack에 웜을 뿌렸을 때 하필 Nx 개발자들이 있어 Nx 토큰도 TeamPCP가 가져갔다는 점. 그 결과 VS Code 확장 프로그램인 Nx Console(NX 콘솔)에 악성 버전이 추가됐고, 이 확장을 설치·실행하면 해당 환경에서 GitHub·NPM 크리덴셜을 찾아 외부로 전송한다.
- 자막 "10스택"→TanStack, "MPM"→NPM, "기터"→GitHub로 문맥 교정.

### [12:38–13:09] 18분 만에 삭제됐지만 6천 건 다운로드, GitHub 3,800 repos 유출
악성 Nx Console 버전은 게시 18분 만에 삭제됐지만, 그 사이 6천 건이 다운로드됐다. 그리고 그 6천 건 중에 하필 GitHub 직원의 컴퓨터가 있어, GitHub 내부 저장소 3,800개의 소스 코드가 털렸다(화자 인용). TeamPCP가 또 대어를 낚은 것.

### [13:09–14:04] GitHub 판매 글과 GitHub의 공식 확인
TeamPCP는 "이번엔 GitHub다"라며 GitHub 데이터를 판다는 글을 올린다. 가짜·과장 정보일 수도 있어 GitHub에 사실 여부를 물으니, GitHub는 "공격자가 주장하는 약 3,800개의 저장소 유출 규모는 지금까지의 조사 결과와 대체로 일치합니다"라고 답했다(화자 인용). 화자는 "대체로 일치"라는 표현이 "틀린 말은 아닌데 완전히 맞다고 하긴 애매한, 맞는 방향" 정도의 뉘앙스라고 해석한다.
- 자막 "기/기터/깃업"은 문맥상 모두 GitHub로 교정. 사실 여부를 물은 대상과 답변 주체를 GitHub로 해석했으며, 이 해석에는 [불명확] 여지 있음.

> "공격자가 주장하는 약 3,800개의 저장소 유출 규모는 지금까지의 조사 결과와 대체로 일치합니다." [13:32]

### [14:04–14:59] 파급력과 BreachForums 콜라보 공모전
TeamPCP의 파급력은 지금 장난이 아니고, 전 세계 보안 업계가 주목하며 범죄자들 사이에서도 "핫스타"가 됐다. 이 인기를 업고, BreachForums(브릿치 포럼)와 콜라보로 공모전을 연다 — "샤이 훌루드를 오픈 소스로 공개하겠다"며, 가장 큰 규모의 공급망 공격을 한 사람에게 1,000달러(약 150만 원)를 지급하겠다는 것. 화자는 금액 자체는 크지 않지만 "이런 장난까지 하고 있다"는 점이 시사하는 바가 크다고 본다. 그러면서 이 사건은 아직 끝난 게 아니며 밝혀진 것은 여기까지고, 공급망 공격의 여파는 다 확인되지 않았고 어쩌면 지금이 시작일 수도 있어 무섭다고 말한다.
- 포럼명 자막 "브릿치 포럼"을 BreachForums로 교정.

### [14:59–15:47] 교훈① — 타겟이 개발자로, 확장 프로그램을 조심
분위기가 바뀌었다 — 예전엔 일반 사용자를 노렸다면 이제 해커들은 "개발자를 털자"로 목표를 바꿨다. 앞으로 특히 조심할 것은 확장 프로그램이다: VS Code 확장, 브라우저 확장, 그리고 많이 쓰는 AI 도구들. 최근 이런 확장 프로그램에 의한 해킹 제보가 화자에게 들어오고 있으며, 개발자가 악의 없이 만든 정상 프로그램에도 공급망 공격으로 악성 코드가 삽입되는 경우가 있다고 한다.

> "일반인이 아니라 개발자를 털자." [15:07]

### [15:47–16:31] 교훈② — 자동 업데이트와 바이브 코딩의 위험
시대가 또 바뀐 지점으로 "자동 업데이트가 조금 위험할 수도 있다"를 든다. 다만 자동 업데이트를 하지 말라는 건 아니고, 보안 업데이트는 꼬박꼬박 해야 한다. 더 걱정되는 건 바이브 코딩 — AI에게 "만들어 줘"만 해서 만든 사이트·프로그램이 어떤 라이브러리·패키지를 쓰는지 모르는 사람이 대부분이라, 공급망 공격의 영향력이 앞으로 더 커질 것이다. 바이브 코딩을 하는 사람은 자기 코드가 쓰는 라이브러리·패키지 버전이 안전한지 체크해 보길 권한다.

### [16:31–17:34] 교훈③ — 버전 리스트 관리와 "끝나지 않는" 보안
자기 코드가 쓰는 라이브러리·패키지 버전 리스트는 스스로 관리하고 있어야 하며, 그 버전에서 취약점이 나오는지는 그때그때 확인해야 한다. AI가 알아서 "그거 취약해"라고 자동으로 챙겨주지 않기 때문. 한 번 안전 확인하고 신경을 끄면 안 되는 이유는, 지금은 안전하다고 확신했던 패키지에서도 나중에 취약점이 나오기 때문이다. 정보보안은 "뚫리고 막고"의 반복이라 절대 끝나지 않으며, 끝날 수 있는 유일한 방법은 사람들이 세뇌돼 생각하는 힘을 잃었을 때뿐이라고 표현한다.

> "열심히 한번 딱 해 놓고 신경을 끄고 싶은데 그러면 안 돼. 계속 잘해야 돼요." [16:56]

### [17:34–18:22] [의견] 방어 투자의 딜레마
[의견] 화자는 "보안계 월급이 두 배로 오르겠냐"는 물음에 "그건 아니다"라며, 방어에 돈 쓰는 것이 늘 아깝게 여겨지는 회사 입장을 이해한다고 말한다. 예로 작년에 정보보안에 1억을 써서 해킹이 안 일어났다면, 올해 2억을 쓰기는 어렵다 — 1억으로도 됐으니까. 오히려 "1억으로 됐는데 8천만 원으로 되지 않을까" 하며 줄이게 되고, 1억이 충분해서 안 됐는지 아슬아슬하게 안 됐는지 알 길이 없기에 예산을 줄이다 결국 당한다. 이것이 정보보안의 근본적 어려움이라는 것으로 영상을 맺는다.
