## 요약 (주제별)

### 1. M5 Ultra 핵심 스펙과 화자가 주목한 지점
- 애플이 M6와 M5 Ultra를 함께 공개. M6는 애플 최초의 2nm 칩이지만, 화자가 먼저 주목한 건 M5 Ultra의 **통합 메모리 대역폭 1.2TB/s**.
- M3 Ultra는 800GB/s 이상 → M5 Ultra 1.2TB/s로 **약 50% 증가**. 메모리 **용량**은 M3 Ultra도 이미 최대 512GB였으므로 크게 늘어난 게 아니고, 달라진 건 **읽어오는 속도**.
- 화자의 요약: "큰 모델을 넣을 메모리는 이미 있었고, 이번엔 그 모델을 움직이는 **통로**가 넓어졌다."

### 2. 칩 구조 — 4다이 + 차세대 울트라 퓨전
- M시리즈 **최초의 4다이 구조**. 듀얼 다이 M5 Max 두 개를 차세대 울트라 퓨전으로 결합, 물리적으로는 4개 다이지만 소프트웨어에서는 하나의 프로세서처럼 동작.
- 칩을 쪼개면 제조에는 유리하나 다이 간 통신 지연이 성능을 깎음 → 울트라 퓨전은 패키징 단계에서 다이 사이에 대량의 고속 신호선을 연결.
- 이번 세대 **연결 밀도 이전 대비 6배 이상**, **다이 간 대역폭 4.4TB/s 이상**.
- 두 숫자의 역할 구분(화자가 명시): 1.2TB/s = 통합 메모리 대역폭 / 4.4TB/s = 다이를 묶는 내부 연결 속도.

### 3. LLM 추론 구조 — 프리필 vs 디코드
- **프리필(prefill)**: 프롬프트·문서·코드 입력을 한 번에 읽는 구간. 입력 토큰을 병렬 계산 → **행렬 연산 성능** 의존. M5 세대 GPU 코어마다 들어간 **뉴럴 액셀러레이터**가 여기서 작동.
- **디코드(decode)**: 답을 한 토큰씩 생성하는 구간. 매 토큰마다 거대한 모델 가중치를 메모리에서 읽어야 함 → **메모리 대역폭** 의존.
- 코딩 에이전트는 답 생성 토큰보다 코드·파일·도구 실행 결과를 **읽는** 토큰이 훨씬 많을 수 있어, 프리필이 느리면 매 작업마다 긴 코드 재독에 시간이 크게 소모됨.
- 대역폭 산수(화자의 단순화 가정, 실측 아님): 양자화 dense 모델 가중치 100GB를 토큰당 한 번 훑는다고 가정 시 800GB/s → 이론상 초당 약 8회, 1.2TB/s → 약 12회. 화자는 "실제 속도가 정확히 8/12토큰이라는 뜻은 아니다"라고 단서를 붙임.

### 4. 애플 실리콘의 통합 메모리 구조와 맥 스튜디오의 위치
- 일반 PC는 시스템 RAM과 GPU VRAM이 분리되어 있지만, 애플 실리콘은 CPU·GPU가 같은 통합 메모리를 공유 → 맥 스튜디오에서 GPU가 수백 GB 풀에 직접 접근 가능.
- 엔비디아 데이터센터 GPU와 단순 비교 대상이 아니라고 화자가 선을 그음: 최신 HBM 기반 AI 가속기는 대역폭 자체가 수 TB/s 단위이고, 대규모 학습·다중 사용자 동시 처리 서버는 엔비디아가 훨씬 강함.
- 맥 스튜디오의 의미는 **한 명의 사용자가 책상 위 한 대에서 GPU 접근 가능한 수백 GB 메모리를 거의 통째로 쓰며 큰 모델을 계속 돌린다**는 데 있음.

### 5. 오픈 모델 격차 축소와 MLX 생태계
- 몇 년 전엔 성능 좋은 모델이 OpenAI·구글·Anthropic 서버 안에 있어 개인이 받을 수 있는 모델과 격차가 컸으나, 지금은 그 간격이 빠르게 축소.
- 최근 공개된 **270억 파라미터 규모 멀티모달 모델**을 직접 내려받아 사용 가능 (모델명은 `[불명확: 원문 "QN 3.8 27빌리언"`, Qwen 계열 추정]).
- **MLX** = 애플 머신러닝 연구팀이 만든 애플 실리콘용 오픈소스 프레임워크. 그 위의 **MLX LM**으로 모델 로드·양자화·파인튜닝·실행을 비교적 간단히 처리.
- 허깅페이스 MLX 커뮤니티에 이미 **수천 개 모델**. 새 오픈 모델이 나오면 4비트·8비트 등 MLX 변환본이 빠르게 따라오고, **MTP(멀티 토큰 예측)를 스페큘레이티브 디코딩에 쓰는 드래프트 모델**까지 나옴 → 사용자가 직접 변환·양자화·실행환경 구축할 필요 없음.
- 올해 WWDC에서 **MLX LM 서버로 OpenAI API 호환 로컬 서버를 만드는 방법**을 직접 시연. 기존 코딩 에이전트의 API 주소만 로컬로 바꾸면 되고, 에이전트는 백엔드가 클라우드인지 책상 위 맥 스튜디오인지 신경 쓸 필요가 없음.
- [의견] 화자는 MLX를 "애플이 하나 더 만든 ML 프레임워크"가 아니라 **새 오픈 모델을 애플 실리콘으로 가져오는 통로**로 평가.

### 6. 애플 자체 파운데이션 모델 3세대
- 올해 애플이 **구글과 함께 만든 3세대 애플 파운데이션 모델** 공개. 온디바이스 모델과 프라이빗 클라우드 컴퓨트 서버 모델을 분리 운영.
- 가장 큰 온디바이스 모델은 전체 규모 **약 200억 파라미터**.
- 메모리 전략: **전체 가중치를 NAND에 저장**하고 요청에 필요한 **전문가(expert) 일부만 DRAM으로 로드**. NAND는 DRAM보다 훨씬 느려 매 토큰마다 전문가를 교체하면 병목이 커지므로, 첫 요청 처리 시 필요한 전문가를 골라두고 생성 중에는 데이터 이동을 줄이는 설계.
- 화자가 뽑는 공통 주제: 모델이 커질수록 **얼마나 계산하느냐 못지않게 가중치를 어디에 두고 얼마나 빨리 가져오느냐**가 중요해짐.

### 7. 남는 질문과 화자가 해보고 싶은 3가지 테스트
- 파이프라인(새 모델 공개 → MLX 변환본 → 로컬 서버로 에이전트 연결)은 이미 빨라졌고, 남은 질문은 **"얼마나 빠르게 돌아가느냐"** 하나.
- [의견] 화자는 512GB M5 Ultra 구매를 고민 중이나 "콘텐츠 하나 찍겠다고 덜컥 살 만한 가격은 아니"라고 함.
- 구비 시 테스트 항목 ① 실제 사용 가능한 가장 큰 오픈 모델의 **디코드 속도(토큰/초)** ② Qwen 계열 모델 + **MTP 드래프터 스페큘레이티브 디코딩**의 체감 속도 향상폭 ③ **코딩 에이전트를 몇 시간 연속 돌려도 클라우드 API 대신 로컬 모델을 쓸 만한지** — 화자는 ③이 가장 궁금하다고 밝힘.
- [의견] 갈림길: 초당 두세 토큰이면 결국 손이 안 감 / 충분한 속도 + 빠른 프리필이면 사용 방식 자체가 바뀜(토큰 사용량 신경 안 쓰고 에이전트 장시간 구동, 외부 서버로 보내기 싫은 코드·문서도 전부 로컬 처리).

### 8. 애플의 AI 경쟁 위치 재평가 (화자 논지)
- 그동안의 평가: 애플 인텔리전스 출시 후 애플은 AI 경쟁에서 뒤처졌다는 평. 새 Siri는 지연, OpenAI·구글·Anthropic이 프런티어 성능을 올리는 동안 애플 자체 모델 존재감은 약했음.
- 현재의 세 갈래 진전: ① 자체 파운데이션 모델 3세대 ② 구글과 협력해 외부 모델 수용 ③ MLX로 오픈 모델을 애플 실리콘 위로 이식.
- 구조적 이점: **좋은 오픈 모델이 세상에 나올수록, 애플이 직접 학습하지 않았는데도 맥에서 할 수 있는 일이 함께 늘어남.**
- [의견] 애플이 이미 가진 자산(자체 실리콘 설계, 통합 메모리 구조, macOS + 개발 도구, 플랫폼 맞춤 MLX)이 여기서 크게 작용. "모델 하나만 놓고 경쟁할 때는 불리했지만, 경쟁축이 '좋은 모델을 어떤 기기에서 얼마나 빠르고 편하게 오래 돌리느냐'로 넓어지면 애플이 원래 잘하던 영역과 다시 겹친다."

## 3줄 오리엔테이션
- 화자는 M5 Ultra에서 512GB 통합 메모리 용량보다 **1.2TB/s 메모리 대역폭**(M3 Ultra 대비 약 50% 증가)에 주목한다. 큰 모델을 "올리는 것"은 이미 됐고, 이제 "쓸 만한 속도로 움직이는가"가 남았다는 논지.
- LLM 추론을 프리필(입력 읽기, 행렬 연산 성능 의존)과 디코드(토큰 생성, 메모리 대역폭 의존)로 나눠 설명하며, 코딩 에이전트처럼 몇 시간씩 코드를 반복해 읽는 작업에서 두 구간 모두가 체감 시간으로 누적된다고 본다.
- 하드웨어(4다이 구조·울트라 퓨전)와 소프트웨어(MLX 생태계, 오픈 모델 급성장, 애플 자체 파운데이션 모델 3세대)가 맞물리면서, "모델 자체 경쟁"에서 불리했던 애플이 "좋은 모델을 어떤 기기에서 얼마나 오래 편하게 돌리느냐"라는 확장된 경쟁축에서는 원래 강점과 다시 겹친다는 것이 화자의 결론.

## 전문 — 시간순 워크스루

### [00:00–00:39] M6가 아니라 M5 Ultra의 숫자 하나
애플이 M6와 함께 M5 Ultra를 공개했다. M6는 애플 최초의 2nm 칩이라 그 자체로 볼 게 많지만, 화자는 오히려 M5 Ultra의 숫자 하나가 먼저 눈에 들어왔다고 말한다. 그 숫자는 **통합 메모리 대역폭 초당 1.2TB**다. 메모리 용량은 M3 Ultra도 이미 최대 512GB를 지원했으므로 갑자기 크게 늘어난 게 아니고, 달라진 건 그 메모리를 읽어오는 속도다.

> "M3 울트라가 800GB/세컨드 이상이었다면 M5 울트라는 1.2TB/세컨드, 그러니까 50%가 는 거예요." [00:32]

### [00:39–01:26] 로컬 AI에서 지금까지의 기준: 용량
그동안 거대한 AI 모델을 로컬에서 돌린다고 하면 가장 먼저 본 건 메모리 **용량**이었다. 모델 파일이 100GB, 200GB를 넘어가면 일단 메모리에 들어가야 시작이라도 할 수 있기 때문이다. 애플 실리콘은 CPU와 GPU가 같은 통합 메모리를 쓰기 때문에 이 지점에서 원래부터 독특했다 — 일반 PC는 시스템 RAM과 GPU VRAM이 나뉘어 있지만, 맥 스튜디오에서는 GPU가 수백 GB짜리 통합 메모리 풀에 직접 접근할 수 있다. M3 Ultra 때 이미 최대 512GB까지 지원했기 때문에 큰 모델을 올리는 것 자체는 가능했다.

### [01:26–01:55] 올라가는 것과 쓸 수 있는 것은 다르다
그런데 모델이 그냥 올라가는 것과 실제로 그걸 쓸 수 있는 것은 다른 얘기다. 아무리 똑똑한 모델이어도 초당 두세 토큰씩 답이 나오면 오래 쓰기 어렵다. 질문 하나 하고 기다리는 정도는 괜찮지만, 코딩 에이전트에게 코드를 읽히고 수정시키고 테스트 결과를 다시 읽히는 작업을 몇 시간씩 계속하면 그 속도 차이가 그대로 작업 시간으로 누적되기 때문이다. 그래서 요즘 개인용 로컬 AI에서는 모델 크기와 함께 **토큰/초(tokens per second)** 가 굉장히 중요해졌다.

### [01:55–02:33] 추론의 두 구간 ①: 프리필과 코딩 에이전트
LLM 추론은 크게 두 구간으로 볼 수 있다. 넣은 프롬프트·문서·코드 같은 **입력을 한 번에 읽는 프리필(prefill)**, 그리고 그 내용을 바탕으로 답을 한 토큰씩 만들어내는 **디코드(decode)** 다. 프리필은 많은 입력 토큰을 병렬로 계산할 수 있어 행렬 연산 성능의 영향을 크게 받는데, M5 세대 GPU 코어마다 들어간 **뉴럴 액셀러레이터**가 이 구간에서 힘을 쓴다. 특히 코딩 에이전트는 실제로 답을 만드는 토큰보다 코드·파일·도구 실행 결과를 계속 읽는 토큰이 훨씬 많을 수 있어서, 프리필이 느리면 에이전트가 매 작업마다 긴 코드를 다시 읽느라 시간을 많이 쓰게 된다.

### [02:33–03:16] 추론의 두 구간 ②: 디코드와 대역폭 산수
반대로 디코드에서는 메모리 대역폭의 영향이 커진다. 한 명의 사용자가 한 토큰씩 답을 받아보는 상황에서는 매 토큰을 생성할 때마다 거대한 모델 가중치를 메모리에서 계속 읽어와야 하기 때문이다. 화자는 이를 단순화한 산수로 설명한다 — 양자화된 dense 모델의 가중치가 100GB이고 토큰 하나를 만들 때 그 100GB를 한 번 훑는다고 가정하면, 800GB/s에서는 이론적으로 초당 약 8번, 1.2TB/s에서는 약 12번이 된다.

> "실제 속도가 정확히 8토큰이나 12토큰으로 나온다는 뜻은 아닌데요. 그래도 왜 메모리 대역폭이 50% 늘어난 게 로컬 LLM에서 중요한지는 이 정도만 봐도 감이 오죠." [03:04]

정리하면 M3 Ultra에도 큰 모델을 담을 512GB 메모리는 있었고, 이번에는 **그 모델을 움직이는 통로가 더 넓어진 것**이다.

### [03:16–04:07] M시리즈 최초의 4다이 구조와 차세대 울트라 퓨전
M5 Ultra의 구조도 그 방향에 맞춰 꽤 크게 바뀌었다. 이번 M5 Ultra는 M시리즈 최초의 **4다이 구조**로, 두 개의 듀얼 다이 M5 Max를 다시 차세대 울트라 퓨전으로 묶었다. 물리적으로는 네 개의 실리콘 다이지만 소프트웨어에서는 하나의 거대한 프로세서처럼 동작하도록 만든 구조다. 칩을 여러 조각으로 나누면 제조에는 유리하지만 다이 사이 통신이 느려지면서 전체 성능이 떨어지므로, 울트라 퓨전은 패키징 단계에서 다이와 다이 사이에 굉장히 많은 고속 신호선을 연결한다. 이번 세대에서는 그 **연결 밀도가 이전보다 6배 이상 높아졌고, 다이 간 대역폭은 4.4TB/s 이상까지 올라갔다**.

### [04:07–04:19] 두 숫자의 역할 구분
화자는 숫자 혼동을 명시적으로 막는다. 앞서 말한 1.2TB/s는 **통합 메모리 대역폭**이고, 4.4TB/s는 네 개의 다이를 하나처럼 묶어주는 **내부 연결 속도**다. 둘 다 큰 숫자지만 역할은 서로 다르다.

### [04:19–04:53] "그래서 어떤 모델을 돌릴 건데?" — 몇 년 전의 빈틈
하드웨어가 여기까지 좋아졌어도 몇 년 전이라면 한 가지 문제가 남았을 것이다. 그래서 과연 어떤 모델을 돌릴 것인가. 당시에는 성능이 정말 좋은 모델들이 OpenAI·구글·Anthropic 같은 회사 서버 안에 있었고, 개인이 직접 받을 수 있는 모델과는 성능 차이가 컸다. 그런데 지금은 이 간격이 굉장히 빠르게 줄고 있다. 최근 공개된 [불명확: 원문 "QN 3.8 27빌리언" — Qwen 계열 모델로 추정되나 정확한 명칭 불확실] 같은 경우 **270억 파라미터 규모의 멀티모달 모델**을 직접 내려받아 쓸 수 있다.

### [04:53–05:16] MLX 변환본이 곧바로 따라오는 생태계
그리고 맥에서는 이런 모델이 공개되면 얼마 지나지 않아 **MLX용 버전**도 따라온다. 원본 모델을 받아 애플 실리콘에 맞게 직접 변환하고 양자화하고 실행 환경을 처음부터 만들 필요가 없다는 뜻이다. 위 모델도 이미 4비트·8비트 같은 여러 MLX 변환본이 올라왔고, **MTP(멀티 토큰 예측)를 스페큘레이티브 디코딩에 활용할 수 있게 만든 드래프트 모델**까지 나왔다.

### [05:16–05:42] MLX가 하는 역할
MLX는 애플 머신러닝 연구팀이 만든 애플 실리콘용 오픈소스 프레임워크다. 그 위에 MLX LM이 있어서 모델을 불러오고 양자화하고 파인튜닝하고 실행하는 작업을 비교적 간단하게 할 수 있다. 허깅페이스의 MLX 커뮤니티에는 이미 수천 개 모델이 올라와 있고, 새 오픈 모델이 공개되면 맥에서 돌릴 수 있는 버전이 상당히 빠르게 따라온다.

### [05:42–06:07] WWDC의 로컬 OpenAI 호환 서버 시연
올해 WWDC에서는 아예 **MLX LM 서버를 이용해 OpenAI API와 호환되는 로컬 서버를 만드는 방법**까지 직접 보여줬다. 맥에 모델을 띄워 놓고 기존 코딩 에이전트의 API 주소만 로컬로 바꾸는 식이다.

> "그러면 에이전트 입장에서는 뒤에 있는 모델이 클라우드 서버에 있는지, 아니면 제 책상 위에 맥 스튜디오에서 돌아가는지를 크게 신경 쓸 필요가 없는 거예요." [05:57]

### [06:07–06:18] MLX의 위상에 대한 화자 해석
[의견] 이 정도까지 오면 MLX는 "애플이 하나 더 만든 머신러닝 프레임워크" 정도가 아니라, **새로운 오픈 모델이 나왔을 때 애플 실리콘으로 가져오는 통로**가 상당히 잘 만들어지고 있는 것이라고 화자는 평가한다.

### [06:18–06:47] 애플 자체 모델 3세대와 NAND 상주 MoE 방식
애플 자체 모델도 멈춘 게 아니다. 올해 애플은 **구글과 함께 만든 3세대 애플 파운데이션 모델**을 공개했다. 기기 안에서 돌아가는 온디바이스 모델과 프라이빗 클라우드 컴퓨트에서 돌아가는 서버 모델을 따로 두고 있고, 가장 큰 온디바이스 모델은 전체 규모가 **약 200억 파라미터**까지 올라왔다. 이 모델도 메모리 문제를 꽤 적극적으로 다루는데, **전체 가중치를 NAND에 저장해 두고 요청에 필요한 전문가(expert) 일부만 DRAM으로 가져오는 방식**을 쓴다.

### [06:47–07:12] 그 설계가 피하려는 병목
NAND는 DRAM보다 훨씬 느리기 때문에 매 토큰마다 전문가를 계속 바꿔버리면 병목이 굉장히 커진다. 그래서 처음 요청을 처리할 때 필요한 전문가를 골라두고 생성 중에는 데이터 이동을 줄이는 방향으로 설계했다. 화자는 여기서 같은 주제가 반복된다고 짚는다 — 모델이 커질수록 **얼마나 많이 계산하느냐 못지않게, 가중치를 어디에 두고 얼마나 빨리 가져오느냐**가 진짜 중요해지고 있다는 것.

### [07:12–07:43] 엔비디아 데이터센터와 비교하지 않는 이유
물론 맥 스튜디오와 엔비디아 데이터센터 GPU를 단순 비교할 필요는 없다. 최신 HBM을 쓰는 AI 가속기는 메모리 대역폭 자체가 몇 TB/s 단위이고, 대규모 학습이나 수많은 사용자를 동시에 처리하는 서버에서는 엔비디아가 훨씬 강하다. 맥 스튜디오의 위치는 다르다 — **한 명의 사용자가 책상 위 컴퓨터 한 대에서 GPU가 접근 가능한 수백 GB 메모리를 거의 통째로 쓰면서 상당히 큰 모델을 계속 돌릴 수 있다**는 데 의미가 있다.

### [07:43–08:09] 예전과 달라진 지점, 그리고 남는 질문
예전에는 좋은 로컬 하드웨어를 갖춰 놓고도 결국 중요한 작업은 클라우드 모델에 물어보는 경우가 많았다. 지금은 새 모델이 공개되고 → MLX 변환본이 나오고 → 로컬 서버로 띄워 기존 에이전트에 연결하는 과정까지 굉장히 빨라졌다. 그래서 남는 질문은 하나, **"이게 얼마나 빠르게 돌아가느냐"** 다.

### [08:09–08:24] 화자의 구매 고민
[의견] 화자는 512GB짜리 M5 Ultra를 실제로 살지 말지 고민 중이라고 밝힌다. 가격을 생각하면 콘텐츠 하나 찍겠다고 쉽게 덜컥 살 만한 물건은 아니라는 것.

### [08:24–08:50] 구비한다면 해볼 세 가지 테스트
1. 실제로 쓸 수 있는 **가장 큰 오픈 모델**을 올렸을 때 디코드 속도가 몇 토큰/초까지 나오는지.
2. 위 Qwen 계열 모델에 **MTP 드래프터를 붙여 스페큘레이티브 디코딩**을 했을 때 체감 속도가 얼마나 더 올라가는지.
3. **코딩 에이전트를 몇 시간씩 계속 돌려도 클라우드 API 대신 로컬 모델을 쓸 만한지.** 화자는 이 마지막 테스트가 가장 궁금하다고 말한다.

### [08:50–09:13] 속도가 갈라놓는 두 시나리오
[의견] 로컬 모델이 충분히 똑똑해도 초당 겨우 두세 토큰이라면 결국 손이 잘 안 갈 것이다. 반대로 큰 모델이 충분한 속도로 나오고 긴 코드베이스를 읽는 프리필까지 빨라진다면 사용 방식 자체가 달라질 것 같다고 본다 — 토큰 사용량을 계속 신경 쓰지 않고 에이전트를 오래 돌려 놓을 수도 있고, 외부 서버로 보내기 싫은 코드나 문서도 전부 로컬에서 처리할 수 있다는 것.

### [09:13–09:32] 그동안의 애플 평가
애플 인텔리전스가 처음 나온 뒤 애플은 AI 경쟁에서 계속 뒤처졌다는 평가를 받아왔다. 새로운 Siri는 늦어지고, OpenAI·구글·Anthropic이 프런티어 모델 성능을 빠르게 올리는 동안 애플 자체 모델의 존재감은 상대적으로 약했다.

### [09:32–09:53] 지금의 세 갈래 진전
그런데 지금은 ① 애플도 자체 파운데이션 모델을 3세대까지 끌어올렸고, ② 구글과 협력하며 외부 모델도 받고 있고, ③ MLX를 통해 오픈 모델까지 애플 실리콘 위로 가져오고 있다. 화자는 그 결과 **세상에 좋은 오픈 모델이 새로 등장할수록, 애플이 직접 그 모델을 학습하지 않았는데도 맥에서 할 수 있는 일이 같이 늘어난다**고 정리한다.

### [09:53–10:21] 경쟁축이 넓어지면 애플의 자산이 작동한다
[의견] 이때 애플이 이미 가진 것들이 크게 작용한다 — 애플 실리콘을 직접 설계하고, 통합 메모리 구조를 만들고, macOS와 개발 도구를 같이 가져가면서 MLX까지 자기 플랫폼에 맞춰 만들어 왔다는 점이다.

> "AI 모델 하나만 놓고 경쟁을 할 때는 애플이 분명히 불리했거든요. 그런데 경쟁의 일부가 '좋은 모델을 어떤 기기에서 얼마나 빠르고 편하게 오래 돌릴 수 있느냐' 이걸로 넓어지게 되면 애플이 원래 잘하던 영역과 다시 겹치기 시작합니다." [10:06]

### [10:21–10:58] 마무리 — 512GB보다 1.2TB/s
그래서 이번 M5 Ultra에서 512GB보다 1.2TB/s가 더 눈에 들어왔다는 것이 화자의 결론이다. 큰 모델을 넣을 메모리는 이미 있었고, 그 사이 쓸 만한 오픈 모델도 많아졌고 MLX 생태계도 빠르게 컸다. 이제 **그 모델을 실제로 쓸 만큼 빠르게 움직일 수 있는지**가 남았다. 만약 M5 Ultra를 구비하게 된다면 "이 모델이 실행됩니다"가 아니라 실제로 몇 토큰/초가 나오는지, 프리필은 얼마나 빠른지, 하루 종일 로컬 에이전트를 돌려 놓을 만한 컴퓨터가 됐는지까지 직접 확인해 보고 싶다며 영상을 마친다.
